### 1.2 需求摘要

> 从开发设计文档提炼，**禁止超出文档范围**。

**业务目标**：优化平台无权限提示气泡（NoPermissionPopover.vue）的使用体验——让用户能从气泡一键到达权限申请/成员管理路径，并去除与普通用户日常申请无关的 platform（system）/组织（product）级角色组噪音。

**核心功能点**：

1. **申请指引链接跳转**：气泡「申请指引」按角色归属级别渲染可点击链接
   - 项目级（project）：指引文案中「项目管理->成员管理」变可点击链接，点击跳转 `/apps/noPermissionApply?showApply=true`（复用现有权限申请页，到达后自动弹出申请弹窗：组织/项目/角色/审核人）
   - 仓库级（repo）：指引文案中「代码仓管理->成员管理」变可点击链接，点击跳转 `/apps/repos?projectId=&repoId=&showRepoUserManage=1`（代码仓管理页自动打开对应仓库成员管理）；当前使用场景未传入 repoId 时，该链接降级为纯文本
   - 通用（general）：保持纯文本「联系人工客服进行咨询」
2. **角色组过滤**：无权限气泡的角色归属展示只过滤掉 platform（system）、组织（product）两级角色组，保留项目（project）、仓库（repo）、通用（general）
3. **空态**：过滤后无任何角色组可展示时，显示原空态文案「暂无角色配置信息，请联系项目管理员或通过服务单咨询。」（文案不变，展示条件由「后端 rolesByLevel 为空」调整为「过滤后为空」）

**业务规则/边界**：
- 链接渲染与角色归属级别强绑定：project→权限申请页、repo→代码仓成员管理、general→纯文本
- repo 级链接在未传入 repoId 时降级纯文本（降级不影响其他场景）
- 空态判定基于过滤后结果而非后端原始返回

**异常场景**：无 repoId 的 repo 级指引、过滤后角色组为空、全部为 system/product 角色组、混合级别角色组。

### 1.5 测试策略

- 手工测试：覆盖角色组过滤（system/product 剔除、project/repo/general 保留、混合组合、过滤后为空）、申请指引链接渲染（project/repo/general 三级）、链接跳转行为（权限申请页弹窗、代码仓成员管理打开、无 repoId 降级纯文本）、空态文案。需低权限账号触发真实无权限气泡，或通过页面数据构造角色组组合验证。
- 自动化测试：气泡为全局组件、触发路径依赖真实无权限场景，首选手工验证 + 截图证据；如环境稳定可对角色组过滤/链接渲染做 `auto_ui` 脚本，脚本位置 `src/automation/software_implementation_ci_toolchain/ui/no_permission_popover/`（待 Stage 3 确认）。
