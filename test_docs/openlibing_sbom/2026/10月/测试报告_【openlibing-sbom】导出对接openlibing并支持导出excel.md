## 5. 补充说明

本次需求涉及 openlibing-web（前端导出入口）、openlibing-sbom（sbom-web，两个提交接口与导出执行器）、openlibing-framework（任务记录/状态机/签名 URL/过期清理，零改动）三个服务，纯导出能力改造，无表结构变更。评审定案以 2026.10.22 评审修改点优先于设计初稿：类型组件与置灰行为、弹窗标题、气泡文案、声明文档仍为同步、异步采用线程池（不使用 MQ）均按评审口径验证。全部 13 条用例（P0×3 / P1×9 / P2×1，均为手工）按「页面操作取证 + 下载文件解析 + framework `/export/detail` 任务记录 + 服务日志 + OBS 对象」多通道取证；Excel 内容断言以 xlsx 解析统计行数与逐列比对，SBOM 文档与同步导出基线采用结构化比对避免序列化顺序误判。缺陷 issue #161 为 TC-ISSUE146-004（Excel 列口径与数据一致性）执行中发现并已回归通过。故障注入类用例（线程池饱和/拒绝、OBS 不可达、生成异常、进程重启）在测试环境执行后已恢复线程池参数与 OBS 连通性，并复核无残留任务与临时文件。安全 6 维度声明：认证校验由 TC-ISSUE146-011 未登录 401/403 间接覆盖；横向越权由 TC-ISSUE146-012 覆盖；纵向越权豁免（不新增角色与权限点，导出权限与制品列表同源）；传输安全豁免（提交走 HTTPS 网关，下载走 framework 既有 OBS 签名 URL，本需求零改动）；CSRF 豁免（无新增浏览器跨域表单入口，沿用平台既有防护）；敏感信息防护豁免（OBS AK/SK 解密与 task data 由既有实现承载，零改动）。DFX 仅记录观察值：20 万包 Excel 导出内存峰值未随全量线性增长、并发 2 个 Excel 均完成、Excel 与文档两线程池互不阻塞、连续文档任务串行且内存不叠加、无 OOM/连接耗尽；需求未给出耗时与内存硬阈值，故不做阈值判定。本期不测范围：framework 任务记录/状态机/签名 URL/过期清理逻辑；SPDX/CycloneDX Writer 实现（复用 `writeSbom`）；线程池容量与拒绝策略参数调优（部署侧）；多实例部署下的任务分发治理（线程池为进程内执行，不提供跨实例投递）；声明文档异步化（后续排期）。本期不产出自动化脚本——导出链路依赖 gateway 登录态、framework 任务记录、线程池异步执行与 OBS，本地无法构建；后续可在测试环境以 API + 轮询方式脚本化「提交 → 轮询 → 下载校验」。
