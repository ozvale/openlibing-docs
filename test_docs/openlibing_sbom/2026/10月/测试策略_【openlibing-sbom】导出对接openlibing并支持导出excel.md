# 导出对接openlibing并支持导出excel 测试策略设计说明书

## 1. 基本信息

- **对应task(issueID)链接**: https://gitcode.com/openlibing/openlibing-sbom/issues/146
- **需求名称**: 【openlibing-sbom】导出对接openlibing，并支持导出excel
- **核心目标**:
  当前 sbom 仅支持导出 SPDX / CycloneDX 规范文档，需支持导出 Excel 全量数据并对接 openlibing 导出框架。交付内容：①「全量导出」弹窗新增「类型」组件区分「软件物料清单（SBOM）」与「软件成分数据（.xlsx）」，选 Excel 后下方条件框置空置灰（弹窗尺寸不跳变），「导出SBOM信息」弹窗标题改为「导出软件物料清单（SBOM）」，全量导出气泡文案同步修改；②新增 `POST /sbom-api/exportSbomExcel`（type=SBOM_PACKAGE，Excel 线程池并发 2）与 `POST /sbom-api/exportSbomDocument`（type=SBOM_DOCUMENT，文档线程池并发 1），共用编排为 framework `/export/internal-server/create` 建任务 → 提交线程池 → 异步线程 CAS 抢占 → 生成本地临时文件 → CAS（正在上传文件）→ OBS 上传 → CAS 回写成功与 objectKey；失败回写「导出失败：原因」（截断 500 字符），finally 删除临时文件；③Excel 生成按分页游标全量取数（size=500）→ EasyExcel 多 Sheet（10 万行/Sheet），列口径 14 列（软件包名称/版本、依赖类型/语言类型/包管理器类型、严重/高危/中危/低危/无风险/未知、License、PURL、Supplier/来源信息）；④异步采用线程池（不使用 MQ），双线程池隔离；声明文档导出本期仍为同步；`exportSbom` / `exportSbomOptions` 保留不变；⑤状态文案契约「导出任务已创建 / 导出文件生成中 / 正在上传文件 / 导出成功」，失败前缀「导出失败」，《我的导出》新增类型标签 `SBOM_PACKAGE: 'SBOM包清单'`、`SBOM_DOCUMENT: 'SBOM文档'`。
- **开发责任人**: 陈明旭
- **测试责任人**: 赵威

## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1.全量导出弹窗类型切换与交互约束验证**:

- 前置条件: 测试环境已部署本需求版本；账号已登录且有制品权限；已取得评审定稿的 UI 文案（类型选项、弹窗标题、气泡文案）
- 测试步骤:
  1. 展开导出下拉菜单，断言仍为「全量导出」「声明文档」两项
  2. 点击「全量导出」，断言弹窗标题为「导出软件物料清单（SBOM）」且新增「类型」组件
  3. 断言类型选项为「软件物料清单（SBOM）」「软件成分数据（.xlsx）」
  4. 选择 Excel，断言三级联动条件框置空置灰且弹窗尺寸不跳变
  5. 切回 SBOM，断言条件框恢复可用且尺寸稳定（录屏取证）
  6. 悬停「全量导出」，断言气泡文案已更新
  7. 关闭重开，断言类型恢复默认无残留
  8. 断言「声明文档」入口仍存在
- 预期结果: 菜单两项不变；标题正确；类型切换与置灰行为正确；气泡文案更新；无状态残留

**2.SBOM规范文档异步导出端到端验证**:

- 前置条件: 测试环境已部署；制品有 SBOM 数据；账号有权限；OBS 与文档导出线程池可用；已记录同步导出基线文件
- 测试步骤:
  1. 类型选 SBOM，选择合法规范组合提交
  2. 断言请求发往 exportSbomDocument，参数完整并返回 recordId
  3. 断言浮窗出现且任务名含制品名与规范版本
  4. 断言状态依次流转四段文案（导出任务已创建 / 导出文件生成中 / 正在上传文件 / 导出成功）
  5. 断言成功后自动下载
  6. 校验文件名 `<制品名>---sbom.<json|xml|yaml>`
  7. 解析文件，断言规范内容合法、包列表一致
  8. 与同步导出基线结构化比对，断言内容一致
  9. 《我的导出》断言类型标签「SBOM文档」
- 预期结果: 提交成功、状态流转正确、自动下载、内容与同步导出一致

**3.软件包清单Excel全量导出端到端验证**:

- 前置条件: 制品包数据完整（建议 ≥1000）；账号有权限；OBS/Excel 导出线程池可用；已记录全量总条数与当前筛选条件
- 测试步骤:
  1. 先设置列表筛选并记录筛选后/全量条数
  2. 类型选 Excel，确认条件框置灰
  3. 提交，断言请求发往 exportSbomExcel 并返回 recordId
  4. 断言状态流转至成功并自动下载
  5. 打开 Excel，断言表头为 14 列
  6. 统计数据行数，断言等于全量包数（不受筛选影响）
  7. 抽查行与页面比对
  8. 断言任务名含软件包清单语义、《我的导出》标签「SBOM包清单」
  9. 断言 objectKey 已回写
  10. 重复导出，断言行数与表头稳定
- 预期结果: 全量导出成功，行数=全量总数，14 列表头，标签正确

**4.Excel导出列口径与数据一致性验证**:

- 前置条件: 准备统计完整制品 P1 与部分无统计制品 P2；含多 License 与无 License 的包；已记录页面列展示值作为基线
- 测试步骤:
  1. 导出 P1，逐列断言来源字段（package.name / package.version / dependencyType / language / pkgManagerType）
  2. 断言严重/高危/中危/低危/无风险/未知六列与 packageStatistics 对应
  3. 断言 License 逗号拼接且按 licenseId 排序无重复
  4. 断言 PURL/Supplier/来源信息正确
  5. 导出 P2，断言无统计时回退 externalVulRefs 且与页面一致
  6. 断言语言/包管理器缺失导出 Others
  7. 断言 PURL 为空取主 PURL（记录规则）

**5.零数据与Sheet分片导出验证**:

  2. 导出 Z1，断言 1 行数据
  3. 导出 Z2，断言多 Sheet 递进命名

  6. 抽查跨 Sheet 首尾，断言无重复跳行
  7. 断言每个 Sheet 带表头
  8. 断言文件可正常打开
- 预期结果: 零数据保表头；分片大小与总行数正确；无丢失/重复

**6.异步任务状态机与进度浮窗验证**:

- 前置条件: 可提交常规与慢任务；可查看 `/export/detail` 与浮窗；已获取状态文案契约
- 测试步骤:
  1. 提交较大文档任务，记录 detail 状态
  2. 断言浮窗四段文案逐字一致且按序流转

  7. 断言超时后仍可刷新并获得最终状态与下载
  8. 关闭浮窗后任务继续，重开可见最新状态
  9. 断言重复轮询不重复下载
- 预期结果: 文案与契约一致、单向流转、成功后下载；超时不终止后端任务

**7.我的导出记录与类型标签验证**:

- 前置条件: 已提交并完成两类任务；账号可访问《我的导出》；已确认 framework 记录存在
- 测试步骤:
  1. 断言两条任务可见且倒序
  2. 断言标签分别为「SBOM包清单」「SBOM文档」
  3. 断言任务名规则正确
  4. 断言详情展示状态/时间/大小/失败原因
  5. 断言成功任务可下载且文件名正确
  6. 断言进行中任务无下载入口
  7. 断言既有类型标签无回归
  8. 换账号断言仅见本人任务
  9. 记录任务保留周期（3 天清理为 framework 既有能力）
- 预期结果: 标签正确、任务名正确、状态完整、按用户隔离、既有类型无回归

**8.失败链路与异常兜底验证**:

- 前置条件: 测试环境可调整线程池参数（核心/最大线程数、队列容量、拒绝策略）或具备开发提供的故障开关，故障可逆；可重启服务实例；可查看服务日志、任务 message、OBS 对象与本地临时目录；已记录正常链路基线
- 测试步骤:
  1. 占满 Excel 导出线程池后提交导出，断言接口失败或回写「导出失败：任务提交失败：…」，不遗留假成功
  2. 恢复线程池参数/执行器后重提，断言成功
  3. 使 OBS 不可达或使用错误 AK/SK，断言「导出失败：OBS 上传失败」
  4. 断言上传失败后本地临时文件已被 finally 删除
  5. 构造生成阶段异常，断言回写「导出失败：原因」且截断不超过 500 字符
  6. 断言失败任务在《我的导出》可见、状态「导出失败」且无下载入口
  7. 提交大制品导出后立即重启实例，断言不假成功、无半成品 OBS 对象、状态停留「导出任务已创建」
  8. 记录步骤 7 任务在《我的导出》的表现与 framework 3 天清理行为
  9. 模拟任务先被置失败再执行，断言 CAS 不覆盖失败态
  10. 恢复所有故障注入，断言环境与数据复原
- 预期结果: 各异常均回写明确失败原因（前缀「导出失败」），不出现假成功；临时文件在所有失败路径清理、原因截断 500 字符；进程重启后不产生半成品文件；失败态不被后续 CAS 覆盖

**9.重复提交防抖与重复执行幂等验证**:

- 前置条件: 测试环境已部署；可观察任务列表与异步执行日志；具备重复提交同一 recordId 到线程池的手段（调试入口/接口重放）；可访问 OBS 对象列表与本地临时目录
- 测试步骤:
  1. 连续快速点击「确认」5 次，断言仅 1 次请求与 1 个任务，按钮提交中禁用
  2. 断言浮窗仅 1 条任务
  3. 对同一 recordId 重复提交到线程池 2 次，断言仅一次 CAS 抢占成功，其余直接 return
  4. 断言 OBS 仅 1 个 objectKey 对应对象，无重复上传
  5. 断言任务记录仅回写一次「导出成功」，状态不回退
  6. 断言重复执行未产生额外临时文件残留
  7. 双击《我的导出》任务下载，断言不重复建任务、仅触发下载
  8. 进行中再次提交同制品同类型，断言可建独立新任务且各自 objectKey 互不干扰
  9. 断言合理间隔可正常提交（防抖不吞合法新任务）
- 预期结果: 前端防抖生效只建 1 个任务；同一 recordId 重复执行被 CAS 拦截，无重复 OBS 对象与重复回写；进行中再次提交可创建独立新任务

**11.导出提交接口契约与参数校验验证**:

### 3.2 安全与隐私测试专项

**12.横向越权导出防护验证**:

- 前置条件: 账号 A/B 各有权限制品 P_A/P_B，互相无权限；可调用两个提交接口；可查任务与 OBS
- 测试步骤:
  1. A 正常导出 P_A，断言成功
  2. A 导出 P_B（Excel），断言拒绝且无任务/OBS
  3. A 导出 P_B（文档），断言拒绝
  4. A 篡改 userId 为 B 再导出 P_B，断言仍拒绝
  5. B 反向导出 P_A，断言拒绝
  6. 不存在/他租户制品，断言不泄漏存在性
  7. 断言《我的导出》无拒绝记录
  8. 断言 B 无法查询/下载 A 的 recordId
  9. 代码审查权限口径与列表查询一致（checkPermissionByProductType）
  10. 清理并确认无越权产物
- 预期结果: 越权导出全部被拒且无产物；篡改 userId 无效；任务与下载按用户隔离

### 3.3 性能与伸缩性测试专项

**13.大数据量导出性能与内存占用验证**:

- 前置条件: 准备 ≥20 万包制品与超大文档制品；可获取 Pod 监控与任务耗时；测试环境资源独享

  2. 提交 20 万包 Excel，记录总/生成/上传耗时

  4. 观察业务接口 P95 变化
  5. 并发 2 个 Excel，断言 Excel 线程池并发 2 且均完成
  6. 并发 Excel+文档，断言两线程池独立执行、互不阻塞
  7. 连续 3 个文档，断言文档线程池串行且内存不叠加
  8. 观察 5 分钟超时提示与最终成功
  9. 断言无 OOM/连接耗尽/卡死
  10. 记录文件大小与 Sheet 数
- 预期结果: 内存受控、线程池并发隔离生效、业务可用、无 OOM；超时提示不影响任务
