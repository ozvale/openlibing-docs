# ICSL安全送检排查及整改（SBOM范围） 测试策略设计说明书

## 1. 基本信息

- **对应task(issueID)链接**: https://gitcode.com/openlibing/openlibing-codecheck/issues/372
- **需求名称**: 【openLiBing】ICSL安全送检排查及整改（SBOM 范围）
- **核心目标**:
  完成 ICSL 送检安全问题的排查、分析与修复，保障 openlibing 送检。本策略仅覆盖 SBOM 相关范围（openlibing-sbom、openlibing-sbom-tools 两仓），按 12 类安全变更类型组织 12 条场景级用例，不逐条展开到单个 issue。SBOM 范围共采集安全问题 109 条（openlibing-sbom 46 条、openlibing-sbom-tools 63 条），其中 closed / 修复已合入 7 条（openlibing-sbom#84、#120，openlibing-sbom-tools#17~#21），其余 102 条为 open 未修复，按「不计入」口径剔除、不进入分母。判定采用「负向拒绝 + 正向回归」配对：先验证原攻击/越权/注入载荷被拒绝，再验证合法业务行为与整改前一致；每条场景用例的覆盖对象为 `执行记录跟踪表.xlsx` 对应明细 sheet，聚合规则 fail > block > skip > pass。
- **开发责任人**: 陈洪亮/陈明旭
- **测试责任人**: 赵威

## 3. 专项验证设计和执行详情

### 3.1 安全与隐私测试专项

**1.认证鉴权与越权整改验证（P0）**:

- 前置条件: beta 测试环境可用，明细 sheet 中已修复 issue 满足 closed 或修复 PR 已合入；高权/低权账号（SECURITY_HIGH_PRIV_USER / SECURITY_LOW_PRIV_USER）与跨租户数据可用；覆盖 openlibing-sbom 写路径与解压链路（含 #96 内存缓冲与 GZIP 解压场景）
- 测试步骤:
  1. 按「01_认证鉴权与越权」明细 sheet 逐条定位已修复 issue 涉及接口/页面，记录原始攻击载荷
  2. 匿名（无 token）调用接口，记录状态码与响应，断言鉴权拦截且不返回业务数据
  3. 低权限账号调用同一接口，断言 403 且无数据泄漏
  4. 构造空白/空 userId 与伪造身份调用，断言不再默认放行（#95/#102/#103/#138 类问题）
  5. 高权限账号执行同一操作，断言功能正常（正向回归）
  6. 记录请求/响应截图、服务端日志与任务记录作为证据，回填明细 sheet
- 预期结果: 已修复的认证/鉴权/越权问题在匿名、低权、跨租户三种身份下均不可利用；合法用户功能不变；证据可追溯

**2.敏感数据与凭证治理验证（P0）**:

- 前置条件: 可访问两仓配置文件、镜像构建产物、服务日志与 trace 输出目录；明细 sheet 中已修复项为 openlibing-sbom-tools#17~#21（SENS 系列）
- 测试步骤:
  1. 检索配置与镜像层，断言无 AK/SK、口令、git 凭证明文（#86/#104/#108 类）
  2. 触发构建与扫描链路，检查 trace_data、execsnoop/sslsni 日志，断言凭证明文已脱敏或不再落盘（#17~#21）
  3. 检查服务日志与异常输出，断言无 SBOM 明文内容与凭据（#124/#139）
  4. 验证缓存/临时目录清理行为，断言凭证不再残留
  5. 执行一次合法构建与上传，断言功能正常（正向回归）
  6. 保存检索命令输出与脱敏前后对比作为证据
- 预期结果: 凭证与敏感数据不再以明文出现在配置、镜像、日志与缓存中；合法链路正常

**3.输入校验与注入防护验证（P1）**:

- 前置条件: 可调用 sbom-web 相关接口与 sbom-tools 外部参数入口；具备构造 XXE/注入载荷能力
- 测试步骤:
  1. 提交含外部实体与 DTD 的 XML/SBOM 文件，断言 XXE 被拦截（#97/#132）
  2. 构造 SQL/日志注入与特殊字符参数，断言转义或校验生效（#143/#144/#79）
  3. 对外部参数（task_id、落盘路径、服务地址、正则配置）传入非法值，断言校验拒绝（sbom-tools#55~#60）
  4. 提交缺失必填/超长/类型错误参数，断言明确校验错误
  5. 使用合法文件与合法参数回归，断言解析与业务正常
  6. 记录请求响应与日志证据
- 预期结果: 注入与非法参数全部被拒，无异常堆栈外泄；合法输入功能正常

**4.SSRF与外连安全验证（P0）**:

- 前置条件: 服务部署于可访问内网与公网的测试环境；可构造 URL 类入参
- 测试步骤:
  1. 向 URL 类参数提交内网地址、回环地址、云元数据地址，断言拒绝或不可达（#107 及 tools 相关项）
  2. 构造 302 重定向指向内网，断言重定向后仍被拦截
  3. 构造域名解析到内网的 DNS 场景，断言校验生效
  4. 检查重定向 URL 日志，断言签名参数未明文打印
  5. 使用合法外网地址回归，断言请求正常
  6. 记录请求响应与网络日志
- 预期结果: 内网/元数据/重定向绕过均不可达；日志无时效签名明文；合法外连正常

**5.路径穿越与文件处理验证（P1）**:

- 前置条件: 可上传/下载 SBOM 包与归档文件；可访问临时目录与 OBS 对象列表
- 测试步骤:
  1. 构造含 `../` 的归档条目（ZipSlip）上传，断言解包拦截（#92/#125/tools#65）
  2. 构造恶意 OBS objectKey 与下载参数，断言落盘路径校验生效（#126/#68）
  3. 上传非白名单类型文件，断言拒绝（#128）
  4. 验证签名/下载临时文件用后清理（#129/#137）
  5. 合法包上传下载回归，断言文件完整可用
  6. 检查目标目录与临时目录无越界写入残留
- 预期结果: 路径穿越与任意写入被拒，临时文件清理彻底；合法文件处理正常

**6.命令注入与不可信执行验证（P0）**:

- 前置条件: 具备 sbom-tools 运行环境与 fork PR 测试仓库；可构造被扫描工程内容
- 测试步骤:
  1. 在目标工程植入恶意 setup.py / 构建脚本，断言不执行 pip install 或外部命令（tools#46/#62）
  2. 构造 trace 日志驱动重执行场景，断言不可信输入不被执行（#63）
  3. 使用 fork PR 提交带 secret 的 workflow 代码，断言密钥不可读取（#64）
  4. 构造 task_id 与参数注入，断言管道拆分与参数传递安全（#42/#54）
  5. 正常工程扫描回归，断言 SBOM 生成正常
  6. 记录执行日志与进程树证据
- 预期结果: 不可信代码/命令不被执行，fork PR 无法获取凭证；正常扫描功能正常

**7.传输与Web安全基线验证（P1）**:

- 前置条件: 可通过 HTTPS/HTTP 访问服务入口；具备响应头与 TLS 检查工具
- 测试步骤:
  1. 检查响应安全头（CSP、X-Frame-Options、HSTS 等）与 Cookie 属性，断言符合基线（#111/#141）
  2. 构造包名等入参写入 Content-Disposition，断言已编码无头注入（#111）
  3. 尝试 HTTP 明文访问与不安全加密套件，断言拒绝或重定向（tools#32/#78）
  4. 校验 Fulcio/服务端证书校验开关，断言默认不可跳过
  5. 验证 CSRF 防护对写接口生效（#141）
  6. 页面正常操作回归，断言功能不受影响
- 预期结果: Web 安全基线与 TLS 要求满足，头注入与 CSRF 不可利用；业务正常

**8.弱算法与签名重放验证（P1）**:

- 前置条件: 可获取上行请求与签名实现；可重放已捕获请求
- 测试步骤:
  1. 抓取上行请求，断言签名覆盖报文体与关键字段（tools#48）
  2. 篡改报文体后重放，断言签名校验失败
  3. 原请求重复重放，断言时间戳/防重放机制拒绝重复请求
  4. 检查算法与密钥长度，断言无 MD5 等弱算法
  5. 验证 sbom-tracer 不以 root 重放不可信参数（#43）
  6. 合法请求回归，断言验签与业务正常
- 预期结果: 签名覆盖完整、重放与篡改被拒、无弱算法；合法请求正常

**9.拒绝服务与资源滥用验证（P1）**:

  6. 记录耗时、内存与错误响应
