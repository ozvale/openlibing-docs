## 5. 补充说明

本次被测对象为 sbom-action（GitCode 插件仓，单文件 Node action，非团队成员微服务，用例编号前缀 `TC-ISSUE001-NNN`）。无独立 Web 界面，全部 13 条用例（P0×3 / P1×9 / P2×1，均为手工）在 GitCode 流水线中以「job 日志 + action output（ATOMGIT_OUTPUT / ATOMGIT_STEP_SUMMARY）+ openlibing-sbom 平台任务详情」三方取证方式执行。入参定案以需求评论区与需求串讲为准：attribute 平铺为一级 input、trivy-version 与 sbom-output 移除（工具版本与输出路径由插件内置，用户参数无法覆盖）、project_name 可选并基于 gitUrl 反查社区，多匹配按串讲定案「默认取一」（设计文档「报错要求显式指定」一说不作为判定依据，实际实现结果已在 TC-ISSUE001-004 中记录）。addProduct 上报 gitUrl 覆盖 gitcode 与 atomgit 双域名及 HTTPS/SSH 两种 remote 形式，反查结果一致。OIDC 链路（ID Token → STS → APIW V11 签名）本地无法复现，全部在云端执行机验证；缺失 `permissions: id-token: write` 时启动即失败并给出可操作指引，且不产生平台副作用。上传链路按 `addProduct`（already exists 容忍）→ `publishSbomFile`（`spdx_2.2_json_sbom`，202 `{success, taskId, errorInfo}`）验证，nightly 重跑产品全局唯一、任务按次新增。env=prod（`https://apig.openlibing.com:443`）与 env=test（`https://f209a4ca505e492b96d2dc70f5578641.apic.cn-southwest-2.huaweicloudapis.com`）数据落点隔离已确认。安全 6 维度中：认证校验与敏感信息防护覆盖（TC-003 / TC-012 / TC-013），横向越权、纵向越权、CSRF 因无多用户资源入口与 Web 会话而豁免，传输安全由 HTTPS 网关切换间接覆盖。本期不测范围：openlibing-sbom 服务端 productType 反查逻辑实现（跨仓，插件侧仅做 gitUrl 采集与上报）、CodeArts 存量流水线改造、trivy 检测引擎自身判定口径、插件详情链接可下载能力（排期延至下月）。DFX 维度需求未给出耗时/并发/资源阈值，analyze-all-python=true 的耗时增量仅记录观察值，不做阈值判定；本期无自动化脚本，API 直连因 OIDC 机机调用无用户入口无法本地构造合法 ID Token，接口契约由开发单测覆盖。
