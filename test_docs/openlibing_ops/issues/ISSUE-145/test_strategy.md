1. 验证修复后主表「门禁E2E执行时长[平均]/[最长]」列所有数值保留2位小数（整数秒场景显示 `x.00`，无数据场景显示 `--` 不算违规）。
2. 验证「门禁E2E执行时长(不含重试)」两列保持2位小数，与含重试列格式一致（同行对比）。
3. 验证看板「导出」产物中门禁E2E执行时长相关列数值格式与页面展示一致（同为2位小数），防止修复仅覆盖页面渲染未覆盖导出。

### 1.7 风险与约束

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 现场数据恰好全为2位小数，无法暴露"格式化逻辑缺失"回归 | 修复验证置信度降低 | 用例断言采用全量行遍历 + 严格正则（`^\d+\.\d{2}$`），任何一行任一列出现 1 位小数/整数裸值即失败；含整数裸值检测（如 `30` 应显示 `30.00`） |
| 主表数据依赖数仓 T+1 同步，验证窗口内数据可能变化 | 断言对象不稳定 | 断言只针对格式（正则），不针对具体数值；`--` 空值显式豁免 |
| 不含重试列当前仅 1 个仓有数据 | 一致性断言样本不足 | 用例对无数据行豁免（`--`），有数据行严格断言；若全量行均无数据则用例给出明确 skip 结论而非误 pass |
| 导出文件下载路径在 CI 环境不可写 | 导出用例执行受阻 | 导出用例支持本地执行凭证，CI 缺失时标注 block 并说明 |
