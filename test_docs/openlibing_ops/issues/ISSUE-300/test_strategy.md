#### 1.2.1 申请卡数对拍口径定稿（用户 2026-10-28 手工更新版脑图）

用户 2026-10-28 更新的测试设计脑图直接给出三条曲线与申请卡数字段的 Doris 对拍公式与事实表，口径定稿如下（用例 010~013/015/017/019/021/023/025 的预期结果 SQL 均取自脑图，一字未改）：

| 指标/字段 | 对拍公式 | 数据源（三平台分表） |
|---|---|---|
| 总卡数（曲线） | `SUM(actual_npu_num)`，按 `resource_pool_name` 分组与资源池筛选联动 | `sdi_rd_efc_server_machine_hidevlab`（机器静态维表） |
| 使用卡数（曲线） | 运行明细的申请卡数汇聚 | 运行任务 job 级申请卡数（见下行） |
| 等待卡数（曲线） | 排队明细的申请卡数汇聚 | 排队任务 job 级申请卡数（见下行） |
| 申请卡数（job 级，三平台统一公式） | `GREATEST(FLOOR(CAST(npu_second AS DOUBLE) / job_duration), 1)`——npu_second 除以 job_duration 向下取整、下限 1 | codearts `internal.openlibing.dwr_rd_efc_build_job_fact`；github `internal.openlibing.dwr_rd_efc_workflow_run_job_github_fact`；gitcode `internal.openlibing.dwr_rd_efc_workflow_run_job_gitcode_fact` |

- **时间窗字段（脑图定稿）**：排队任务以 `job_name` 筛任务名、`job_start_time` 筛开始时间、`job_run_start_time` 筛结束时间；运行任务以 `job_name` 筛任务名、`job_run_start_time` 筛开始时间、`job_end_time` 筛结束时间；均要求 `job_duration > 0`
- **对拍样本（脑图定稿，执行时按此取样）**：codearts 任务名 `UT_ARM_A2_Part_02`；github 任务名 `forward / test / collect / collect`；gitcode 任务名 `SCA`；样本时间窗 2026-09-14 18:10~18:45（运行任务 codearts 至 18:45，其余至 18:15）
- **口径修订记录（用户 2026-10-28 17:38 再次手工更新脑图）**：申请卡数取整方式由四舍五入（`GREATEST(ROUND(npu_second/job_duration, 0), 1)`）修订为向下取整（`GREATEST(FLOOR(npu_second/job_duration), 1)`），节点结构无增删；015/017/019/021/023/025 共 6 条字段值计算用例的预期结果描述与 SQL 已同步修订，用例编号不变
- 与原 1.2 `dwr_rd_efc_resource_npu_detail_5m`（5m 切片明细源）的关系：切片明细源仍是页面明细列表取数来源；脑图定稿对拍采用 job 级事实表 + npu_second/job_duration 公式，执行阶段以脑图口径为准，若页面取数与脑图口径不一致以缺陷形式提交开发确认
