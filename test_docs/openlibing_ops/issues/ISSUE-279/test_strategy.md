### 1.2 需求摘要

> 依据 issue #279 需求描述 + MR #236 代码走查（2026-10-17，branch feat-279-pr-pipeline-time-filter）+ Doris 真值数据探查（2026-10-17，internal.openlibing 库）提炼。

需求原文：期望工程能力运营看板 PR 数据筛选时间是基于流水线运行时间进行（当前是基于 PR 创建时间）；PR 流水线相关的数据，根据时间查询时，使用流水线创建时间进行过滤，而非 PR 创建时间。

改造范围（代码走查确认，仅 2 处 Mapper 时间谓词，不改变对外接口字段与参数）：

| #   | 文件                                                                                              | 改造点                                                                                                                                                               | 影响字段                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 1   | `OpsMainStatMapper.xml` `queryMainStat`（POST /gateway/openlibing-ops/manage/ops-overview/main）  | `pr_run_sample` CTE：`WHERE pr.created_at between #{req.startTime} and #{req.endTime}` → `WHERE u.start_time >= #{req.startTime} AND u.start_time <= #{req.endTime}` | prDurationP90（PR执行时长P90）、resourceQueueTime（资源排队时长）、buildQueueP90（构建排队P90）、dtQueueP90（测试排队P90） |
| 2   | `OpsRepoDetailMapper.xml`（POST /gateway/openlibing-ops/common/detail，category=ops-repo-detail） | `pr_run_sample` CTE 同样由 `pr.created_at` 改为 `u.start_time`                                                                                                       | prDuration、resourceQueueTime、buildQueueP90、dtQueueP90（仓库级）                                                         |

口径语义（TimeReq.java 走查）：`startDate` → `startTime = 当日 00:00:00`（>= 闭区间下端）；`endDate` → `endTime = 当日 23:59:59`（<= 闭区间上端）。

MR #236 影响说明（开发自述）：

- PR 在窗口前创建、流水线在窗口内运行：由**不计入改为计入**（switch-in）；
- PR 在窗口内创建、流水线在窗口后运行：由**计入改为不计入**（switch-out）；
- 达标灯 `passStatus` 可能随 P90 变化翻转，属预期。

单位语义（走查确认，脚本对拍须按单位换算）：main `prDurationP90` 为**分钟**（OpsOverviewMainResp VO 注释）；repo-detail `prDuration` VO 注释亦为分钟，但其 SQL `pr_duration = e2e_duration_p90`（PERCENTILE(duration_ms/1000,0.9)，秒值）**未见 /60 转换，疑透出秒值**——单位歧义为存量问题，脚本以「单位自适应断言」隔离（见 1.7 风险 R1）。排队三字段（buildQueueP90/dtQueueP90/resourceQueueTime）均为分钟、2 位小数，且 `resourceQueueTime = ROUND(build_p90/60,2) + ROUND(dt_p90/60,2)` 恒等。

### 1.3 测试目标

1. **口径切换正确性（核心）**：main 与 repo-detail 两接口的 PR 执行时长/排队指标按 `u.start_time`（流水线开始时间）过滤取数，与 Doris 真值对拍一致；能用判别样本（HPCKit -11.8%、mindsdk-referenceapps +10.2%）区分新旧口径
2. **窗口边界正确性**：startDate 00:00:00 ~ endDate 23:59:59 闭区间语义；下边界/上边界/跨月边界的 run 归属正确；switch-in 计入、switch-out 排除
3. **指标自洽性**：resourceQueueTime = buildQueueP90 + dtQueueP90 恒等成立；p90 仅取 COMPLETED 且 end_time 非空、排队取全部状态（含 CANCELED/FAILED）的语义保持
4. **回归无波及**：资源消耗（prCpuUsage/prNpuUsage）、nightly 指标、NPU 使用率（issue_210 新增字段）等非 PR 时间口径字段不受影响
5. **UI 联动正确**：主表 PR执行时长/排队列、repo-tab 下钻明细随时间筛选器切换按新口径刷新；达标灯 passStatus 随 P90 翻转（预期行为）
6. **性能无劣化**：main 近 90 天大窗口响应时间在阈值内（`u.start_time` 过滤替换 `pr.created_at` 后执行计划无劣化，MR 测试计划要求 EXPLAIN 对比，由开发提供、脚本侧断言 RT）
7. **安全基线**：6 维度逐一声明（本需求为纯只读改造，无新增写接口）
