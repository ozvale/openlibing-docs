### 1.2 需求摘要

> 从开发设计文档提炼，**禁止超出文档范围**。

- **缺陷现象**（Issue 描述）：构建任务实际未执行，但看板显示「执行成功」——
  看板对流水线/构建任务状态的展示与实际执行状态不一致。
- **数据链路**（既有 TC-ISSUE135 需求建立的链路基线）：PR门禁看板流水线状态数据来源于
  数仓统一表 + 桥表（PR ↔ pipeline run 关联），PR 明细经
  `POST /gateway/openlibing-ops/pipeline/info`（type=pipeline）返回关联 run 集合
  （状态、耗时，job 按 BUILD/DT/CHECK 分组）。
- **缺陷机理推断**（据「构建任务未执行仍显示成功」）：无构建任务 run 记录时，
  状态判定逻辑缺少「未执行」分支，回退/默认为「成功」展示。
- **页面结构**（页面探索 2026-10-08 实测，beta，projectId=300066）：
  - 筛选区含「流水线状态」筛选器，取值：成功 / 失败
  - 主表「代码仓指标汇总统计」无任务状态列；无行展开明细入口
  - 趋势分析 7 图表（PR总数 / 门禁E2E执行时长 / 编译任务时长 / 测试任务时长 / 编译任务并发数 / 测试任务并发数 / 代码检查任务时长）

### 1.3 测试目标

1. 验证修复后「流水线状态」数据判定与实际构建任务执行状态一致：**无构建任务执行记录的 PR/仓库，其状态不得被展示或统计为「成功」**。
2. 验证 `pipeline/info` 接口（type=pipeline）返回的 run 状态字段与数仓统一表实际状态一致，无 run 时不得默认成功。
3. 验证看板「流水线状态」筛选（成功/失败）结果与接口/数仓真实状态一致（筛选数据正确性回归）。
4. 关联回归：数仓统一表 gitcode 流水线 run/job 数据完备性、PR↔run 桥表关联、pipeline 接口结构契约（TC-ISSUE135-001/007/008 基线复用）。
