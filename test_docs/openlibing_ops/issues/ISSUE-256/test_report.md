### 缺陷详情

#### #278: 使用率分析-资源池明细总卡时计算错误

- **关联用例**: TC-ISSUE256-012
- **缺陷issue**: https://gitcode.com/openlibing/openlibing-ops/issues/278
- **严重级别**: 严重（池级汇总与机器级明细不一致，核心指标计算错误）
- **状态**: 已关闭（closed，2026-10-19；关闭评论附修复截图）
- **复现步骤**:
  1. 进入资源运营看板-使用率分析页，点击 KPI 面板池卡片打开资源池明细抽屉
  2. 设 72h 时间窗口，展开资源池机器列表，逐行读取每台机器总卡时并求和
  3. 与池行折叠头「总卡时」展示值比对
- **实际结果**: 池行「总卡时」展示值 ≠ Σ机器总卡时（池级汇总与机器级明细不一致）
- **预期结果**: 池行总卡时 = 池内所有机器 IP 总卡时之和（静态口径 = Σ维表 actual_npu_num 静态卡数 × 窗口小时数）
- **影响范围**: 使用率分析页-资源池使用率详情池行「总卡时」汇总值
- **复现概率**: 100%（首轮执行稳定复现）
- **回归验证**: 2026-10-20~21 生产环境 TC-ISSUE256-012 通过（池行 = Σ机器且 = 静态卡数×窗口小时数自洽）

#### #276: 使用(占用)卡时、使用(占用)率计算错误

- **关联用例**: TC-ISSUE256-014
- **缺陷issue**: https://gitcode.com/openlibing/openlibing-ops/issues/276
- **严重级别**: 严重（核心指标计算错误）
- **状态**: 已关闭（closed，2026-10-19；关闭评论附修复截图）
- **复现步骤**:
  1. 进入资源运营看板-使用率分析页，点击 KPI 面板池卡片打开资源池明细抽屉
  2. 设 72h 时间窗口，展开资源池机器列表，逐行读取每台机器使用(占用)卡时并求和
  3. 与池行折叠头「使用(占用)卡时」展示值及「使用率(占用)」率值比对
- **实际结果**: 池行「使用(占用)卡时」展示值 ≠ Σ机器使用(占用)卡时；「使用(占用)率」率值与占用卡时/总卡时口径不符
- **预期结果**: 池行使用(占用)卡时 = 池内所有机器 IP 使用(占用)卡时之和；使用率(占用) = 使用(占用)卡时 ÷ 总卡时
- **影响范围**: 使用率分析页-资源池使用率详情池行「使用(占用)卡时」汇总值与「使用率(占用)」率值
- **复现概率**: 100%（首轮执行稳定复现）
- **回归验证**: 2026-10-20~21 生产环境 TC-ISSUE256-014 通过（池行 7264.55 = Σ机器 7264.55；8313.35 ≈ Σ机器 8313.34，取整容差内）

## 4. 测试结论

### 4.1 结论

**允许发布**

### 4.2 结论依据

- **功能覆盖**: 14 条用例与设计脑图 14 个测试点逐字对齐（14/14，0 差异 0 缺失），覆盖资源总览页池级三卡时（总卡时/总使用(占用)卡时/总利用卡时）字段存在性与计算一致性、使用率分析页池级两卡时（总卡时/总使用(占用)卡时）字段存在性与计算一致性、两页面机器类型列存在性与维表值对拍
- **P0用例结果**: 全部通过（7/7：001/004/006/008/009/012/014）
- **P1用例结果**: 全部通过（7/7：002/003/005/007/010/011/013）
- **缺陷情况**: 首轮执行发现 2 个产品计算缺陷（#276/#278，均为严重级）已修复关闭，生产环境全量重执行 14/14 通过即回归验证，两缺陷修复均已生效；无遗留缺陷
- **执行环境**: 生产环境 www.openlibing.com（TEST_ENV=prod），14 条均为只读 UI 断言无写操作副作用；生产适配项（池名全称化/基线窗口/容差标定/DOM 适配等 8 项）均为脚本层调整，用例断言意图不变，登记测试策略 §1.9
- **遗留风险**: ①FP2 机器列表 5 指标排序脑图未含用例（v1.5 范围收敛登记，评审确认是否补充）；②使用率分析类目脑图无「总利用卡时」用例（该类目无 used 数据源且 showUsage=false，需求差异登记）；③池级总卡时口径（effective 兜底 vs 原值）待需求方定稿（参与开源统一资源池-华北-910C 两口径差 69%，生产执行按 effective 口径验证通过）；④beta 环境 502 故障期间未执行，beta 部署恢复后可按同套脚本回归
