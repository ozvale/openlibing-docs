## 2. 需求摘要

> 依据 Issue 原文（设计文档链接为模板占位符，经测试人员确认以实际系统探索为业务输入）与 beta 环境页面探索（探索记录因 2026-08-31 存储层异常丢失，未留存），**禁止超出范围发散**。

建设测试质量看板（遗留问题），核心内容：

- **核心指标**：遗留问题数 = 致命×1 + 严重×1 + 一般×1 + 提示×1（四级权重均为 1）；统计对象为 Issue 类型 `Bug-Report` 或标签含 `bug`；无严重级别定义时按"一般问题"统计
- **看板维度**：组织维度（测试运营菜单）与项目维度（测试管理菜单），分别按"社区-子组织/分组"与"代码仓"粒度展示
- **展示内容**：测试问题数（Bug总数）、遗留问题数、遗留DI 及各级别问题数
- **明细时间范围**：今日 / 近 7 天 / 近 30 天 / 近 90 天
- **范围外**：趋势图另行设计，不在本次验证范围

**页面探索补充事实**：功能已在 beta 部署。项目维度入口完整（测试管理→质量风险，`/apps/qualityRiskProject?projectId=3`，iframe 嵌 `/ops/dashboard/quality-risk-project/3`）；组织维度页面已部署且有数据（`/ops/dashboard/quality-risk-org`），但侧边栏无"测试运营"菜单入口。计数公式实测：`issueLegacyCount = critical + major + minor + trivial + nopriority`，与 Issue 口径一致。

## 3. 测试目标

1. 验证项目维度看板菜单入口、页面加载与 7 张汇总指标卡片展示（R2、R4）
2. 验证组织维度看板页面加载、指标展示与社区列表展示（R1，入口按直达 URL，菜单缺失作为发现项）
3. 验证遗留问题数计算口径（五级计数求和，API 层公式断言 + UI 层展示一致性）（R3）
4. 验证明细数据时间范围切换（今日/近7天/近30天/近90天）及三接口联动刷新（R5）
5. 验证明细列表分页与全量导出文件结构（行数与列结构）（R4 延伸）
6. 验证 Bug 总数与遗留问题数等关联指标的展示与数据一致性（R4、R6 间接验证）
7. 验证无严重级别问题的独立分桶展示与总数计算（R7，按实测实现口径验证，与 Issue 描述差异记录为观察项）
8. 安全验证：匿名/伪造 token 访问看板接口应被拒绝；低权限账号访问看板接口应被拒绝；响应体不泄露敏感信息

## 5. 测试策略

### 5.1 手工测试

- UI 视觉与交互细节：组织维度"维度筛选器"交互、日期区间选择器自定义范围、时间切换时弹层重叠现象（探索发现 #3）的浏览器实际表现
- 导出文件人工核对：xlsx 打开核验列头、行数与页面明细一致性（自动化校验结构，人工抽核内容）
- 组织维度菜单入口确认：开发补部署"测试运营"菜单后人工验证入口可达性（依赖项，当前 blocked）
- 手工用例归档位置: `assets/docs/openlibing/openlibing_ops/test_case.md`（openlibing_ops 为历史非标准目录，统一清单）

### 5.2 自动化测试

- **API 层（优先）**：4 接口契约与状态码断言、遗留问题数公式断言（每行/汇总均满足五级求和）、汇总卡片值 = 明细分页全量求和一致性、导出行数 = 明细 total、时间参数四档映射正确性
- **UI 层**：项目维度菜单导航 + iframe 内卡片/表格渲染、组织维度直达 URL 加载、时间范围四档切换触发三接口重查、分页翻页、导出下载文件落盘
- **安全层**：匿名调用看板接口（期望 401/403）、伪造 token 调用（期望拒绝）、低权限账号 `pub_LIBING` 调用（期望拒绝）、响应体敏感字段扫描
- 自动化用例归档位置: `assets/docs/openlibing/openlibing_ops/test_case.md`
- 自动化脚本位置:
  - `src/tests/openlibing/openlibing_ops/api/beta/quality_dashboard/`
  - `src/tests/openlibing/openlibing_ops/ui/beta/quality_dashboard/`
  - `src/tests/openlibing/openlibing_ops/security/beta/quality_dashboard/`

**安全维度覆盖声明（规则 04 强制）**：

| 维度                                | 覆盖状态 | 原因                                                                                 |
| ----------------------------------- | -------- | ------------------------------------------------------------------------------------ |
| 认证校验 (auth_check)               | 覆盖     | 匿名 / 伪造 token 调用 4 个看板接口应被拒绝                                          |
| 纵向越权 (vertical_check)           | 覆盖     | 低权限账号 `pub_LIBING` 调用看板接口（对照高权限基线）应被拒绝                       |
| CSRF 防护 (csrf_check)              | 不覆盖   | 4 个接口均为只读查询/导出（文件生成不落库），无数据变更语义，无 CSRF 场景            |
| 横向越权 (horizontal_check)         | 不覆盖   | 看板数据按社区/项目聚合展示，无跨用户私有资源语义；跨 projectId 隔离已由既有基线覆盖 |
| 传输安全 (transport_check)          | 不覆盖   | beta 环境全站 HTTPS + Cookie Secure/HttpOnly 已由 2026-08-11 基线验证，本期不重复    |
| 敏感信息防护 (sensitive_data_check) | 覆盖     | 扫描 4 个接口响应体，不泄露 token/密码/密钥/手机号/邮箱等敏感字段                    |

### 5.3 验证方法（数据一致性三层校验）

| 校验层      | 校验内容                                                                              | 实施载体                      |
| ----------- | ------------------------------------------------------------------------------------- | ----------------------------- |
| 公式层      | `issueLegacyCount == critical + major + minor + trivial + nopriority`（各级别权重 1） | API 用例（汇总行 + 明细每行） |
| 汇总-明细层 | 汇总卡片 summary 值 == detail 分页全量 records 求和                                   | API 用例                      |
| 前后端层    | UI 卡片展示值 == statistics 接口返回值；UI 表格行 == detail 接口记录                  | UI 用例（网络抓取对照）       |
| 导出层      | 导出 xlsx 行数 == detail total（全量，不受分页限制）；列结构与页面一致                | API 用例                      |

## 6. 风险与约束

| 风险                                                                  | 影响                                      | 缓解措施                                                                                              |
| --------------------------------------------------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 组织维度菜单入口缺失（侧边栏无"测试运营"）                            | R1 菜单可达性无法验证                     | UI 用例按直达 URL `/ops/dashboard/quality-risk-org` 设计并标注；作为发现项反馈开发                    |
| 框架接口间歇 503（get-operation-permissions / judge-account-visitor） | 组织页面首载"暂无数据"，可能 flaky        | 用例增加刷新重试；503 期间不误判为功能缺陷；重试后仍失败才判 fail                                     |
| 遗留DI 公式未定义（Issue 未提及，实测 DI=遗留数）                     | DI 无法做公式断言                         | DI 仅做"卡片=接口=表格"一致性校验，公式问题记录为待确认                                               |
| R6 统计口径（Bug-Report 或标签含 bug）为后台过滤逻辑，前端不可观测    | 无法直接黑盒断言过滤规则                  | 通过 issueBugCount 与 issueLegacyCount 的数据关系间接观察（当前实测两者相等），作为观察项记录，不断言 |
| 无严重级别问题按"一般"统计（Issue）vs 独立"无优先级"分桶（实现）      | 需求与实现口径差异                        | 因权重均为 1，总数计算不受影响；差异记录为观察项反馈开发确认                                          |
| 当前 beta 数据全部为无优先级问题                                      | 无法构造致命/严重/一般/提示各级别非零数据 | 公式断言退化为"零值分量 + 非零 nopriority 求和"仍可验证；若后续出现多级别数据可加强                   |
| 时间切换"今日"时日期选择面板弹出（控件重叠）                          | UI 自动化点击稳定性                       | 对"今日"切换做容错定位（关闭弹层后再断言）                                                            |
