## 2. 需求摘要

> 来源：Issue #43 描述正文（开发设计文档），禁止超出文档范围。

测试运营看板新增"测试质量看板（遗留问题）"模块，展示组织/项目维度的遗留问题（缺陷/安全/门禁/代码检查等）分布与趋势，支撑质量风险识别与运营决策。

核心功能点：
- F1 双维度视角：组织维度（/ops/dashboard/quality-risk）与项目维度（/ops/dashboard/quality-risk-project），支持路由参数深链
- F2 L1 概览：KPI 卡片（遗留问题汇总）+ 社区/项目列表，支持分页、排序
- F3 L2/L3 下钻：L2 子组织列表、L3 代码仓明细列表，面包屑导航逐级返回
- F4 趋势折线图：遗留问题趋势，支持时间范围筛选
- F5 导出按钮：后台接口未就绪，前端预留
- F6 数据源接口：issue-legacy-statistics（KPI）/ issue-legacy-trend（趋势）/ common/detail（category=issue-legacy-detail，表格）

## 3. 测试目标

针对 Issue #43 的 7 条验收标准，在 beta 环境（projectId=3）完成端到端验证：

1. 组织/项目维度页面正常渲染，KPI 卡片与表格数据正确
2. 社区 → 子组织 → 代码仓逐级下钻与面包屑返回正常
3. 表格分页、排序、时间范围筛选正常
4. 趋势图按 PR 门禁看板样式展示，无数据时展示空态
5. 代码仓列可点击跳转
6. 导出按钮预留（提示"开发中"）
7. ESLint / Prettier / type-check 通过（前端代码质量项，由开发 PR 流水线保障，测试侧不直接验证，标注豁免）

## 4. 测试范围

| 测试类型 | 是否覆盖 | 说明 |
|----------|----------|------|
| UI功能测试 | 是 | 双维度页面渲染、KPI 卡片、下钻导航、面包屑、分页、时间筛选、趋势图、代码仓跳转、导出按钮 |
| API接口测试 | 是 | 3 个核心接口的请求/响应/分页/时间参数/异常参数验证 |

| 安全测试 | 是 | 认证校验、横向越权（projectId 数据隔离）、敏感信息防护、传输安全复用既有基线 |

> 注：验收标准 7（ESLint/Prettier/type-check）属于前端构建质量，由开发 CI 保障，不在测试侧覆盖范围，已在需求分析中标注。

## 5. 测试策略

### 5.1 手工测试

覆盖场景（UI 交互体验类，自动化成本高或难以稳定断言）：
- 导出按钮点击后的提示文案与按钮状态（验收标准 6）
- 趋势图样式与 PR 门禁看板一致性（验收标准 4 的样式部分）
- 无数据空态展示（验收标准 4 空态部分）
- 面包屑多级返回的视觉正确性
- 手工用例归档位置: `assets/docs/openlibing/openlibing_ops/quality_risk/manual_test_cases.md`

### 5.2 自动化测试

覆盖场景：
- UI 自动化（Playwright）：双维度页面加载断言、KPI 卡片渲染、L1→L2→L3 下钻、面包屑返回、时间范围切换后数据刷新、代码仓链接跳转属性
- API 自动化（requests + pytest）：3 个接口的正向/分页/时间参数/异常参数（等价类+边界值）
- 性能自动化：3 接口响应时间阈值断言
- 安全自动化：匿名/低权限调用接口拒绝验证、projectId 横向数据隔离、响应敏感字段检查
- 自动化用例归档位置: `assets/docs/openlibing/openlibing_ops/quality_risk/auto_test_cases.md`
- 自动化脚本位置: `src/tests/openlibing/openlibing_ops/{api,ui,performance,security}/beta/quality_risk/`

## 6. 风险与约束

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 导出接口后台未就绪，前端仅预留 | 导出行为断言只能验证"预留"而非真实导出 | 按验收标准 6 验证提示"开发中"；历史实测发现导出接口实际返回 200 且按钮静默禁用 4 秒无提示，需与开发确认是否缺陷 |
| 看板数据每日变化（近 N 天窗口滚动） | KPI 数值断言易脆弱 | 断言采用"数值非负、各严重级之和=总数、两维度数值关系（项目≤组织）"等不变量，不硬编码 364/28 等具体值 |
| 时间范围"自定义"交互复杂 | 自动化稳定性差 | 自定义日期范围用 API 参数验证替代 UI 验证 |
| 组织维度下钻依赖线上数据存在 LingQu 社区 | 下钻用例依赖数据 | 用例内置数据存在性检查，无数据时 skip 并注明 |
| 安全测试双账号需要保持低权限纯净 | 越权结论失真 | 复用 SECURITY_LOW_PRIV 账号体系，测试前不调整角色 |
