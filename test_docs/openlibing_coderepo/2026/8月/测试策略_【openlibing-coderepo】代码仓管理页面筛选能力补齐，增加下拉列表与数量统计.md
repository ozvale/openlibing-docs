# 【openlibing-coderepo】代码仓管理页面筛选能力补齐，增加下拉列表与数量统计 测试策略设计说明书

## 1. 基本信息

* **需求链接**: https://gitcode.com/openlibing/openlibing-coderepo/issues/93
* **对应task(issueID)链接**: https://gitcode.com/openlibing/openlibing-coderepo/issues/93
* **需求名称**: 【openlibing-coderepo】代码仓管理页面筛选能力补齐，增加下拉列表与数量统计
* **核心目标**:
  在代码仓管理原有查询和导出功能上，补齐新增字段的后端过滤能力，扩展 query-repo / export-repo 多选过滤入参；新增 query-repo-filter-meta 筛选元数据接口，为下拉列表提供各筛选项可选值及命中数量，支撑下拉列表与数量统计（维度预览语义）。
* **开发责任人**: 杨攀
* **测试责任人**: 徐愚冰

## 2. 测试维度确认

* [x] **功能自检测试**

> * **目的:** 确保新增筛选字段过滤正确、元数据接口返回可选值与数量统计准确、已有筛选语义不回归。

> * **触发条件:** 需求标签含 `need_itest`。

* [ ] **可靠性与韧性测试**
* [ ] **可服务性与可观测性测试**

## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1. 仓库负责人、默认分支筛选验证**:
* 前置条件:代码仓管理列表存在多条仓库数据，包含仓库负责人与默认分支信息
* 测试步骤:
    1. 进入代码仓管理页面，按仓库负责人（repoOwners）筛选
    2. 按默认分支（defaultBranchNames）筛选
    3. 验证筛选结果只包含匹配的仓库
* 预期结果: 仓库负责人、默认分支筛选结果正确

**2. 代码风格自动修复、告警抑制自动检视、自动触发接口扫描筛选验证**:
* 前置条件:代码仓管理列表存在仓库数据，包含开关类字段
* 测试步骤:
    1. 按代码风格自动修复（isAutoFormats）筛选
    2. 按告警抑制自动检视（isSuppressionEnableds）筛选
    3. 按自动触发接口扫描（autoTriggerDesignScans）筛选
    4. 验证各开关字段筛选结果正确
* 预期结果: 三个开关类新增字段筛选结果正确

**3. 建仓人、系统录入人、最后更新人筛选验证**:
* 前置条件:代码仓管理列表存在多条仓库数据，包含人员字段
* 测试步骤:
    1. 按建仓人（platformCreateBys）筛选
    2. 按系统录入人（createBys）筛选
    3. 按最后更新人（updateBys）筛选
    4. 验证各人员字段筛选结果正确
* 预期结果: 三个人员类新增字段筛选结果正确

**4. 已有字段筛选语义回归验证**:
* 前置条件:代码仓管理列表存在仓库数据
* 测试步骤:
    1. 按已有字段筛选：代码托管平台（platforms）、用途（purposes）、可见性（visibilities）、开源类型（openSources）、状态（statuses）
    2. 按已有字段筛选：语言（repoLanguages）、接管PR管理（assumePrs）、自动触发门禁流水线（autoTriggers）
    3. 验证筛选语义与优化前一致
* 预期结果: 已有字段筛选语义不变，筛选结果正确

**5. 多选筛选组合验证**:
* 前置条件:代码仓管理列表存在多种属性的仓库数据
* 测试步骤:
    1. 同时选择多个筛选项（如多个平台、多个负责人）
    2. 组合不同维度筛选条件（如平台 + 负责人 + 状态）
    3. 验证多选与组合筛选结果正确
* 预期结果: 多选与组合筛选结果准确，与条件一致

**6. 筛选元数据接口固定枚举返回验证**:
* 前置条件:代码仓管理存在仓库数据
* 测试步骤:
    1. 调用 query-repo-filter-meta 接口
    2. 验证固定枚举维度（platform / purpose / visibility / openSource / status / repoLanguage / assumePr / autoTrigger / isAutoFormat / isSuppressionEnabled / autoTriggerDesignScan）始终返回完整选项列表
    3. 验证含 count=0 的选项也返回
* 预期结果: 固定枚举维度返回完整选项列表，包含 count=0 项

**7. 筛选元数据接口动态候选返回验证**:
* 前置条件:代码仓管理存在仓库数据
* 测试步骤:
    1. 调用 query-repo-filter-meta 接口
    2. 验证动态候选维度（repoOwner / defaultBranchName / platformCreateBy / createBy / updateBy）返回项目内 DISTINCT 值 ∪ 已选值
    3. 验证未出现过的值不返回（除已选值外）
* 预期结果: 动态候选维度返回项目内 DISTINCT ∪ 已选值

**8. 数量统计维度预览语义验证**:
* 前置条件:存在已选 platforms=["gitcode"]、statuses=["normal"] 的筛选场景
* 测试步骤:
    1. 调用 query-repo-filter-meta，观察 platform 维度的预览统计
    2. 验证 platform 维度统计时保留 statuses 等其它条件，不含 platforms 自身条件
    3. 观察 status 维度预览统计，验证保留 platforms 等其它条件，不含 statuses 自身条件
    4. 验证统计数量符合「在当前其它条件下，选该项有多少条」语义
* 预期结果: 数量统计遵循维度预览语义，统计结果正确

**9. query-repo 与 query-repo-filter-meta 联动验证**:
* 前置条件:代码仓管理页面可访问
* 测试步骤:
    1. 点击「查询」按钮
    2. 验证前端同时请求 query-repo 与 query-repo-filter-meta 两个接口
    3. 验证两个接口 Body 携带相同的过滤条件
    4. 验证元数据接口不含分页、排序参数
* 预期结果: 两个接口同时调用，过滤条件一致，元数据接口无分页排序

**10. 导出与筛选联动验证**:
* 前置条件:代码仓管理列表已设置筛选条件
* 测试步骤:
    1. 设置新增筛选字段条件（如仓库负责人、默认分支）
    2. 点击导出（export-repo）
    3. 验证导出数据仅包含筛选后的结果
* 预期结果: 导出数据与当前筛选条件下的列表数据一致

### 3.2 体验测试专项

**11. 下拉列表与数量统计展示体验验证**:
* 前置条件:代码仓管理页面可访问
* 测试步骤:
    1. 打开各筛选下拉列表，验证选项展示清晰、数量统计可读
    2. 执行多选筛选操作，验证即时响应、无卡顿
    3. 验证已选筛选条件标签展示清晰，支持清除
* 预期结果: 下拉列表与数量统计展示清晰，多选操作流畅，反馈明确

### 3.3 集成测试专项

**12. 前端查询→列表+元数据端到端链路验证**:
* 前置条件:代码仓管理页面可访问
* 测试步骤:
    1. 点击「查询」触发 query-repo 与 query-repo-filter-meta 联动请求
    2. 验证列表筛选结果与下拉列表选项、数量统计相互一致
    3. 修改筛选条件后重新查询，验证列表与元数据同步更新
* 预期结果: 列表结果、下拉选项与数量统计一致，联动正常

### 3.4 性能测试专项

**13. 筛选元数据接口响应时间验证**:
* 前置条件:存在较多仓库数据（多项目场景）
* 测试步骤:
    1. 调用 query-repo-filter-meta 接口
    2. 记录接口响应时间
    3. 验证接口响应时间在可接受范围内，不随数据量明显退化
* 预期结果: 元数据接口响应时间可接受，数量统计计算性能正常
