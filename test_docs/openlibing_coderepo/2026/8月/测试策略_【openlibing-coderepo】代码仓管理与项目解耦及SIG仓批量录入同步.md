# 代码仓管理模块-代码仓管理与项目解耦及SIG仓批量录入同步 测试策略设计说明书

## 1. 基本信息

* **需求链接**: https://gitcode.com/openlibing/openlibing-coderepo/issues/90
* **对应task(issueID)链接**: https://gitcode.com/openlibing/openlibing-coderepo/issues/90
* **需求名称**: 代码仓管理与项目解耦（同 repo_url 跨项目提示不覆盖）+ SIG 组 sig-info.yaml 批量录入整合既有同步链路
* **核心目标**:
  在保持 repo_info「一项目一行、多行并存」模型（`(repo_url, project_id)` 唯一）前提下：① 用户录入/编辑代码仓时，同 repo_url 已在其他项目录入则从上次配置复制到表单，跨项目配置不一致仅提示性告警不覆盖；② 全局配置弹窗维护各平台公共账号令牌、gitcode 角色映射、SIG `sig-info.yaml` 路径列表（`config_json.sigInfoLocations` 按平台分键），保存时校验有效性、变更检测后异步触发同步；③ SIG 同步整合进 `/sync-repo`、`POST /global-config` 与 `syncRepoInfoHandler` 定时任务（移除独立接口 `/project-config/trigger-sig-sync` 与 `/project-config/sig-sync-status`）；SIG 仓默认参数自动填充，无效 sig 路径跳过不阻断，失效路径下线硬删对应录入仓库；`repo_info` 新增 `repo_source`（manual/sig）；异步同步具备分布式锁并发控制与代次协作中断（令牌/配置变更自增项目代次，在途任务步骤边界自检中止并按最新配置重跑）。迭代：openLiBing-202608（release_202608_iter2）。
* **设计文档**: 未找到独立设计文档（Issue #90 正文含完整需求设计：主成功场景/扩展场景/约束/非功能需求，本策略以 Issue 正文为设计基线）

## 2. 测试维度确认

* [x] **功能自检测试**
> * **测试重点:** 跨项目同 repo_url 配置复制与提示（不覆盖）、`validate-sig-path` 多路径逐条校验（路径存在性+文件存在性，>20 条拒绝）、全局配置保存校验（sig 路径域名与平台键一致、公共账号令牌校验任一无效阻断保存+同步）、变更检测（sig 路径/公共账号无变化不触发同步）、SIG 同步默认参数自动填充（别名/责任人/用途/开源类型/默认分支/公共账号令牌/各开关，默认分支不可修改）、`repo_source` 字段区分 manual/sig、移除 `trigger-sig-sync`/`sig-sync-status` 独立接口。
> * **目的:** 确保解耦提示、SIG 批量录入、同步整合全链路功能正确。
> * **触发条件:** 强制执行。

* [x] **体验测试**
> * **测试重点:** 全局配置弹窗中 sig 路径多路径维护交互、令牌仅回显"是否已设置"不回显明文的展示、跨项目配置不一致提示文案的引导性、SIG 同步进度反馈。
> * **目的:** 确保配置维护与提示交互易用、敏感信息展示合规。
> * **触发条件:** 涉及前端交互改造。

* [x] **集成测试**
> * **测试重点:** `/sync-repo` 异步同步全链路（平台/分支同步 + SIG 仓同步导入新增/硬删已下线 + 用户同步）；`syncRepoInfoHandler` 定时任务 SIG 同步步骤；`updateGlobalConfig` 保存成功后异步触发同步；7 个下游仓（codecheck/cicd/framework/anti-poison/sca/gateway/vulnerability）repo_info 层面零改动回归；迁移脚本（`project_gitcode_role_mapping` → 新全局配置表，旧表废弃）。
> * **目的:** 验证同步链路整合、跨仓兼容与数据迁移正确。
> * **触发条件:** 需求标签含 `need_itest`。

* [x] **安全与隐私测试**
> * **测试重点:** 敏感信息（令牌）不回显明文仅回显是否已设置；所有第三方 API 调用 accessToken 走请求头 `Authorization: Bearer`；所有 HTTP 客户端显式设置连接/读取超时；业务日志（`updateGlobalConfig`/`syncRepoInfoHandler`）独立 operation 且内容已去令牌。
> * **目的:** 确保令牌全链路不泄露。
> * **触发条件:** 改动涉及凭证配置与第三方 API 调用。

* [x] **可靠性与韧性测试**
> * **测试重点:** 分布式锁防重复执行（获取锁失败提示已有任务在执行）；无效 sig 路径批量校验单条失败不阻断其余路径、同步执行阶段跳过不阻断；失效 sig 路径下线硬删对应 sig 录入仓库；代次协作中断（令牌/配置变更自增项目代次，在途任务步骤边界自检发现代次过期即中止并重新提交按最新配置执行）；`TokenChangeConsumer` 收到 framework 令牌变更事件中断在途任务重跑；迁移脚本幂等可重跑；失败计数/重试提示。
> * **目的:** 确保异步同步任务并发安全、异常可控、令牌变更下任务一致。
> * **触发条件:** 涉及核心 Core 服务变更，且架构设计含可靠性与韧性设计。

## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1. 跨项目同 repo_url 配置复制与提示验证**:
* 前置条件: 同一 repo_url 已被项目 A 录入
* 测试步骤:
    1. 项目 B 录入同 repo_url 仓库，验证表单自动复制项目 A 的上次录入配置（可修改）
    2. 修改部分配置后提交，验证仅提示与其他项目配置不一致（提示性告警），不覆盖项目 A 配置
    3. 验证 `(repo_url, project_id)` 唯一约束生效、repo_url 无全局唯一拦截
    4. 验证项目 A 的原配置在项目 B 提交后保持不变
* 预期结果: 复制-可改-仅提示-不覆盖，符合"一项目一行、多行并存"模型

**2. sig-info.yaml 路径校验验证**:
* 前置条件: 各平台存在有效/无效的 sig-info.yaml 路径
* 测试步骤:
    1. 调用 `validate-sig-path` 传入多条路径，验证逐条返回校验结果（路径存在性 + 文件存在性），单条失败不阻断其余
    2. 传入 >20 条路径，验证直接拒绝
    3. 传入与平台键不一致域名的路径（如 gitcode 键下配 gitee 域名路径），验证保存时被校验拦截
* 预期结果: 多路径校验、上限拦截、域名-平台键一致性校验均生效

**3. 全局配置保存与变更检测验证**:
* 前置条件: 用户具备全局配置操作权限
* 测试步骤:
    1. 维护各平台公共账号（用户名+令牌）、gitcode 角色映射、sig 路径列表，任一校验无效时验证阻断保存+同步
    2. 全部有效保存，验证保存成功后异步触发同步
    3. 再次保存且 sig 路径/公共账号无变化，验证不触发同步（变更检测）
    4. 仅修改 sig 路径或仅修改公共账号，验证各自能触发同步
* 预期结果: 校验阻断、变更检测、异步触发行为符合设计

**4. SIG 仓同步与默认参数填充验证**:
* 前置条件: 全局配置已设置有效 sig 路径
* 测试步骤:
    1. 通过 `/sync-repo` 提交同步任务，验证 SIG 仓导入新增：默认参数自动填充（别名/责任人/用途/开源类型/公共账号令牌/各开关）
    2. 验证默认分支从代码托管平台获取且不可修改
    3. 验证 `repo_source = sig`（手动录入仓 `repo_source = manual`）
    4. 无效 sig 路径验证仅跳过、不阻断后续同步
    5. sig 路径下线后再次同步，验证硬删对应 sig 录入仓库（不影响 manual 仓库）
* 预期结果: SIG 仓同步导入、参数填充、来源标识、失效路径处理全部正确

**5. 同步链路整合与旧接口移除验证**:
* 前置条件: 服务已部署新版本
* 测试步骤:
    1. 验证 `/project-config/trigger-sig-sync`（POST）与 `/project-config/sig-sync-status`（GET）已移除（404）
    2. 验证 SIG 同步仅通过 `/sync-repo`、`POST /global-config`、`syncRepoInfoHandler` 定时任务三条链路触发
    3. XXL-Job 控制台确认 `syncRepoInfoHandler` 无任务参数（自动同步全部 project_info 记录，按平台名 gitcode/gitee/github 区分）
* 预期结果: 旧接口移除干净，三条同步链路全部可用

### 3.2 体验测试专项

**6. 配置弹窗与提示交互验证**:
* 前置条件: 前端已部署改造版本
* 测试步骤:
    1. 全局配置弹窗维护多平台 sig 路径，验证逐条校验结果展示清晰
    2. 验证令牌已设置时仅回显"已设置"状态，不回显明文
    3. 跨项目配置不一致提示文案验证引导性（说明不会覆盖其他项目）
* 预期结果: 交互清晰、敏感信息展示合规、提示文案准确

### 3.3 集成测试专项

**7. 定时任务与下游仓兼容验证**:
* 前置条件: XXL Job admin 已配置 `syncRepoInfoHandler`
* 测试步骤:
    1. 触发 `syncRepoInfoHandler` 定时任务，验证平台/分支/SIG/用户同步步骤完整执行、SIG 同步步骤记录独立 operation 日志
    2. 抽查 7 个下游仓（codecheck/cicd/framework/anti-poison/sca/gateway/vulnerability）读取 repo_info 功能，验证零改动正常工作
    3. 执行迁移脚本（`project_gitcode_role_mapping` → 新全局配置表），验证数据迁移正确、旧表废弃、删除产品/项目级联清理指向新表
* 预期结果: 定时任务链路完整、下游仓零回归、迁移正确

### 3.4 安全与隐私测试专项

**8. 令牌安全验证**:
* 前置条件: 系统运行正常
* 测试步骤:
    1. 抓包/日志验证第三方 API 调用 accessToken 仅在 `Authorization: Bearer` 请求头
    2. 验证所有 HTTP 客户端显式设置连接/读取超时
    3. 检查 `updateGlobalConfig` / `syncRepoInfoHandler` 业务日志内容无令牌明文
    4. 验证全局配置查询接口令牌不回显明文
* 预期结果: 令牌全链路（传输/日志/回显）不泄露

### 3.5 可靠性与韧性测试专项

**9. 并发控制与代次协作中断验证**:
* 前置条件: 可触发同步任务并修改配置/令牌
* 测试步骤:
    1. 并发触发两次同步任务，验证分布式锁防重复执行、获取锁失败提示已有任务在执行
    2. 同步任务在途时修改令牌/配置，验证项目代次自增、在途任务在步骤边界自检发现代次过期即中止，并重新提交按最新配置执行
    3. framework 令牌变更：验证 `TokenChangeConsumer` 收到事件后中断该项目在途任务并按新令牌重跑
    4. 重跑迁移脚本，验证幂等无重复数据
    5. 构造同步失败场景，验证失败计数与重试提示
* 预期结果: 并发互斥、代次中断重跑、令牌变更联动、迁移幂等全部符合设计
