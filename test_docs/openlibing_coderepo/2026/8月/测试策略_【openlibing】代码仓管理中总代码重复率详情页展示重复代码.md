# 【openlibing】代码仓管理中总代码重复率详情页展示重复代码 测试策略设计说明书

## 1. 基本信息

* **需求链接**: https://gitcode.com/openlibing/openlibing-coderepo/issues/89
* **对应task(issueID)链接**: https://gitcode.com/openlibing/openlibing-coderepo/issues/89
* **需求名称**: 【openlibing】代码仓管理中总代码重复率详情页展示重复代码
* **核心目标**:
  代码仓管理"总代码重复率"详情页点击文件后，直接展示该文件中的重复代码块及其上下文，并在侧边栏展示与之重复的配对文件代码片段，让用户可在网页上完成"查看 → 定位 → 修改"闭环。重复块入库可追溯，上下文快照仅存重复块±5行，代码内容 Base64 编码存储，查询接口校验仓库访问权限。
* **开发责任人**: 闫兆鸿
* **测试责任人**: 徐愚冰

---

## 2. 测试维度确认

* [x] **功能自检测试**
> * **测试重点:** 重复率详情页点击文件跳转代码视图、monaco-editor 上下文片段拼接（重复块±5行 + 省略占位）、重复块高亮、drawer 多页签展示所有出现位置、tab 切换、上一个/下一个跳转、drawer 放大缩小；异常场景：旧 record 无 snapshot_data 占位展示、同文件内重复块独立 tab、完全一致文件（metricType=4）不展示具体重复代码、旧版插件未上报新字段兼容。
> * **目的:** 确保重复代码展示、定位、修改闭环功能符合预期，异常场景处理正确。
> * **触发条件:** 强制执行。

* [x] **体验测试**
> * **测试重点:** drawer 打开/切换/缩放交互流畅性、代码视图展示清晰性、操作反馈。
> * **目的:** 满足用户需求，超出用户期望；判定产品是否能让用户快速的接受和使用。
> * **触发条件:** 需求标签含 `need_experience`。

* [x] **集成测试**
> * **测试重点:** code-metrics-action 插件重复块上报 → openlibing-coderepo 后端存储与查询 → openlibing-web 前端代码视图与 drawer 展示的端到端链路、历史 pipelineRunId 重复块可追溯。
> * **目的:** 消除插件、后端、前端多系统集成的级联影响风险，保证各环节数据一致。
> * **触发条件:** 需求标签含 `need_itest`。

* [x] **安全与隐私测试**
> * **测试重点:** 查询接口仓库访问权限校验（groupId 越权返回 403）、代码内容 Base64 编码存储、后端日志不打印代码内容、上报接口 APIG 签名 + HTTPS。
> * **目的:** 验证权限校验与数据安全符合要求，代码内容不泄露。
> * **触发条件:** 涉及鉴权、输入、凭证、敏感数据场景。

* [x] **可靠性与韧性测试**
> * **测试重点:** 旧 record 无 snapshot_data 的降级行为、上下文快照仅存重复块±5行且无 TTL 长期保留、历史记录完整可查。
> * **目的:** 确保快照缺失等异常场景下系统行为正确、数据不丢失。
> * **触发条件:** 涉及核心Core服务变更，且架构设计含可靠性与韧性设计。

* [ ] **可服务性与可观测性测试**
* [x] **性能与伸缩性测试**
> * **测试重点:** 单文件代码视图接口（快照命中）响应 < 500ms、单重复块详情接口响应 < 200ms、插件单次上报体量 < 10MB（超过分批）。
> * **目的:** 满足性能 SLO，确保代码视图与重复块详情接口响应达标。
> * **触发条件:** 涉及核心Core服务变更，且架构设计含性能与伸缩性设计。

## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1. 重复率详情页点击文件跳转代码视图验证**:
* 前置条件:代码度量扫描成功，产生 record 与 file_detail 数据，插件版本已升级到支持重复块上报
* 测试步骤:
    1. 进入代码仓管理"总代码重复率"详情列表
    2. 点击某文件的文件路径
    3. 验证跳转到代码查看页面并正确加载该文件内容
* 预期结果: 点击文件路径成功跳转代码视图，内容加载正确

**2. 上下文片段拼接与重复块高亮验证**:
* 前置条件:文件存在重复代码块且已入库
* 测试步骤:
    1. 打开文件代码查看页面
    2. 验证重复块上下文片段按 ±5 行拼接，其他部分以 `... N lines omitted ...` 占位
    3. 验证重复块用底色高亮展示
* 预期结果: 上下文片段拼接正确，省略占位清晰，重复块高亮准确

**3. 点击重复块弹出 drawer 多页签展示验证**:
* 前置条件:文件存在重复代码块
* 测试步骤:
    1. 点击某个高亮重复块
    2. 验证右侧 drawer 弹出
    3. 验证顶部多页签展示该组所有出现位置，每个 tab 标签为 `文件名:起始行-结束行`
* 预期结果: drawer 正常弹出，多页签完整展示所有出现位置，tab 标签格式正确

**4. drawer tab 切换不同出现位置验证**:
* 前置条件:重复组包含多个出现位置
* 测试步骤:
    1. 打开 drawer
    2. 依次点击不同 tab
    3. 验证各 tab 对应的代码片段正确展示
* 预期结果: tab 切换后代码片段正确更新，与对应出现位置一致

**5. drawer 上一个/下一个跳转相邻重复块验证**:
* 前置条件:文件存在多个重复块
* 测试步骤:
    1. 打开 drawer
    2. 点击"下一个"按钮跳转到当前文件相邻重复块
    3. 验证页面高亮同步滚动且 drawer 内容同步切换
    4. 点击"上一个"按钮验证反向跳转
* 预期结果: 上一个/下一个按钮正确跳转相邻重复块，高亮与 drawer 内容同步

**6. drawer 放大缩小验证**:
* 前置条件:drawer 已打开
* 测试步骤:
    1. 使用多档宽度切换 drawer 宽度
    2. 拖拽 drawer 边缘调整宽度
    3. 验证缩放后 drawer 内容展示正常
* 预期结果: drawer 支持多档宽度切换与边缘拖拽，缩放后内容展示正常

**7. 旧 record 无 snapshot_data 占位展示验证**:
* 前置条件:存在本需求上线前扫描的旧 record（无 snapshot_data）
* 测试步骤:
    1. 打开无 snapshot_data 的旧 record 文件代码视图
    2. 验证左侧代码区显示"该记录无代码快照"占位，且不触发 Git API 降级拉取
    3. 验证该文件的重复块列表仍正常展示
    4. 点击重复块打开 drawer，验证代码片段可查看
* 预期结果: 无快照时正确占位展示，不降级拉取，重复块列表与 drawer 正常

**8. 同文件内重复代码块独立 tab 验证**:
* 前置条件:文件内部存在多个相同代码块（如多个相同 catch 块）
* 测试步骤:
    1. 打开文件代码视图并点击重复块打开 drawer
    2. 验证每个出现位置均为独立 tab
    3. 验证同组出现位置（含同文件其他位置）归为同一 group_id
    4. 验证同文件多个位置的 tab 标签带行号区间区分
* 预期结果: 同文件内重复块为独立 tab，group_id 归组正确，tab 标签可区分

**9. 完全一致文件（metricType=4）验证**:
* 前置条件:存在完全一致的重复文件（metricType=4）
* 测试步骤:
    1. 打开 metricType=4 文件详情
    2. 验证不展示具体重复代码（重复内容为整个文件）
    3. 验证由 duplicatedFiles 列表展示同组文件
* 预期结果: metricType=4 文件不展示具体重复代码，duplicatedFiles 列表正确

**10. 旧版插件未上报新字段的 record 兼容验证**:
* 前置条件:存在旧版插件扫描的 record（未上报 duplicationOccurrences / snapshotData）
* 测试步骤:
    1. 查看旧版插件扫描的 record 详情列表
    2. 验证详情列表照常展示，不报错
    3. 验证现有 metricType=0/1/2/4 详情接口行为不变
* 预期结果: 旧版插件 record 照常展示，现有接口行为不受影响

### 3.2 体验测试专项

**11. drawer 交互体验验证**:
* 前置条件:文件存在重复代码块
* 测试步骤:
    1. 依次执行打开 drawer、tab 切换、上一个/下一个、放大缩小操作
    2. 验证各操作即时响应、切换流畅无卡顿
    3. 验证代码视图展示清晰、高亮与 tab 标签易读
    4. 验证操作反馈（打开/关闭/切换）明确
* 预期结果: drawer 交互流畅、反馈清晰，代码视图展示友好

### 3.3 集成测试专项

**12. 插件上报→后端入库→前端展示端到端链路验证**:
* 前置条件:代码仓已接入 code-metrics-action 插件，openlibing-coderepo 服务与前端可访问
* 测试步骤:
    1. 触发 code-metrics-action 扫描，产生含 duplicationOccurrences / snapshotData 的上报
    2. 验证后端正确接收并入库重复块与上下文快照数据
    3. 在 openlibing-web 前端打开对应代码仓重复率详情页
    4. 验证前端正确展示重复代码块与配对文件代码片段
* 预期结果: 插件上报、后端存储查询、前端展示的端到端链路正常，数据一致

**13. 历史 pipelineRunId 重复块可追溯验证**:
* 前置条件:同一代码仓存在多个历史 pipelineRunId 的扫描结果
* 测试步骤:
    1. 查看历史 pipelineRunId 的重复率扫描结果
    2. 点击历史扫描的文件查看重复代码块
    3. 验证历史记录的重复代码块完整可查
* 预期结果: 历史扫描记录的重复代码块完整可追溯，数据不丢失

### 3.4 安全与隐私测试专项

**14. 查询接口仓库访问权限校验验证**:
* 前置条件:存在无权限用户与有权限用户
* 测试步骤:
    1. 使用无权限用户调用单文件代码视图/重复块详情接口
    2. 使用 groupId 越权访问其他仓库数据
    3. 验证越权访问返回 403
    4. 验证有权限用户正常访问
* 预期结果: 越权访问返回 403，权限校验正确

**15. 代码内容安全与日志脱敏验证**:
* 前置条件:重复代码数据已入库
* 测试步骤:
    1. 验证入库的代码内容为 Base64 编码存储
    2. 触发后端日志，验证日志不打印任何代码内容
    3. 验证上报接口沿用 APIG 签名 + HTTPS
* 预期结果: 代码内容 Base64 存储、日志无代码内容泄露、上报接口鉴权正常

### 3.5 可靠性与韧性测试专项

**16. 上下文快照存储与保留策略验证**:
* 前置条件:重复代码数据已入库
* 测试步骤:
    1. 验证上下文片段快照仅存储重复块±5行，未缓存完整文件
    2. 验证快照无 TTL 长期保留，历史记录完整可查
    3. 模拟快照缺失场景，验证前端占位展示正常
* 预期结果: 快照存储策略符合约束，历史数据长期可查，缺失场景降级正常

### 3.6 性能测试专项

**17. 单文件代码视图接口响应时间验证（<500ms）**:
* 前置条件:文件代码快照已命中缓存
* 测试步骤:
    1. 调用单文件代码视图接口（快照命中场景）
    2. 记录接口响应时间
    3. 验证响应时间 < 500ms
* 预期结果: 单文件代码视图接口响应时间 < 500ms

**18. 单重复块详情接口响应时间验证（<200ms）**:
* 前置条件:存在重复块数据
* 测试步骤:
    1. 调用单重复块详情接口
    2. 记录接口响应时间
    3. 验证响应时间 < 200ms
* 预期结果: 单重复块详情接口响应时间 < 200ms

**19. 插件单次上报体量验证（<10MB）**:
* 前置条件:code-metrics-action 插件可触发
* 测试步骤:
    1. 触发插件上报重复数据
    2. 验证单次上报体量 < 10MB
    3. 构造超大体量场景，验证超过 10MB 时自动分批上报
* 预期结果: 单次上报体量 < 10MB，超限时正确分批
