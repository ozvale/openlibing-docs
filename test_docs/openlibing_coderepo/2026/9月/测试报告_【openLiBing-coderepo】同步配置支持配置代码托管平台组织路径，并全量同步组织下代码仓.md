## 2. 测试过程

### 2.1 功能测试专项

**1.组织路径保存与回显验证（含归一）**:

- 预期结果: 支持组织登录名、GitCode 组织页、Gitee 主页、GitHub 组织页等形式，库内 `config_json.orgLocations` 与 GET 回显均为归一后的登录名，不存原始 URL
- **测试结果**： Passed
- **证明截图**: 待补充

**2.组织路径校验与无效报错验证**:

- 预期结果: 超出数量、跨平台域名、仓库/SIG URL、空串/`..`/归一后含 `/` 等输入被拒绝；远端预检失败返回 `code=failed` 且 data 携带无效明细，不写库
- **测试结果**： Passed
- **证明截图**: 待补充

**3.配置合并写入与兼容性验证**:

- 预期结果: 未提交平台保留旧值；不传 `orgLocations` 视为未修改；旧 `config_json` 无该键视为空列表，行为向后兼容
- **测试结果**： Passed
- **证明截图**: 待补充

**4.三类入口全量同步组织仓验证**:

- 预期结果: 页面手动同步、保存配置触发的异步同步、XxlJob 定时任务三类入口均按最新库内配置全量同步组织仓，导入结果一致，同步请求体不携带组织字段
- **测试结果**： Passed
- **证明截图**: 待补充

**5.组织内新增导入与下线硬删除验证**:

- 预期结果: 组织内新增仓自动导入且 `repo_source=org`；不在合并全集内的 `repo_source ∈ {sig, org}` 仓被硬删除；同一 `(platform, owner, repo)` 去重，导入来源取 sig
- **测试结果**： Passed
- **证明截图**: 待补充

**6.repo_source 区分与存量来源对账改判验证**:

- 预期结果: org / sig 来源正确区分；org→sig 改判不受开关控制；manual→发现来源仅在 `isMigrateToSig` 开启时发生（SIG 清单优先写 sig，仅组织清单写 org）；已是 sig 不改 org；manual 仓不参与硬删除；对账仅更新 `repo_source` 与审计字段
- **测试结果**： Passed
- **证明截图**: 待补充

**7.仓库列表来源展示、筛选与导出验证**:

- 预期结果: 列表正确显示「组织同步录入」，来源维度筛选（filter-meta `repoSource`）生效，导出结果包含组织来源映射
- **测试结果**： Passed
- **证明截图**: 待补充

### 2.2 体验测试专项

**1.全局配置来源表格交互验证**:

- 预期结果: 组织与 SIG 统一为可增删来源表格，空配置有占位行、表头有 tooltip 说明；失焦与保存均能校验并提示；未保存切换有提示、保存后按既有行为关闭，空值不触发 trim 异常
- **测试结果**： Passed
- **证明截图**: 待补充

**2.仓库列表组织来源展示可读性验证**:

- 预期结果: 「组织同步录入」标识清晰、与 SIG 来源可区分，筛选项与列表展示一致
- **测试结果**： Passed
- **证明截图**: 待补充

### 2.3 集成测试专项

**1.前后端端到端联调验证**:

- 预期结果: 配置提交格式（`orgLocations` 与 `sigInfoLocations` 同级、按平台字符串数组）与后端契约一致；查询兼容组织对象、URL 对象与字符串；列表展示与后端 `repo_source` 一致
- **测试结果**： Passed
- **证明截图**: 待补充

**2.组织同步与进度/互斥机制协同验证**:

- 预期结果: 组织同步纳入既有同步链路的进度统计与项目级互斥，不与手动/定时链路并发写 `repo_info`
- **测试结果**： Passed
- **证明截图**: 待补充

**3.多平台组织枚举集成验证**:

- 预期结果: GitCode / Gitee / GitHub 三平台均按 `per_page` 分页拉取全量组织仓，去重合并为 `(platform, owner, repo)` 全集，无截断与重复
- **测试结果**： Passed
- **证明截图**: 待补充

### 2.4 安全与隐私测试专项

**1.组织路径注入与路径穿越防护验证**:

- 预期结果: 空串、含 `..`、归一后仍含 `/`、跨平台域名、仓库/SIG URL 等输入全部被拒绝；归一后登录名不含 `/`，不存在路径穿越
- **测试结果**： Passed
- **证明截图**: 待补充

**2.越权校验验证**:

- 预期结果: 保存走现有全局配置权限、同步走现有 `/sync-repo` 项目权限，越权请求被拒绝
- **测试结果**： Passed
- **证明截图**: 待补充

**3.敏感信息保护验证**:

- 预期结果: 令牌日志掩码；`GlobalConfigVO` 只回显组织名（不含令牌）；失败日志只记录组织名与状态码
- **测试结果**： Passed
- **证明截图**: 待补充

### 2.5 可靠性与韧性测试专项

**1.抓取失败跳过硬删除保护验证**:

- 预期结果: 任一类路径抓取失败时 `shouldDelete=false`，跳过硬删除不误删仓库，单条失败计入 `failedLocations`
- **测试结果**： Passed
- **证明截图**: 待补充

**2.仅配组织路径时仓库不丢失验证**:

- 预期结果: 组织成功枚举计入 `resolvedLocations`，仅配置组织路径时组织仓正常导入，不被「`resolvedLocations==0` 跳过导入」丢弃
- **测试结果**： Passed
- **证明截图**: 待补充

**3.硬删除范围保护验证**:

- 预期结果: 硬删除仅作用于 `repo_source ∈ {sig, org}`，`repo_source=manual` 的仓不受影响
- **测试结果**： Passed
- **证明截图**: 待补充
