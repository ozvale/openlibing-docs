# 【openLiBing-coderepo】同步配置支持配置代码托管平台组织路径，并全量同步组织下代码仓 测试策略设计说明书

## 1. 基本信息

* **需求链接**: https://portal.edevops.huawei.com/ipdproject/third/2109653108
* **对应task(issueID)链接**: https://gitcode.com/openlibing/openlibing-coderepo/issues/142
* **需求名称**: 【openLiBing-coderepo】同步配置支持配置代码托管平台组织路径，并全量同步组织下代码仓
* **核心目标**:
  代码仓全局配置新增「组织路径」配置项 `orgLocations`（与 SIG 路径 `sigInfoLocations` 并列），支持填写组织登录名或组织主页 URL，保存时归一为登录名后写入 `config_json`；
  一次配置后，用户手动同步、保存配置触发的异步同步、XxlJob 定时任务三类入口均按最新库内配置枚举组织全量仓库：组织内新增仓自动导入、下线仓自动硬删除，并以 `repo_source=org` 与 `sig` 来源区分；
  存量仓来源对账支持 org 迁移为 sig（SIG 清单优先，不受开关控制），`isMigrateToSig` 开关语义扩展为「同步迁移录入来源」；仓库列表与导出同步体现组织同步来源。
* **开发责任人**: xiezhiqiang
* **测试责任人**: 徐愚冰

## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1.组织路径保存与回显验证（含归一）**:
* 前置条件: 具备全局配置权限的账号，项目已配置平台公共账号令牌
* 测试步骤:
    1. 在全局配置中为各平台填写组织路径，混合使用组织登录名与组织主页 URL
    2. 保存后查询 `GET /project-config/global-config`，检查 `orgLocations` 回显
    3. 检查库内 `config_json.orgLocations` 落库值
* 预期结果: 支持登录名（`openlibing`）、GitCode 组织页（`.../org/openlibing`）、Gitee 主页（`gitee.com/openEuler`）、GitHub 组织页（`github.com/orgs/apache`）等形式；库内与 GET 回显均为归一后的登录名，不存原始 URL

**2.组织路径校验与无效报错验证**:
* 测试步骤:
    1. 各平台合计填写超过 20 条，检查是否被拒绝
    2. 在 gitcode 键下填写非 gitcode 域名、或填写仓库/SIG 路径（含 `blob`/`tree`/`raw`）、空串、含 `..`、归一后仍含 `/`，逐一保存
    3. 填写不存在的组织，或令牌无权限访问的组织
* 预期结果: 超出数量、跨平台域名、仓库/SIG URL、非法字符输入均被拒绝；远端预检失败时返回 `code=failed` 且 data 携带无效明细，**不写库**

**3.配置合并写入与兼容性验证**:
* 测试步骤:
    1. 仅提交部分平台的 `orgLocations`，检查未提交平台的库内旧值
    2. 模拟旧客户端不传 `orgLocations` 保存，检查库内与回显
    3. 使用无 `orgLocations` 键的旧 `config_json` 触发同步，检查是否按空列表处理
* 预期结果: 未提交平台保留旧值；不传 `orgLocations` 视为未修改该字段；旧 JSON 无该键视为空列表，行为向后兼容

**4.三类入口全量同步组织仓验证**:
* 前置条件: 组织路径已配置且对应组织下存在仓库
* 测试步骤:
    1. 页面点击「同步仓库」（`POST /sync-repo`），观察组织仓是否全量导入
    2. 修改组织路径后保存配置，观察是否触发异步同步并按新配置执行（任务内读库，非请求体）
    3. 触发 XxlJob 配置发现同步（step8），观察定时链路是否同样读取 `orgLocations`
* 预期结果: 三类入口均可全量同步组织仓库，导入结果一致；同步请求体不携带组织字段

**5.组织内新增导入与下线硬删除验证**:
* 测试步骤:
    1. 在远端组织下新增一个仓库后触发同步，检查该仓是否自动导入且 `repo_source=org`
    2. 在远端组织下删除/转移某仓后触发同步，检查该仓是否被硬删除
    3. 检查同时出现在 SIG 清单与组织清单的仓的导入来源
* 预期结果: 新增仓自动导入；不在合并全集内的 `repo_source ∈ {sig, org}` 仓被硬删除；同一 `(platform, owner, repo)` 去重，导入时来源取 sig

**6.repo_source 区分与存量来源对账改判验证**:
* 测试步骤:
    1. 检查组织路径导入的仓 `repo_source=org`，SIG 路径导入的为 `sig`
    2. 构造已按组织导入、后又出现在 SIG 清单中的仓，触发同步，检查来源是否改判为 sig
    3. 分别以 `isMigrateToSig` 开启/关闭，检查 manual 来源仓是否迁移为本次发现来源
    4. 检查已是 sig 的仓是否被改成 org；检查 manual 仓是否在硬删除范围内
* 预期结果: org / sig 来源正确区分；org→sig 改判不受开关控制；manual→发现来源仅在开关开启时发生（SIG 清单优先写 sig，仅组织清单写 org）；已是 sig 不改 org；manual 仓不参与硬删除；对账仅更新 `repo_source` 与审计字段

**7.仓库列表来源展示、筛选与导出验证**:
* 测试步骤:
    1. 在仓库列表查看「来源」列，检查组织同步录入仓的展示
    2. 使用来源维度筛选，检查 `repo_source` 过滤结果
    3. 导出仓库列表，检查来源列取值映射
* 预期结果: 列表正确显示「组织同步录入」，源码筛选（filter-meta `repoSource`）生效，导出结果包含组织来源映射

### 3.2 体验测试专项

**1.全局配置来源表格交互验证**:
* 测试步骤:
    1. 打开全局配置，检查组织与 SIG 是否统一为可增删的来源表格
    2. 清空配置，检查空配置占位行与表头 tooltip 说明
    3. 输入非法路径后失焦、再点击保存，检查校验拦截
    4. 修改配置后未保存即切换页签/离开，检查未保存切换提示；保存后检查弹窗关闭行为
* 预期结果: 表格可增删、占位行与 tooltip 正常；失焦与保存均能校验并提示；未保存切换有提示、保存后按既有行为关闭，空值不触发 trim 异常

**2.仓库列表组织来源展示可读性验证**:
* 测试步骤: 在仓库列表定位组织来源仓，检查来源标识与筛选项文案
* 预期结果: 「组织同步录入」标识清晰、与 SIG 来源可区分，筛选项与列表展示一致

### 3.3 集成测试专项

**1.前后端端到端联调验证**:
* 前置条件: web 连 beta 后端，组织路径已配置
* 测试步骤: 在配置页填写登录名与组织主页 URL → 保存 → 回显 → 触发同步 → 仓库列表查看组织来源仓
* 预期结果: 配置提交格式（`orgLocations` 与 `sigInfoLocations` 同级、按平台字符串数组）与后端契约一致；查询兼容组织对象、URL 对象与字符串；列表展示与后端 `repo_source` 一致

**2.组织同步与进度/互斥机制协同验证**:
* 测试步骤: 配置组织路径后触发手动同步，观察同步进度与项目锁行为；同步期间触发定时任务
* 预期结果: 组织同步纳入既有同步链路的进度统计与项目级互斥，不与手动/定时链路并发写 `repo_info`

**3.多平台组织枚举集成验证**:
* 测试步骤: 分别为 GitCode、Gitee、GitHub 配置组织路径，触发同步，核对枚举结果
* 预期结果: 三平台均按 `per_page` 分页拉取全量组织仓，结果去重合并为 `(platform, owner, repo)` 全集，无截断与重复

### 3.4 安全与隐私测试专项

**1.组织路径注入与路径穿越防护验证**:
* 测试步骤: 提交空串、含 `..`、归一后仍含 `/`、跨平台域名、仓库/SIG URL 等形式
* 预期结果: 写入口先归一再校验，上述输入全部被拒绝；归一后的登录名不含 `/`，拼入平台 URL 时不存在路径穿越

**2.越权校验验证**:
* 测试步骤: 以无全局配置权限账号保存 `orgLocations`；以无项目权限账号调用 `/sync-repo`
* 预期结果: 保存走现有全局配置权限、同步走现有 `/sync-repo` 项目权限，越权请求被拒绝

**3.敏感信息保护验证**:
* 测试步骤: 检查保存/同步失败日志与 `GlobalConfigVO` 返回内容
* 预期结果: 令牌日志掩码；VO 只回显组织名（不含令牌）；失败日志只记录组织名与状态码

### 3.5 可靠性与韧性测试专项

**1.抓取失败跳过硬删除保护验证**:
* 测试步骤: 构造某一路径（SIG 或组织）枚举接口失败/返回不可信的场景，触发同步
* 预期结果: 任一类路径抓取失败时 `shouldDelete=false`，跳过硬删除，不误删仓库；单条失败计入 `failedLocations`

**2.仅配组织路径时仓库不丢失验证**:
* 测试步骤: 项目仅配置组织路径（无 SIG 路径），触发同步，检查组织仓是否被导入
* 预期结果: 组织成功枚举计入 `resolvedLocations`，不会因「`resolvedLocations==0` 跳过导入」导致组织仓全部丢弃

**3.硬删除范围保护验证**:
* 测试步骤: 构造 `repo_source=manual` 的仓不在发现全集中，触发同步
* 预期结果: 硬删除仅作用于 `repo_source ∈ {sig, org}`，manual 来源仓不受影响
