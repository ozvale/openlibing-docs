## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1.分支管理页度量指标展示与空数据态（AC1）**:

- 前置条件: beta 环境已部署改造分支；页面验证前先手动触发一次全量刷数（XxlJob `branchMetricsSyncHandler` 空参），避免存量空列被误判为缺陷
- 测试步骤: 进入分支管理页，核对五类度量列展示；查看无快照分支的展示
- 预期结果: 五类度量正常展示；无快照时指标项为 `null`、页面显示 `--`

**2.分支管理页度量排序与跨页数据稳定性（AC1/AC3）**:

- 测试步骤: 按各度量列升降序排序，翻页核对数据；核对分页控件与无数据态
- 预期结果: 排序单调、跨页不重不漏；空值位置遵循 MySQL 默认

**3.分支管理页度量值跳转详情与列表一致性（AC1）**:

- 测试步骤: 点击度量值跳转详情（依赖 master 前端 `file-detail` 响应回填 `runId`），核对列表值与详情值
- 预期结果: 列表值与详情数据同源一致

**4.新扫描上报后分支管理页度量刷新（AC4）**:

- 测试步骤: 触发一次真实度量上报（使用已在分支清单登记的分支）→ 轮询分支列表/详情接口确认刷列 → 页面核对刷新
- 预期结果: 页面度量刷新为新快照值；其他分支不受影响

**5.分支查询一次返回五项度量快照（AC2）**:

- 测试步骤: 调用 `POST /repo/branch/list`、`POST /project-repo/query-repo-branch`，核对结构与取值
- 预期结果: 一次返回五项指标，每项为 `{value}`（不返回 `pipelineRunId`），不访问 `code_metrics_record` 全历史

**6.度量排序下推与分页边界完整性（AC3）**:

- 测试步骤: 对五个度量字段分别升降序，核对排序单调与跨页连续性
- 预期结果: 排序走 SQL `ORDER BY` 下推，跨页不重不漏

**7.度量上报成功后五项指标同步刷新（AC4）**:

- 测试步骤: 上报受理后轮询分支列表/详情接口（5s 间隔、上限 5 分钟）确认落库与刷列
- 预期结果: 取该分支最新一条记录刷列；缺键列写 `NULL`、后续上报自愈；刷列失败仅告警不阻断上报

**8.列表度量与详情数据同源一致性**:

- 测试步骤: 同一 `repoId + branchName` 取列表快照值与 `file-detail`（不传 `pipelineRunId` 取最新一条），核对 `pipelineRunId/runNumber/checkTime`
- 预期结果: 指向同一条记录；可计算的代码规模（文件 `loc` 求和）做数值校验一致

**9.两个分支查询入口度量口径一致性**:

- 测试步骤: 项目维度与单仓维度结果按 `repoId + branchName` 对齐后逐指标 diff
- 预期结果: 五项指标口径一致

**10.分支查询异常排序参数与容错语义**:

- 测试步骤: 传入非法排序字段/方向/注入字符/超长/缺参，核对兜底语义
- 预期结果: 统一兜底（`sortField` 非法回落 `update_at desc`、`sortOrder` 仅识别 `asc`），不 500、不泄露 SQL；`pageSize` 上限 200、`projectId` 必填
