## 2. 测试过程

### 2.1 功能测试专项

**1.分支管理页度量指标展示与空数据态（AC1）**:

- 预期结果: 分支管理页五类度量（代码规模/平均代码行数/平均圈复杂度/总代码重复率/总文件重复率）正常展示；无快照时指标项为 `null`、页面显示 `--`
- **测试结果**： Passed（TC-ISSUE257-001）

**2.分支管理页度量排序与跨页数据稳定性（AC1/AC3）**:

- 预期结果: 按度量排序单调、跨页不重不漏；分页控件与无数据态表现正常
- **测试结果**： Passed（TC-ISSUE257-002）

**3.分支管理页度量值跳转详情与列表一致性（AC1）**:

- 预期结果: 点击度量值跳转详情，列表值与详情数据同源一致
- **测试结果**： Passed（TC-ISSUE257-003）

**4.新扫描上报后分支管理页度量刷新（AC4）**:

- 预期结果: 上报受理 → 异步入库 → 刷列 → 页面度量刷新可见
- **测试结果**： Passed（TC-ISSUE257-004）

### 2.2 接口测试专项

**1.分支查询一次返回五项度量快照（AC2）**:

- 预期结果: `POST /repo/branch/list`、`POST /project-repo/query-repo-branch` 一次返回五项指标，结构为 `{value}`（快照路径不返回 `pipelineRunId`），查询不再访问 `code_metrics_record` 全历史
- **测试结果**： Passed（TC-ISSUE257-005）

**2.度量排序下推与分页边界完整性（AC3）**:

- 预期结果: 五项指标升降序、空值位置、跨页不重不漏一致；排序走 SQL `ORDER BY` 下推
- **测试结果**： Passed（TC-ISSUE257-006）

**3.度量上报成功后五项指标同步刷新（AC4）**:

- 预期结果: 上报异步入库后取该分支最新一条记录刷列，缺键列写 `NULL`、后续上报自愈
- **测试结果**： Passed（TC-ISSUE257-007；run #19 真实上报 `b22c6be29fe84f3ca2627305fefc5b2c` 后五项即时刷新为 3982 / 24.61 / 6.31 / 10.87 / 0，pytest `1 passed in 45.93s`；未被上报的 `master` 分支指标不变）

**4.列表度量与详情数据同源一致性**:

- 预期结果: 列表 `codeScale` 与详情 `file-detail` 的 `loc` 汇总一致，指向同一条最新记录
- **测试结果**： Passed（TC-ISSUE257-009）

**5.两个分支查询入口度量口径一致性**:

- 预期结果: 项目维度 `repo/branch/list` 与单仓维度 `query-repo-branch` 按 `repoId + branchName` 对齐后五项指标一致
- **测试结果**： Passed（TC-ISSUE257-010）

**6.分支查询异常排序参数与容错语义**:

- 预期结果: 非法排序字段/方向/注入字符统一兜底，不 500、不泄露 SQL；`pageSize` 上限 200、`projectId` 必填
- **测试结果**： Passed（TC-ISSUE257-012）

### 2.3 写入刷列异步观测说明

`/metrics/code/report` 仅返回「上报已受理，正在异步导入」，入库与刷列由 MQ 消费者完成；TC-007 以轮询分支列表/详情接口确认落库（5s 间隔、上限 5 分钟），未以受理响应直接判定成功。

## 4. 遗留问题与风险说明

| 缺陷 ID | 缺陷描述     | 严重程度 | 处理意见 |
| ------- | ------------ | -------- | -------- |
| —       | 无未关闭缺陷 | —        | —        |

**遗留观察项（缺陷候选）**：

- `POST /gateway/openlibing-coderepo/repo/branch/list` 传 `platforms=gitcode` 稳定返回 `code=5010000, msg=异常`（仅传 `repoUrlLike`/`branchNameLike` 正常）；而 `code-metrics-scan` 输出的结果深链正是 `?platforms=gitcode&repoUrlLike=…&branchNameLike=…`，需确认前端实际枚举取值与深链可用性（建议提测确认后决定是否提缺陷）。

**遗留风险与说明**：

- **AC2/AC3 为代码级证据**：「不再访问全历史 / SQL 下推 / 内存排序删除」属实现级结论，黑盒仅做功能等价验证（快照值正确 + 排序单调 + 跨页连续），报告中引用实现分支（`feat-metrics-latest-snapshot` @ `24e3596b`）只读核对结论。
- **缺键清空旧值**：缺键列直接写 `NULL`（会覆盖旧值）、页面显示 `--`、后续上报自愈为既定实现语义，已按此验证，仍建议产品书面确认是否符合预期。
- **存量刷数（AC5）与机机接口（AC6）**：由开发自验证覆盖（XXL-JOB 三种模式、14215 分支秒级预演、`latest-by-commit/batch` 契约不变），测试侧不重复设计用例。
- **Tag 场景**：Tag 管理页前端暂无入口，`branchType='1'` 的 Tag 行未做 UI 级验证（后端刷列仅限 `branch_type='0'`，Tag 行列值恒为 `NULL`）。
- **环境性失败（非缺陷）**：run #2 / #16 上报入库成功但快照列未刷新，经确认为 BETA 部署期间/其他开发本地服务抢占 MQ 消费，部署恢复后连续两次即通过。
