## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1.安全编译选项插件链接输出（子需求一）**:

- 前置条件: 含被测插件的 GitCode 流水线；平台已录入仓/已登记分支
- 测试步骤: 触发插件扫描上报，读取工作流概览与 action output，核对链接（子）。
- 预期结果: 上报成功后按每个产物包输出 1 条「安全编译选项扫描结果（<包名>）」链接，双通道输出，key 末尾为小写 `url`

**2.安全编译选项插件未录入 tip 与上报失败**:

- 测试步骤: 使用未录入平台的仓触发；构造上报失败场景
- 预期结果: 未录入输出服务端 tip 文案；上报失败无链接/提示且主流程不中断

**3.安全编译选项插件双鉴权与存量输出无回退**:

- 测试步骤: 分别以 AK/SK 与 OIDC 路径触发；核对既有开启率/计数输出
- 预期结果: 两条路径均输出链接；既有输出格式与内容不变

**4.代码度量插件链接输出（子需求二）**:

- 测试步骤: 触发代码度量插件扫描上报，读取概览与 output
- 预期结果: 输出固定单条「代码度量指标扫描结果」链接，点击落地平台代码仓度量详情页并按仓库筛选置顶

**5.代码度量插件两类提示与上报失败**:

- 测试步骤: 构造仓未录入 / 分支未登记场景；构造上报失败
- 预期结果: 两类场景输出对应 tip；上报失败不输出链接/提示、扫描正常完成

**6.代码度量插件双鉴权与存量指标无回退**:

- 测试步骤: 分别以 AK/SK 与 OIDC 路径触发；核对既有 5 项代码度量指标
- 预期结果: 两条路径均输出链接；既有指标输出不变

**7.跨插件联合场景**:

- 测试步骤: 在同一流水线内同时触发两个插件任务
- 预期结果: 两个插件任务均输出各自链接

## 4. 依赖与前置条件

- GitCode 流水线（含被测插件特性分支）可用于触发两个插件的扫描与上报；插件运行需 Python 3.10（security-compilation 需 pyelftools）
- openLiBing 平台已录入 / 未录入的代码仓与分支数据（用于链接态与 tip 态构造）
- 目标仓库/分支测试数据：`openlibing-test/zlib` 等
- 取证通道：`gitcode actions run/job/log`（流水线日志）+ 工作流概览（`ATOMGIT_STEP_SUMMARY`）+ action output（`ATOMGIT_OUTPUT`）
