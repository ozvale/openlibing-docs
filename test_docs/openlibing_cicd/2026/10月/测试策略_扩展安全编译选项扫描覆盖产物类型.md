## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1.任意后缀 ELF 文件纳入扫描验证（AC1）**:

- 前置条件: zlib 测试项目工作流已改造收集步骤，产物含 CMakeFiles/.o/.a + 特性验证样例
- 测试步骤: push `develop` 触发工作流 → 插件扫描 → 核对流水线 job 日志（`Scan completed: N ELF files checked`、各选项 rate/count）
- 预期结果: `.obj`/`.c.obj`/无后缀/任意后缀 ELF 按内容纳入扫描（与后缀无关）

**2.可重定位目标文件判定口径验证（AC1）**:

- 测试步骤: 核对 ET_REL 文件的链接期与编译期选项统计口径
- 预期结果: 链接期选项返回 N/A 不计分母；编译期选项经符号表检出并纳入统计，口径与现有 `.o` 一致

**3.静态库按内容识别解包验证（AC2）**:

- 测试步骤: 扫描含改名/无后缀 `.a` 静态库的样例
- 预期结果: `.a` 按内容识别解包，内部目标文件编译期选项检出

**4.改名或缺失后缀归档识别验证（AC2）**:

- 测试步骤: 扫描改名 `.dat` 与无后缀 ar 归档样例
- 预期结果: 均被解包

**5.嵌套归档递归解包验证（AC2）**:

- 测试步骤: 扫描嵌套归档样例
- 预期结果: 逐层递归解包，内部目标文件检出

**6.顶层产物包改名后仍可解析验证（AC2）**:

- 测试步骤: 将顶层产物包去后缀 / 追加非法后缀后触发扫描
- 预期结果: 仍正常解析

**7.产物原件与归档内副本去重验证（AC3）**:

- 测试步骤: 构造同一文件多处存放（归档成员与树内原件）场景
- 预期结果: 同一文件仅计一次；归档成员与树内已见内容重复时按成员侧去重，树内真实路径保留

**8.diting 大包整体回归计数验证（AC3）**:

- 测试步骤: 以特性分支扫描 `pack_diting_community.tar.gz`，与改造前 `@master` 基线对照
- 预期结果: 约 4840 个独立文件

**9.损坏或非产物文件容错验证（AC4）**:

- 测试步骤: 扫描含截断包/文本文件等损坏/非产物样例
- 预期结果: 不中断扫描流程，记录失败文件

**10.现有 elf 扫描结果无回退验证（AC4）**:

- 测试步骤: 扫描规范命名的既有 `.elf` 产物样例
- 预期结果: 扫描正常完成、上传成功、无崩溃，既有判定无回退
