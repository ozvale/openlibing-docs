# 数据级权限管控能力建设 测试策略设计说明书

## 1. 基本信息

- **对应task(issueID)链接**: https://gitcode.com/openlibing/openlibing-cicd/issues/223
- **需求名称**: 数据级权限管控能力建设
- **核心目标**:
  在 8 个服务（framework/cicd/codecheck/coderepo/gateway/platform-release/sca/anti-poison）上建设数据级权限管控能力：user_role_info 表新增 perm_group_id 字段（存量数据默认 0=默认分组）；权限组全生命周期管理（创建/编辑/删除，删除自动连带清理成员记录）；资源级绑定（单条流水线绑定权限组）实现组内成员可见可操作、组外用户拒绝且查看收紧；三个全局角色（admin/super_admin/platform_operater）绕过权限组检查；cicd 鉴权 RPC 失败 fail-closed（拒绝访问）；framework 先行部署，其余服务随后适配。
- **开发责任人**: 杨宇萌
- **测试责任人**: 赵威

## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1.权限组列表与默认组展示验证**:

- 前置条件: framework 已部署权限组能力，user_role_info 表已新增 perm_group_id 字段
- 测试步骤:
  1. 查看权限组列表页
  2. 核对默认分组（0）存在及存量成员归属
- 预期结果: 权限组列表正常展示，默认分组存在且存量数据默认归入默认分组

**2.权限组创建编辑删除与连带清理验证**:

- 前置条件: 存在可配置的管理员账号
- 测试步骤:
  1. 创建自定义权限组并编辑组名
  2. 为组配置成员后删除该组
  3. 查询原组成员归属
- 预期结果: 权限组可创建/编辑/删除，删除后自动连带清理成员记录，无残留选项

**3.成员管理一页化与组内成员维护验证**:

- 前置条件: 已存在自定义权限组
- 测试步骤:
  1. 在一页化成员管理中添加/移除成员
  2. 查询组成员列表
- 预期结果: 组内成员可正确维护，成员分组信息正确保存

**4.流水线设置权限组绑定与解绑操作验证**:

- 前置条件: 存在流水线与自定义权限组
- 测试步骤:
  1. 在流水线设置中绑定权限组
  2. 解除绑定后查看流水线权限归属
- 预期结果: 绑定/解绑操作生效，解绑后资源回退到默认分组

**5.绑定组流水线组内成员操作验证**:

- 前置条件: 流水线已绑定自定义权限组，组内存在成员
- 测试步骤:
  1. 组内成员查看并触发该流水线
- 预期结果: 组内成员可正常查看与操作绑定流水线

**6.绑定组流水线组外用户拒绝与查看收紧验证**:

- 前置条件: 流水线已绑定自定义权限组，存在组外普通用户
- 测试步骤:
  1. 组外用户尝试查看该流水线
  2. 组外用户尝试触发该流水线
  3. 以三个全局角色（admin/super_admin/platform_operater）访问该流水线
- 预期结果: 组外用户查看收紧且操作被拒绝；三个全局角色不受权限组限制可正常访问

**7.权限组管理接口参数校验验证**:

- 前置条件: 权限组管理接口（query-groups/create-group/update-group/delete-group/bind-resource）已按重命名后路径提供
- 测试步骤:
  1. 传入有效参数调用各权限组管理接口
  2. 传入重名组名、空更新体、不存在的组 ID、默认组删除、缺失必填参数等无效类
- 预期结果: 有效类成功；无效类返回明确错误码与提示，不出现 500

**8.资源绑定接口语义验证**:

- 前置条件: 存在组 G1/G2 与多条流水线资源
- 测试步骤:
  1. 将资源从 G1 换绑至 G2 后正反查
  2. 将资源移回默认组后重复操作（幂等）
  3. 批量绑定部分资源 ID 失效
  4. 解绑后资源回退默认组
- 预期结果: 换绑覆盖、移回默认组幂等、批量部分失败整体不回滚且成功项生效、解绑回退，正反查/批量查一致

**9.权限总览接口与流水线详情权限字段验证**:

- 前置条件: 已存在绑定关系与不同权限用户
- 测试步骤:
  1. 查询权限总览接口结构
  2. 以不同用户查询流水线详情权限字段
  3. 以无权限用户访问
- 预期结果: 总览结构契约一致，详情权限字段与用户权限匹配，无权限返回 403

**10.8 服务原功能回归与 L3 权限矩阵专项验证**:

- 前置条件: 8 服务已完成权限组适配合入
- 测试步骤:
  1. 回归 framework/codecheck/coderepo/cicd/platform-release/sca/anti-poison 各服务原功能
  2. 回归 gateway 网关全站鉴权
  3. 执行 L3 权限矩阵专项回归
- 预期结果: 各服务原功能无回归，网关鉴权正常，L3 权限矩阵行为符合预期

### 3.2 安全与隐私测试专项

**11.绑定组资源鉴权矩阵验证**:

- 前置条件: 存在绑定权限组的资源、组内/组外身份及四类权限身份
- 测试步骤:
  1. 以四类身份×组内/组外×查看/触发操作构造鉴权矩阵逐一验证
  2. 未登录访问绑定资源接口
  3. 独立环境下注入 cicd 鉴权 RPC 故障
- 预期结果: 鉴权矩阵按权限组语义生效（组内允许/组外拒绝，全局角色放行）；未登录 401；RPC 失败 fail-closed 拒绝访问

**12.权限组管理横向越权与权限点校验验证**:

- 前置条件: 存在分属不同权限组的账号 A/B 及权限组管理接口
- 测试步骤:
  1. 账号 A 以篡改 userId/组 ID 方式访问 B 所属权限组资源
  2. 越权调用权限组管理接口
- 预期结果: 横向越权被拦截，伪造身份不泄露他人权限组数据，越权调用返回明确拒绝
