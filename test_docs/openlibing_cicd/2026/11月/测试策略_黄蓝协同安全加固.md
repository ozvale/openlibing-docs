### 1.2 需求摘要

> 详见 `测试过程数据/需求分析文档.md` 1.2 / 1.6 `FP-01~FP-08` / 1.7 `BR-01~BR-07` / 1.8 `EX-01~EX-08`。

黄区同步流水线新增用户白名单校验：蓝区触发链路（插件 PR 触发、push 直发、黄区手动触发）将触发用户账号随 MQS 传送到黄区；黄区按「黄区用户名单」（账号→产品映射）判断触发用户是否属于目标产品，仅产品内用户允许拉起同步流水线；非产品用户拒绝且无同步动作，PR 回显失败标签与无权限原因。白名单以黄区名单为准，不实时查蓝区成员。

### 1.3 测试目标

1. 验证产品内用户经 PR 插件触发、push 直发、黄区手动触发均可正常拉起同步流水线（FP-01/FP-04/FP-07）。
2. 验证非产品用户（名单外、产品不匹配、无产品映射、账号缺失）在三个入口均被拒绝且零副作用（FP-05/FP-07/FP-08，BR-03/BR-04）。
3. 验证拒绝结果正确回显（失败标签 + 无权限原因）（FP-06，BR-06）。
4. 验证名单变更（移出/重新加入）后的生效行为与多产品用户放行口径（FP-02/FP-03）。

**维度组合定稿说明（v3.23 自动定稿）**

- 方案 A「仅手工功能验证」：覆盖放行/拒绝主路径，但遗漏名单变更类边界。
- 方案 B「手工功能 + 名单变更边界」：与用户手动验证方式一致，覆盖放行、拒绝与名单变更；推荐采用。
- 方案 C「追加自动化」：黄区不可观测、账号不可自主构造，自动化收益低，不采用。
- **定稿：方案 B**。

### 1.5 测试策略

- 手工测试（全部用例由用户手动执行，AI 只输出过程文档）：
  - P0：产品内用户经 PR 评论 `sync` 触发 → 同步成功与成功标签（FP-04）。
  - P0：非产品用户 PR 触发 → 拒绝拉起、无同步记录、失败标签 + 无权限原因（FP-05/FP-06）。
  - P0：账号在名单但产品不匹配 → 拒绝（FP-03/BR-02）。
  - P0：产品内用户 push 直发 → 同步正常（FP-07）。
  - P1：产品内用户黄区手动触发 → 同步成功；非产品用户手动触发 → 拒绝（FP-07）。
  - P1：非产品用户 push 直发 → 拒绝（FP-07）。
  - P1：账号无产品映射 / 移出产品后再次触发 → 拒绝（FP-03/EX-03/EX-07）。
  - P2：账号缺失 fail-closed、重新加入后恢复、多产品任一命中。
- 自动化测试：本需求不生成自动化脚本（黄区内部不可观测、测试账号由用户控制）。
- 优先级：P0 覆盖产品内放行与核心拒绝路径；P1 覆盖多入口与名单变更；P2 覆盖兜底与安全边界。

### 1.7 风险与约束

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 黄区内部校验与名单数据不可观测 | 只能通过外部现象推断是否校验 | 以「是否拉起同步流水线 / 是否产生同步记录 / PR 标签」为判据，必要时请开发协助确认 |
