### 1.2 需求摘要

详见 `测试过程数据/需求分析文档.md`：1.2 需求背景与目标、1.5 接口清单（API-01~API-49）、1.6 功能点 `FP-01~FP-08`、1.7 业务规则 `BR-01~BR-11`、1.8 异常边界 `EX-01~EX-11`。

简述：网关 `PermissionCheckFilter` 下线前，cicd 侧以类级 `@ProjectAuth` 承接 49 个 `/project/{projectId}/**` 端点的项目级鉴权；类级 projectId 仅信任路径变量、pulls 子路径菜单 URL 坍缩、项目级与流水线级 AND 叠加、不继承 visitor 分支、方法级存量行为不变。测试目标是证明「迁移前后鉴权行为逐端点等价」。

### 1.3 测试目标

1. 验证 49 端点类级鉴权生效：项目 admin 放行、项目成员/项目外用户按菜单权限判定、纯 visitor 仍 403、匿名 401。
2. 验证类级 projectId 只取路径变量，缺失 fail-closed（400），query/body 伪造不参与判定。
3. 验证 pulls 及其子路径菜单 URL 坍缩为 `/pr/pulls/{number}`、`/pr/gitcode/pulls/{number}`。
4. 验证项目级 + 流水线级 AND 叠加（任一失败即拒绝），方法级 3 个端点行为不变。
5. 验证已知偏差 `get-pr-pipeline` 前后均 403，不作为缺陷上报。
6. 核对端点完整性：49 个端点清单守恒，7 个 Controller 均声明类级 `@ProjectAuth`。

### 1.4 测试范围

| 测试类型 | 是否覆盖 | 说明 |
|----------|----------|------|
| UI功能测试 | 否 | 本需求无前端代码与交互变更；页面表现由 API 鉴权结果决定，UI 层不单独设计用例（BETA 页面回归并入手工角色矩阵的抽检项） |
| API接口测试 | 是 | 49 端点鉴权规则断言：401/403/400 语义、路径变量 fail-closed、pulls 坍缩、AND 叠加、方法级不变（对应 FP-01~FP-07、BR-02~BR-10） |
| DFX测试 | 否 | 无新增性能指标、无缓存变更（每请求 1 次 SQL，与网关删除前一致）；不做独立性能用例，执行时记录单接口响应时间作为观察项（对应 FP 无、design 5 章） |
| 安全测试 | 是 | 6 维度逐项声明：① 认证校验 覆盖（EX-01 匿名 401）；② 横向越权 覆盖（EX-04/EX-05 跨项目、query 伪造 projectId）；③ 纵向越权 覆盖（EX-04 纯 visitor/低权限 403）；④ 传输安全 不覆盖（本次不改传输链路，由既有 04_安全测试/TC-ISSUE372-007 基线覆盖）；⑤ CSRF 不覆盖（本次不涉及状态变更的 CSRF 机制改造，沿用网关既有策略）；⑥ 敏感信息防护 不覆盖（无新增响应字段，错误码仅回传标准提示） |

> 维度组合定稿（v3.23，AI 按推荐定稿）：**API + 安全为主，UI/DFX 不覆盖**。
> 备选方案与权衡：A「API + 安全 + UI 抽检」——UI 抽检可发现前端对 403 的展示异常，但本需求前端零改动、BETA 角色矩阵已验证等价性，增量有限；B「仅 API」——遗漏手工角色矩阵与页面侧观察，无法满足验收标准第 8 条；C「全量 49 端点 × 7 角色」——组合爆炸（343 组）且多数组合对判定无区分度。推荐 A'（API+安全为主 + 手工角色矩阵抽检），即本策略。

### 1.5 测试策略

- 手工测试：BETA 响应等价对比——按 7 个 Controller 各取 1 个代表端点（含 gitcode 通道、multipart 上传、pulls 子路径），以「项目 admin / 项目成员低权限 / 纯 visitor / 匿名」四身份调用，逐条与网关删除前基线比对；`get-pr-pipeline` 单独确认前后均为 403 并标注已知偏差。
- 自动化测试：将上述等价矩阵转为 API 脚本断言（状态码 + errorCode + 与基线一致），并覆盖拒绝来源区分（401 `MISSING_USER_ID` / 403 `PERMISSION_DENIED`）；脚本位置 `src/automation/software-cicd/sec/development_management/pr_management/beta/`（登记在各用例 .md「脚本位置」字段）。
- 覆盖边界（最小对比集口径）：pulls 坍缩（由 PrController 代表端点间接覆盖）、缺路径变量 fail-closed、两级 AND 叠加、占位符改名、49 端点清单与 SQL 零改动，共 5 项在脑图中标记为豁免，由开发单测 `AuthInterceptorTest`（61 例）与代码评审覆盖，测试侧不重复验证。
- 优先级：P0 = 7 控制器四身份等价矩阵 + 方法级 3 端点不变；P1 = 拒绝来源区分 + `get-pr-pipeline` 已知偏差。

### 1.7 风险与约束

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 网络环境 WAF 拦截（历史 requests 通道被 401） | 自动化批量请求被误判为攻击，结果不可信 | 安全用例串行批次执行，沿用 `SECURITY_WAF_BATCH_SIZE`/`COOLDOWN_SEC`，失败先区分 WAF 401 与业务 403 |
| 角色账号不足（项目外用户、platform_operater、repo_observer 未提供） | 角色矩阵覆盖不全 | 上述角色走手工补采；自动化先用 admin / 低权限 / 匿名三类身份，结论写明覆盖边界 |
| `menu_url_info` 各环境数据不一致 | 48 端点「等价」基线无法比对（缺网关删除前的对照数据） | 以「48 端点对项目 admin 放行、对无权限身份 403」为等价口径；`get-pr-pipeline` 单独断言 403 并标注已知偏差 |
| PR 分支与线上部署差异（BETA 已部署但可能非 PR head 最新提交） | 断言与实际实现不一致 | 执行前用 `/openlibing-cicd` 版本标识或部署记录核对提交；不一致则标注「待复测」 |
| 网关过滤器仍在线 | cicd 与网关双通道并存，无法单独证明 cicd 侧校验生效 | 以 cicd 侧错误码（`MISSING_PROJECT_ID` / `PERMISSION_DENIED`）与日志特征区分来源；不把网关拒绝当作 cicd 通过 |
