* 黄区（源仓侧）与蓝区（目标仓侧）测试环境就绪，跨仓 PR 同步链路（webhook + MQS）已部署 dev 分支构建产物（关联 PR !584）。
* 三平台测试仓库准备：gitcode / gitee / github 各一个测试仓库，用于验证主动触发接口跨平台兼容性。
* 测试数据：准备含 extension 字段的 pipeline-status 回调报文模板、含 tgt_branch/account 的 MQS 消息模板、gitee_pr_info 元数据样本。

### 3.1 功能测试专项

> 参考测试设计方向
> * 回调主路径：pipeline-status 回调携带 extension 时正确落库，pipelineInfo 可查询展示。
> * 主动触发接口：必填参数校验、三平台兼容、中断旧非终态流水线并创建新记录。
> * MQS 消息字段：tgt_branch 与 account 字段正确补充。
> * 元数据落库：gitee_pr_info 按全局 id + 平台补全，轮询可见。
> * 异常兜底：MQS 发送失败时新流水线记录置 FAILURE。

**1.pipeline-status回调_extension字段落库与查询（主路径）**:

* **步骤一**：构造 pipeline-status 回调请求，携带 extension 扩展字段（含错误码 `errorCode` 与构建流水线链接 `buildUrl`），发送至回调接口
* **预期结果**: 回调成功响应，extension 字段正确落库至流水线记录表
* **步骤二**：通过 pipelineInfo 查询接口（或前端页面）查询该流水线记录
* **预期结果**: 返回的 pipelineInfo 中包含 extension 中的错误码与构建详情链接，前端可正确展示

**2.pipeline-status回调_无extension字段兼容回归**:

* **步骤一**：构造 pipeline-status 回调请求，不携带 extension 扩展字段，发送至回调接口
* **预期结果**: 回调成功响应，流水线记录正常落库，extension 字段为空/默认值，不影响既有回调链路行为

**3.主动触发接口_必填参数校验**:

* **步骤一**：调用 `POST /cross-region/pr-sync/trigger`，逐一缺失必填参数（组织 org / 仓库 repo / PR 编号 prNumber / PR 全局 id prGlobalId / 平台 platform）
* **预期结果**: 缺失任一必填参数时返回参数校验错误（4xx），错误信息明确指出缺失字段名

**4.主动触发接口_非法platform参数**:

* **步骤一**：调用主动触发接口，platform 参数传入非法值（如 `gitlab`、空字符串、数字等）
* **预期结果**: 返回参数校验错误，拒绝创建流水线记录

**5.主动触发接口_中断旧非终态流水线**:

* **步骤一**：先调用主动触发接口创建一条流水线记录（状态为 RUNNING/PROCESSING 等非终态）
* **步骤二**：再次调用主动触发接口，使用相同的 PR 参数触发新的同步
* **预期结果**: 旧的非终态流水线记录被中断（状态置为终态如 INTERRUPTED/CANCELLED），新流水线记录创建成功并返回新 msgId

### 3.2 集成测试专项

**1.黄区→蓝区回调端到端_extension字段完整链路验证**:

* **步骤一**：在黄区触发 PR 同步后，黄区流水线执行完成并回调蓝区 pipeline-status 接口，回调报文携带 extension（错误码 + 构建详情链接）
* **预期结果**: 蓝区回调接口正确接收并落库，前端 pipelineInfo 页面可查询并展示错误码与构建详情链接，端到端链路完整

**2.黄区创建映射_蓝区触发PR同步_标签打印与报告展示链接全流程验证**:

* **步骤一**：在黄区创建跨仓 PR 映射关系（配置源仓/目标仓、分支映射等要素）
* **预期结果**: 映射关系创建成功，可通过查询接口确认映射要素完整
* **步骤二**：在蓝区通过主动触发接口（POST /cross-region/pr-sync/trigger）触发 PR 同步
* **预期结果**: 同步流程正常启动，流水线记录创建成功并返回 msgId
* **步骤三**：同步完成后，在蓝区查看 PR 标签打印结果（如同步状态标签、源/目标分支标签）
* **预期结果**: PR 标签正确打印并打在对应 PR 上，标签内容与实际同步状态一致
* **步骤四**：在蓝区前端页面查看 pipelineInfo 报告展示链接（错误码、构建流水线详情链接）
* **预期结果**: 报告展示链接可正确跳转至构建流水线详情页，错误码与实际同步结果一致，全流程（映射创建→触发同步→标签打印→报告展示）闭环

**3.MQS消息收发一致性_tgt_branch与account跨服务传递**:

* **步骤一**：触发 PR 同步后，分别在 MQS 生产端（发送方）与消费端（接收方）捕获消息体，比对 tgt_branch 与 account 字段值
* **预期结果**: 生产端与消费端消息体中 tgt_branch 与 account 字段值一致，跨服务传递无丢失或篡改
