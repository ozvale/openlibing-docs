### 3.1 功能测试专项

**1.自动重置流水线标签验证**:
* 前置条件：无
* 测试步骤：
* 1.创建一个PR并触发流水线运行
* 2.等待流水线完成并生成标签
* 3.向PR提交新的代码更新
* 4.验证流水线标签是否自动重置
* 预期结果：
* PR代码更新时，流水线标签自动重置

**2.自动重置流水线标签验证-PR关闭**:
* 前置条件：无
* 测试步骤：
* 1.创建一个PR并触发流水线运行
* 2.等待流水线完成并生成标签，关闭PR
* 3.向PR提交新的代码更新，重启PR
* 4.验证流水线标签是否自动重置
* 预期结果：
* PR代码更新时，流水线标签自动重置

**3.多轮代码更新验证**:
* 前置条件：无
* 测试步骤：
* 1.创建一个PR
* 2.多次向PR提交代码更新
* 3.验证每轮代码更新后流水线标签是否都能自动重置
* 预期结果：
* 多次代码更新后，流水线标签都能自动重置

**4.不同类型代码更新验证**:
* 前置条件：无
* 测试步骤：
* 1.创建一个PR
* 2.分别提交不同类型的代码更新（如修改文件、添加文件、删除文件）
* 3.验证每种类型的代码更新是否都能触发流水线标签重置
* 预期结果：
* 不同类型的代码更新都能触发流水线标签重置

**5.流水线状态验证**:
* 前置条件：无
* 测试步骤：
* 1.创建一个PR并触发流水线运行
* 2.在流水线运行过程中向PR提交代码更新
* 3.验证流水线状态是否正确处理
* 4.确认新的流水线是否能够正常启动
* 预期结果：
* 流水线运行过程中提交代码更新，系统能够正确处理，新的流水线能够正常启动

### 3.2 体验测试

**6.用户体验验证**:
* 前置条件：无
* 测试步骤：
* 1.创建一个PR并提交代码更新
* 2.观察PR页面上的流水线标签状态变化
* 3.验证状态更新是否清晰可见
* 4.检查相关通知是否及时准确
* 预期结果：
* PR页面上的流水线标签状态变化清晰可见，相关通知及时准确，用户体验良好
