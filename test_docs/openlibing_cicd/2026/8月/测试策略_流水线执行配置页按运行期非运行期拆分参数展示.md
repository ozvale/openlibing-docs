# 流水线执行配置页按运行期/非运行期拆分参数展示 测试策略设计说明书

## 1. 基本信息

* **需求链接**: https://gitcode.com/openlibing/openlibing-cicd-web/issues/64
* **需求编号**: -
* **需求名称**: 流水线执行配置页按运行期/非运行期拆分参数展示
* **核心目标**:
  验证 openlibing-cicd-web 流水线执行配置弹窗（pipelineRunDialog.vue）能够依据 detailInfo 接口返回的 `is_runtime` 字段将流水线参数拆分为「运行参数配置」（可编辑）与「非运行期参数」（只读灰字）两部分展示，并保证执行提交时两部分参数被正确合并后发送到 postPipelineRun 接口，覆盖边界场景（全运行期、全非运行期、无参数、is_runtime 为 null 等）与异常场景。

### 3.1 功能测试专项

> 参考测试设计方向
> * 参数拆分：验证 detailInfo 接口返回的 variables 按 is_runtime 字段正确拆分为运行期与非运行期两组。
> * 可编辑性：验证运行期参数可编辑名称/值、可增删行；非运行期参数只读、灰字、不可编辑。
> * 提交合并：验证执行提交时两部分参数合并后发送到 postPipelineRun 接口，数据结构与格式正确。
> * 边界场景：验证全运行期、全非运行期、无参数等场景。
> * 异常场景：验证 variables 为 null 等场景。

**1.流水线无参数_面板展示**:

* **步骤一**：选择一条流水线参数为空（variables 为空数组或 null）的流水线，打执行配置弹窗
* **预期结果**: 弹窗正常打开，"运行参数配置"折叠面板下无参数行，"非运行期参数"折叠面板不显示（v-if 判定长度为 0）
* **步骤二**：直接点击确定提交
* **预期结果**: 提交请求中 variables 为空数组，接口正常响应，流水线触发执行


**2.流水线仅含运行期参数_非运行期面板不显示**:

* **步骤一**：选择一条 variables 中所有参数 `is_runtime === true` 的流水线，打开执行配置弹窗
* **预期结果**: "运行参数配置"折叠面板正常展示所有参数行，名称/类型/值可编辑，存在增删按钮
* **步骤二**：检查"非运行期参数"折叠面板
* **预期结果**: "非运行期参数"折叠面板不显示（nonRuntimeParams 长度为 0，v-if 判定不渲染）


**3.流水线仅含非运行期参数_运行参数配置无行**:

* **步骤一**：选择一条 variables 中所有参数 `is_runtime !== true`（含 false/null/undefined）的流水线，打开执行配置弹窗
* **预期结果**: "运行参数配置"折叠面板下无参数行（executionParams 为空），表单校验自动通过
* **步骤二**：检查"非运行期参数"折叠面板
* **预期结果**: "非运行期参数"折叠面板正常展示所有参数行，参数为只读、灰字（color: #909399）、不可编辑


**4.流水线同时含运行期与非运行期参数_分别展示**:

* **步骤一**：选择一条 variables 中同时存在 `is_runtime === true` 与 `is_runtime !== true` 参数的流水线，打开执行配置弹窗
* **预期结果**: 两个折叠面板均展示；"运行参数配置"面板展示运行期参数，可编辑名称/值、可增删行
* **步骤二**：检查"非运行期参数"折叠面板
* **预期结果**: "非运行期参数"折叠面板展示非运行期参数，只读、灰字、不可编辑，name/type/value 与接口返回一致


**5.运行期参数可编辑_名称值增删**:

* **步骤一**：在"运行参数配置"折叠面板中，修改某个运行期参数的 name 与 value
* **预期结果**: 修改成功，输入框正常响应
* **步骤二**：点击"+"按钮新增一行参数，填写 name 与 value
* **预期结果**: 新增行展示正常，可编辑
* **步骤三**：点击某行的删除按钮
* **预期结果**: 对应行被移除，其余行不受影响


**6.非运行期参数只读_不可编辑**:

* **步骤一**：在"非运行期参数"折叠面板中，尝试点击/修改参数的 name、type、value
* **预期结果**: 所有字段均不可编辑，无输入框响应，文字为灰色（#909399）
* **步骤二**：检查是否存在增删按钮
* **预期结果**: 非运行期参数区域不存在增删按钮


**7.执行提交_两部分参数合并发送**:

* **步骤一**：配置运行期参数的值，保持非运行期参数默认值，点击确定提交
* **预期结果**: postPipelineRun 请求的 variables 字段包含运行期与非运行期两部分参数，每项为 `{name, value}` 结构，顺序为运行期在前、非运行期在后
* **步骤二**：对比提交的 variables 与 detailInfo 接口返回的 variables
* **预期结果**: 运行期参数值为用户修改后的值，非运行期参数值为接口返回的原始值，参数数量一致


**8.variables为null_异常处理**:

* **步骤一**：构造 detailInfo 接口返回 `res.data.variables` 为 null/undefined 的场景（可借助 mock），打开执行配置弹窗
* **预期结果**: 不进入 if 分支，executionParams 与 nonRuntimeParams 保持初始空值，两个折叠面板均不展示参数行，弹窗不报错
