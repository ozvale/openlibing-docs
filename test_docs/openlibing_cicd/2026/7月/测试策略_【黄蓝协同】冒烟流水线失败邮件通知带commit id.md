### 3.1 功能测试专项

> 参考测试设计方向
> * 邮件模板字段校验：验证 commit id 字段在模板中正确展示，包括短 SHA（7位）和长 SHA（40位）两种格式。
> * 边界与异常输入：验证 commit id 为空、commit id 超长、commit id 包含特殊字符时的兜底逻辑。
> * 邮件发送链路：验证 SMTP/MQS 通道在流水线失败时正常触发，且不影响主流程。

**1.发送邮件的接口可正常调用发送邮件**:

* **步骤一**：调用发送邮件的接口，传入收件人、邮件主题、邮件正文（含 commit id）等参数
* **预期结果**: 接口返回 2xx 成功状态，邮件实际投递到收件人邮箱
* **步骤二**：在收件人邮箱中查看邮件
* **预期结果**: 邮件正常接收，主题、正文、commit id 字段均按预期展示


**2.流水线执行结果邮件效果展示**:

* **步骤一**：在测试代码仓库触发冒烟流水线，使其中一个阶段任务执行失败
* **预期结果**: 流水线状态变为失败，系统自动发送失败邮件通知
* **步骤二**：在收件人邮箱中查看邮件正文，确认包含流水线执行结果、commit id 及跳转链接
* **预期结果**: 邮件内容完整，commit id 与实际失败 commit 一致，能够通过链接定位到失败 commit 与流水线报告
