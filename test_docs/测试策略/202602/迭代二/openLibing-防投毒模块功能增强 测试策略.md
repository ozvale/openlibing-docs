### 3.1 功能测试专项

**1. 权限矩阵验证: 使用不同成员权限分别打开内部、外部开源仓**
- **对应task(issueID)链接**: 284
- **预期结果**:
    - **系统管理员**: 内部开源仓(**正常打开**), 开源仓(**正常打开**)
    - **项目管理员**: 内部开源仓(**正常打开**), 开源仓(**正常打开**)
    - **仓库成员**: 内部开源仓(**正常打开**), 开源仓(**正常打开**)
    - **项目成员**: 内部开源仓(**正常打开**), 开源仓(**正常打开**)
    - **游客**: 内部开源仓(**无法打开**，应提示无权限或跳转登录), 开源仓(**正常打开**)

### 3.4 安全与隐私测试专项
**参考测试设计方向**
- **最小特权原则 (PoLP)**：验证服务账户（Service Account）是否无法越权操作未授权的资源。
- **软件供应链审计**：通过 SBOM 检查，验证容器镜像中是否存在已知的高危 CVE 漏洞。
- **敏感信息外泄防护**：检查日志、监控指标及 API 报错中是否夹带了明文密钥或隐私数据。

**1. 鉴权校验与访问控制: 模拟未登录用户（游客）及低权限用户尝试访问受限资源（内部开源仓）**
- **对应task(issueID)链接**: 284
- **预期结果**:
    - 未登录以“**游客**”身份访问【**内部开源仓**】时，系统应拦截请求，返回“**无法打开**”或提示无权限/跳转登录。
    - 已登录但无特定权限的角色访问受控资源时，严格遵循权限矩阵定义，**不得越权访问**。
