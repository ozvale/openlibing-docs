### 3.1 功能测试专项

> 参考测试设计方向
> * API 语义验证：验证 HTTP 状态码（2xx, 4xx, 5xx）的使用是否符合 RESTful 规范。
> * 边界与非法输入：验证大数据量、空字段、特殊字符及非法 JSON 格式的拦截能力。
> * 业务状态机闭环：验证资源从"创建中"到"运行中"再到"已释放"的全生命周期逻辑。

**1.指标配置功能验证**

* **对应task(issueID)链接:** https://gitcode.com/openlibing/openlibing-framework/issues/53
* **前置条件**: 入口：openlibing-个人头像-管理中心-运营运维-特性运营看板
* **步骤一**：
  - 1.打开流水线配置
* **预期结果**:
  - 1.指标数据列表查询成功
* **步骤二**：
  - 1.新增指标，尝试不按要求填写数据（如空或长名称，中文键名）
* **预期结果**:
  - 1.新增失败，因为数据规则不符
* **步骤三**：
  - 1.修改访问量指标，由count改成rate类型，或者不按链接格式输入url
* **预期结果**:
  - 1.不显示访问量数据，因为指标类型已更改，url输入框提示需要按链接格式输入值
* **步骤四**：
  - 1.删除访问量指标，然后重新配置
* **预期结果**:
  - 1.指标数据由消失然后又重新显示

**2.上报异常的运营数据**

* **对应task(issueID)链接:** https://gitcode.com/openlibing/openlibing-framework/issues/53
* **前置条件**: 入口：openlibing-个人头像-管理中心-运营运维-特性运营看板
* **步骤一**：
  - 1.不对流水线访问量指标进行配置，直接进行访问量上报
* **预期结果**:
  - 1.openlibing流水线未显示有数据上报
* **步骤二**：
  - 1.对流水线访问量进行指标配置
* **预期结果**:
  - 1.指标配置成功
* **步骤三**：
  - 1.上报异常数据（如极大数，负数，非数字）
* **预期结果**:
  - 1.响应异常，或上报成功但看板未展示异常数据

**3.运营数据上报后接收**

* **对应task(issueID)链接:** https://gitcode.com/openlibing/openlibing-framework/issues/53
* **前置条件**: 入口：openlibing-个人头像-管理中心-运营运维-特性运营看板
* **步骤一**：
  - 1.点击配置数据指标（如新增流水线的访问量指标）
* **预期结果**:
  - 1.配置列表中展示新增的访问量指标
* **步骤二**：
  - 1.调用数据上报接口，模拟上报数据（如今日openlibing项目，流水线的访问量字段为50）
* **预期结果**:
  - 1.流水线行，openlibing列显示绿色对钩，表示有数据上报。点击详情看到该日访问量为50
* **步骤三**：
  - 1.将流水线的访问量指标删除
* **预期结果**:
  - 1.对应单元格显示灰色，点击显示未接入，上方例如接入率数据下降了
