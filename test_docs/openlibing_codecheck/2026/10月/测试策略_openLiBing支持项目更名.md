# openLiBing支持项目更名 测试策略设计说明书

## 1. 基本信息

- **需求链接**: https://gitcode.com/openlibing/openlibing-coderepo/issues/208
- **对应task(issueID)链接**: https://gitcode.com/openlibing/openlibing-coderepo/issues/208
- **需求名称**: 【需求】【openLiBing】openLiBing支持项目更名
- **核心目标**: 以「下线 `${majun.project.name}` 后两服务（coderepo / codecheck）原有功能回归」为主线，验证**既有能力正常、无项目名错位**。平台在 framework 支持项目更名后，各业务库（Mongo / Redis 等）冗余存储的 `project_name` / `projectName` / `account` 等字段与母表 `project_info.project_name` 不一致会导致规则集、看板、屏蔽等功能异常；本需求下线 Nacos `${majun.project.name}` 配置并做存量治理。
- **开发责任人**: 杨攀（openlibing-coderepo / openlibing-codecheck）
- **测试责任人**: 徐愚冰

## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1.项目更名后仓库规则集查询正常（AC-A）**:

- 测试步骤: 更名后进入代码仓管理仓库详情「规则集」，核对数据
- 预期结果: 查询正常、无项目名错位

**2.项目更名后社区 codecheck 规则集查询正常（AC-A）**:

- 测试步骤: 查询社区 codecheck 规则集
- 预期结果: 正常返回，不依赖 majun 映射

**3.项目更名后社区防投毒规则集查询正常（AC-A）**:

- 测试步骤: 查询社区防投毒规则集
- 预期结果: 正常返回

**4.项目更名后门禁检查社区与仓库联动正常（AC-B）**:

- 测试步骤: 门禁/每日检查社区下拉切换并核对仓库联动
- 预期结果: 联动正常，不再依赖 majun 名匹配与 Redis `inc_` 前缀

**5.项目更名后看板与工作台数据正常（AC-B）**:

- 测试步骤: 核对看板/工作台数据与更名前基线
- 预期结果: 数据一致、无丢失

**6.项目更名后问题屏蔽功能正常（AC-B）**:

- 测试步骤: 核对问题屏蔽列表与操作
- 预期结果: 功能正常、`projectName` 口径一致

**7.项目更名后规则集本地库查询命中正常（AC-B）**:

- 测试步骤: 查询规则集本地库
- 预期结果: 命中正常、口径统一

**8.项目更名后 SIG 规则集读写口径统一正常（AC-B）**:

- 测试步骤: 核对 coderepo 与 codecheck 的 SIG 规则集读写
- 预期结果: 口径统一（以 `repo_id` 或一致社区名为准）

**9.项目更名后敏感词规则集正常（AC-B）**:

- 测试步骤: 核对敏感词规则集
- 预期结果: 正常（该集合不纳入 majun 下线）

**10.项目更名后 Redis 社区缓存清理与重建一致（AC-B）**:

- 测试步骤: 核对 Redis `inc_{旧社区名}` 清理与 `inc_{新社区名}` 重建
- 预期结果: 读写一致

**11.项目更名后代码检查平台识别无回退（AC-B）**:

- 测试步骤: 核对代码检查平台识别
- 预期结果: 不因映射下线误判为 gitee

## 4. 测试范围

| 测试类型    | 是否覆盖       | 说明                                                                               |
| ----------- | -------------- | ---------------------------------------------------------------------------------- |
| UI功能测试  | 是（系统功能） | 代码仓管理 / 规则集 / 门禁检查 / 检测中心 / 敏感词集 / 代码检查既有 Web 功能的回归 |
| API接口测试 | 否             | 不涉及 A 方案内部刷数接口；既有功能回归以 UI 功能行为承载                          |
| DFX测试     | 否             | 项目名一致性治理，无性能/可靠性阈值变化                                            |
| 安全测试    | 否             | 不触碰认证、越权、传输与敏感字段                                                   |

## 5. 依赖与前置条件

- 两服务（openlibing-coderepo / openlibing-codecheck）改造分支已部署至测试环境（beta）
- 一个具备既有数据的可更名测试项目（更名前已有仓库规则集/看板/屏蔽/敏感词集等数据），且更名前/后均可访问
- 具备代码仓管理 / 规则集 / 门禁检查 / 检测中心 / 敏感词集操作权限的测试账号
- 需要时可核查 Mongo 集合与 Redis `inc_{社区名}` key 的手段
