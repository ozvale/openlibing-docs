## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1.分支管理告警数列展示与数值正确性验证**:

- 前置条件: 已接入代码检查的仓库 R（含分支 B1/B2/B3，其中 B1、B2 有分支级告警数据，B3 无告警）；无分支/未接入代码检查的仓库 S；测试账号具备代码仓管理与代码检查页面权限
- 测试步骤:
  1. 进入代码仓管理 → 仓库 R → 分支管理页，断言列表新增"代码检查告警数"列且默认可见
  2. 记录 B1、B2、B3 各行告警数展示值，分别进入代码检查页按对应分支过滤并记录过滤后告警总数，逐一比对
  3. 断言各分支告警数相互独立（B1 的告警不计入 B2 行）
  4. B3（无告警分支）行断言展示 0
  5. 仓库 S（无分支/未接入）分支管理页断言页面正常、不报错、告警数列为空或 0
  6. 新增告警数据（或触发一次检查）后刷新分支管理页，断言对应分支告警数刷新正确
- 预期结果: 告警数列正常展示；各分支告警数与代码检查页按分支过滤后的数量完全一致；分支间数据独立互不串计；无告警展示 0；空数据态不报错；数据刷新后展示同步

**2.告警数点击跳转与分支过滤条件传递验证**:

- 前置条件: TC-ISSUE360-001 前置数据就绪（B1/B2 有告警、B3 为 0）；存在含空格、中文、`/` 的特殊字符分支名且带告警数据的分支；超长分支名（200+ 字符）分支 1 个；测试账号具备代码检查页面权限
- 测试步骤:
  1. 点击 B1 行告警数，断言跳转到代码检查页面且过滤器自动带上分支=B1
  2. 断言跳转后列表数据仅为 B1 分支的告警（与跳转前记录的过滤后数量一致）
  3. 点击 B3 行告警数（0），断言跳转行为符合设计（0 时可点击带条件跳转或置灰不可点，以实际设计为准记录结论）
  4. 点击特殊字符分支名的告警数，断言 URL 中分支名正确编码、跳转后过滤器展示原分支名、过滤结果正确
  5. 点击超长分支名告警数，断言编码后 URL 可正常跳转不截断、过滤正确
  6. 浏览器后退返回分支管理页，再次点击其他分支告警数无串态
- 预期结果: 点击跳转均携带正确分支过滤条件；过滤后数据与分支管理展示数一致；特殊字符/超长分支名编码正确不丢失不截断；0 告警分支交互符合设计；多次跳转无串态

**3.告警数查询接口分支过滤参数校验验证**:

- 前置条件: beta 环境可访问；API 账号具备代码仓管理权限；仓库 R（B1 有告警 N1 条、B2 有告警 N2 条，N1≠N2）
- 测试步骤:
  1. 有效类：带 repoId + branch=B1 查询断言返回 N1；branch=B2 查询断言返回 N2（分支过滤生效且相互独立）
  2. 有效类：branch 传不存在的分支名，断言 200 且返回 0（空结果非报错）
  3. 无效类：缺 repoId / repoId 不存在，断言返回明确业务错误码（非 500）
  4. 边界值：branch 为空字符串 "" 与超长（200+ 字符），断言行为明确（按缺参处理或 400）、不 500
  5. 注入探测：branch 携带 SQL 注入串（`' OR 1=1 --`）与特殊字符（空格/中文/`/`），断言参数化查询生效不注入、特殊字符正常过滤返回
- 预期结果: 有效类分支过滤数值正确且分支间独立；不存在分支返回 0；无效类返回明确业务错误码；边界值不 500；注入串无放大效果（返回空或 0）

**4.branch null 默认接入分支聚合与存量兼容验证**:

- 前置条件: 仓库 R 已接入代码检查且配置了默认接入分支（默认分支上有告警数据 D 条，非默认分支 B2 有告警 N2 条，D≠N2）；仓库管理页既有"代码告警数"展示的改前行为已知（改前数值记录为基线）
- 测试步骤:
  1. 接口带 repoId、不传 branch（即 branch=null），断言返回默认接入分支聚合告警数 D（而非全部分支总和，也非 N2）
  2. 接口带 repoId、显式传 branch=null 字符串，断言与不传 branch 行为一致
  3. 对照：显式传 branch=默认接入分支名，断言与步骤 1 结果一致（null 与显式默认分支等价）
  4. 存量回归：打开仓库管理页查看既有"代码告警数"列，断言仓库 R 数值与改前基线一致
  5. 多仓库抽查 2-3 个存量仓库，断言仓库管理页告警数均与改前基线一致
- 预期结果: branch=null 返回默认接入分支聚合值；null 与显式默认分支等价；仓库管理页既有告警数展示与改前完全一致（零回归）
