## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1. 统计字段返回值正确性验证**:
* 前置条件:门禁检查页面存在已执行的门禁任务数据
* 测试步骤:
    1. 进入门禁检查页面
    2. 打开浏览器开发者工具，查看 summary 列表接口响应
    3. 验证 issueCount / solveCount / ignoreCount / inReviewCount / invalidCount 五个统计字段返回值
    4. 将接口返回值与页面实际展示的统计数字进行比对
* 预期结果: 五个统计字段返回值正确，与页面展示一致

**2. task 展示字段返回值正确性验证**:
* 前置条件:门禁检查页面存在已执行的门禁任务数据
* 测试步骤:
    1. 进入门禁检查页面
    2. 查看 summary 列表接口响应中的 task 字段
    3. 验证 owner / title / mrId / gitUrl / executeDate 字段返回值
    4. 将接口返回值与页面实际展示的任务信息进行比对
* 预期结果: task 展示字段返回值正确，与页面展示一致

**3. 门禁任务执行完成（Success/Failed）后字段刷新验证**:
* 前置条件:存在可触发的门禁任务
* 测试步骤:
    1. 记录触发前 summary 列表接口返回的统计字段与 task 字段
    2. 触发门禁任务执行，等待其状态变为 Success 或 Failed
    3. 重新请求 summary 列表接口
    4. 验证统计字段与 task 字段已正确刷新（写路径缓存刷新生效）
* 预期结果: 门禁任务执行完成后，接口返回的字段值正确更新，与最新状态一致

**4. 缺陷状态变更（屏蔽、审核、撤销、失效同步）后统计字段刷新验证**:
* 前置条件:门禁检查页面存在缺陷数据
* 测试步骤:
    1. 记录变更前 summary 列表接口返回的统计字段
    2. 依次对缺陷执行屏蔽、审核、撤销、失效同步等状态变更操作
    3. 每次变更后重新请求 summary 列表接口
    4. 验证对应统计字段（如 ignoreCount / solveCount / invalidCount）正确刷新
* 预期结果: 缺陷状态变更后，相关统计字段正确更新，缓存刷新生效

**5. 翻页/筛选场景下字段数据一致性验证**:
* 前置条件:门禁检查页面存在多页数据
* 测试步骤:
    1. 在门禁检查页面进行翻页操作
    2. 应用筛选条件（如按状态、时间筛选）
    3. 每次操作后查看 summary 列表接口返回
    4. 验证字段返回值与页面展示一致，无脏读
* 预期结果: 翻页/筛选后字段返回值正确，与页面展示一致

### 3.2 可靠性与韧性测试专项

**6. 缓存未命中/刷新异常场景下降级验证**:
* 前置条件:门禁检查页面可访问
* 测试步骤:
    1. 模拟缓存失效或刷新失败场景（如清空缓存后直接查询）
    2. 请求 summary 列表接口
    3. 验证接口能降级为实时查询并返回正确数据，不出现空数据或错误数据
* 预期结果: 缓存异常时接口降级正常，数据正确返回

### 3.3 性能测试专项

**7. summary 列表接口响应时间验证（≤1s）**:
* 前置条件:门禁检查页面存在数据
* 测试步骤:
    1. 进入门禁检查页面，使用浏览器开发者工具/抓包工具记录 summary 列表接口耗时
    2. 重复执行打开页面、翻页、筛选操作，记录多次接口响应时间
    3. 取多次响应时间的最大值与平均值
    4. 验证接口响应时间是否在 1 秒以内
* 预期结果: 接口响应时间 ≤ 1s，页面 LCP 达标

**8. 缓存命中时接口响应时间验证**:
* 前置条件:门禁检查页面已加载过数据（缓存已生成）
* 测试步骤:
    1. 首次请求 summary 列表接口，记录响应时间
    2. 缓存命中场景下再次请求该接口，记录响应时间
    3. 对比两次响应时间，验证缓存命中后响应时间显著降低且 ≤ 1s
* 预期结果: 缓存命中后接口响应时间显著降低，控制在 1 秒以内
