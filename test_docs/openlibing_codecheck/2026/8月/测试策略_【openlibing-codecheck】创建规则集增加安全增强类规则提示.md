# 代码检查模块-创建规则集增加安全增强类规则提示 测试策略设计说明书

## 1. 基本信息

* **需求链接**: https://gitcode.com/openlibing/openlibing-codecheck/issues/180
* **对应task(issueID)链接**: https://gitcode.com/openlibing/openlibing-codecheck/issues/180
* **需求名称**: 创建规则集增加安全增强类规则提示（安全增强包购买确认）
* **核心目标**:
  "代码检查安全增强"类规则属付费增强能力。前端（openlibing-web）在规则集配置页（新增/复制/修改三场景共用）实时检测勾选规则中是否包含安全增强类规则（`ruleTages` 含 `security_enhance`），包含时在保存按钮旁常驻 warning 提示并附华为云购买链接（region 取自社区对接华为云项目，默认 `cn-southwest-2`），提示**不阻断保存**；后端（openlibing-codecheck）识别华为云 `未购买安全增强包` 错误（保存路径与查询路径分别翻译为友好中文提示），并加固非数字错误码解析兜底。
* **设计文档**: `openlibing-docs/spec/openlibing-web/task_design/security-enhance-purchase-confirm/proposal.md`、`design.md`（关联 Issue openlibing/openlibing-web#275）

* **测试责任人**: 徐愚冰

## 2. 测试维度确认

* [x] **功能自检测试**

> * **目的:** 确保提示实时联动、不阻断流程、错误翻译兜底正确。
> * **触发条件:** 强制执行。

* [x] **体验测试**

> * **触发条件:** 涉及前端交互改造。

## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1. 前端安全增强规则实时提示验证**:
* 前置条件: 规则集配置页可用，规则列表含安全增强类规则（`ruleTages` 含 `security_enhance`）
* 测试步骤:
    1. 新增规则集场景，勾选 1 条安全增强类规则，验证保存按钮旁实时出现 warning 提示框
    2. 再勾选普通规则、取消安全增强规则勾选，验证提示框实时消失
    3. 未勾选任何安全增强规则时，验证不出现提示框
    4. 验证提示基于 `handleSubmitData()` 产出的最终 `ruleIds` 计算，随勾选实时联动
* 预期结果: 提示随勾选实时出现/消失，判定口径与后端分类一致

**2. 购买链接与 region 验证**:
* 前置条件: 社区已对接华为云项目
* 测试步骤:
    1. 点击提示框中"增强规则集包"链接，验证新窗口打开华为云订阅页（`packageType=feature`）
    2. 验证 URL 中 `region` 取自 `/openlibing-framework/project/get-project-detail-info` 返回的 `data.hwProjectEntity.region`
    3. 构造未获取到 region 的场景，验证默认 `cn-southwest-2`
* 预期结果: 链接可达、region 正确、默认值兜底生效

**3. 提示不阻断保存验证**:
* 前置条件: 已勾选安全增强类规则且提示框展示中
* 测试步骤:
    1. 点击保存，验证正常走原有保存流程
    2. 复制规则集到社区场景，验证仍走已有复制确认弹窗
    3. 未购买增强包时勾选并保存，验证前端不强制拦截（由后端错误翻译兜底）
* 预期结果: 提示仅引导，不阻断勾选与保存行为

**4. 后端华为云错误翻译验证**:
* 前置条件: 可构造华为云返回 `{"error_code":"CC.00050006","error_msg":"...未购买安全增强包"}` 的场景
* 测试步骤:
    1. 未购买增强包时保存含安全增强规则的规则集，验证前端收到友好中文提示（非原始英文拼接串）
    2. 未购买增强包时查询规则列表，验证错误不再显示"获取规则列表失败"，而是真实原因友好提示
    3. 构造非数字错误码（`CC.00050006`），验证不再触发 `NumberFormatException`
    4. 构造其他错误路径，验证 `error_msg` 原样透传，行为与现状一致
* 预期结果: 两条路径错误翻译精准、错误码解析健壮、其余路径零变化

### 3.2 体验测试专项

**5. 提示文案与交互体验验证**:
* 前置条件: 前端已部署改造版本
* 测试步骤:
    1. 验证提示文案为 `包含"代码检查安全增强"类规则，请确保已购买增强规则集包。`
    2. 验证提示为按钮旁常驻展示（非弹窗），不遮挡保存按钮与勾选操作
    3. 修改/复制场景分别进入配置页，验证同样生效
* 预期结果: 文案准确、常驻展示、三场景一致生效

### 3.3 可靠性与韧性测试专项

**6. 单元测试覆盖验证**:
* 前置条件: openlibing-codecheck 代码仓可执行 mvn test
* 测试步骤:
    1. 运行 `RestCodeCheckUtil` 相关单元测试，验证"未购买安全增强包"识别分支、非数字错误码兜底分支覆盖
    2. 运行 `RuleDelegateImpl` 相关测试，验证查询路径透出真实原因
    3. 确认公共层 `signAndExecute`/`signAndExecuteWithException` 无改动、相关消费点测试通过
* 预期结果: 单元测试覆盖上述分支且全部通过
