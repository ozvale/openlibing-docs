# 代码检查模块-门禁检查、版本级检查支持多选代码仓 测试策略设计说明书

## 1. 基本信息

* **需求链接**: https://gitcode.com/openlibing/openlibing-codecheck/issues/181
* **对应task(issueID)链接**: https://gitcode.com/openlibing/openlibing-codecheck/issues/181
* **需求名称**: 版本级检查、门禁检查 CodeCheck 子页面支持多选代码仓
* **核心目标**:
  门禁检查 / 版本级检查页面 CodeCheck 子页的仓库下拉筛选框支持多选，列表按所选仓库集合过滤（后端 `QuerySummaryModel` 新增 `repoNames`，`repoNameEn in` 查询，空值回退 `repoName` 单值保证向后兼容）；多选仓库时分支下拉展示所选仓库分支的去重并集（分支仍单选），仓库切换时清空已选分支。范围变更（2026-08-25）：列表全量导出已取消，仅保留仓库多选筛选。
* **设计文档**: `openlibing-docs/spec/openlibing-codecheck/task_design/summary-multi-repo-export/design-v2.md`（关联 Issue #174）
* **开发责任人**: 陶获权
* **测试责任人**: 徐愚冰

## 2. 测试维度确认

* [x] **功能自检测试**
> * **测试重点:** 门禁检查 / 版本级检查 CodeCheck 子页仓库下拉多选过滤正确性、单选场景向后兼容（不传 `repoNames` 回退 `repoName`）、`repoNames` 优先级（两字段同时传值时 `repoNames` 优先）、分支下拉去重并集与分支筛选联动、清空/重置行为（`repoNames` 重置为空数组）、多选与其他筛选项（时间区间、mrId、result 等）组合过滤。
> * **目的:** 确保多选过滤、兼容回退、分支并集联动等核心行为正确。
> * **触发条件:** 强制执行。

* [x] **体验测试**
> * **测试重点:** 多选交互（`multiple` + `collapse-tags` + `collapse-tags-tooltip`、`filterable` 保留、多选场景 `allow-create` 禁用）、collapse 折叠标签不撑爆筛选栏、仓库切换清空已选分支的提示体验、翻页/排序在多选条件下正常。
> * **目的:** 确保多选筛选交互易用、无布局异常与误导性选项。
> * **触发条件:** 涉及前端交互改造。

* [ ] **集成测试**
* [ ] **安全与隐私测试**
* [ ] **可靠性与韧性测试**
* [ ] **可服务性与可观测性测试**
* [x] **性能与伸缩性测试**
> * **测试重点:** `repoNameEn in` 查询走既有索引、多选扩大结果集后分页查询（pageNum/pageSize 服务端分页）行为不变、分支并集计算（flatMap + Set 去重）无感知延迟。
> * **目的:** 确保多选查询无性能退化。
> * **触发条件:** 涉及核心查询条件变更。

## 3. 专项验证设计和执行详情

### 3.1 功能测试专项

**1. 门禁检查 CodeCheck 子页仓库多选过滤验证**:
* 前置条件: 门禁检查页面存在多仓库检查汇总数据
* 测试步骤:
    1. 进入门禁检查 CodeCheck 子页，仓库下拉多选 [repoA, repoB]
    2. 验证列表仅包含所选仓库集合的记录（`repoNameEn ∈ repoNames`）
    3. 增减所选仓库，验证列表随之刷新
    4. 验证单选场景（仅选 1 个仓库）结果与优化前一致
* 预期结果: 多选过滤正确，单选向后兼容

**2. 版本级检查 CodeCheck 子页仓库多选过滤验证**:
* 前置条件: 版本级检查页面存在多仓库检查汇总数据
* 测试步骤:
    1. 进入版本级检查 CodeCheck 子页，仓库下拉多选多个仓库
    2. 验证列表按所选仓库集合过滤
    3. 验证 manifestBranch、时间区间、result、isCompile 等既有过滤保留生效
* 预期结果: 多选过滤正确，既有过滤条件不受影响

**3. 分支下拉并集与联动验证**:
* 前置条件: 所选仓库各自有不同的分支集合，存在同名分支
* 测试步骤:
    1. 多选 [repoA, repoB]，验证分支下拉展示两仓库分支的去重并集（大小写不敏感排序与现有单选一致）
    2. 在并集中选择分支，验证列表按仓库集合 + 分支组合过滤正确
    3. 切换/增减所选仓库，验证已选分支被清空、分支选项重新计算
* 预期结果: 分支并集去重正确，分支筛选在多仓上下文下仍可用，切换仓库清空已选分支

**4. 参数兼容规则验证**:
* 前置条件: 可通过接口直接构造请求
* 测试步骤:
    1. `repoNames` 非空数组 → 验证 `repoNameEn in(repoNames)`
    2. `repoNames` 空/缺省且 `repoName` 非空 → 验证回退单值过滤（与历史调用方行为一致）
    3. 两者均空 → 验证无仓库过滤
    4. 两者同时非空 → 验证 `repoNames` 优先
* 预期结果: 四种参数组合行为与设计兼容规则一致，历史调用方（APIG 网关等）零影响

**5. 清空/重置与组合筛选验证**:
* 前置条件: 系统运行正常
* 测试步骤:
    1. 多选仓库后点击重置，验证 `repoNames` 清空、列表恢复全量
    2. 多选仓库 + 时间区间 + mrId + result 组合筛选，验证结果正确
    3. 多选条件下翻页、排序，验证分页数据正确
* 预期结果: 重置行为正确，组合筛选与分页排序正常

### 3.2 体验测试专项

**6. 多选交互体验验证**:
* 前置条件: 前端已部署改造版本
* 测试步骤:
    1. 验证仓库下拉支持多选、`collapse-tags` 折叠展示、tooltip 查看完整选择
    2. 验证多选场景无法自定义输入（`allow-create` 已禁用），`filterable` 搜索仍可用
    3. 选择较多仓库时验证筛选栏布局不被撑爆
    4. 验证 AntiPoison（反投毒）子页与子行展开等既有功能不受影响
* 预期结果: 交互符合设计，无布局异常，无关页面零回归

### 3.3 性能测试专项

**7. 多选查询性能验证**:
* 前置条件: 项目仓库数较多（数十个）
* 测试步骤:
    1. 多选大量仓库查询列表，验证响应时间在可接受范围
    2. 使用 explain 验证 `repoNameEn in` 查询走既有索引
    3. 验证多选扩大结果集后分页行为不变（服务端分页）
* 预期结果: in 查询走索引无退化，分页查询响应达标
