## 2. 测试过程

### 2.1 功能测试专项

**1.各工具插件报告转 SARIF 格式统一性验证**:

- 预期结果: 8 款工具报告均转换为合法 SARIF 2.1.0，工具名 / 规则 ID / 级别 / 文件位置 / 代码片段字段完整且语义正确，后端无需按工具差异化解析
- **测试结果**： Passed
- **证明截图**: 待补充

**2.上传插件 OBS 路径与前缀验证**:

- 预期结果: 路径为 `{前缀}/{仓库名}/{yyyyMMdd}.{HH}/{runId|manual}/{文件名}`，前缀按 `{toolName}-results` 动态生成，工具名缺失兜底 `code-arts-check-results`，`runId` 缺失用 `manual`
- **测试结果**： Passed
- **证明截图**: 待补充

**3.region.snippet 自动补齐验证**:

- 预期结果: 缺 snippet 的 result 按 `uri` + 行号读源码补齐并写回；已有 snippet 跳过；源码不可读静默跳过，不阻断上传
- **测试结果**： Passed
- **证明截图**: 待补充

**4.APIG 回调 payload 验证**:

- 预期结果: 回调经 V11-HMAC-SHA256 签名 + `X-Security-Token` 鉴权成功；`obsUrl` 恒为数组；`source` 为 `GITCODE_ACTION`；HTTP 2xx 且 `code === 200 || code === 0` 判定为成功
- **测试结果**： Passed
- **证明截图**: 待补充

**5.codecheck 解析入库与页面展示验证**:

- 预期结果: 回调触发解析后数据入库，代码检查页面按工具 / 类别正确展示，告警条目数、路径、行号、规则、级别、代码片段与 SARIF 内容一致
- **测试结果**： Passed
- **证明截图**: 待补充

**6.build-result.json 构建产物验证**:

- 预期结果: 单文件 `buildings` 为对象、多文件为数组；`type` 为 `{toolName}代码检查结果（sarif）`；与 SARIF 同路径（首个工具目录前缀）
- **测试结果**： Passed
- **证明截图**: 待补充

**7.多工具同一仓库共存验证**:

- 预期结果: 各工具 SARIF 分别落到各自 `{toolName}-results` 前缀互不覆盖，页面可同时展示多个工具的检查结果
- **测试结果**： Passed
- **证明截图**: 待补充

**8.零告警 / 空报告场景验证**:

- 预期结果: 空 `results` 的 SARIF 正常上传并回调成功，解析后页面展示为无告警，不报错、不产生脏数据
- **测试结果**： Passed
- **证明截图**: 待补充
