### 3.1 功能测试专项

> 参考测试设计方向

> - 业务状态机闭环：验证资源从“创建中”到“运行中”再到“已释放”的全生命周期逻辑。

**1. 大镜像 stop 本地存档(docker save|pigz 替代 push)与删除/重启打断清理**:大镜像（>100GB）走 docker push 到 harbor：耗时长（易撞 push 超时）、占满带宽、大镜像 push 失败率高。stop 流程需要为大镜像提供本地存档替代 push 的方案。

- **对应task(issueID)链接:** : 1.https://gitcode.com/openlibing/hidevlab-transport-service/issues/111
- **预期结果**:
  stop 大镜像（>阈值）生成 <root_dir>/backup/<ctr>.tar.gz + .sha，回调 saveType=local_save，后续 docker_clear 正常
  磁盘不足 / 取 root dir 失败：回调 result=failed + 原因，容器保留
  stop 小镜像（≤阈值）：走原 push，回调 saveType=push
  /docker/multi/delete：清理 tarball + .sha（幂等）
  restart 打断在飞 save：kill + 清半截 tarball/.sha，从 store 起容器
  image_save / clear 流程不受影响（走 push）
