> 仓：openlibing/upload-ut-action

## 关联 issue

- openlibing/upload-ut-action#9：JacocoParser 嵌套惰性正则解析超大报告存在 O(n²) 回溯风险
- openlibing/upload-ut-action#10：覆盖率 pct 无 0-100 边界约束，恶意报告可产生 >100% 越界值上报

## 代码事实核实（评估前复核）

### #9 ReDoS 风险定级修正

`src/parser/JacocoParser.js:75-76`：

```js
const pkgRe = /<package\s+name="([^"]*)">([\s\S]*?)<\/package>/g;
const sfRe  = /<sourcefile\s+name="([^"]*)">([\s\S]*?)<\/sourcefile>/g;
```

- 两个正则均为「前缀锚定 + 惰性量词 + 字面闭合标签」，**不含嵌套无限量词歧义**，非指数型 catastrophic backtracking；最坏为 O(n²) 线性回溯（扫描器按低危标注，定性一致）
- 触发前提：jacoco.xml 来自 CI 产出，MR 场景下不可信 PR 可操控报告内容与体积
- 实测风险边界：50MB 级恶意构造 XML 的解析延迟在秒级，不构成进程级 DoS；真正风险是超大文件一次性 `readFileSync` 进内存

### #10 越界值唯一真实入口

全部 6 个 parser 的 covered/total 均来自 `\d+` 正则（仅非负整数）或 JSON 数值字段，数学上 `c/t ≤ 1`，**pct 输出不可能 >100**。唯一例外：

`src/parser/CoveragePyParser.js:59`：

```js
metrics.lineCoverage = pct(totals.percent_covered, 100);
```

`totals.percent_covered` 是 coverage.py JSON 中已算好的百分比字段，直接透传——恶意/异常 JSON 构造 `percent_covered: 150` 即产生 `lineCoverage: 150` 上报。**即 #10 的真实触面仅此一处**，pct 函数本身无需全局改动。

## 改动点清单

| # | 文件:行 | 改动 | 分类 |
| --- | --- | --- | --- |
| 1 | src/parser/JacocoParser.js:69（parseFile） | 新增报告文件大小上限（建议 10MB）：`fs.statSync` 超限抛错并输出 `[WARN] jacoco.xml 超过大小上限，跳过解析`，本次执行不产生覆盖率上报 | **新增输入拒绝** |
| 2 | src/parser/JacocoParser.js:75-76 | 消除 `[\s\S]*?` 大范围回溯：改为「逐标签行匹配」或「分段切片后单段惰性匹配」，语义保持"取 <package>/<sourcefile> 块"不变 | **数据处理链路变化**（实现重构） |
| 3 | src/parser/CoveragePyParser.js:59 | `pct` 结果 clamp 到 0-100：`Math.min(100, Math.max(0, v))`（仅此入口，不动 pct 全局签名） | **输出契约变化**（仅异常输入分支） |

## 为什么绕不开

1. **#9 大小上限**：O(n²) 回溯的根治是避免对超大输入跑正则，纯算法重写无法同时覆盖"超大文件内存占用"，必须引入拒绝语义——这天然是行为变化（原行为：多大都硬解析；新行为：超限拒绝）。上限阈值可调，但拒绝本身必须用户拍板。
2. **#9 正则重写**：可选。若用户认为秒级延迟可接受，可只做改动 1（上限）放弃改动 2（重写），把 #9 降级为「部分整改 + 已知风险登记」。**这是本评估请用户裁决的核心取舍**。
3. **#10 clamp**：正常 coverage.py 输出 percent_covered ∈ [0,100]，clamp 对合法数据零影响；仅异常/恶意输入下上报值从 150 变为 100。不动它则越界值继续透传给 coderepo 后端。

## 验证方式

- 改动 1：构造 11MB 合法 jacoco.xml → 断言抛错路径 + action 以明确 WARN 退出；正常 1MB 报告全量回归 36 个既有用例
- 改动 2（若获批）：用现有 jacoco 测试样本 + 深嵌套/超长属性恶意样本，断言解析结果与原实现逐字段一致
- 改动 3：`percent_covered=150` → 断言输出 100；`percent_covered=85.5` → 断言输出 85.5（合法值不受影响）
- 统一在 `fix-security-remediation` 分支联测

## 回滚方案

- 三个改动点相互独立，均可单点 revert（改动 1/2 在 JacocoParser.js，改动 3 在 CoveragePyParser.js）
- 回滚后行为回到当前版本：超大报告硬解析、percent_covered 透传
