### 1.2 为什么暂缓切默认值

- 回调报文只携带 `obsUrl`（[ObsUploader.js:203-212](file:///e:/work/huawei/fork/upload-ut-action/src/obs/ObsUploader.js)），由后端 `UtCoverageController.reportUtCoverage` 侧按该 URL 下载。
- 代码注释与 `action.yml` 输入说明明确写有「当前后端通过匿名 HTTP GET 下载；后端切换为带凭证下载后配置 private」（[ObsUploader.js:194](file:///e:/work/huawei/fork/upload-ut-action/src/obs/ObsUploader.js)、`action.yml:43`）。
- 若插件单方面把缺省值改为 `private`，后端匿名下载将 403，直接打断覆盖率入库链路 → 属**默认值/默认行为变化**（硬规则 2-2），且依赖跨仓契约。
- 结论：与 upload-sarif-action #11/#25 同类，**暂缓待后端支持带凭证或签名 URL 下载后统一切换**。

### 1.3 可选的等价加固

- 无。默认值切换必然改变对外行为，不属于等价加固白名单；`obs_acl` 参数化本身已完成。
- 可选（需评审）：将 `action.yml` 中 `obs_acl` 说明与日志提示保留即可，不新增行为。

## 二、#21 public-read 覆盖率数据明文可读且无大小上限【中】

### 2.1 逐点核实

| 序号 | 位置                                                              | 核实结论                                                                                           |
| ---- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 1    | `src/obs/ObsUploader.js:142`（`dist/index.js` 同步）              | 属实，但已参数化，默认 `public-read`。与 #4 同一根因，处理方式一致：暂缓待后端联动                 |
| 2    | `src/obs/ObsUploader.js:132-142` 写临时文件后直接上传，无大小校验 | 属实。`JSON.stringify(standardJson, null, 2)` 全量落盘后 `putObject`，全程无 `stat` / 长度上限判断 |

### 2.2 风险与边界

- `standardJson` 来源于被测仓库的覆盖率报告解析结果，体量由仓库自身代码规模决定；正常单仓报告通常为 MB 级以内。
- 异常/恶意仓库可产出超大报告，导致：OBS 对象存储占用、后端下载带宽与解析内存消耗；插件侧无任何兜底。
- 该改动若「拒绝超过阈值的上传」属于**新增输入拒绝 + 资源限制阈值**（硬规则 2-5 / 2-6），必须先确定合法最大体量口径，不能在安全整改中自行拍定。

### 2.3 候选方案（待用户裁决）

| 方案 | 改动                                               | 分类                        | 说明                                                |
| ---- | -------------------------------------------------- | --------------------------- | --------------------------------------------------- |
| A    | 新增可选输入 `max_upload_bytes`，缺省 `0` = 不限制 | 新增可选参数，缺省行为不变  | 等价加固；使用方按需开启，默认零行为变化            |
| B    | 内置硬上限（如 50 MB），超限报错                   | 资源限制阈值 + 失败语义变化 | 需后端确认合法大报告体量分布，属须评审              |
| C    | 维持现状，不加上限                                 | 非问题/观察项               | 与 upload-sarif-action #26 的「易用性取舍」口径一致 |
