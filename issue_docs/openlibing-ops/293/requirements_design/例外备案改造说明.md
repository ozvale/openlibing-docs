# #293 例外备案和 committer 审核一体化改造说明

## 1. 本期范围

- 仅优化“例外备案和 committer 审核一体化”场景。
- 排队 P90、NPU 成功口径等其他优化不在 `feature_293_new` 实施。
- 涉及一个 ETL SQL：
  - `例外备案每日汇聚_优化.sql`：写入 `dwi_repo_pipeline_quality_day`
- 项目级聚合 SQL（`仓库配置指标汇总.sql`）与现网逻辑完全一致，无需修改，本次不归档。
- 后端只调整仓库明细对 `uses_proper_codecheck` 的消费方式。

## 2. 现状 SQL 问题

### 2.1 仓库级（代码风格自动修复 例外备案每日汇聚.sql）

| 问题                                          | 影响                                                     |
| --------------------------------------------- | -------------------------------------------------------- |
| GitCode 只取每个仓库最新一次 PR 运行          | 最新运行失败或配置缺失时，仓库被误判                     |
| 未过滤 `pipeline_status`                      | 失败、取消运行参与判定                                   |
| `has_new_codecheck` 用 `MIN` 跨 pipeline 聚合 | 要求所有 pipeline 都有新版，和“样本中任一次单次达标”冲突 |
| GitHub 只取每个 workflow 最新 run             | 没有按 PR 采样概念，且未过滤 `status`                    |

### 2.2 项目级（仓库配置指标汇总.sql）

| 问题                          | 说明                                                        |
| ----------------------------- | ----------------------------------------------------------- |
| 分母为 `COUNT(*)`             | 实际是“全部运营仓库”，无成功运行仓库按 `uses_proper=0` 计入 |
| 原需求文档写“NULL 不参与分母” | 与现网 SQL 不一致，需要修正                                 |

## 3. 目标口径

- 统计日：`stat_date` 使用 `CURRENT_DATE()`，不额外限定 D-1。
- GitCode 成功运行：`dwr_rd_efc_pipeline_run_fact.pipeline_status = 'COMPLETED'`。
- GitHub 成功运行：`dwi_rd_efc_workflow_run_raw_github.status = 'COMPLETED'`。
- 采样单位（不额外限定统计日截止时间）：
  - PR 范围：先从有成功运行的 PR（`pr_run`）中筛 `state='merged'`，按 `merged_at` 倒序取每仓最新 10 个 PR；
  - 运行范围：这 10 个 PR 经桥表关联的成功流水线：
    - GitCode：`pr_id IS NOT NULL` + `pipeline_name LIKE 'pr-pipeline%'` + `pipeline_info` 未删除 + `pipeline_status='COMPLETED'`；
    - GitHub：`pr_id IS NOT NULL`（`pipeline_run_id=workflow_run_id`、`pipeline_name=workflow_name`、`git_type='github'`）+ `event in ('pull_request','pull_request_target')` + `status='COMPLETED'`。
- 按单次运行判定：
  - GitCode：`new=1 且 old=0` 达标；
  - GitHub：`old=0`，job 名命中 `pre-commit` / `lintrunner` 即 `new=1`。
- 仓库级：样本中任意一次运行达标，`uses_proper_codecheck=1`。
- 仓库级 `has_old/new`、job 明细：取最近一次成功运行，仅用于展示。
- 无成功运行：`has_old/new=NULL`，`uses_proper_codecheck=0`，仍计入项目级分母。

## 4. 修改方案

### 4.1 GitCode 仓库级

1. 用 `gitcode_recent_run` 替换 `latest_pr_run`：
   - `pipeline_status='COMPLETED'`；
   - `pr_id IS NOT NULL`，保留 `LOWER(r.pipeline_name) LIKE 'pr-pipeline%'` 限定 PR 流水线；
   - `dwi_rd_efc_pipeline_info` 保持 `JOIN` + `pi.is_deleted != 1`，不引入新表范围；
   - 关联 `merged_recent_pr`（从 `pr_run` 中筛出的已合入 PR，取最新 10 个），只保留这些 PR 的运行。
2. `pr_job_detail` 改为关联这 10 个 PR 的成功运行，不再只关联最新一次。
   - 同一 run 关联多个 PR 时（桥表存在该情况，实测 GitCode 有 133 个 run），先按 `run_id` 去重再编 `rn`。
3. 新增 run 级聚合：
   - `run_has_old_codecheck`、`run_has_new_codecheck`；
   - `old_codecheck_jobs`、`new_codecheck_jobs`。
4. 仓库级聚合：
   - `uses_proper_codecheck = MAX(CASE WHEN run_has_new=1 AND run_has_old=0 THEN 1 ELSE 0 END)`；
   - `has_old/new` 和 job 明细取 `rn=1` 的最近成功运行；
   - 删除跨 pipeline 的 `MIN(has_new)`。

### 4.2 GitHub 仓库级

1. 用 `github_recent_pr` 替换 `github_pr_workflow_latest`：
   - `status='COMPLETED'`；
   - `event in ('pull_request','pull_request_target')`；
   - INNER JOIN `sdi_rd_efc_pipeline_run_pr_relation_codearts`，`pr_id IS NOT NULL` 确认 PR 关联（`pipeline_run_id=workflow_run_id`、`pipeline_name=workflow_name`、`git_type='github'`）；
   - 关联 `merged_recent_pr`（从 `pr_run` 中筛出的已合入 PR，取最新 10 个），只保留这些 PR 的成功运行。
2. 每次运行判定：
   - job 名命中 `pre-commit` / `lintrunner`，不再判断 workflow 名称。
3. 仓库级聚合：
   - `has_old_codecheck=0`；
   - `uses_proper_codecheck = MAX(run_has_new_codecheck)`；
   - `has_new` 和 job 明细取 `rn=1` 的最近成功运行。
4. 无成功 PR workflow 运行时不产生 codecheck 行，插入时 `COALESCE(...,0)`。

### 4.3 项目级

- `pipeline_agg` 的分母保持 `COUNT(*)`，即全部运营仓库。
- 无成功运行仓库的 `uses_proper_codecheck=0`，计入分母。
- 快照日期使用 `CURRENT_DATE()`。
- 如果 `dwi_repo_pipeline_quality_day` 不能保证 `(project_id, repo_id, stat_date)` 唯一，建议将分母改为 `COUNT(DISTINCT rp.repo_id)`。

### 4.4 后端消费

文件：`openlibing-ops/src/main/resources/mapper/OpsRepoDetailMapper.xml`

- `uses_proper_codecheck` 直接读取 ETL 字段，不再由 `has_old/new` 推导。
- `codecheck_detail` 优先判断 `uses_proper_codecheck=1`，达标时返回 `NULL`。
- 同步更新 `OpsRepoDetailResp` / `OpsRepoDetailDetailResp` 的字段注释。

## 5. 验证建议

1. **单次运行场景**：
   - 最新运行失败，但样本内存在仅新版检查 → 达标；
   - 一次旧版运行 + 一次仅新版运行 → 达标；
   - 每次运行都新旧并存 → 不达标；
   - 全部只有旧版或无检查任务 → 不达标；
   - 无成功运行 → `uses_proper=0`，计入分母。
2. **项目级对账**：
   - `exception_review_rate = SUM(uses_proper_codecheck=1) / COUNT(*)`；
   - 分母只包含运营仓库。
3. **日期检查**：
   - `dwi` 和 `dm` 的 `stat_date` 都使用 `CURRENT_DATE()`。
4. **后端**：
   - 达标仓库 `codecheckDetail` 为空；
   - 不达标仓库展示最近一次成功运行的旧版/新版任务说明。
