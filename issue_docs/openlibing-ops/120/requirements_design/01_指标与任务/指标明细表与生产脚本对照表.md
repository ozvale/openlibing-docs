# 指标明细表与生产脚本对照表（审核用）

> 依据：design.md v4 终版 + 2026-09-20 表名规范化（dwi/dm 统一 `*_rd_efc_*` 标准前缀）。
> 用途：逐指标审核"明细表 → 字段 → 生产脚本"三要素。规则详情见 design.md §5 对应小节。
> 通用口径（§3）：NA = `score NULL` + `is_na=1`（汇聚分母剔除）；**0 分是有效得分**；
> 一批扫描统一 `scan_time`；历史批次全保留；机器人 = login 含 `bot/robot/[bot]`。

### 表④ `dwi_rd_efc_security_file_scan` — 指标 2/3/4/6/12/14/15（Python P1）

**生产者**：`security_file_scan.py`（P1 文件扫描脚本，DS Shell 任务）
**上游依赖**：仓库列表 `sdi_rd_efc_repo_operate_conf WHERE is_operate=1`（136 仓）+ 浅克隆（--depth 1）+ PACKAGING 比对 `raw_euler_package_info`（4951 包已到位；sdi 表建成后 `--euler-table` 可切换）
**结构**：一仓 × 一 metric_code 一行，`detail_json` 按 metric_code 异构
**UNIQUE KEY**：`(repo_id, metric_code, scan_time)`

通用字段：

| 字段                              | 类型         | 含义                                |
| --------------------------------- | ------------ | ----------------------------------- |
| repo_id / metric_code / scan_time | —            | KEY 前三列                          |
| repo_url                          | VARCHAR(512) | 仓库地址                            |
| detail_json                       | JSON         | 按 metric_code 的结构化明细（见下） |
| score                             | DECIMAL(5,2) | 该指标得分；NA=NULL                 |
| is_na                             | TINYINT      | 是否 NA                             |
| etl_time                          | DATETIME     | 入库时间                            |

各 metric_code 的 detail_json 结构与打分规则：

**2 COPYRIGHT（版权合规，权重 10，§5.2）**

| detail_json         | 说明                                                                   |
| ------------------- | ---------------------------------------------------------------------- |
| target_file_count   | 目标后缀文件总数                                                       |
| matched_count       | 含声明文件数                                                           |
| by_ext              | `[{ext, file_count, matched_count, matched_files:[…截断200], sample}]` |
| oversize_file_count | 超 8MB 读取上限文件数（仍计入分母按未匹配）                            |

打分：`10 × matched_count / target_file_count`；正则（C1 无空格口径）`Copyright\(c\)\s*\d{4}\s+Huawei Technologies Co\.`；扫描后缀 `.go .java .py .js .c .cpp .rs .ts .sh .bat`；无目标文件 → NA

**3 DANGEROUS_WF（危险工作流，权重 10，§5.3）**

| detail_json   | 说明                                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------------- |
| wf_file_count | workflow 文件数                                                                                         |
| findings      | `[{path, unsafe_checkout:bool, untrusted_context:[变量名], reason}]` 每文件一条，解析失败记 parse_error |

打分：发现任一危险模式 = 0，未发现 = 10，无 workflow → NA。危险模式：① `allow-unsafe-pr-checkout: true`；② steps 中直接使用不可信上下文变量（github/atomgit/gitcode 三前缀 × issue.title、pull_request.title/body、comment.body、head_commit.message→commits[].message、head_ref 共 18 个变体）。workflow 目录兼容 `.gitcode/workflows` 与 `.gitcode/workflow` 两种拼写

**4 TOKEN_PERM（令牌权限，权重 7.5，§5.4，C5 五条）**

| detail_json   | 说明                                                                |
| ------------- | ------------------------------------------------------------------- |
| wf_file_count | workflow 文件数                                                     |
| files         | `[{path, top_perm, job_perms:{job:perm}, has_write, parse_error?}]` |
| stat          | `{readonly, write, no_top_job_ro}` 三类文件计数                     |

打分（文件级分类后汇总）：全 READONLY=10（规则1）／全 WRITE=0（规则2/3）／部分 WRITE=`10×(1−写文件数/总数)`（规则5）／无写且全"未配置+job只读"=9（规则4）／无写混合=`10−未配置数/总数`（9~10 内插，规则 1/4 边界严格对齐）。无 workflow → NA。遗留：gitcode 权限校验模型映射待李洪峰（不阻塞）

**6 BINARY_ARTIFACTS（二进制制品，权重 7.5，§5.6）**

| detail_json    | 说明                         |
| -------------- | ---------------------------- |
| binary_count   | 命中数（全量计数）           |
| bad_file_paths | 违规文件路径列表（截断 200） |
| truncated      | 是否截断                     |

打分：`max(0, 10 − 命中数)`；后缀清单 `.exe .dll .so .dylib .a .o .obj .pyc .class .jar .war .ear .zip .tar .gz .7z .rar .bz2 .xz .pdf .doc .docx .xls .xlsx`；无 NA（.git 由 git ls-files 天然排除）

**12 PACKAGING（软件包发布，权重 5，§5.12）**

| detail_json          | 说明                                                                    |
| -------------------- | ----------------------------------------------------------------------- |
| has_workflow         | .gitcode workflow 目录下有 yml/yaml                                     |
| workflow_paths       | 命中的 workflow 文件相对路径                                            |
| in_openeuler_project | 归一化 URL（atomgit.com→gitcode.com）在 euler 包清单中；清单不可用=NULL |
| openeuler_project    | 命中的 os_project 列表                                                  |
| nightly              | 恒 "unsupported"（Nightly 场景无法确定使用仓库）                        |

打分：有 workflow **或** 在 openEuler 工程 = 10；否则 **NA**（不存在 0 分——未检测到不代表没有打包流程）

**14 SAST（静态分析，权重 5，§5.14）**

| detail_json    | 说明                                          |
| -------------- | --------------------------------------------- |
| has_precommit  | 根目录存在 .pre-commit-config.yaml            |
| precommit_path | 命中路径                                      |
| hooks          | repos[].hooks[].id 列表（解析失败不影响判定） |

打分：存在 = 10，否则 0；无 NA

**15 SECURITY_POLICY（安全策略，权重 5，§5.15，C3）**

| detail_json | 说明                                                                                    |
| ----------- | --------------------------------------------------------------------------------------- |
| file_path   | 命中路径（优先级 .gitcode/ > 根 > docs/ > 小写；精确文件名匹配保证 Windows/Linux 一致） |
| disclosure  | 含披露关键词（report/vulnerability/disclos/exploit/cve）                                |
| link        | 含联系链接（邮箱 / mailto: / http(s)）                                                  |
| free_text   | 有非标题非空行的实质内容                                                                |

打分：仓内存在 = 10，否则 0（社区 5 分分支预留，本期无数据源）；无 NA。三检测仅落明细不参与计分
