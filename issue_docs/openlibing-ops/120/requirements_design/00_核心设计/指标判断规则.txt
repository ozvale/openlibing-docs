十四、依赖锁定
1、判定规则的检查内容修改为：项目在构建和发布过程中使用的所有依赖应固定到具体的哈希值而非可变版本标签，确保构建的可重复性和依赖的安全性。
（1）Docker 镜像固定：Dockerfile 中的 FROM 指令应使用镜像的摘要哈希（@sha256:...）而非可变标签。如需使用 FROM ubuntu:22.04 这样的可读标签，应同时注释说明对应的哈希值，并在 CI 中验证一致性。
（2）构建流水线固定：工作流中的 uses 指令应固定到完整的 commit SHA（@<40位SHA>），而非版本标签（如 @v3）。
（3）包管理器固定：对于 npm 应使用 package-lock.json、Python 使用 requirements.txt 固定具体版本、Go 使用 go.sum 等 lock 文件固定整个依赖树。
（4）例外说明：Go 模块的完整语义化版本被视为已固定，因为 Go 工具链会在首次下载时验证内容哈希。Shell 脚本中的基础工具（如 apt-get install）如果无法通过哈希固定，应在 CI 中通过版本锁定和缓存机制降低风险。
