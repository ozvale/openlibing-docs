## 0. 全局约束（先读）

- **仓库清单**：`sdi_rd_efc_repo_operate_conf`，取 `is_operated=1` 的仓库，作为所有接口任务的遍历清单（含 repo_id、repo_url/项目名）。
- **调度**：DolphinScheduler，接口拉取层每日一次，遍历仓库循环调用 GitCode 对应 API。
- **落表**：先落 raw 层（原始字段全量保留），再清洗到 sdi 层（去重/标准化/机器人识别）。
- **凭证**：GitCode token 走既有凭证管理，勿硬编码。
- 所有 raw 表补 `repo_id`（关联仓库）与 `etl_time`（拉取时间）；sdi 表补 `repo_id` 便于下游按仓 join。
- 若调用的 raw 表已存在，**复用不重建**。

## 2. 各任务字段与清洗规则

### T1 分支保护（指标3）

- **API 资源**：仓库分支保护规则。
- **raw 字段（建议存）**：repo_id、branch_name、protection_rules_json(原始)、enabled(bool)、required_reviews(要求评审人数)、dismiss_stale、code_owner_required、has_required_status_checks、has_required_conversation、has_lock_and_upstream、force_push_allowed、deletion_allowed、etl_time。
- **sdi 清洗**：按默认分支（`sdi_repo_info` 定）一行一仓，布尔字段标准化 0/1。
- **供指标3** 五层阶梯判定（见 §3.3）。

### T2 PR 设置/合并设置（指标3）

- **API 资源**：仓库 PR/合并设置。
- **raw 字段**：repo_id、require_pull_request_reviews、required_approving_review_count、dismiss_stale_reviews、require_code_owner_review、require_conversation_resolution、require_status_checks、etl_time。
- **sdi 清洗**：一仓一行，布尔标准化 0/1。
- **供指标3** T2/T3 层判定。

### T3 PR 评审记录（指标2）

- **API 资源**：每仓库最近已合入 PR 的 review 评论/评审记录。
- **raw 字段**：repo_id、pr_number、comment_author_user_id、comment_author_login、is_bot(接口若提供)、comment_state、comment_body、created_at、etl_time。
- **sdi 清洗 `sdi_rd_efc_pr_review_reviewer`**：
  - 判定 author 是否**机器人**：author_login 含 bot/robot/[bot] 关键字，或 user_id 命中机器人名单。
  - 一张 PR 只要有**至少 1 条非机器人有效评审**（如 approved，非仅 layman 评论）→ 判定该 PR 已被人工评审。
- **供指标2** 已评审 PR 数（分子），与 PR 清单（指标2/4 共用 `dwi_rd_efc_pr_info_sum` 最近30次合入PR、剔除机器人作者）join。

### T4 Webhook 列表（指标19）

- **API 资源**：仓库 webhook 列表。
- **raw 字段**：repo_id、webhook_id、active(bool)、config_url/config_events、config_has_secret(bool)、config_content_type、etl_time。
- **sdi 清洗**：一库一行，`active` 布尔；`config_has_secret`=webhook 是否配置 secret。
- **供指标19**：无活跃 webhook→NA；活跃且均配 secret→10。

### T5 Release 列表（指标14 + 指标9佐证）

- **API 资源**：仓库 releases（含资产 assets）。
- **raw 字段**：repo_id、release_tag、release_name、published_at、draft/bool、prerelease/bool、assets_json(名称/大小/下载url)、has_sha256_asset(bool)、has_signature_asset(bool)、etl_time。
- **sdi 清洗**：一仓按 releases 多行。
- **供指标14**：最近（最新一个非 draft/prerelease）release 是否含 sha256 校验和资产 + 签名资产，均有→10。
- **供指标9 佐证**：最近是否有成功发布的 release。

### T6 贡献者列表（指标17）

- **API 资源**：仓库 contributors。
- **raw 字段**：repo_id、user_id、user_login、follower_of(user/company 字段若提供)、contributions_count、etl_time。
- **sdi 清洗**：按人去重；无法取公司组织时可留空，交由 SQL 侧按 login 分组近似。
- **供指标17**：贡献者所属组织/公司去重后数量 ≥3 → 10。

## 3. 服务指标的打分规则（0~10）

### 3.1 指标2 代码评审（CODE_REVIEW）

- 分母 n = 最近 30 次已合入 PR **剔除机器人创建者**后的数量。
- 分子 m = 其中**已通过人工评审**（T3 判定）的 PR 数。
- `score = m / n * 10`；`n=0` → NA（`is_na=1`, score=NULL）。
- 落表：`dwi_rd_efc_security_pr_scan`，字段含 `pr_unreviewed_detail`（未通过原因明细）。

### 3.2 指标3 分支保护（BRANCH_PROTECTION）

- 五层阶梯，逐层**必须全满足**才算该层通过，未满足某层则该层及后续不得分；T5 本期暂空。
- 计分 = 满足层权重累计：T1=3, T2=3, T3=2, T4=1, T5=1(空)。
  - T1(3)：要求 PR 评审（require_pull_request_reviews）
  - T2(3)：必须代码所有者评审 / 必须 status checks
  - T3(2)：stale 评审 dismiss / 对话必须解决
  - T4(1)：禁止 force push / 禁止删除
  - T5(1)：预留
- 落表：`dwi_rd_efc_security_branch_protect_scan`，`tier_result`/`tier_detail` 记录逐层判定。

### 3.3 指标14 发布签名（SIGNED_RELEASES）

- 取最近一个正式 release（非 draft/prerelease）。
- 同时含 **sha256 校验和资产 + 签名资产** → score=10；否则按缺失项扣减 / NA。
- 落表：`dwi_rd_efc_security_meta_api_scan(SIGNED_RELEASES)`，`detail_json` 记录 release 资产明细。

### 3.4 指标17 贡献者多样性（CONTRIBUTORS）

- 贡献者所属**组织/公司去重后数量 ≥3** → 10。
- 落表：`dwi_rd_efc_security_meta_api_scan(CONTRIBUTORS)`，`detail_json` 记录组织分组。

### 3.5 指标19 Webhook 安全（WEBHOOKS）

- 无活跃 webhook → NA。
- 有活跃 webhook 且均配置 secret → 10；否则按未配 secret 的占比扣减。
- 落表：`dwi_rd_efc_security_meta_api_scan(WEBHOOKS)`。

### 3.6 指标9 发布 Packaging（辅助，非本批主目标）

- 本任务只提供 "最近是否成功 release" 佐证字段；完整计分在文件扫描链路(PACKAGING)完成。

---

## 4. NA 与综合约定

- NA 语义：`score=NULL` + `is_na=1`；宽表 dm 该列存 NULL。
- 每批扫描所有指标用**同一 `scan_time`**；dwi 各表入库时间=实际完成时间，`scan_time` 由批次号统一。
- 预留指标（7/10/11/15）**不在本次接口任务范围**，只 dm 列占位，无需实现。

---

## 5. 验收要点（执行 agent 自查）

1. 6 个任务均按仓库清单遍历，raw → sdi 落表成功。
2. `sdi_rd_efc_pr_review_reviewer` 能正确标记机器人作者，评审人判定得到"已人工评审"PR 数与 PR 清单一致。
3. 指标3 五层阶梯示例仓库的判定与权重求和正确。
4. 指标14 能识别最新 release 的 sha256/签名资产。
5. 指标19 能区分活跃 webhook 与 secret 配置。
6. 所有接口任务失败不影响预留指标，重跑幂等（按批次/按天覆盖本批）。
