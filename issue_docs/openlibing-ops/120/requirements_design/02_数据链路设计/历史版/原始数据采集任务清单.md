## 0. 全局约束（先读）

- **仓库清单**：`sdi_rd_efc_repo_operate_conf` 取 `is_operated=1`，作为所有采集任务的遍历清单（含 repo_id、repo_url/owner/name）。
- **调度**：DolphinScheduler；接口采集每日一次，按仓库循环调用 GitCode API。
- **落表**：接口数据先落 raw（原始字段全量），再清洗到 sdi（去重/布尔标准化/机器人识别）。
- **凭证**：GitCode token 走既有凭证，禁止硬编码。
- raw/sdi 表均带 `repo_id`（关联仓库）与 `etl_time`（采集时间）。
- 若目标 raw/sdi 表已存在，**复用不重建**。

## 2. 需新建「接口采集」的原始数据

> 每个任务给出 GitCode API（源自 Excel 内记录的真实文档链接）、要采的字段、落 raw/sdi。

### T1 分支保护配置（服务指标3 Branch-Protection）

- **API**（Excel 原文链接）：
  - `v5/repos/{owner}/{repo}/protect-branches` → 字段 `no_one_can_push`（默认分支 protection 时为 true）
  - `v5/repos/{owner}/{repo}/pull-request-settings` → `merge_method`、`only_allow_merge_if_pipeline_succeeds`、`approval_required_approvers`
- **raw 表**：`raw_repo_branch_protection`（保护分支 JSON 原文）；`raw_repo_pr_setting`（README：合并/审查设置）
- **sdi 清洗 `sdi_rd_efc_branch_protection` / `sdi_rd_efc_pr_setting`**：按默认分支一仓一行；布尔标准化 0/1；关键字段：
  - `force_push_allowed`（反向：阻止强制推送）
  - `deletion_allowed`（反向：禁止删除）
  - `merge_method != 'merge'`（要求 merge commit，即半线性/fast-forward）
  - `only_allow_merge_if_pipeline_succeeds`（状态检查：流水线通过）
  - `approval_required_approvers > 2`（≥2 审查者）
- **判级（交给指标计算，采集 agent 只需采回字段）**：五层 3/3/2/1/1；T₅（取消过期审查+管理员约束）本期暂空。

### T2 PR 评审记录（服务指标2 Code-Review）

- **采集来源**：GitCode PR 评论（`raw_pr_comment_gitcode` 若已存在直接复用；否则采 PR 下的 review/comment 记录）
- **raw 字段**：repo_id、pr_number、评论人 user_id、评论人 login、评论类型(/lgtm、/approve 等)、评论时间、etl_time
- **sdi 清洗 `sdi_rd_efc_pr_review_reviewer`**：
  - **机器人识别**：GitCode 用「评论/用户名是否含 `bot`」判断（Excel 明确：名称含 bot 即机器人）
  - 判定某 PR 已人工评审：存在非机器人且非 PR 创建人的有效评审记录（/lgtm 或 /approve）
- **产出**：PR 是否被人工审批的标记，供指标2 分子使用。

### T3 Release 信息（服务指标14 Signed-Releases）

- **API**：GitCode release 接口
- **raw 表**：`raw_release`；字段：repo_id、release_tag、release_name、published_at、draft/prerelease、assets_json（名称/大小/下载 url）、has_sha256_asset、has_signature_asset、etl_time
- **sdi `sdi_rd_efc_release`**：一仓按 release 多行，最新非 draft/prerelease 为"最新正式发布"
- **判级**：存在 sha256 + 签名资产 → 达标；**无 release 不计算分数（NA）**

### T4 贡献者信息（服务指标17 Contributors）

- **API**（Excel 原文链接）：
  - `v5/repos/{owner}/{repo}/contributors`
  - `v5/users/{username}/orgs`（取贡献者所属组织）
- **raw 表**：`raw_contrib`；字段：repo_id、user_id、user_login、org_name、contributions_count、etl_time
- **sdi `sdi_rd_efc_repo_contributor`**：按人去重，关联组织
- **判级**：贡献者所属组织/公司去重后 **≥3 → 10 分**

### T5 Webhook 信息（服务指标19 Webhooks）

- **API**（Excel 原文链接）：`v5/repos/{owner}/{repo}/hooks`
- **raw 表**：`raw_repo_webhook`；字段：repo_id、webhook_id、`active`、config_password、config_url/events、etl_time
- **sdi `sdi_rd_efc_repo_webhook`**：一钩一行
- **判级**：`active==true` 的活跃钩子，其 `password` 字段**非空/非""** 才安全；无活跃钩子→NA

## 3. 需新建（确认）「PR↔流水线」关联（服务指标4 CI-Tests）

- **核心**：判定每个 PR 是否跑了 CI。
- 采集 agent 需**确认 GitCode workflow 数据是否已清洗**；关联表定位为 `dm_rd_efc_project_pipeline_relation`（Excel 原文），并核对是否能用 `repo_url + PR 号` 判定 PR 有无流水线。
- **产出**：`{PR编号: 是否跑CI}` 映射，供指标4（跑 CI 成功的 PR 占比）使用。
