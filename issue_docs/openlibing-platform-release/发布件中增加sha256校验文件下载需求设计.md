# 发布件中增加 sha256 校验文件下载需求设计

## 1. 基础信息

* **需求链接**: https://gitcode.com/openlibing/openlibing-platform-release/issues/74
* **需求名称**: 发布件中增加 sha256 校验文件（多后缀候选下载）
* **开发责任人**: disiqi
* **关联提交**: bddd24cf sha256后缀修改

---

## 2. 需求场景说明

> 发布件下载流程中，需要同时下载与发布件配套的 SHA256 校验文件，用于下载后做完整性校验。不同发布团队生成的 SHA256 文件后缀不统一（`.sha256`、`.sha256sum`、`.SHA256`、`.sum` 等），原实现硬编码只匹配 `.sha256` 一种后缀，导致其他后缀的校验文件被漏下载，校验环节缺失。

## 3. 需求验收标准

> 1. 下载发布件时，按候选后缀优先级依次尝试下载 SHA256 校验文件，命中第一个存在的即返回。
> 2. 候选后缀覆盖 `.sha256`、`.sha256sum`、`.SHA256`、`.sum` 四种常见命名。
> 3. 所有候选后缀都不存在时，不抛异常，返回空 Optional，主发布件正常下载不受影响。
> 4. 下载到的校验文件路径加入 `downloadPathList`，与主文件一起返回。

## 4. 需求设计与分解

| 功能点 | 描述 | 涉及对象 |
|--------|------|---------|
| 候选后缀常量 | 定义按优先级排序的后缀候选数组 | SoftwareObsDownloadServiceImpl |
| 多后缀尝试下载 | 依次尝试每个后缀，命中即返回 | downloadSha256ByCandidateSuffixes |
| 无命中处理 | 全部不存在时返回 Optional.empty() | downloadSha256ByCandidateSuffixes |
| 路径归集 | 命中的校验文件路径加入下载列表 | downloadObsFile |

### 4.1 核心逻辑方案

#### 4.1.1 架构设计

- **服务层**：`SoftwareObsDownloadServiceImpl` 负责从 OBS 桶下载发布件及配套校验文件。
- **常量定义**：`SHA256_SUFFIX_CANDIDATES` 静态常量数组，按优先级排列候选后缀。
- **方法拆分**：新增私有方法 `downloadSha256ByCandidateSuffixes` 封装多后缀尝试逻辑，原 `downloadSha256FileIfExist` 复用为单后缀下载能力。

#### 4.1.2 候选后缀设计

```
private static final String[] SHA256_SUFFIX_CANDIDATES = {".sha256", ".sha256sum", ".SHA256", ".sum"};
```

优先级从左到右依次尝试，命中第一个存在的即返回，避免重复下载。

#### 4.1.3 核心流程

**downloadObsFile 中调用点**：
1. 主发布件下载完成、路径加入 `downloadPathList` 后。
2. 调用 `downloadSha256ByCandidateSuffixes(obsClient, bucketName, objectKey, localFolder, fileName)`。
3. 遍历 `SHA256_SUFFIX_CANDIDATES`：
   - 构造 `sha256ObjectKey = baseObjectKey + suffix`
   - 构造 `sha256LocalPath = localFolder/baseFileName + suffix`
   - 调用 `downloadSha256FileIfExist` 尝试下载
   - 命中（Optional 有值）立即返回该路径
4. 全部未命中返回 `Optional.empty()`。
5. 调用方通过 `.ifPresent(downloadPathList::add)` 将路径加入下载列表。

#### 4.1.4 异常处理

| 异常类型 | 触发条件 | 处理方式 |
|---------|---------|---------|
| 单后缀对象不存在 | OBS 返回 404 | `downloadSha256FileIfExist` 内部吞掉，返回 Optional.empty，继续下一个后缀 |
| 全部后缀不存在 | 四个候选都未命中 | 返回 Optional.empty，主文件下载不受影响 |
| OBS 访问异常 | 网络/鉴权异常 | 由上层 try-catch IOException 记录日志，不影响主文件下载 |
