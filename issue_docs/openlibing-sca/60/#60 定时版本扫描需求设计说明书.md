## 2. 需求场景说明

> 描述"在什么情况下，为了解决什么问题，用户需要做什么"。

在 SCA 版本扫描场景中，运营人员目前只能通过页面手动触发版本扫描（`POST /version/scan/startVersionScan`）。对于需要持续合规看护的重点仓库，运营人员需要反复手动触发扫描，效率低且容易遗漏。

核心痛点：缺乏自动化的周期性扫描能力，无法对已接入版本扫描的仓库按配置进行每日例行扫描。

**解决方案**：在手动版本扫描接入表 `tbl_manual_version_scan` 上扩展定时扫描标记（`is_scheduled`），运营人员可将任意已接入版本扫描的仓库标记为"定时扫描"；系统通过定时任务按 cron 周期性地筛选出这些仓库，经过体积门禁（超大仓库跳过）后逐个投递到**独立的定时串行队列**（`version_scheduled_queue`，concurrency=1），由消费者串行执行扫描，避免与手动扫描 / 接口扫描争抢资源，并将扫描状态（扫描中/成功/失败）回写到接入表供前端展示。

## 3 需求验收标准

> 明确需求完成的标志，必须是可量化、可测试的。

- [x] 运营人员可通过 `POST /version/scan/batchUpdateScheduled` 批量开启/关闭仓库的定时扫描标记（`is_scheduled`），添加仓库接口 `POST /version/scan/save` 同样支持设置该标记
- [x] 定时任务按 Apollo 配置的 cron（默认每小时整点）触发，通过 Redis 分布式锁（`manual_version_scheduled_scan_<env>`）保证多实例部署下同一时刻只有一个实例执行分发
- [x] 定时任务筛选条件为 `is_scheduled = 1 AND is_version_scan = 1 AND branch_id IS NOT NULL`；扫描中（`scan_status = 1`）的仓库跳过，避免同一周期内重复入队
- [x] 单仓库分发失败（异常）只记录 error 日志，不影响其他仓库继续分发
- [x] 体积门禁：仓库大小超过 100MB（102400 KB，取平台仓库详情 API 的 `size` 字段）时跳过投递，仅回写 `is_oversize = 1`（`scan_status` 不变）；超大仓库仍参与后续每次体积探测，仓库瘦身（≤100MB）后自动恢复定时扫描并重置 `is_oversize = 0`
- [x] 定时扫描消息固定投递到独立串行队列 `version_scheduled_queue`（exchange `amq_version_scheduled_direct`，concurrency=1），与手动扫描队列、`/scan/version` 接口队列完全隔离
- [x] 扫描完成后回写状态：成功 → `scan_status = 2`、失败 → `scan_status = 3`，同时写入 `finish_time`；消费失败时 `basicReject` 不重入队，并清理工作区文件、`tbl_scan.scan_result` 置 -1
- [x] 查询接口 `POST /version/scan/query` 返回 `isScheduled`、`isOversize`、`scanTime`、`finishTime` 及扫描耗时（`finish_time - scan_time`，单位 s）

#### 核心设计决策

1. **独立串行队列隔离**：定时扫描统一投递到 `version_scheduled_queue`（concurrency=1 串行消费），不与手动扫描的 `version_manual_big/small` 队列、`/scan/version` 接口的 `version_big/small` 队列共享，避免批量定时任务在扫描高峰期挤占手动/门禁扫描资源。定时队列不区分仓库大小（体积已由分发前门禁拦截）。
2. **体积门禁（100MB）与自动恢复**：分发前调用平台（Gitee/GitCode）仓库详情 API 的 `size` 字段（单位 KB，响应体仅几 KB）判断仓库体积，超过 100MB（102400 KB）跳过投递、仅标记 `is_oversize=1`。筛选仓库时**不过滤** `is_oversize`，超大仓库每天仍参与体积探测，瘦身后在正常分发路径重置 `is_oversize=0` 自动恢复，无需人工干预。查询失败/未知平台返回 empty，不阻断分发。
3. **扫描中跳过**：`scan_status = 扫描中(1)` 的仓库在当次触发时跳过，避免定时周期（可配置为小时级）与长耗时扫描叠加导致同一仓库重复入队。
4. **单仓失败隔离**：`startScheduledScan` 循环内对每个仓库单独 try-catch，单仓异常仅记录 error 日志，继续处理后续仓库。
5. **分布式锁防多实例重复分发**：多实例部署下，`DistributedLockService.acquireLock(manual_version_scheduled_scan_<env>, 5s)` 保证同一触发时刻只有一个实例执行分发，异常时 finally 释放锁。
6. **状态回写复用手动扫描机制**：定时扫描投递时 `manualScan=true`，扫描完成/失败后 `updateManualVersionScanStatus` 按 `reposId+branchId` 回写 `scan_status` 与 `finish_time`，操作人记为 `system`；`scan_time` 在分发时写入，因此前端展示的耗时（`finish_time - scan_time`）在队列积压时包含排队等待时间。
7. **失败消息不重入队**：消费异常后 `basicReject(requeue=false)`，配合状态回写为"扫描失败"，避免失败消息无限重试占用串行队列；运营人员可通过手动扫描重新触发。

### 4.2 数据库设计

**表名：tbl_manual_version_scan**（MySQL，版本扫描接入表，本次为增量加列）

本次新增字段（Liquibase 变更集：`src/main/resources/db/changelog/mysql/20260827/add-tbl-manual-version-scan-columns.xml`）：

| 字段名 | 数据类型 | 约束 | 描述 |
|--------|---------|------|------|
| is_scheduled | TINYINT | 默认 0，可空 | 是否定时扫描：0-否，1-是 |
| is_oversize | TINYINT | 默认 0，可空 | 是否超大仓库跳过定时扫描：0-否，1-是 |
| finish_time | DATETIME | 可空 | 扫描结束时间 |
| create_by | VARCHAR(64) | 可空 | 创建人 |
| update_by | VARCHAR(64) | 可空 | 修改人 |

相关既有字段：

| 字段名 | 说明 |
|--------|------|
| repo_id / branch_id | 仓库/分支定位键，状态回写按二者更新 |
| is_version_scan | 是否接入版本扫描：0-否，1-是 |
| scan_status | 扫描状态：0-未执行扫描，1-扫描中，2-扫描成功，3-扫描失败（`ManualVersionScanStatus` 枚举） |
| scan_time | 扫描开始时间（分发入队时刻写入） |

**关键 SQL**（`TblManualVersionScanMapper.xml`）：

```sql
-- selectScheduledScanRepos：定时任务筛选待扫描仓库
SELECT * FROM tbl_manual_version_scan
WHERE is_scheduled = 1
  AND is_version_scan = 1
  AND branch_id IS NOT NULL
-- 不过滤 is_oversize：超大仓库每天仍参与体积探测，瘦身后自动恢复定时扫描
```

### 4.3 接口设计

##### 4.3.1 批量更新定时扫描标记接口

- **URL**: `/version/scan/batchUpdateScheduled`
- **方法**: POST
- **请求体**: `ManualVersionScanScheduledBatchPo`
    - ids: List\<String\>（必填，接入记录 ID 集合，`@NotEmpty`）
    - isScheduled: Integer（必填，0-关闭 / 1-开启，`@NotNull`）
- **请求参数**: userName: String（操作人）
- **返回**: `ResponseEntity<Integer>` - 实际更新的记录数

##### 4.3.2 添加仓库接口（支持定时标记）

- **URL**: `/version/scan/save`
- **方法**: POST
- **请求体**: `ManualVersionScanAddPo`
    - repoId: Integer（必填）
    - branchId: Integer / branchName: String
    - isVersionScan: Integer（1-接入 / 0-不接入）
    - isScheduled: Integer（是否定时扫描，默认 0）
- **请求参数**: userName: String（操作人）
- **返回**: `ResponseEntity<TblManualVersionScan>` - 保存后的接入记录

##### 4.3.3 接入记录查询接口

- **URL**: `/version/scan/query`
- **方法**: POST
- **请求体**: `ManualVersionScanQueryPo`（communityId、repoId、branchId、scanStatus、isScaAdd、pageNum、pageSize）
- **返回**: `ResponseEntity<DPage<ManualVersionScanVO>>` - 分页结果，含 `scanStatus`、`isScheduled`、`isOversize`、`scanTime`、`finishTime`、`duration`（秒）

##### 4.3.4 批量手动触发扫描接口（对照，定时扫描不走此接口）

- **URL**: `/version/scan/startVersionScan`
- **方法**: POST
- **请求体**: `List<ManualVersionScanStartPo>`（repoId、branchId、branchName）
- **请求参数**: userName: String（操作人）
- **返回**: `ResponseEntity<List<ManualVersionScanStartResultVO>>` - 每条记录的触发结果（单条失败不影响其他条）
