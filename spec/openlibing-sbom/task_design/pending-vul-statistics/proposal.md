# SBOM 漏洞数「待闭环」口径改造（pending-vul-statistics）

## 需求背景

SBOM 管理页（制品信息、软件成分数据）中的漏洞数展示位当前展示**全部漏洞数量**。用户实际关注的是"还有多少漏洞没闭环"：已挂起、已拒绝、已完成、不受影响（UNAFFECTED）的漏洞不应占用用户注意力。同时漏洞详情弹窗缺少闭环视角的信息（是否闭环、Issue 状态），无法支撑用户按待闭环优先处理漏洞。

isPending（是否待闭环）的真值判断依赖漏洞运营平台（openlibing-vulnerability 服务）MongoDB `cve_details` 文档中的 issue 级字段（issue_customize_state / issue_state / issue_labels / cvss_score），sbom 侧数据不全，口径必须在 vulnerability 服务源头实现后经既有 `GET .../ci-admin/cve/details?org=` 接口透传。

顺带修复两个页面缺陷：

1. 软件成分数据按依赖类型筛选后，结果行仍出现筛选范围外的依赖类型（如筛选「直接依赖」却出现「直接/间接依赖」行）——分组行展示值与筛选命中值不同源；
2. 全量导出功能上线时把「类型」radio 放进了导出弹窗，需要调整：xlsx 入口上提到导出按钮下拉菜单并更名，弹窗恢复为纯 SBOM 导出形态。

## 功能描述

**做**：

- 制品信息、软件成分数据的漏洞数主数字切换为**待闭环数**（恒显示，含 0），悬浮整块气泡展示「全部 X · 待闭环 Y」；全量数为 0 的级别块维持灰显；
- 列表表头「漏洞风险数值」更名为「待闭环漏洞数」，表头旁气泡提示「点击漏洞刷新可以更新最新的待闭环漏洞数」；
- 软件成分列表新增「漏洞总数」块（取 `package_statistics.vul_count`，主数字展示待闭环总数；**不支持点击跳转**），漏洞总数与各级别支持表头手动排序；
- 制品列表点级别块 → 展开软件成分数据并联动「漏洞级别筛选」自动选中该类型；点总数块 → 筛选选「全部类型」；联动后漏斗图标旁弹小气泡「已按XX类型筛选」，约 3 秒自动消失，带 × 手动关闭；
- 漏洞详情弹窗新增「是否闭环」（issue 级）「Issue 状态」（issue_state 中文映射）两列与「是否闭环」下拉筛选（是/否/清空，按**漏洞级** external_vul_ref.is_pending 过滤）；进入弹窗默认**未闭环优先**排序，同一漏洞多 issue 折叠时主行优先展示未闭环 issue；
- 软件包详情页 CVE 表格（columns2 模式）适配同款「是否闭环」「Issue 状态」列与筛选；
- Excel 导出新增「待闭环漏洞数」列，原总数列改名「漏洞总数」区分；
- 导出按钮下拉菜单：原「全量导出」更名「全量软件物料清单（SBOM）」，新增「全量软件成分数据（.xlsx）」直导出入口（无需表单直接提交导出任务）；导出弹窗移除「类型」radio，固定 SBOM 导出；
- 软件成分数据依赖类型筛选：分组行展示的 dependency_type 取组内命中过滤条件的值；
- 待闭环重算路径 3 个：解析跑批（写入点①）/ 漏洞刷新（写入点②，顺带重算制品级）/ xxl-job 每日清洗任务（写入点③，sbom 新接入 xxl-job，quartz `FetchMajunCveJob` 保持现状双轨）。

**不做**：

- 弹窗「漏洞状态」列取值逻辑不变（stateMap 命中值 > issueCustomizeState > `--`）；
- 「漏洞总数」块不支持点击跳转；
- quartz 同步任务不停用（xxl 侧 `fetchMajunCveHandler` 默认停用，仅管理台手动触发作应急/补偿）；
- 依赖类型筛选本身的选项与交互不变（只修行展示值）。

## 验收标准

- [ ] 制品/成分列表主数字恒展示待闭环数（含 0），悬浮整块展示「全部 X · 待闭环 Y」；全量 0 的级别块灰显
- [ ] 待闭环口径与漏洞运营「漏洞修复列表 + 超期清单」过滤口径一致（四条件，已完成算已闭环；未提单不算待闭环）
- [ ] 点制品级别块/总数块 → 成分列表展开且漏洞级别筛选自动选中对应类型/「全部类型」，漏斗旁 3 秒气泡提示、× 可手动关闭
- [ ] 弹窗默认未闭环优先排序（`is_pending DESC → score DESC`）；「是否闭环」筛选按漏洞级 is_pending 过滤；行内展示 issue 级是否闭环与 Issue 状态；多 issue 折叠主行优先未闭环
- [ ] 软件包详情页 CVE 表格展示同款两列与筛选
- [ ] Excel 导出含「待闭环漏洞数」列，原总数列名「漏洞总数」
- [ ] 导出下拉两项「全量软件物料清单（SBOM）」「全量软件成分数据（.xlsx）」；弹窗仅保留规范/版本/格式
- [ ] 依赖类型筛选「直接依赖」时结果行仅展示「直接依赖」
- [ ] 每日清洗任务使 evf/统计与 lifecycle 夜间刷新达成一致（gamma 量级首轮 4~6 分钟、日常约 1 分钟）
- [ ] 存量数据由重算路径回刷；重算前 pending 列为 NULL，主数字展示 `--`（区别于真 0）并在气泡标注待重算，「是否闭环」筛选对 NULL 安全（筛「否」时可见，与展示口径一致）
