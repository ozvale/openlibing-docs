Design Review：sbom-action 返回产物详情地址

openlibing/openlibing-sbom#185 · 变更名 sbom-detail-link-output · 影响仓：openlibing-sbom / sbom-action / openlibing-web · 2026-11-19

一、需求背景

  • sbom-action 插件输出结果只有任务 ID（taskId），使用者无法从流水线直接跳转查看 SBOM 产物详情。
  • 详情落地页为平台 SBOM 页 /apps/sbomManage?projectId=&name=：projectId 恢复项目上下文（壳层 guard 现有能力）；name 为新增支持参数——进入页面后自动按制品名过滤并选中该制品，直接展示其软件成分数据（"打开某个制品的数据"）。
  • 展示形态对齐 code-metrics-action 的任务结果面板（链接表 + 指标表），并输出包数量 / 关系数量（复用插件本地 SPDX 统计）。
  • 额外增强（用户追加）：sbomManage 页制品表筛选参数 URL 化并双向同步——读：URL 携带筛选参数（name / names / 分支等 attr 动态字段 / 解析状态 / 待闭环漏洞级别包含·排除）进入页面自动筛选；写：页面筛选变化时 router.replace 写回 URL，复制链接即可分享当前筛选状态（分支、待闭环漏洞数等）。
  • 遗留查询接口 querySbomPublishResult 的 sbomRef 仍指向旧 hash 页 #/sbomPackages——本次一并升级为同一 sbomManage 地址（projectId 反查失败时 sbomRef 置空软降级，不影响 success/finish），统一跳转入口。

二、UI 变化（可交互预演）

变化点：新增任务结果面板「链接」表 + 「包数量 / 关系数量」指标行  ·  新增列表页筛选参数 URL 双向同步（读：URL 自动过滤 + 单值 name 选中制品；写：筛选变化 router.replace 写回） ·  不变STEP_OUTPUT 既有行 / 页面其余交互 / 软件成分数据区内容  ·  升级遗留 querySbomPublishResult 的 sbomRef 改指新页地址（API 行为，无 UI 变化）

三、决策点

决策结论依据
projectId 获取（D1）addProduct 确定最终 productType 后，统一调用 framework 机机接口 GET /internal-server/get-project?projectName=<productType> 精确反查 projectId；失败/未命中 → 抛 AddProductException 上报失败，无降级framework 是平台项目主数据权威源；显式/缺省回填/already-exists 容忍三路径在 addProduct 返回后收敛；/internal-server 与现有 feign 调用同鉴权域；硬失败与 coderepo 反查现有语义一致
域名配置（D2）复用既有 sbom.service.website.domain（Nacos 配 https://www.openlibing.com）避免两套域名配置；未配置时 detailLink=null + warn，不阻塞上报
落地页形态（D3）列表页 ?projectId=&name=：过滤 + 自动选中制品行，联动展示其软件成分数据详情直连路由当前不存在；页面已有 @current-change 选中联动机制，复用成本最低
契约承载（D4）PublishSbomResponse 新增 detailLink；service 返回 AddAndPublishResult(taskId, detailLink)纯增量字段向后兼容；调用方仅 ApigController 一处
URL 筛选参数化（D5）制品表筛选双向同步：读=onMounted 解析 name（单值，detailLink 场景）/names/attr 动态字段（branch、softwareName…）/scanStatus/vulInclude/vulExclude → 初始化筛选统一查询，单值 name 自动选中；写=筛选变化 router.replace 写回（保留 projectId 等壳层参数，空筛选删 key）；多值逗号分隔，scanStatus 组值内逗号冲突用 | 分隔；names 多值仅筛选不选中用户增强诉求：分享/跳转可携带筛选状态（分支、待闭环漏洞级别等）；detailLink 生成侧仍只带 projectId+name 保持最简；成分区筛选/排序/分页不 URL 化避免状态爆炸
遗留接口 sbomRef 升级（D6）querySbomPublishResult 的 sbomRef 换用同一 sbomManage pattern，projectId 复用 resolvePlatformProjectId 反查；软降级：反查失败/domain 缺失 → sbomRef=null + warn，success/finish 不受影响；删除旧 pattern 常量（唯一调用方即该路径）查询接口主 payload 是 success/finish，sbomRef 为辅助信息，硬失败会把 framework 故障放大到存量查询；publish 路径硬失败是因为必须保证链接可得才允许上报成功

四、风险点

风险等级缓解
/internal-server/get-project 对 feign 直连的鉴权拦截行为低与现有 checkPermissionByProductType 同前缀同鉴权域；联调首验此调用
project_info 同名重复项目（无唯一约束）低精确匹配取首条 + warn 日志暴露，属平台数据治理问题
Nacos 域名配置缺失 / 错误导致链接不可用中detailLink=null 不阻塞上报；发布检查项加入配置核对
发布顺序：插件先于后端上线低插件读不到 detailLink 仅不输出链接行，概览组正常，无报错
URL name 无匹配制品（已改名 / 未上报）低筛选条空结果提示"暂无相关内容"，用户手动清除筛选即可（现有空态交互）
GitCode 面板 ATOMGIT_OUTPUT 渲染规则变化低行为对齐 code-metrics 线上实际效果，随其回归
URL 写回与壳层参数（projectId 等）共存冲突低router.replace 仅增删本页筛选 key，壳层参数原样保留；非法/未知参数值解析时忽略
querySbomPublishResult 的 sbomRef 链接形态变化（旧 hash 链接失效）低全仓检索未发现 sbomRef 程序化消费方（sbom-tools 仅消费 success/finish/taskId）；旧 hash 页路由保留，历史消息旧链接仍可访问
