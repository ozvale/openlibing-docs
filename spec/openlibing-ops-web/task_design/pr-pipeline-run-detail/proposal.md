# PR 流水线执行明细前端下钻

## 需求背景

关联 Issue：https://gitcode.com/openlibing/openlibing-ops/issues/294

工程能力运营看板需要从 PR 流水线聚合指标定位到具体运行，PR 门禁看板需要从执行次数核对运行样本，并继续查看单次运行的任务明细。

## 功能描述

- 工程能力项目详情的 PR 流水线仓库表格中，PR 执行时长、构建资源排队时长、测试资源排队时长三列数值支持点击。
- PR 门禁看板仓库表格新增“执行次数”列，数值支持点击，并联动当前流水线状态和仓库行范围。
- 两类入口复用同一张 17 列流水线执行明细；点击流水线名称单元格（含运行编号）下钻该运行的 9 列任务明细。
- 复用 `POST /common/detail` 的 `ops-pr-pipeline-run-detail` 和 `ops-pr-pipeline-job-detail` category。
- 执行明细与任务明细标题中的仓库名称、运行编号与流水线名称支持跳转，平台以浅蓝标签展示。
- 支持 GitCode、GitHub、CodeArts 运行及任务链接。

## 不做事项

- 不修改工程能力项目详情顶部 KPI 卡片。
- 不修改后端、SQL、接口契约、Nightly 明细和其他业务仓。
- 不调整 PR 个数、趋势图或跨看板统计口径。
- 不提供“查看任务”独立操作列，下钻入口内嵌在流水线名称单元格。

## 验收标准

- [x] 工程能力仓库表格三个指标与 PR 门禁执行次数打开同一执行明细组件。
- [x] 工程能力入口仅 PR 执行时长传 `pipelineStatus=true`，PR 门禁入口透传当前三档状态及页面筛选。
- [x] 执行明细展示 17 个数据列，任务明细展示 9 个数据列，空值显示 `--`，支持分页。
- [x] 执行明细 12 个数字列、任务明细 3 个数字列支持排序，单位统一以 `(min)`、`(卡时)` 后缀呈现。
- [x] 点击执行明细的流水线名称单元格可打开对应 `pipelineRunId` 的任务明细。
- [x] 标题中的仓库名称、运行编号与流水线名称按平台规则跳转；无法生成链接或缺少字段时显示普通文本。
- [x] 仓库地址统一经 `isSafeHttpUrl` 校验，非 http(s) 地址不渲染为链接。
- [x] 相关测试、类型检查和构建通过。

## 影响范围

仅修改 `openlibing-ops-web` 前端业务代码；规格文档归档到 `openlibing-docs`。
