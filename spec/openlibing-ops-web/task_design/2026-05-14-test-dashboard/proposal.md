# 测试看板提案

## 概述

设计并实现一个测试资源消耗看板页面，用于展示和分析测试任务与测试用例的 vCPU/NPU 资源消耗数据，支持多层级下钻查看。

## 背景与动机

### 问题陈述

当前系统缺乏对测试资源消耗的可视化分析能力，无法直观地了解：

- 各组织、项目的测试资源消耗情况
- 流水线级别的资源分布
- 具体测试任务和测试用例的资源消耗明细

### 业务价值

1. **资源优化**：帮助团队识别高消耗的测试任务和用例，优化资源分配
2. **成本控制**：通过可视化展示，让管理层了解测试资源使用情况
3. **决策支持**：为测试策略调整提供数据支撑

## 目标

### 核心目标

1. 构建四层级的数据展示架构：组织-项目 → 流水线 → 测试任务 → 测试用例
2. 展示四个关键指标：任务vCPU消耗、任务NPU消耗、用例CPU消耗、用例NPU消耗
3. 支持页面跳转式下钻，逐层查看详细数据

### 非目标

- 权限控制（本次不实现）
- 数据导出功能（本次不实现）
- 其他下钻方式（抽屉、弹窗、内嵌展开模式暂不实现）

## 关键指标说明

| 指标           | 说明                    | 单位 |
| ------------ | --------------------- | -- |
| 测试任务 vCPU 消耗 | 测试任务执行过程中消耗的虚拟CPU资源   | 核时 |
| 测试任务 NPU 消耗  | 测试任务执行过程中消耗的神经网络处理器资源 | 卡时 |
| 测试用例 CPU 消耗  | 单个测试用例执行消耗的CPU资源      | 核时 |
| 测试用例 NPU 消耗  | 单个测试用例执行消耗的NPU资源      | 卡时 |

## 展示方式

### 组织-项目汇总页面

1. **表格视图**：传统表格形式，支持分页、排序
2. **卡片视图**：以卡片形式展示各组织及项目，直观展示资源消耗占比

### 下钻展示方式

采用**页面跳转模式**：

- 点击行后跳转到新路由
- URL 结构：`/dashboard/test-dashboard/:orgId/:projectId/:pipelineId/:taskId`
- 优点：支持浏览器前进/后退、可分享链接
- 适用场景：需要完整查看详情的场景

## 设计参考

参照 `docs/design_D2_visual_analytics_v9.html` 文件中的设计风格：

- 现代、简洁的UI设计
- 清晰的数据可视化
- 流畅的交互动画
- 响应式布局

## 成功标准

1. 用户能够快速查看各组织、项目的资源消耗汇总
2. 用户能够逐层下钻查看详细数据
3. 页面加载时间 < 2秒
4. 支持至少 1000 条数据的流畅展示

## 风险与依赖

### 风险

1. 数据量过大时可能影响性能 - 需要实现分页和虚拟滚动
2. API 接口可能尚未就绪 - 需要与后端团队协调

### 依赖

1. 后端 API 提供测试资源消耗数据
2. 现有的基础组件库（base-table、base-tabs 等）
3. ECharts 图表库
