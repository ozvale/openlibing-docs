# 测试用例覆盖率看板（test-coverage）

## 需求背景

openlibing-ops-web 缺少面向测试用例资产的覆盖率视图。各社区（product）下沉淀的项目、代码仓、分支、路径积累了大量测试用例，需要一个看板回答：测试用例总量与通过/执行情况、变化趋势、薄弱环节，并支持下钻到单条用例的执行记录。

## 功能描述

### 总览页（无 productId）

1. 顶部时间筛选：今日 / 近 7 天 / 近 30 天 / 近 90 天（默认近 7 天）+ 自定义范围，复用 `time-range-filter.vue`，联动本页 KPI / 图表 / 表格。
2. 5 个 KPI 卡片：测试用例总数 / 通过用例 / 失败用例 / 执行率 / 通过率，复用公共 `base-kpi-card.vue`。
3. 全宽图表：测试用例执行率 & 通过率趋势（双折线 + 面积渐变）。
4. 两列图表：各社区通过率趋势（多折线）、各社区测试用例分布（通过/失败堆叠柱）。
5. 社区列表：按社区分组（rowSpan + 合计徽章）、项目行圆点，列含总用例 / 通过 / 失败 / 执行率 / 通过率；点击社区或项目名下钻详情。

### 详情页（有 productId）

1. 面包屑：总览 / 社区 / 项目 / …（超过 6 级折叠为 ···，浮层展示中间层级）+ 时间筛选。
2. 项目结构树侧栏（懒加载）：product → project → repo → branch → dir → file 六层；展开时按需拉取子级并在会话内缓存；拖拽调宽（默认 288，180–500）；一键收起；可折叠为 48px 窄条（仅恢复按钮）。
3. 主区：节点标题 + 5 个 KPI + 执行趋势图（跨 2 列）+ 用例状态环形图（通过 / 失败 / 未执行）。
4. 子节点列表（file 节点隐藏）+ 测试用例详情表（10 条/页）+ 执行记录弹窗（15 条/页）。

## 不做什么

- 不做后端实现（前端按通用接口契约以 `category` 定型 API 层与 TS 类型，后端后续对接）。
- 不做鉴权 / 权限控制（沿用宿主壳 401/403 postMessage 机制）。
- 不做数据导出、列设置。
- 不引入 Pinia store（状态由视图层 + 页面内组合式函数管理）。
- 样式 Tailwind 优先，不新建页面级 style.less。

## 验收标准

- [ ] 路由 `/dashboard/test-coverage/:productId?` 可访问，菜单「测试用例覆盖率看板」。
- [ ] 总览页：时间筛选 + 5 KPI + 全宽双折线 + 两列图表 + 社区分组表，布局与交互符合设计。
- [ ] 详情页：面包屑 + 结构树（懒加载 / 拖拽 / 一键收起 / 折叠窄条）+ KPI + 趋势图 + 环形图 + 子节点表 + 用例表 + 执行记录弹窗。
- [ ] 颜色全部走项目色板（主色 `#2563eb`，图表色板 `#2563eb / #0ea5e9 / #10b981 / #f59e0b / #8b5cf6 / #ef4444 / …`）。
- [ ] 时间筛选联动所有数据区；总览可下钻详情；详情面包屑 / 树 / 子节点表可在节点间导航。
- [ ] 用例表 10 条/页、执行记录表 15 条/页；各空态文案正确。
- [ ] 数据请求在视图层 / 组合式函数中，`to()` 元组处理，错误由拦截器统一提示，无重复 toast。
- [ ] `lint` / `type-check` / `test:unit` / `build` 全部通过；config / utils 有配套单元测试。
