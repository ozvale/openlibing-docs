# 【openLiBing】扩展安全编译选项扫描覆盖产物类型 — 技术设计

## 1. 方案设计

### 1.1 现状问题

单文件识别本身已按 ELF 魔数判定（支撑任意后缀，`.obj` 亦可通过），但扫描入口存在两处非内容限制使其无法落地，另缺内容去重，合计三处导致漏扫与重复计数（`.dbg` 调试符号文件、编译器探测桩文件属显式排除的非核查对象，不在此列）：

| #   | 问题                       | 位置                                                | 后果                                                                                                                                                   |
| --- | -------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | 跳过构建中间产物目录       | `SKIP_DIRS` 含 `CMakeFiles`                         | `.obj` / `.c.obj` 等嵌入式工具链产物的可重定位文件（多存放于构建中间目录）全部漏扫，5 项编译期选项（sp/fortify/ftrapv/stackClash/fstackCheck）核查盲区 |
| 2   | 归档识别依赖后缀白名单     | `try_extract_archive` 的 zip/tar/run/deb 后缀元组   | 后缀不规范、改名或无后缀的归档（如 `.a` 静态库）不被解包，内部 ELF 漏扫                                                                                |
| 3   | 去重范围需限定在归档成员侧 | `analyze_single` 入口（归档成员与树内路径混同处理） | 归档解包后成员与树内原件同内容并存会重复计数；而树内不同归属的独立路径不应因内容一致被合并（实测误合并 5 个 `.elf` 原件与 5 个打包副本等独立路径）     |

### 1.2 方案

1. **文件识别内容化（总原则）**：产物文件是否纳入扫描只看内容——单文件按 ELF 魔数判定（`.obj`、`.c.obj`、无后缀等任意命名均可），归档包按 zip/tar/ar 内容试探识别；`.dbg` 等显式排除的非核查对象保持现状
2. **放开构建中间目录**：`SKIP_DIRS` 移除 `CMakeFiles`，保留 `__pycache__` / `.git` / `.svn` / `node_modules`
3. **成员限定内容去重 + 两遍扫描**：仅解包归档成员按内容 SHA256 去重；树内真实路径一律保留并登记哈希供成员比对；树内阶段先行扫描、归档成员第二遍统一处理（按包内相对路径排序，结果可复现）

三项能力正交，可独立验证；但去重应与放开目录同批次交付，否则统计口径虚增。

### 1.3 关键决策

| 决策            | 选择                                                        | 备选                       | 理由                                                                                                                                                                                           |
| --------------- | ----------------------------------------------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 识别依据        | 以文件内容为准（ELF 魔数 / 归档魔数），不以后缀为前提       | 后缀白名单 + 按需扩展      | 工具链产物后缀多样（`.obj`/`.c.obj`/无后缀），枚举必然遗漏；内容判定一次覆盖                                                                                                                   |
| `.dbg` 后缀排除 | 保留（显式排除的非核查对象）                                | 移除                       | `.dbg` 为 `objcopy --only-keep-debug` 拆出的调试符号文件：不装载、不交付，非调试段内容已被剥离，扫描无核查价值且引入 N/A 噪音与大文件开销；属对象过滤而非识别限制                              |
| 去重方式        | 内容 SHA256，仅对归档成员生效（树内真实路径不做跨路径合并） | 全量内容去重（对所有文件） | 全量去重会将不同归属、仅内容巧合一致的独立路径误合并（实测 `.elf` 原件/打包副本被合并不可见）；成员去重精准覆盖去重初衷场景（原件 + 归档成员重复计数），且对所有归档成员一致、不做 `.a` 特殊化 |
| 归档识别        | 内容魔数试探（zip/tar/ar）                                  | 继续扩展后缀白名单         | 不依赖命名规范；试探失败自然回退单文件处理                                                                                                                                                     |
| `.run` 自解压包 | 保留现有后缀 + 内部探测                                     | 纳入魔数试探               | Makeself 无固定魔数，维持现状避免回归                                                                                                                                                          |
| 7z/rar 等格式   | 本期不支持                                                  | 支持                       | 需三方依赖（py7zr/rarfile），超出本期范围                                                                                                                                                      |
| LiteOS 等 RTOS  | 不纳入                                                      | 纳入                       | Ascend 指南 12 项全部限定"Linux 平台用户态"；RTOS 无 MMU/动态装载器，链接期选项无意义，编译期选项依赖 glibc 接口亦不成立                                                                       |
| 检测器逻辑      | 不改动                                                      | —                          | 14 项检测在 ELF 上已就绪，本需求只改"文件发现"环节                                                                                                                                             |

## 2. 实现逻辑设计

### 2.1 文件识别（以内容为唯一依据）

**单文件**：`is_elf_file` 按 ELF 魔数（`\x7fELF`）判定，与后缀、文件名无关——`.obj`、`.c.obj`、无后缀等任意命名的 ELF 文件均进入 14 项检测（`.dbg` 调试符号文件、编译器探测桩文件为显式排除的非核查对象，见 2.3）。现状已具备该判定能力，本需求通过放开构建中间目录使其实效。

**归档包**：改写 `try_extract_archive`，按下表按内容试探识别。

| 序号 | 判断依据                        | 处理                                                                                     |
| ---- | ------------------------------- | ---------------------------------------------------------------------------------------- |
| 1    | 文件头 zip 魔数（`PK\x03\x04`） | zipfile 解压（覆盖 `.zip`/`.jar`/`.whl`/`.apk`/`.hap`/`.nupkg` 等全部 zip 系，无需后缀） |
| 2    | 文件头 ar 魔数（`!<arch>\n`）   | ar 解析（复用 `_extract_ar`，覆盖 `.a`/`.deb`）                                          |
| 3    | tarfile 试探（`mode='r:*'`）    | tar 解压（自动探测 gz/bz2/xz 压缩，覆盖 `.tar`/`.tar.gz`/`.tgz` 等，无需后缀）           |
| 4    | `.run` 后缀（保留现状）         | 现有内部探测逻辑（shell 头 + 载荷）                                                      |
| 5    | 以上全部失败                    | 返回 None → 按普通文件处理（交 `analyze_single` 走 ELF 魔数预检）                        |

说明：tarfile 试探对非 tar 文件抛 `tarfile.ReadError`，由异常兜底返回 None，不阻断扫描；zip 试探可用 `zipfile.is_zipfile` 预判（读中央目录，开销小）。

### 2.2 成员限定内容去重 + 两遍扫描

**去重语义**：去重初衷是避免同一内容以「原件 + 归档成员」形态重复计数（如构建目录散落的 `.o` 与 `.a` 内成员、归档内的打包副本）。树内真实路径（不同归属、各自独立存在）即使内容一致也一律保留可见，不做跨路径合并。

**两遍扫描**：第一遍扫描全部树内真实路径（顶层目标包内容视作真实路径立即解压；其余归档仅登记待解压清单），第二遍按包内相对路径排序统一解压归档并扫描成员——树内路径先登记内容哈希，成员不抢占代表权，结果与遍历顺序无关且可复现。

```python
seen_hashes = set()  # 扫描会话级集合：树内路径先登记，成员后比对

def analyze_single(file_path, scan_options, scan_root, member_prefix):
    if not is_elf_file(file_path):
        return None                       # 现有 ELF 魔数预检（支持任意后缀，含 .obj）
    h = _sha256_of_file(file_path)        # 分块流式读取，避免大文件全量载入内存
    if member_prefix and h in seen_hashes:
        return None                       # 仅归档成员：与已见内容重复时跳过
    seen_hashes.add(h)                    # 树内路径一律保留并登记哈希供成员比对
    ...                                   # 现有 14 项检测逻辑不变
```

**成员路径消歧**：归档成员多为裸名（如 `interrupt.c.obj` 在多个 `.a` 间同名），成员 `filePath` 带归档包包内相对路径前缀（`<归档包相对路径>/<成员相对路径>`）；顶层扫描目标自身视作包根不加前缀；嵌套归档（`.deb` > `data.tar.gz`）前缀逐级追加。

去重范围为单次扫描会话（进程级），跨会话不共享。

### 2.3 目录与后缀过滤调整

- `SKIP_DIRS`：移除 `CMakeFiles`（保留其余四项）
- `SKIP_SUFFIXES = ('.dbg',)`：不变（显式排除调试符号辅助文件，属非核查对象过滤，不是后缀识别限制）
- `SKIP_BASENAMES = {'CMakeCCompilerId', 'CMakeCXXCompilerId', 'feature_tests'}`（原 `SKIP_NAMES` 固定文件名改为按**去后缀基名**匹配）：覆盖探测桩在目标工具链下的实际命名（`.o` / `.obj` / `.c.obj` / `.bin` 等）；探测目录下的链接产物（如 `CompilerIdC/` 的 `a.out`）不跳过——它是真实编译产物，可核查工具链默认编译行为

## 4. 数据模型设计

无。扫描结果条目结构（`filePath` / `fileName` / `options`）与上传协议（`overviewData` / `fileDetails`）字段结构不变；变化仅体现在数据内容（扫描文件集合更全、树内真实路径全部保留）。

口径变化提示：树内真实路径（含构建中间目录产物、产物原件与打包副本等独立路径）全部保留可见；归档成员与树内已见内容重复时跳过、不重复计数。diting 包最终 4842 行均为树内真实路径（1659 个 `.a` 成员内容全部与树内重复，0 行进入结果）。文件数较历史报告上升属漏扫修正；同一内容在多个独立路径并存属预期行为，不再合并。

## 5. 性能设计

| 项          | 评估                                                                                                    |
| ----------- | ------------------------------------------------------------------------------------------------------- |
| SHA256 计算 | 每 ELF 文件一次流式哈希（分块读），diting 包树内 4842 个 + 归档成员 1659 个待哈希文件，增加秒级开销     |
| 归档试探    | 每非 ELF 文件一次头部读取（数百字节）+ tarfile 试探；失败路径有异常构造开销，整体可忽略                 |
| 两遍扫描    | 树内路径先扫、归档成员第二遍统一处理（排序保证可复现），不重复遍历；diting 包结果 10 → 4842（漏扫修正） |
| 内存        | `seen_hashes` 集合 + `details` / `pending_archives` 列表：共约 6500 项记录，数百 KB～数 MB 量级         |

## 6. API 接口设计

## 7. 安全设计

- **路径穿越防护**：现有 `_entry_path_unsafe` 校验对所有归档成员生效；`.a`、改名归档的内部成员同样校验，本次改造不绕过该防护
- **损坏归档兜底**：魔数命中但内容损坏时，解压异常被捕获、打印告警并跳过，不阻断整体扫描
- **依赖安全**：无新增三方依赖（zipfile / tarfile / hashlib 均为标准库），不引入供应链风险
- **去重不影响判定正确性**：去重仅跳过与已见内容重复的归档成员（内容相同 → 检测结果必然相同，只影响计数不改开启率）；树内真实路径不做合并，无判定丢失
- **无凭证/权限变更**

## 8. 需求设计检查清单对照（requirement-design-check）

本需求为扫描器插件内部逻辑变更，不涉及列表/查询接口、数据库表结构、前端页面、ID 设计，故与"筛选/排序/分页/主键/索引/接口精简/字段全链路穿透/迁移 SQL"相关的条目均不适用。适用条目：

- 第 5 条（可扩展性）：识别依据内容而非后缀枚举，新增归档格式只需扩展内容试探分支（未来可加 7z/rar），本期不引入；去重集合为会话级，不做跨会话持久化
- 第 16 条（重复逻辑下沉单一来源）：归档识别逻辑集中于 `try_extract_archive` 单一函数，不在多处判断；`dist/sec_option_scan.py` 与 `dist/bin/sec_option_scan.py` 双副本必须字节一致（现有约束，实现时遵守）

## 风险 & 缓解

| #   | 风险                                                                                                  | 缓解                                                                                                        |
| --- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| R1  | 结果文件数较历史报告上升（diting 包 10 → 4842，含构建中间目录与打包副本等独立路径），可能引起理解偏差 | 交付说明明确口径（漏扫修正 + 树内路径全保留）；同一路径明细完整可见，成员路径带包内前缀消歧                 |
| R2  | tarfile 试探对超大非 tar 文件的 IO 开销                                                               | `tarfile` 仅读头部判断格式，失败即返回；必要时先按魔数（`ustar` / `\x1f\x8b` / `BZh` / `\xfd7zXZ`）预筛     |
| R3  | 放开 CMakeFiles 后，CMake 编译器探测产物（CompilerIdC / CompilerIdCXX 目录）可能被扫入，引入噪音      | 已按去后缀基名（`SKIP_BASENAMES`）跳过探测桩各命名变体；探测目录下的链接产物（`a.out`）保留可见（复核确认） |
| R4  | 归档识别改写可能造成现有 `.deb` / `.jar` / `.whl` / `.run` 行为回归                                   | 补充针对性回归用例（各格式各一例），diting 包 + 现有样例产物双回归                                          |
