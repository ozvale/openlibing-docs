# 【openLiBing】扩展安全编译选项扫描覆盖产物类型

## 需求背景

嵌入式工具链构建的产物包中，可重定位目标文件常以 `.obj`（如 `.c.obj` 命名）等非 Linux 惯用后缀存放在构建中间目录下，静态库以 `.a` 归档分发。当前扫描器对产物文件的识别受目录位置与后缀约定限制——跳过构建中间目录、仅按后缀白名单识别归档包——导致后缀不符合约定的 ELF 产物被漏扫，安全编译选项核查存在盲区；同时归档解包（`.a` 等）会将与树内原件同内容的成员重复计入，需要成员侧的重复计数控制。产物文件是否纳入扫描应只取决于文件内容（是否为 ELF、是否为归档），而不取决于文件名后缀；仅保留 `.dbg` 调试符号文件、编译器探测桩文件这类显式非核查对象的排除。

实测 diting 产物包（`pack_diting_community.tar.gz`，40324 个文件）：

| 类别                            | 数量                          | 当前状态                                                          |
| ------------------------------- | ----------------------------- | ----------------------------------------------------------------- |
| 散落 `.obj`（ELF 可重定位文件） | 约 4822 个                    | 全部位于 CMakeFiles 目录下被跳过                                  |
| `.a` 静态库                     | 721 个（约 4599 个 ELF 成员） | 因仅按后缀识别归档，未解包扫描                                    |
| 最终产物 `.elf`                 | 5 个（10 个路径）             | 已扫描；10 个路径均为独立产物，全部保留可见（不做跨路径内容合并） |

按 [Ascend 安全编译指南](https://gitcode.com/Ascend/community/blob/master/docs/contributor/Ascend-secure-compile-guide.md)，栈保护（SP）、FORTIFY（FS）、ftrapv、fstackCheck、stackClash 五项编译期选项的明文作用范围包含"可重定位文件（.o）"——上述文件漏扫直接导致编译期安全选项核查覆盖不足。

## 功能描述

1. **产物文件识别不再依赖文件后缀，统一按文件内容判定**：内容为 ELF 的文件一律纳入扫描，包括 `.obj`、`.c.obj` 等嵌入式工具链产物后缀、无后缀文件及其他任意后缀；内容为归档包（zip/tar/ar）的一律解包后递归扫描，后缀不规范、改名或缺失的归档包同样能正确识别
2. **显式非核查对象排除保持不变**：调试符号文件（`.dbg`）与编译器探测桩文件（如 `CMakeCCompilerId.o`）继续排除、不参与核查；此项为有意的对象过滤，不属于后缀识别限制
3. 不再按目录位置跳过构建中间目录，构建现场的可重定位目标文件与最终产物同等纳入扫描
4. 归档成员与树内已见内容重复时不再重复计数（如 `.a` 成员与构建目录散落原件同内容共存），避免归档解包引入计数虚增；树内不同路径的独立文件即使内容一致也全部保留、各自可见（不做跨路径内容合并）

不涉及：

- 不适配 LiteOS 等 RTOS 平台的安全编译选项体系，扫描范围仍以 Linux 平台产物为限
- 不新增需第三方依赖的归档格式（7z/rar 等）支持
- 不改动 14 项检测器的判定逻辑、插件输入参数与上传协议字段结构

## 验收标准

- [ ] 产物文件后缀不构成扫描门槛：`.obj`、`.c.obj`、无后缀等任意命名的 ELF 文件均被扫描（`.dbg` 调试符号文件等显式非核查对象除外），判定口径与现有 `.o` 一致（可重定位文件的链接期选项返回 N/A，不计入分母）
- [ ] 任意后缀的归档包（含 `.a`）按内容识别并解包，内部目标文件的编译期选项可正常检出
- [ ] 归档成员不重复计数：同一内容以「树内原件 + 归档成员」形态共存时成员侧跳过（diting 包 1659 个 `.a` 成员内容全部与树内重复，0 行进入结果）；树内真实路径全部保留——diting 产物包回归结果为 4842 行（`.elf` 原件与打包副本 10 个路径均可见）
- [ ] 损坏或非产物文件不影响扫描流程，现有 `.elf` 扫描结果无回退

## 影响范围

- 仓库：`openlibing/security-compilation-options-action`（扫描脚本 `dist/sec_option_scan.py` 及同步副本 `dist/bin/sec_option_scan.py`）
- 无新增依赖（zipfile / tarfile / hashlib 均为 Python 标准库）
- 无接口、数据模型、上传协议变化
- 已决定：关闭 PR #23（`.a` 后缀方式）与 Issue #11，`.a` 支持由本需求的归档内容识别统一实现，不再走后缀白名单方式
