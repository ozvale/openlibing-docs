# 工具举报功能规格说明

## 1. 概述

### 1.1 功能背景

工具举报功能允许 openLiBing 平台用户对存在违规内容、质量问题的工具进行举报，由工具归属项目的管理者在 SLA 时限内核实处理。若管理者超时未核实，系统将自动下架被举报工具，保障平台内容质量。

### 1.2 核心目标

- 提供用户举报工具的标准化流程
- 确保工具管理者在 SLA 时限内处理举报
- 超时自动下架机制，降低违规工具对平台的影响
- 完整记录举报处理全链路

### 1.3 角色定义

| 角色 | 说明 |
|------|------|
| 举报人 | 平台任意用户，可对工具发起举报 |
| 工具管理者 | 工具归属项目的 `PROJECT_TOOL_MANAGER` 角色，负责核实举报、管理工具上下架 |
| 系统 | 定时任务执行 SLA 超时自动下架 |

## 2. 数据模型

### 2.1 表结构：`tool_report`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR(32) | 主键，UUID |
| tool_id | VARCHAR(32) | 被举报工具ID，关联 tool_info |
| tool_name | VARCHAR | 工具名称（冗余） |
| version_id | VARCHAR(32) | 被举报版本ID，NULL=举报整个工具 |
| version | VARCHAR | 版本号（冗余） |
| report_content | LONGTEXT | 举报内容 |
| report_by | VARCHAR(32) | 举报人用户ID |
| report_time | VARCHAR(20) | 举报时间，格式 `yyyy-MM-dd HH:mm:ss` |
| status | VARCHAR(2) | 状态：`0`-待核实 `1`-核实属实 `2`-核实不属实 |
| review_by | VARCHAR(32) | 核实人用户ID |
| review_time | VARCHAR(20) | 核实时间 |
| review_remark | LONGTEXT | 核实备注 |
| owner_project_id | INT | 归属项目ID |
| sla_deadline | VARCHAR(20) | SLA 截止时间 |
| sla_expired | VARCHAR(2) | 是否已超时自动下架：`0`-否 `1`-是 |

### 2.2 状态枚举

| status | 含义 | 说明 |
|--------|------|------|
| 0 | 待核实 | 初始状态，等待工具管理者核实 |
| 1 | 核实属实 | 举报内容确认属实，工具/版本将被下架 |
| 2 | 核实不属实 | 举报内容不属实，不做处理（如有超时下架则恢复） |

## 3. 业务流程

### 3.1 提交举报流程

```
用户提交举报
  │
  ├─ 校验：toolId 不能为空
  ├─ 校验：reportContent 不能为空
  ├─ 校验：工具是否存在
  ├─ 校验：该工具是否存在待核实的举报（防重复举报）
  ├─ 校验：如果指定了 versionId，校验版本存在且属于该工具
  │
  ├─ 创建举报记录
  │   ├─ status = "0"（待核实）
  │   ├─ slaDeadline = 当前时间 + slaHours（默认72h）
  │   └─ slaExpired = "0"
  │
  ├─ 入库
  └─ 异步通知工具管理者（邮件）
```

**约束规则**

| 规则 | 说明 |
|------|------|
| 防重复举报 | 同一工具存在 status=0 的举报记录时，阻止再次提交，提示"该工具已举报，审核中" |
| SLA 期间工具状态 | 举报提交后工具保持在线，不受影响 |
| 版本级举报 | 可选指定版本举报，未指定则视为举报整个工具 |
| SLA 截止时间 | 提交时根据 `tool.report.sla-hours` 配置计算，默认 72h |

### 3.2 核实举报流程

```
工具管理者核实举报
  │
  ├─ 校验：reportId 不能为空
  ├─ 校验：status 不能为空
  ├─ 校验：举报记录是否存在
  ├─ 校验：举报记录 status 必须是 "0"（防止重复核实）
  ├─ 权限校验：操作用户必须是该工具归属项目的工具管理者
  │
  ├─ 更新举报记录
  │   ├─ status = 传入值（1=属实 / 2=不属实）
  │   ├─ reviewBy = 核实人ID
  │   ├─ reviewTime = 当前时间
  │   └─ reviewRemark = 核实备注
  │
  └─ 根据核实结果执行操作
      ├─ 属实（status=1）
      │   ├─ 有 versionId → 下架该版本
      │   └─ 无 versionId → 下架整个工具
      │
      └─ 不属实（status=2）
          ├─ slaExpired=0 → SLA 期间未下架，无需处理
          └─ slaExpired=1 → 已超时自动下架，恢复上架
```

**权限说明**

核实操作需要用户具有 `PROJECT_TOOL_MANAGER` 角色，且属于被举报工具归属项目。

### 3.3 主动上下架流程

```
工具管理者主动上下架
  │
  ├─ 校验：toolId 不能为空
  ├─ 校验：validFlag 不能为空
  ├─ 校验：工具是否存在
  ├─ 权限校验：操作用户必须是该工具归属项目的工具管理者
  │
  ├─ 如果指定了 versionId
  │   ├─ 校验版本存在且属于该工具
  │   └─ 更新 tool_version.valid_flag
  │
  └─ 未指定 versionId
      └─ 更新 tool_info.valid_flag
```

### 3.4 SLA 超时自动下架流程

```
定时任务（每小时整点触发）
  │
  └─ 查询所有满足条件的记录
      ├─ status = "0"（待核实）
      ├─ sla_expired = "0"（未超时处理过）
      └─ sla_deadline < 当前时间
      │
      ├─ 对每条记录
      │   ├─ 有 versionId → 下架该版本
      │   └─ 无 versionId → 下架整个工具
      │
      ├─ 标记 sla_expired = "1"（防止重复处理）
      │
      └─ 异步通知工具管理者（邮件）
```

**定时任务配置**

| 配置项 | 值 |
|--------|-----|
| Cron 表达式 | `0 0 * * * ?`（每小时整点） |
| 单条处理失败 | 不影响其他记录，打印错误日志 |

## 4. 状态机

```
                    ┌─────────────────────────────────────────────────────┐
                    │                    SLA 期间                         │
                    │                                                     │
                    │  提交举报 ──→ 待核实(0) ──核实属实(1)──→ 下架工具    │
                    │                    │                                │
                    │                    ├─核实不属实(2)──→ 不做处理       │
                    │                    │                                │
                    └────────────────────│─────────────────────────────────┘
                                         │
                                   超时未核实
                                         │
                                         ▼
                              自动下架 + sla_expired=1
                                    (仍为待核实0)
                                         │
                              ┌──────────┴──────────┐
                              │                     │
                         后续核实属实(1)        后续核实不属实(2)
                              │                     │
                              ▼                     ▼
                         维持下架              恢复上架
```

## 5. 通知机制

### 5.1 举报提交通知

**触发时机**：用户提交举报成功

**通知对象**：被举报工具归属项目的所有 `PROJECT_TOOL_MANAGER`

**通知方式**：邮件（异步发送）

**邮件内容**：
- 工具名称、版本号、举报人姓名、举报时间、SLA 截止时间、举报内容
- 提示：SLA 截止前登录平台核实处理，超时自动下架

### 5.2 SLA 超时通知

**触发时机**：定时任务执行超时自动下架后

**通知对象**：被举报工具归属项目的所有 `PROJECT_TOOL_MANAGER`

**通知方式**：邮件（异步发送）

**邮件内容**：
- 工具名称、版本号、举报时间、SLA 截止时间、举报内容
- 提示：工具已被自动下架，核实属实维持下架，核实不属实恢复上架

## 6. 接口定义

### 6.1 POST /tool-report/submit

提交工具举报。

**请求参数**（Query）：
- `userId` (string, required) — 用户ID

**请求体**（JSON）：
```json
{
  "toolId": "工具ID",
  "versionId": "版本ID（可选）",
  "reportContent": "举报内容"
}
```

**响应**：
- 成功：`{ "code": 200, "message": "举报成功", "data": "举报记录ID" }`
- 失败：返回错误码和错误消息

### 6.2 POST /tool-report/review

核实举报（工具管理者权限）。

**请求参数**（Query）：
- `userId` (string, required) — 用户ID

**请求体**（JSON）：
```json
{
  "reportId": "举报记录ID",
  "status": "1",          // 1=属实, 2=不属实
  "reviewRemark": "核实备注（可选）"
}
```

### 6.3 POST /tool-report/activate

主动上下架工具或版本（工具管理者权限）。

**请求参数**（Query）：
- `userId` (string, required) — 用户ID

**请求体**（JSON）：
```json
{
  "toolId": "工具ID",
  "versionId": "版本ID（可选）",
  "validFlag": "1"        // 1=上架, 0=下架
}
```

### 6.4 POST /tool-report/list

分页查询举报列表。

**请求体**（JSON）：
```json
{
  "pageNum": 1,
  "pageSize": 10,
  "toolId": "工具ID（可选）",
  "reportBy": "举报人ID（可选）",
  "status": ["0", "1", "2"]
}
```

**响应字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| reportByName | string | 举报人姓名（通过用户表查询） |
| slaDeadline | string | SLA 截止时间 |
| slaExpired | string | 是否已超时自动下架：0=否, 1=是 |

## 7. 配置项

| 配置键 | 默认值 | 说明 |
|--------|--------|------|
| `tool.report.sla-hours` | 72 | SLA 时长（小时），可在 Apollo 动态调整。调整后仅影响新提交的举报 |

## 8. 日志

### 8.1 操作日志

通过 `@LogApi` 注解记录，日志表名 `LOG_TOOL`：

| 操作类型 | 操作描述 | 触发方法 |
|----------|----------|----------|
| REPORT_TOOL | 举报工具 | submitReport |
| REVIEW_TOOL_REPORT | 核实举报 | reviewReport |
| ACTIVATE_TOOL | 激活工具 | activateTool |

### 8.2 业务日志

关键节点通过 SLF4J 记录 `LOGGER.info/warn/error` 日志，包括：
- 收到工具举报
- 举报记录创建
- 开始核实举报
- 核实结果（属实/不属实及对应操作）
- 工具上下架操作
- SLA 超时自动下架
- 权限校验失败
- 通知发送失败

---

## 9. 错误码

| 错误消息 | 触发场景 |
|----------|----------|
| 工具ID不能为空 | submitReport 或 activateTool 中 toolId 未传 |
| 举报内容不能为空 | submitReport 中 reportContent 未传 |
| 工具不存在 | 传入的 toolId 无效 |
| 工具版本不存在 | 传入的 versionId 无效 |
| 版本不属于该工具 | versionId 与 toolId 不匹配 |
| 该工具已举报，审核中 | 同一工具存在待核实的举报 |
| 举报记录ID不能为空 | reviewReport 中 reportId 未传 |
| 核实状态不能为空 | reviewReport 中 status 未传 |
| 举报记录不存在 | reportId 无效 |
| 该举报已核实完成，不能重复核实 | 举报记录 status 已非 0 |
| 您不是该工具归属项目的工具管理者，无权操作 | 操作用户无 PROJECT_TOOL_MANAGER 权限 |
| 有效标识不能为空 | activateTool 中 validFlag 未传 |
| 保存举报信息失败 | 举报记录入库失败 |

---

## 10. 限制与约束

| 约束项 | 说明 |
|--------|------|
| 重复举报 | 同一工具存在待核实的举报时，不允许再次提交 |
| SLA 不可变 | 已存在的举报记录 SLA 截止时间不随配置动态调整 |
| 不可重复核实 | 已核实（status ≠ 0）的举报记录不可再次核实 |
| 单条隔离 | SLA 定时任务单条处理失败不影响其他记录 |
