# 蓝区自建插件 GitHub & GitCode 使用运营看板

## 需求背景

openLiBing 生态对外提供的「GitHub 自建插件」与「GitCode 自建插件」当前缺少统一运营度量能力：插件安装数、活跃数、调用次数、错误率等关键运营指标分散在各自渠道，运营与社区维护人员无法快速感知插件推广效果与使用情况。

本需求在 openlibing-framework 仓建设蓝区自建插件的统一运营度量能力：上报侧兼容 GitHub 与 GitCode 两个渠道的数据上报，看板侧提供统一的指标聚合与查询接口，支撑运营人员日常运营决策。

## 功能描述

### 做什么

1. **统一上报入口**：建设支持 GitHub 与 GitCode 两个渠道的插件使用数据上报接口（安装、卸载、调用、错误等事件）。
2. **指标聚合层**：按渠道 / 时间维度聚合安装数、活跃数、调用次数、错误率等指标，提供查询接口。
3. **看板接口**：提供运营看板数据查询接口（按渠道、时间范围、指标类型聚合返回）。

### 不做什么

1. 不实现前端看板页面布局（仅提供后端聚合接口）。
2. 不接入第三方平台原始数据采集（依赖调用方按契约上报）。
3. 不重构既有插件管理能力（仅新增使用度量）。

## 验收标准

- [x] 支持 GitHub 与 GitCode 两个渠道的插件使用数据上报
- [x] 支持按渠道 / 时间维度 / 指标类型的聚合查询
- [x] 上报数据校验通过，编译与单测通过
- [x] PR 合入 `release_20260923_iter2` 分支

## 影响范围

- **openlibing-framework**：新增插件使用度量的 Entity / DTO / Service / Controller / Mapper XML（具体类名以上线代码为准）
- **数据库**：新增插件使用度量数据表（Liquibase changelog）
- **上游**：调用方按契约上报数据；运营前端对接看板接口
