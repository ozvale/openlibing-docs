# 技术方案设计

## 方案概述

本需求主要涉及工具管理模块的功能增强，包括工具使用申请版本详情展示、待办中心新增工具申请模块、工具举报优化三个部分。技术实现上主要是前端页面的调整和交互逻辑优化，部分功能可能需要后端接口支持。

## 详细设计

### 1. 工具使用申请版本详情展示

#### 实现方式

- 在工具使用申请成功页面增加版本申请情况的展示区域
- 调用后端接口获取申请详情和审核状态
- 在工具详情页面增加审核中状态的标识

#### 涉及文件

- `apps/web-openlibing/src/views/ToolManagement/**/*.vue` - 工具管理相关组件
- 可能涉及API调用和数据展示逻辑的调整

#### 技术细节

1. **版本申请情况展示**
   - 在申请成功页面增加卡片或表格展示版本信息
   - 显示工具名称、版本号、申请时间、审核状态等关键信息
   - 支持点击查看申请详情

2. **审核中状态标识**
   - 在工具详情页面的版本列表中增加审核中状态的标识
   - 使用明显的样式（如颜色、图标）突出显示
   - 提供申请进度的简要说明

### 2. 待办中心-工具创建申请模块

#### 实现方式

- 在待办中心页面新增工具创建申请tab或模块
- 实现我的申请、待我审批、审批历史三个子模块
- 设计表格展示和操作列，支持审批流程

#### 涉及文件

- `apps/web-openlibing/src/views/ToDoCenter/**/*.vue` - 待办中心相关组件
- 新建 `ToolCreateApplication.vue`、`ToolCreateReview.vue`、`ToolCreateReviewHistory.vue` 等组件

#### 技术细节

1. **我的申请模块**
   - 表格列：工具名称、版本号、所属项目、申请时间、审核结果、审核说明、审核时间、操作列

   - 支持按审核结果筛选和搜索

2. **待我审批模块**
   - 表格列：申请人、工具名称、版本号、所属项目、申请时间、操作列
   - 操作列：支持审批和跳转到我的工具-我的待办模块
   - 显示待审批数量提示

3. **审批历史模块**
   - 表格列：申请人、工具名称、版本号、所属项目、申请时间、审核结果、审核说明、审核时间、操作列
   - 操作列：支持查看详情和跳转到我的工具-我已审批模块

### 4. 工具举报优化

#### 实现方式

- 优化举报按钮的样式和位置
- 改进举报弹窗的交互流程和提示信息
- 增加举报成功后的反馈

#### 涉及文件

- `apps/web-openlibing/src/views/ToolManagement/**/*.vue` - 工具管理相关组件

#### 技术细节

1. **举报入口优化**
   - 调整举报按钮的样式，使其更易识别
   - 优化举报入口的位置，方便用户操作

2. **举报流程优化**
   - 简化举报表单，减少不必要的填写项
   - 增加举报原因的选项，提高举报效率
   - 优化提示信息，引导用户正确填写

3. **举报反馈**
   - 增加举报成功的明确提示
   - 显示举报处理的大致流程和时间

## 影响范围分析

### 前端影响

- 工具使用申请成功页面布局调整
- 待办中心页面结构扩展，新增两个模块
- 工具举报功能交互优化
- 可能涉及路由配置的调整

### 后端影响

- 可能需要新增工具创建申请和使用申请相关的API接口
- 可能需要调整现有的审批流程接口

### 兼容性影响

- 本次改动向前兼容，不影响现有功能
- 新增模块为独立功能，不影响现有待办中心模块

## 技术约束

1. 前端改动需遵循项目现有的编码规范和组件设计模式
2. 使用Element Plus组件库，保持UI风格一致
3. 待办中心模块需与现有模块保持一致的交互风格

## 风险评估

### 低风险

- 工具使用申请版本详情展示：纯展示型改动，风险极低
- 工具举报优化：交互优化，风险较低

### 中风险

- 待办中心新增模块：涉及多个新组件和接口对接，需要充分测试

### 风险应对

- 充分测试新增模块的各种场景，确保功能完整性和稳定性
- 与后端开发人员密切配合，确保接口设计和对接的正确性
- 进行用户测试，验证功能设计的合理性
