## ADDED Requirements

### Requirement: 平台列表头筛选

屏蔽规则管理表格必须在**平台**（`platform`）列提供表头筛选，且筛选项固定为 `gitcode` 与 `gitee` 两个静态选项。用户必须能够多选平台并应用筛选，且不得为此发起服务端请求。

#### Scenario: 按单个平台筛选

- **WHEN** 用户打开平台列筛选，选择 `gitee` 并点击「筛选」
- **THEN** 表格仅展示 `platform` 等于 `gitee` 的行
- **AND** 分页总数反映筛选后的行数

#### Scenario: 按多个平台筛选

- **WHEN** 用户同时选择 `gitcode` 和 `gitee` 并应用筛选
- **THEN** 表格展示 `platform` 为上述任一值的行

#### Scenario: 重置平台筛选

- **WHEN** 用户在平台列筛选中点击「重置」
- **THEN** 平台筛选条件被清空
- **AND** 在不受其他筛选约束的前提下，所有行重新展示

### Requirement: 供应商列表头筛选（数据来源于表格）

屏蔽规则管理表格必须在**供应商**（`vendor`）列提供表头筛选。筛选项必须从已加载的全量数据集（`tableDatas`）中对非空 `vendor` 值去重生成，不得从当前页切片数据中提取。

#### Scenario: 供应商选项反映已加载数据

- **WHEN** 屏蔽规则列表接口返回包含供应商 A、B、C 的行
- **THEN** 供应商列筛选展示 A、B、C 作为可选选项

#### Scenario: 按供应商选择筛选

- **WHEN** 用户选择一个或多个供应商并应用筛选
- **THEN** 仅展示 `vendor` 属于所选集合的行
- **AND** 列表接口请求不得携带用于列筛选的 `vendor` 查询参数

### Requirement: 组件名称列表头筛选（数据来源于表格）

屏蔽规则管理表格必须在**组件名称**（`shieldRole`）列提供表头筛选。筛选项必须从已加载全量数据中对非空 `shieldRole` 值去重生成。

#### Scenario: 组件名称选项反映已加载数据

- **WHEN** 屏蔽规则列表接口返回组件名称 X 和 Y
- **THEN** 组件名称列筛选展示 X 和 Y 作为可选选项

#### Scenario: 按组件名称筛选

- **WHEN** 用户选择组件名称并应用筛选
- **THEN** 仅展示 `shieldRole` 与所选值匹配的行

### Requirement: 创建时间列前端排序

**创建时间**（`created`）列必须支持前端升序/降序切换，且不得修改后端。排序必须在分页切片之前作用于已筛选的数据集。

#### Scenario: 创建时间降序排序

- **WHEN** 用户对创建时间列执行降序排序
- **THEN** 所有已筛选行按 `created` 排序，最新记录在前
- **AND** 第 1 页展示排序后列表的首段切片

#### Scenario: 创建时间升序排序

- **WHEN** 用户对创建时间列执行升序排序
- **THEN** 行按 `created` 排序，`created` 最早的记录在前

#### Scenario: 排序与筛选联动

- **WHEN** 平台或供应商筛选处于激活状态，且用户变更排序顺序
- **THEN** 仅对已筛选行进行排序和分页

### Requirement: 移除顶部供应商自动完成搜索

页面不得展示顶部的**供应商名称** `el-autocomplete` 搜索控件。供应商筛选能力必须仅通过供应商列表头筛选提供。

#### Scenario: 自动完成搜索已移除

- **WHEN** 用户查看屏蔽规则管理页面
- **THEN** 表格头部工具栏中不出现供应商名称自动完成输入框

#### Scenario: 列表接口不再用 vendor 参数做列筛选

- **WHEN** 本变更后加载屏蔽规则列表
- **THEN** 请求不得为用户的列筛选携带 `vendor` 参数
- **AND** 供应商筛选仅在前端执行

### Requirement: 上下文切换时重置筛选与排序状态

当用户切换社区或仓库选择时，表格必须将列筛选、排序状态及分页重置为默认值。

#### Scenario: 切换仓库时重置

- **WHEN** 用户选择其他仓库或清空仓库选择
- **THEN** 所有列筛选条件被清空
- **AND** 排序恢复默认状态
- **AND** 页码重置为第 1 页

### Requirement: 筛选与分页组合流水线

表格必须按以下顺序处理数据：先应用所有激活的列筛选，再应用排序，最后按当前页进行切片分页。

#### Scenario: 多列筛选组合

- **WHEN** 用户将平台筛选为 `gitee`，并将供应商筛选为某一特定供应商
- **THEN** 仅同时满足两个条件的行参与排序与分页

#### Scenario: 分页总数反映筛选后条数

- **WHEN** 筛选将数据集从 50 行缩减为 12 行
- **THEN** 分页总数显示为 12
- **AND** 各页切片基于这 12 行计算

### Requirement: 分页器与父组件页码同步

分页器的当前页码与每页条数必须与父组件 `pageNum`、`pageSize` 保持同步。子组件不得单独维护与父组件脱钩的页码状态。

#### Scenario: 筛选后分页器回到第 1 页

- **WHEN** 用户在第 2 页或更后页码应用列筛选或变更排序
- **THEN** 父组件将 `pageNum` 重置为 1
- **AND** 分页器 UI 同步显示第 1 页
- **AND** 表格展示筛选/排序后数据的第 1 页切片

#### Scenario: 筛选后当前页超出范围时校正页码

- **WHEN** 用户位于第 3 页，筛选后总条数不足以支撑第 3 页
- **THEN** 系统自动将 `pageNum` 校正为不超过筛选后最大页码的有效页
- **AND** 表格展示校正后页码对应的数据，不得出现空白页

#### Scenario: 用户点击分页切换页码

- **WHEN** 用户在分页器上切换页码或每页条数
- **THEN** 父组件 `pageNum`、`pageSize` 更新
- **AND** 分页器显示与父组件状态一致

### Requirement: 列头筛选图标激活态展示

当某列存在激活的筛选条件时，该列表头筛选图标必须呈现激活样式（高亮）。实现不得修改 `@/components/filterDropdown.vue`。

#### Scenario: 应用筛选后图标高亮

- **WHEN** 用户对平台、供应商或组件名称列应用筛选且 `tableFilters` 中对应列有值
- **THEN** 该列表头筛选图标以激活色（如 `#409eff`）展示

#### Scenario: 重置或切换上下文后图标恢复默认

- **WHEN** 用户重置该列筛选，或切换社区/仓库导致 `tableFilters` 清空
- **THEN** 对应列筛选图标恢复为非激活样式

### Requirement: 无动态选项时不展示供应商/组件名称筛选

当全量数据中不存在可去重的 `vendor` 或 `shieldRole` 值时，对应列不得展示表头筛选控件，以避免空选项触发无效加载。

#### Scenario: 无供应商数据时不展示供应商筛选

- **WHEN** 已加载的 `tableDatas` 中所有行的 `vendor` 均为空
- **THEN** 供应商列不展示 `filterDropdown` 表头筛选

#### Scenario: 有供应商数据时展示筛选

- **WHEN** 已加载数据包含至少一个非空 `vendor`
- **THEN** 供应商列展示表头筛选，选项为去重后的供应商列表
