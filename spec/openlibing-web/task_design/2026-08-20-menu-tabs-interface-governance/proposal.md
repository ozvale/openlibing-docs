# 需求背景

## 业务场景

菜单管理页面原为单一菜单树管理页面，仅承担菜单的增删改查职责。随着接口治理能力（接口下线治理、接口用途分类、访问白名单管理、误报处理）的引入，需要在菜单管理页面承载更多接口治理相关的管理能力，为研发流程平台的接口安全治理提供统一入口。

## 问题痛点

1. **页面职责膨胀**：接口治理相关功能若继续平铺在菜单管理单页内，会导致单文件代码量过大、维护困难
2. **接口治理能力分散**：已下线接口确认、接口用途/类型分类、访问白名单维护、误报撤销等能力缺少统一管理入口
3. **URL 配置体验不足**：菜单新增/修改弹窗中 URL 地址为纯手输，无法远程模糊检索已有接口地址，也无法对特殊地址（flag=1）进行红色标识提示

## 需求目标

1. 菜单管理页面整改为 tabs 形式，共 5 个 tab：菜单、已下线接口、接口列表、访问白名单接口、误报接口
2. 各 tab 内容拆分为独立子组件，控制单文件代码规模
3. 已下线接口：分页表格 + URL 模糊查询 + 删除/确认误报/撤销误报操作
4. 接口列表：分页表格 + URL 模糊查询 + 接口用途/类型下拉过滤 + 修改弹窗（类型单选必填）+ 手动同步
5. 访问白名单接口：分页表格 + URL 模糊查询 + 新增/修改/删除（三项白名单是/否单选）
6. 误报接口：分页表格 + URL 模糊查询 + 撤销误报操作
7. 菜单 tab 的 URL 配置改为远程模糊过滤下拉，flag=1 时地址值红色回显

## 验收标准

### 功能验收

1. **tabs 改造**
   - 菜单管理页展示 5 个 tab，切换正常，各 tab 懒加载
   - 菜单 tab 保留原有菜单树增删改查能力

2. **已下线接口 tab**
   - 分页、请求 URL 模糊查询过滤生效
   - 操作列按 flag 区分显示撤销误报（flag=1）/确认误报（其他）按钮，均调对应接口
   - 删除按钮调删除接口

3. **接口列表 tab**
   - 分页、请求 URL 模糊查询、接口用途/类型下拉过滤生效
   - 表格列：代码仓、请求方式、请求URL、接口用途/类型、操作
   - 修改弹窗含接口用途/类型单选（必填，7 个选项值），确定调保存接口、取消关闭
   - 手动同步按钮调同步接口

4. **访问白名单接口 tab**
   - 分页、请求 URL 模糊查询生效
   - 新增弹窗含请求方式、请求URL输入 + 三项白名单是/否单选；修改时请求方式/URL 不可编辑
   - 删除按钮执行删除操作

5. **误报接口 tab**
   - 分页、请求 URL 模糊查询生效
   - 操作列撤销误报按钮调撤销误报接口

6. **URL 配置优化**
   - 新增/修改弹窗 URL 地址为下拉选，支持远程模糊过滤调接口取值
   - 修改回显时 flag=1 的地址值显示为红色

### 非功能验收

1. 各 tab 拆分为独立子组件，主文件代码规模可控
2. 不影响现有菜单管理功能的稳定性
3. 代码变更符合项目编码规范
