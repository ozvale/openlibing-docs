# Proposal: 项目名称变更与项目漏洞相关配置

## 需求背景

项目管理模块当前不支持项目名称修改（编辑弹窗中名称输入框 disabled，`updateProject` payload 不含 `projectName`）；新增/修改项目表单中「对接漏洞视图」配置项曾被开发过但因后端未就绪被注释（`projectAddEditForm.vue` L53-58 注释代码，payload 仍提交 `isCve` 字段）；项目管理列表缺少「是否对接华为云项目 / 是否对接代码托管平台 / 是否对接漏洞视图」三个状态列；漏洞视图配置页缺少社区相关配置入口。本次需完整落地这四项能力。

## 功能描述

### 1. 新增/修改项目表单扩展「对接漏洞视图」

- 表单（`projectAddEditForm.vue`，create/edit 复用）恢复并正式启用「对接漏洞视图」radio（是=1 / 否=0），与既有「对接华为云项目」「对接代码托管平台」radio 交互样式一致，**默认选中「否」（isCve='0'），无必填符号、不做非空校验**
- 提交时 `isCve` 正确传入 `addProject` / `updateProject` payload（现有 payload 已含该字段）

### 2. 项目管理列表新增 3 个状态列

- 「项目名称」列之后新增：「是否对接华为云项目」（isHwProject）、「是否对接代码托管平台」（isHaveCommonAccount）、「是否对接漏洞视图」（isCve）
- 字段值 1 展示「是」、0 展示「否」，不涉及筛选/排序/分页/导出能力

### 3. 项目名称修改功能

- 独立编辑弹窗：仅项目名称输入框 + 确认/取消按钮
- 校验：非空、长度限制、项目名称重复校验
- 修改入口采用**操作列图标按钮**方案（见 design.md 方案对比）
- 独立权限标识，校验逻辑与项目管理现有操作（NoPermissionPopover + canHandle）完全一致，无权限不可见入口

### 4. 漏洞视图「社区适配」内新增「社区配置」二级页签

- 进入漏洞视图菜单「配置」页 →「社区适配」（adaptation）左侧二级页签末尾新增「社区配置」
- 含 3 个配置项：gitee 组织名称、gitee 企业名称、接入漏洞的库表社区名称，均为标准 input
- 查看态/编辑态交互、校验、保存后实时生效，完全复用「社区适配」页签内既有配置项模式

## 验收标准

- [ ] 新增项目：「对接漏洞视图」默认选中「否」且无必填符号；切换是/否后提交 payload `isCve=1/0` 正确
- [ ] 修改项目：表单回填当前 `isCve` 值，可修改并正确提交
- [ ] 项目管理列表：项目名称列后展示 3 个新列，值 1/0 分别渲染「是」「否」，树形展开子行正常
- [ ] 有权限用户在操作列可见「修改名称」图标入口；无权限用户不可见（NoPermissionPopover 提示）
- [ ] 修改名称弹窗：空值/超长/重复名称均被拦截并提示；合法修改保存后列表名称实时更新
- [ ] 漏洞视图「配置」→「社区适配」二级页签末尾出现「社区配置」，3 个配置项支持查看/编辑/保存，保存后配置实时生效，交互样式与该页签内既有配置项一致
- [ ] lint 通过，无本次改动引入的类型错误
