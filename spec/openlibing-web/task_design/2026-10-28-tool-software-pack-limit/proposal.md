# 需求背景

## 业务场景

工具管理 → 我的工具 → 新建/编辑工具（`toolItem.vue`）时，用户需要上传工具软件包（zip 压缩包）。前端对压缩包做格式、大小校验，并通过分片方式上传，分片大小由前端硬编码决定。

## 问题痛点

1. **限制硬编码**：软件包大小上限固定写死为 5G，分片大小固定写死为 5MB，提示文案同样写死，无法随部署环境调整。
2. **前后端不一致**：不同部署环境（公有云/私有化）后端允许的软件包大小与分片策略不同，前端硬编码的限制会导致"前端放行、后端拒绝"或"前端误拦截"。
3. **调整成本高**：每次调整限制都需要前端发版，运维侧无法通过配置生效。

## 需求目标

工具管理软件包上传的大小限制与分片大小改为通过后端接口动态获取，接口不可用时使用合理兜底值，保证上传流程可用。

## 验收标准

### 功能验收

1. **限制动态获取**
   - 打开新建/编辑工具弹窗时调用 `GET /tool-apply/get-software-pack-size-limit` 获取 `maxSizeMb`、`maxSizeDesc`、`chunkSizeMb`
   - 上传提示文案展示为"点击选择文件，仅允许上传一个zip格式压缩包，且大小不超过`{maxSizeDesc}`"
2. **大小校验使用接口值**
   - 选择文件后按 `maxSizeMb` 做大小校验，超限提示"文件大小不能超过 `{maxSizeDesc}`！"
   - 非 zip 文件仍提示"只能上传zip压缩包！"并清空文件列表
3. **分片上传使用接口值**
   - 分片大小按 `chunkSizeMb * 1024 * 1024` 计算，分片总数与上传流程保持正常
4. **兜底逻辑**
   - 接口返回非 200、`data` 为空或字段缺失时，使用默认值：`maxSizeMb = 500`、`maxSizeDesc = "500MB"`、`chunkSizeMb = 5`

### 非功能验收

1. 不改变软件包上传的接口地址、请求参数与上传流程
2. 不改变"未填写工具名称/版本名称/操作系统/版本号时禁止上传"的既有约束
3. 代码变更符合项目编码规范，通过 ESLint / pre-commit 检查
