## Purpose

定义发布评审单创建者在评审详情页发起回撤操作的门控条件、调用契约、成功与失败后的可观察行为，以及回撤入口的 UI 位置规则。

## ADDED Requirements

### Requirement: 回撤按钮的显示门控

评审详情页的"基本信息"分区标题右侧 MUST 显示一个"回撤"操作入口，当且仅当同时满足以下两个条件时可见：

1. 评审单当前状态不是"新建"状态。
2. 当前登录用户是该评审单的创建者。

只要任一条件不满足，回撤入口 MUST 不可见。

#### Scenario: 非"新建"状态且当前用户是创建者

- **WHEN** 评审单状态不为"新建"且当前登录用户的用户标识等于评审单的创建者标识
- **THEN** "基本信息"分区标题右侧显示"回撤"按钮

#### Scenario: "新建"状态

- **WHEN** 评审单状态为"新建"（无论当前用户是否为创建者）
- **THEN** "回撤"按钮不显示

#### Scenario: 当前用户不是创建者

- **WHEN** 当前登录用户的用户标识不等于评审单的创建者标识（无论评审单状态如何）
- **THEN** "回撤"按钮不显示

### Requirement: 回撤按钮的位置与对齐

"回撤"按钮 MUST 出现在评审详情页"基本信息"分区标题的右侧，并相对该标题容器靠右对齐。按钮与标题内容 MUST 在同一水平行上，不换行。

#### Scenario: 按钮位置

- **WHEN** 回撤按钮满足显示条件被渲染
- **THEN** 按钮位于"基本信息"分区标题行的右侧，与标题文字基线对齐，按钮相对标题容器右边缘对齐

### Requirement: 回撤操作调用契约

点击"回撤"按钮时，前端 MUST 调用后端回撤接口，请求方法为 `POST`，请求参数通过 query string 传递，包含以下字段：

- `projectId`：当前项目标识（来自应用上下文）
- `userId`：当前登录用户的用户标识
- `id`：当前评审单的标识

请求进行中时，按钮 MUST 进入加载状态并禁止重复点击。

#### Scenario: 发起回撤请求

- **WHEN** 用户点击"回撤"按钮
- **THEN** 前端以 `POST` 方法调用回撤接口，query 参数包含 `projectId`、`userId`、`id`，按钮进入 loading 状态并禁用

#### Scenario: 请求中禁止重复点击

- **WHEN** 回撤请求正在进行中
- **THEN** "回撤"按钮保持 loading 状态且不可再次点击，直到本次请求结束

### Requirement: 回撤成功后刷新数据

回撤接口调用成功后（HTTP 响应中业务码表示成功），前端 MUST 重新拉取当前评审单的完整详情数据，使页面呈现的状态、字段、操作区与回撤后的后端真实状态一致。

#### Scenario: 回撤成功

- **WHEN** 回撤接口返回成功业务码
- **THEN** 前端重新请求评审单详情数据并刷新页面展示，按钮 loading 状态结束，回撤后的评审单状态反映为"新建"（若后端确实将其回退）

### Requirement: 回撤失败的处理

回撤接口调用失败时（网络错误或业务码表示失败），前端 MUST 向用户展示失败提示，且 MUST NOT 刷新评审单数据（保持回撤前的页面状态），按钮 loading 状态结束并恢复可点击。

#### Scenario: 回撤接口返回失败

- **WHEN** 回撤接口返回的响应中业务码表示失败
- **THEN** 前端向用户展示失败提示消息，不刷新评审单数据，按钮结束 loading 状态并恢复可点击

#### Scenario: 回撤请求网络异常

- **WHEN** 回撤请求发生网络异常或未收到响应
- **THEN** 前端向用户展示失败提示消息，不刷新评审单数据，按钮结束 loading 状态并恢复可点击
