## Purpose

定义发布评审详情页底部"操作历史"模块的显示规则、可折叠头行为、分页表格的列契约，以及通过分页接口获取评审单操作记录的调用时机与可观察行为，使详情页用户在不跳转、不弹窗的情况下即可追溯评审单的操作轨迹。

## ADDED Requirements

### Requirement: 操作历史模块的显示

发布评审详情页底部 MUST 显示一个"操作历史"模块，模块结构与详情页已有的"基本信息""制品信息"等模块一致（可折叠头 + 内容区）。模块头标题 MUST 为"操作历史"，默认展开。模块对能够查看该评审详情的所有用户可见，不依赖额外权限。

#### Scenario: 进入详情页展示操作历史模块

- **WHEN** 用户打开发布评审详情页，且详情数据加载成功
- **THEN** 页面底部展示"操作历史"模块，模块头标题为"操作历史"，内容区展示操作历史分页表格

#### Scenario: 折叠与展开操作历史模块

- **WHEN** 用户点击"操作历史"模块头
- **THEN** 模块内容区在展开与折叠状态间切换，与详情页其他模块的折叠行为一致，不影响其他模块状态

#### Scenario: 复制评审场景加载操作历史

- **WHEN** 用户通过"复制"新建评审单进入详情页，后端在复制时已创建新评审记录、分配 `reviewId` 并记录一条"新建"操作
- **THEN** 操作历史模块正常发起第一页请求，表格展示该新评审单的操作历史，首条记录为"新建"操作

### Requirement: 操作历史表格的列定义

操作历史模块内的表格 MUST 包含以下三列，列的数据字段分别对应接口返回数据中的指定字段：

| 列标题   | 数据字段        | 渲染类型           |
| -------- | --------------- | ------------------ |
| 操作名称 | `operationName` | 文本               |
| 操作人   | `operatorName`  | 文本               |
| 操作时间 | `operationTime` | 日期（带日历图标） |

#### Scenario: 表格列渲染

- **WHEN** 模块内成功获取操作历史数据且列表非空
- **THEN** 表格按序展示"操作名称""操作人""操作时间"三列，每行数据从接口返回列表项的对应字段取值；操作时间列以日期类型渲染（带日历图标，与详情页其他日期列风格一致）

#### Scenario: 空字段占位

- **WHEN** 某行某字段值为空或未定义
- **THEN** 该单元格展示"--"占位，与详情页其他表格的空值占位规则一致

### Requirement: 操作历史分页接口调用契约

模块数据加载及分页切换时，前端 MUST 调用 `POST /base/queryReviewHistoryPage` 接口获取分页数据。请求 query 参数 MUST 包含 `projectId`（当前项目标识）与 `userId`（当前登录用户标识）。请求 body MUST 包含 `reviewId`（当前评审单标识）、`pageNum`（页码，从 1 开始）、`pageSize`（每页条数）。

#### Scenario: 详情首次加载请求数据

- **WHEN** 详情数据加载成功且存在有效 `reviewId`（响应 `data.id` 或 URL query 中存在 `reviewId`）
- **THEN** 前端以 `POST` 方法调用 `/base/queryReviewHistoryPage`，query 参数含 `projectId` 与 `userId`，body 含 `reviewId`、`pageNum=1`、`pageSize=10`（默认每页条数）

#### Scenario: 切换页码

- **WHEN** 用户在操作历史表格分页器中点击下一页或指定页码
- **THEN** 前端以新的 `pageNum` 值重新调用 `/base/queryReviewHistoryPage`，其他参数保持不变，表格进入加载状态直到新数据返回

#### Scenario: 切换每页条数

- **WHEN** 用户在操作历史表格分页器中切换每页条数
- **THEN** 前端将 `pageNum` 重置为 1，以新的 `pageSize` 值重新调用接口，表格刷新为第一页数据

### Requirement: 状态变更操作后刷新操作历史

当用户在详情页完成以下任一状态变更操作并收到成功响应后，前端 MUST 将操作历史分页重置到第一页并重新拉取数据：保存评审、发起评审、撤回评审、发布决策（同意发布）、发布漏洞公告。

#### Scenario: 保存评审后刷新

- **WHEN** 用户点击"保存"并收到成功响应（业务码 200）
- **THEN** 操作历史分页重置为 `pageNum=1`，重新调用接口刷新操作历史列表

#### Scenario: 发起评审后刷新

- **WHEN** 用户点击"发起评审"并收到成功响应
- **THEN** 操作历史分页重置为 `pageNum=1`，重新调用接口刷新操作历史列表

#### Scenario: 撤回评审后刷新

- **WHEN** 用户确认撤回并收到成功响应
- **THEN** 操作历史分页重置为 `pageNum=1`，重新调用接口刷新操作历史列表

#### Scenario: 发布决策后刷新

- **WHEN** 用户点击"同意发布"并收到成功响应
- **THEN** 操作历史分页重置为 `pageNum=1`，重新调用接口刷新操作历史列表

#### Scenario: 发布漏洞公告后刷新

- **WHEN** 用户点击"发布公告"并收到成功响应
- **THEN** 操作历史分页重置为 `pageNum=1`，重新调用接口刷新操作历史列表

### Requirement: 与状态轮询解耦

详情页存在的 20s 状态轮询（用于刷新发布/扫描状态）MUST NOT 触发操作历史请求。操作历史仅在首次详情加载、状态变更操作成功后、分页切换时请求，不随状态轮询重复请求。

#### Scenario: 状态轮询不拉取操作历史

- **WHEN** 详情页处于状态轮询中（`reviewStatus` 为发布中等执行态触发 20s 定时器），定时器触发详情数据刷新
- **THEN** 详情数据刷新但操作历史不重新请求，操作历史表格保持当前已加载的数据与分页状态

### Requirement: 分页数据的渲染

接口成功返回后，前端 MUST 将响应中的列表数据渲染到表格，并将响应中的总条数同步到分页器。当总条数为 0 时，表格展示空状态占位。

#### Scenario: 有数据时渲染列表与分页

- **WHEN** 接口返回成功业务码且列表数据非空
- **THEN** 表格渲染列表数据行，分页器展示总条数，当前页码与每页条数反映请求时使用的值

#### Scenario: 无数据时展示空状态

- **WHEN** 接口返回成功业务码且列表数据为空或总条数为 0
- **THEN** 表格展示空状态占位，分页器不展示（或总条数为 0）

### Requirement: 操作历史请求失败的处理

接口调用失败（网络错误或业务码表示失败）时，前端 MUST 向用户展示失败提示，表格数据清空，分页器总条数置为 0，不阻塞详情页其他功能。

#### Scenario: 接口返回失败业务码

- **WHEN** 接口返回的响应中业务码表示失败
- **THEN** 前端向用户展示失败提示消息，操作历史表格数据为空，分页器总条数为 0，详情页其他模块不受影响

#### Scenario: 请求网络异常

- **WHEN** 操作历史请求发生网络异常或未收到响应
- **THEN** 前端向用户展示失败提示消息，操作历史表格数据为空，分页器总条数为 0，详情页其他模块不受影响
