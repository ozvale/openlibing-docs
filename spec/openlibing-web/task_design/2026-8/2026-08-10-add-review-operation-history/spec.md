## Purpose

定义发布评审列表操作列中"操作历史"入口的显示规则、弹窗结构、分页表格的列契约，以及通过分页接口获取评审单操作记录的调用契约与可观察行为。

## ADDED Requirements

### Requirement: 操作历史入口的显示

发布评审列表的操作列中 MUST 显示一个"操作历史"操作入口（图标按钮），该入口对拥有 `platform_release_base` 权限的用户可见。入口与操作列中已有的"复制"、"评审历史"、"删除"等图标并列展示。

#### Scenario: 拥有权限时显示入口

- **WHEN** 当前用户拥有 `platform_release_base` 权限
- **THEN** 评审列表每行操作列显示"操作历史"图标按钮，鼠标悬停时显示"操作历史"文字提示

#### Scenario: 无权限时不显示入口

- **WHEN** 当前用户不拥有 `platform_release_base` 权限
- **THEN** 评审列表操作列不显示"操作历史"图标按钮

### Requirement: 操作历史弹窗的打开

点击"操作历史"图标按钮时 MUST 打开一个弹窗，弹窗标题为"操作历史"。弹窗内渲染一个分页表格，表格展示当前点击行对应评审单的操作记录。弹窗打开时 MUST 立即发起第一页数据请求。

#### Scenario: 点击按钮打开弹窗

- **WHEN** 用户点击某行操作列的"操作历史"图标按钮
- **THEN** 打开标题为"操作历史"的弹窗，弹窗内表格进入加载状态并立即请求该评审单第一页操作历史数据

#### Scenario: 关闭弹窗

- **WHEN** 用户点击弹窗关闭按钮或遮罩层
- **THEN** 弹窗关闭，弹窗内表格数据与分页状态清空，不影响评审列表数据

### Requirement: 操作历史表格的列定义

操作历史弹窗内的表格 MUST 包含以下三列，列的数据字段分别对应接口返回数据中的指定字段：

| 列标题 | 数据字段 |
| --- | --- |
| 操作人 | `operator_name` |
| 操作名称 | `operation_name` |
| 操作时间 | `operation_time` |

#### Scenario: 表格列渲染

- **WHEN** 弹窗打开并成功获取操作历史数据
- **THEN** 表格按序展示"操作人"、"操作名称"、"操作时间"三列，每行数据从接口返回列表项的对应字段取值

### Requirement: 操作历史分页接口调用契约

弹窗打开及分页切换时，前端 MUST 调用 `POST /base/queryReviewHistoryPage` 接口获取分页数据。请求 query 参数 MUST 包含 `projectId`（当前项目标识）和 `userId`（当前登录用户标识）。请求 body MUST 包含 `reviewId`（当前评审单标识）、`pageNum`（页码，从 1 开始）、`pageSize`（每页条数）。

#### Scenario: 首次打开弹窗请求数据

- **WHEN** 用户点击"操作历史"按钮打开弹窗
- **THEN** 前端以 `POST` 方法调用 `/base/queryReviewHistoryPage`，query 参数含 `projectId` 与 `userId`，body 含 `reviewId`、`pageNum=1`、`pageSize=10`（默认每页条数）

#### Scenario: 切换页码

- **WHEN** 用户在弹窗表格分页器中点击下一页或指定页码
- **THEN** 前端以新的 `pageNum` 值重新调用 `/base/queryReviewHistoryPage`，其他参数保持不变，表格进入加载状态直到新数据返回

#### Scenario: 切换每页条数

- **WHEN** 用户在弹窗表格分页器中切换每页条数
- **THEN** 前端将 `pageNum` 重置为 1，以新的 `pageSize` 值重新调用接口，表格刷新为第一页数据

### Requirement: 分页数据的渲染

接口成功返回后，前端 MUST 将响应中的列表数据渲染到表格，并将响应中的总条数同步到分页器。当总条数为 0 时，表格展示空状态。

#### Scenario: 有数据时渲染列表与分页

- **WHEN** 接口返回成功业务码且列表数据非空
- **THEN** 表格渲染列表数据行，分页器展示总条数，当前页码与每页条数反映请求时使用的值

#### Scenario: 无数据时展示空状态

- **WHEN** 接口返回成功业务码且列表数据为空或总条数为 0
- **THEN** 表格展示空状态占位，分页器不展示（或总条数为 0）

### Requirement: 操作历史请求失败的处理

接口调用失败（网络错误或业务码表示失败）时，前端 MUST 向用户展示失败提示，表格数据清空或保持为空，分页器总条数置为 0，不阻塞弹窗（用户可关闭弹窗后重新打开）。

#### Scenario: 接口返回失败业务码

- **WHEN** 接口返回的响应中业务码表示失败
- **THEN** 前端向用户展示失败提示消息，表格数据为空，分页器总条数为 0

#### Scenario: 请求网络异常

- **WHEN** 请求发生网络异常或未收到响应
- **THEN** 前端向用户展示失败提示消息，表格数据为空，分页器总条数为 0
