# 【openlibing-web】代码仓模块改造 — 技术设计

## 一、分支管理 tabs 化与状态保持

### 结构

- `index.vue` 内以 `el-tabs` 承载两个面板：代码仓列表 / 分支管理（`branches.vue`）
- 分支管理面板通过 `branchPaneKey` 控制重建：`goBranch` 进入时递增 key，强制重建组件以清空内部状态（`el-tab-pane` 切换默认不销毁组件，`onMounted` 不会重新执行）

### 状态场景设计

| 场景                     | 行为                             | 实现方式                                                                            |
| ------------------------ | -------------------------------- | ----------------------------------------------------------------------------------- |
| 从代码仓入口进入分支管理 | 重置筛选条件，仅保留入口仓库筛选 | 递增 `branchPaneKey` 重建组件 + 清空 `branchSearchCache` + 重置 `showMetricsDetail` |
| 从代码度量详情返回分支页 | 保留用户修改的条件               | 面板用 `v-show` 保留实例状态                                                        |
| 直接切 tab 离开再回来    | 保持当前状态                     | 组件不销毁，状态自然保留                                                            |

### 其他

- 新增分支管理 API（`api/Repos/`），筛选条件与自动过滤联动
- 修复表格列排序、分页溢出、外层内边距

## 二、仓库入口冲突检测与全局配置弹窗

### 冲突检测

- 新增仓库入口时执行冲突检测，检测结果联动打开全局配置弹窗（`GlobalConfigDialog.vue`，新增文件）
- 冲突/复制入口由 `DuplicationCodeDrawer.vue` 承接调整

### GlobalConfigDialog 设计

- 按平台（Platform）分区展示公共账号与令牌配置，tab 切换
- **仅保存激活 tab**：提交时只序列化当前激活平台的配置，避免误提交其他 tab 未完成数据
- **令牌校验**（`validateToken`）：新增态（无账号）或修改态（正在输入令牌）时令牌必填，错误展示在 input 下方
- **保存失败高亮**：
  - 后端返回配置连接错误（data 为非空数组）时，将每条失败路径清洗后与输入框比对
  - 路径清洗：`trim()` + 去除反引号（后端返回的 path 可能带 `` ` `` 与空格）
  - 匹配到的输入框红色高亮，错误文案「该路径配置不正确，请修正后重试」
- sig-path 提示补充路径格式示例

## 三、SIG 同步流程优化

### useSigSync 组合式函数（新增）

- 抽取 sig 同步轮询逻辑，统一管理同步任务状态
- 轮询带 10 分钟超时上限，超时/完成后自动停止
- 供 `index.vue` 与同步 issue 弹窗共用

### 同步流程

```
录入/编辑 sig 路径
  └─ 批量校验（新增 API）
       └─ 提交同步（同步仓库接口，已合并一键同步能力）
            └─ 返回同步配置校验失败结果 → 展示失败明细
            └─ 成功 → useSigSync 轮询任务状态 → 完成后刷新列表
```

### 接口调整

- 一键同步接口合并进同步仓库接口，前端删除独立调用，合并后仍返回同步配置校验失败结果
- 同步 issue 弹窗新增 go-modify 操作与 sig-info 路径格式示例
- 同步提示文案覆盖 SIG 仓导入场景

## 影响面分析

- 改动集中在 `views/Repos/` 模块与 `api/Repos/`，不涉及公共组件与框架层
- 全量 diff 中另含仓库级 Prettier 格式化（`chore` commit），无行为变化
