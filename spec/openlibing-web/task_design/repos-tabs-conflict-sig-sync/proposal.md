# 【openlibing-web】代码仓模块改造：分支管理 tabs 化、仓库冲突检测与 SIG 同步流程优化

## 需求背景

代码仓（Repos）模块此前为单页列表 + 跳转分支页的形态，存在以下问题：

1. 分支管理独立页面跳转，入口割裂；从代码仓进入分支页时残留上次筛选条件，返回后又丢失用户修改的条件
2. 新增仓库入口时缺少冲突检测，且公共账号令牌等全局配置缺少统一管理入口
3. SIG 仓同步流程分散：一键同步与同步仓库两个接口并存、sig 路径无批量校验、路径格式无示例提示、提交反馈不清晰

本次改造将代码仓列表与分支管理整合为 tabs 形态，新增仓库入口冲突检测与全局配置弹窗，并重构 SIG 同步流程。

## 功能描述

### 1. 分支管理 tabs 化与状态保持

- 代码仓页面以 tabs 同时承载「代码仓列表」与「分支管理」两个面板
- 新增分支管理 API、筛选条件与自动过滤；修复表格列排序、分页溢出、外层内边距
- 从代码仓入口进入分支管理时重建组件并重置筛选条件（仅保留入口仓库筛选）
- 从代码度量详情返回分支页时保留用户修改的条件
- 直接切换 tabs 离开再回来时保持当前状态

### 2. 仓库入口冲突检测与全局配置弹窗

- 新增仓库入口冲突检测，检测结果联动全局配置
- 新增全局配置弹窗（GlobalConfigDialog），按平台分区管理公共账号与令牌
- 仅保存当前激活 tab 的配置，令牌新增态/修改态必填校验
- 保存失败时解析后端返回的非法 sig 路径（清洗反引号与空格），对匹配的输入框红色高亮并提示「该路径配置不正确，请修正后重试」
- sig-path 提示补充路径格式示例

### 3. SIG 同步流程优化

- 抽取 sig 同步逻辑为 useSigSync 组合式函数（轮询同步任务状态，10 分钟超时）
- 同步 issue 弹窗支持 go-modify 操作与 sig-info 路径格式示例
- sig 路径批量校验，同步完成后刷新列表
- 一键同步接口合并进同步仓库接口，合并后仍返回同步配置校验失败结果
- 同步提示文案覆盖 SIG 仓导入

## 不做什么

- 不修改分支管理/同步相关后端接口契约（仅前端消费；一键同步接口由后端侧另行合并）
- 不改动仓库列表查询、克隆、扫描等既有能力的行为

## 验收标准

- [x] tabs 内切换代码仓/分支管理，状态符合三类场景（入口重置 / 详情返回保留 / 切 tab 保持）
- [x] 新增仓库入口触发冲突检测并联动全局配置弹窗
- [x] 全局配置仅提交激活 tab 数据，令牌缺失时阻断提交并提示
- [x] 保存配置失败时非法路径输入框红色高亮并展示错误文案
- [x] SIG 同步全流程可用：路径批量校验 → 同步 → 轮询状态 → 刷新列表
- [x] 同步接口合并后校验失败结果正常返回并展示
