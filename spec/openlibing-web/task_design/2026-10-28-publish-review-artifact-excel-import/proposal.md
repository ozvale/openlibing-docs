# 需求背景

## 业务场景

发布评审 → 评审详情页（`reviewDetail.vue`）→ 制品信息区块，发布负责人（`isDataOwner`）需要逐条手工填写发布制品信息（软件下载方式、发布方式、代码仓、tag 信息、发布名称、流水线及流水线参数等），填写完成后提交评审。

## 问题痛点

1. **逐条填写效率低**：一个版本通常包含多个制品，字段多且重复度高，逐条手工填写耗时长。
2. **易填错**：代码仓、tag、流水线参数等字段需要精确匹配，人工录入容易产生拼写或格式错误，评审阶段才发现问题会导致返工。
3. **缺少批量入口**：已有制品信息表格只能手工新增行，没有批量导入能力，无法与线下维护的制品清单对接。

## 需求目标

在制品信息区块提供"下载制品信息模板"与"上传制品信息"能力，发布负责人可通过 Excel 模板批量维护制品信息，上传后由后端解析并回填到制品信息表格，解析失败时给出可定位的行级错误提示。

## 验收标准

### 功能验收

1. **模板下载**
   - 制品信息区块头部展示"下载制品信息模板"按钮，仅发布负责人可见
   - 下载接口按当前项目 `projectId` 与 `reviewId` 生成模板，文件名为"发布制品信息导入模板.xlsx"
   - 未选择项目或缺少评审 ID 时给出警告提示且不发起请求
2. **模板上传**
   - 制品信息区块头部展示"上传制品信息"按钮，仅发布负责人可见
   - 仅允许上传 `.xlsx` 文件，大小不超过 10MB，超限/格式错误时提示并清空已选文件
   - 上传过程中按钮显示 loading，重复选择文件时提示"文件正在解析中，请稍后重试"
3. **解析成功回填**
   - 解析成功后按接口返回的 `artifactInfoList` 追加到制品信息列表，并提示"已导入制品信息，共 N 条"
   - 代码仓按 `repoUrl` 与仓库列表匹配（忽略末尾 `/` 与 `.git` 后缀），匹配成功回填 `repoId`
   - 未匹配到仓库的 `repoUrl` 去重后提示"以下代码仓未匹配到仓库列表，请手动选择"
4. **解析失败提示**
   - 接口返回 `success = false` 时弹出"制品信息解析失败"弹窗，表格展示 `sheetName`、`rowNum`、`errorMsg`
   - 接口返回非 200 或请求异常时弹出错误提示框展示后端 `msg`

### 非功能验收

1. 不影响制品信息区块原有的手工新增、编辑、删除能力
2. 不影响非发布负责人视角下的按钮展示
3. 代码变更符合项目编码规范，通过 ESLint / pre-commit 检查
