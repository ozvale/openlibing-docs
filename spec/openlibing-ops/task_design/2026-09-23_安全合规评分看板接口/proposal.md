## 1. 需求背景

安全合规评分体系（18 指标，对标 OpenSSF Scorecard）已完成 ETL 链路设计（`docs/0912/design.md`）：
DolphinScheduler → Doris 分层（dwi 明细 → dm 汇聚快照）→ openlibing-ops Java 接口 → 前端看板。

本需求为看板提供 6 个接口，覆盖 4 个页面：

| 页面                             | 接口                                   | 说明                                                            |
| -------------------------------- | -------------------------------------- | --------------------------------------------------------------- |
| 社区汇总                         | 接口 1                                 | 5 个顶层社区列表（openEuler/openGauss/Ascend/openUBMC/booskit） |
| 社区详情·开源项目层（仅 Ascend） | 接口 2                                 | Ascend 下子社区/开源项目列表                                    |
| 代码仓清单                       | 接口 3                                 | 应扫仓库 × 最新批次得分                                         |
| 代码仓详情                       | 接口 4(1) 头部 KPI、接口 4(2) 指标明细 | 单仓得分概要 + 18 指标明细                                      |
| 指标明细抽屉                     | 接口 5                                 | 返回 freemarker 渲染后的 HTML 片段                              |

## 3. 核心口径（需求方逐条拍板记录）

### 3.1 层级模型

```text
顶层社区（= project，社区与 project 是同一实体）
├─ 普通社区（openEuler/openGauss/openUBMC/booskit）：社区 → 仓库直接归属（sdi_repo_info.project_id）
└─ 特殊社区 Ascend（has_sub_community=1）：
        Ascend → 子社区/开源项目（MindCluster/MindIE/MindSpeed/MindStudio，亦为 project）→ 仓库
```

社区与 project 的映射、Ascend 的特殊性标识，统一由**社区配置表**维护（见 design.md §2），便于后续引入新社区。

### 3.2 得分与亮灯（权威公式在 ETL，Java 只读）

| 层级     | 得分                                                                                                            | 亮灯                                               |
| -------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 仓库     | `∑(单项得分×权重) / ∑权重`，NA 与暂缓项分子分母同剔除；两套分：规则项得分（项目层级统计用）/ 全部得分（仅展示） | 得分率（规则项）≥80% 绿(1)、≥50% 黄(2)、<50% 红(3) |
| 项目层级 | `∑仓库规则项得分 / 仓库数量`（无分仓不进分母）                                                                  | 名下仓库灯取最低（MAX(rule_light)）                |
| 社区层级 | **对名下所有仓库重算**（∑仓库分/仓库数，跨子社区；无分仓剔除分母）                                              | 名下仓库灯取最低（MAX(rule_light)）                |

> 社区层级得分与普通社区的 project_score.score_rule 同构（后者本身就是"对名下仓库 AVG"），Ascend 仅是仓库范围跨子社区。社区层级亮灯若按"子社区灯取最低"与"仓库灯取最低"，因 MAX 可传递，结果恒等。

### 3.3 时间口径（statDate = 状态快照日）

统一语义：**"查 2026-09-18" = 查看 09-18 这一天的状态快照，而非"09-18 当天发生的扫描动作"。**

| 场景        | 取数规则                                                                                                                                                  |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 社区/项目级 | `project_score.stat_date = statDate`；当天无快照 → 返回 null；**不传 statDate → 表里最新 stat_date**                                                      |
| 仓库级      | 每仓取 `scan_time ≤ statDate 23:59:59` 的最新批次；该日之前从未扫过 → 该仓得分/亮灯为 null（应扫全集仍展示，NA 态）；**不传 statDate → 每仓各自最新批次** |

> 仓库级口径与 D6 快照口径（"每仓最新批次"聚合）天然同构，保证社区分数 ↔ 仓库清单数字可对账。
> 时间入参**复用 TimeReq.startDate 字段**（endDate/startTime/endTime 不使用）；前端单天查询只传 startDate。

### 3.4 仓库清单全集

代码仓清单以**应扫全集**（`sdi_rd_efc_repo_operate_conf.is_operated=1`）为基准 LEFT JOIN 扫描结果：应扫未扫的仓返回 null 得分/亮灯，前端展示 NA。保证与 project_score.repo_count（含无分仓）数字一致。

### 3.5 通用约定

- 亮灯字段 `light` 直接返回 `rule_light` 数值：1绿 / 2黄 / 3红；null（未扫/全 NA）由前端置灰。
- 得分 DECIMAL 原样返回；**NULL 原样返回 null，前端展示 NA；0 分是有效得分不转 NA**。
- 指标口径以 `dm_rd_efc_security_metric_conf` **全表 18 项**为准（含 deferred 项，其 score 恒 NULL→NA）；metric_conf.status 的差异（如 VULNS 是否已激活）不影响接口设计。
- 默认排序：`light DESC`（红→黄→绿），次级 `score DESC`。
- 分页列表统一走 `POST /common/detail` + category；非分页详情走独立接口。

## 4. 验收标准

1. 6 个接口按 design.md 字段定义可被前端联调（字段名/类型/空值语义一致）。
2. 同一 statDate 下：社区汇总的 repoCount = 该社区代码仓清单总行数（应扫口径）；社区分数可由仓库清单得分复算一致。
3. 不传 statDate 时各层级返回各自最新数据，且与"传表内最新 stat_date"结果一致。
4. 18 指标明细行数与 metric_conf 全表一致，按 display_order 排序，score=NULL 的行前端可展示 NA。
5. 接口 5 返回实体含 html 字段（渲染逻辑后置，字段先定型）。
