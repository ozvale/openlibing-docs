# 项目资源效率环比

## 需求背景

`POST /common/detail` 的 `category=ops-project-resource-efficiency` 当前只返回所选时间窗口内的项目资源效率。看板需要同时展示当前期与紧邻前一等长自然日周期的数据，帮助用户判断 PR 排队、NPU 消耗和资源池使用变化。

## 功能描述

1. 请求新增可选 `includePreviousPeriod`，开启后返回每个当前页项目的上一期指标原值和实际对比窗口。
2. 对比期为当前选择日期范围之前紧邻、自然日数相同且不重叠的窗口。例如当前为 2026-11-20～2026-11-24，对比期为 2026-11-15～2026-11-19。
3. 环比覆盖现有 10 个数值指标，项目名称、项目 ID 和资源池列表不参与。
4. 后端负责两期同口径聚合；前端负责差值、增减率、百分点、趋势图标和颜色等展示计算。
5. 当前期字段、排序、分页和默认请求行为保持兼容。

## 不做什么

- 不由前端调用两次现有分页接口并合并，避免指标排序下项目集合不一致及重复查询。
- 不新增环比差值或增减率排序。
- 不修改数据库表结构、数据内容或 ETL。
- 不在本期引入缓存、并行数据库查询或完整双窗口 SQL 重构。
- 不处理同比、自定义对比期或多周期对比。

## 验收标准

- [ ] `includePreviousPeriod` 缺省或为 `false` 时，不执行对比期查询，现有请求、响应和查询成本不变。
- [ ] 开启后，当前页每条记录包含 `previousPeriod`，其中有实际对比窗口和全部 10 个上一期指标原值。
- [ ] 当前期为 N 个自然日时，上一期为当前开始日期之前紧邻的 N 个自然日，跨月、跨年和单日窗口正确。
- [ ] 对比查询严格限定当前页 `projectIds`，按 `projectId` 合并，不依赖列表下标；当前排序和分页不受上一期数据影响。
- [ ] 两期均保持 `engineeringScope`、项目筛选、GitHub 展示配置、节假日过滤和各指标原有聚合口径。
- [ ] 工作日模式下两期分别使用各自工作日数作为分配率分母。
- [ ] 对比期无数据时返回窗口和 `null` 指标；查询异常不得伪装成无数据。
- [ ] 前端对空值、零分母和百分点有统一展示规则，不出现 `Infinity`、`NaN` 或把无样本当作 0。
- [ ] 相关 Service、Mapper XML 和回归测试通过，对比查询不存在逐项目 N+1 或全项目上一期聚合。

## 影响范围

- 业务仓：`openlibing-ops`
- 接口：`POST /common/detail`，`category=ops-project-resource-efficiency`
- 前端：资源运营看板项目资源效率列表及环比展示
- 文档仓：仅本需求目录
