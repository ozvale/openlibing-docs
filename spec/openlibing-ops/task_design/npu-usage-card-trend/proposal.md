# 使用率分析-卡数趋势（npu-usage-card-trend）

## 需求背景

业务 Issue：https://gitcode.com/openlibing/openlibing-ops/issues/300（父需求 [#208](https://gitcode.com/openlibing/openlibing-ops/issues/208) 第三点「使用率页面」）

> 使用率页面：1、增加曲线图：总卡数和使用卡数、等待卡数的曲线图，下钻和使用卡时趋势图保持一致。

当前「使用率分析」页面只有「趋势分析」（使用率 % + 排队任务数）与「使用率热力图」，缺少以**卡数**为量纲的趋势视图。

## 功能描述

在「使用率分析」页面，于「趋势分析」下方、「使用率热力图」上方新增「卡数趋势」图表：

- 横轴与「趋势分析」完全一致（5 分钟切片，同一时间窗口，同一筛选条件）。
- 三条曲线：总卡数、使用卡数、等待卡数。因等待卡数是队列需求、量级可远超物理容量（实测约 3.1k~6.4k vs 总卡数 1316），采用**双 Y 轴**：左轴「卡数(张)」放总卡数/使用卡数，右轴「等待卡数(张)」放等待卡数。
- 下钻与「趋势分析」一致：点击任一时刻 → 打开任务明细抽屉（排队 tab），展示该切片任务明细。

不做：不改动「趋势分析」「热力图」既有行为；不改动存量接口契约。

## 验收标准

- [x] 页面「趋势分析」与「使用率热力图」之间出现「卡数趋势」卡片，三条曲线图例为 总卡数 / 使用卡数 / 等待卡数。
- [x] 横轴刻度数量与「趋势分析」一致（同一筛选条件下）。
- [x] 总卡数在窗口内为水平线（静态维表存量口径，随项目/资源池筛选变化）。
- [x] 使用卡数 ≤ 总卡数（cap 上限），且 `使用卡数 / 总卡数 × 100` 与「趋势分析」使用率一致。
- [ ] 点击任一时刻，打开任务明细抽屉且默认「排队任务」tab，与「趋势分析」点击行为一致。
- [ ] 切换时间范围 / 项目 / 资源池后，三条曲线同步刷新。

追加要求（本轮联调中确认）：

- [x] 等待卡数取平台任务事实表口径，**同一切片的取值与查询窗口无关**（72h 与 20min 窗口下五个切片逐个相同）。
