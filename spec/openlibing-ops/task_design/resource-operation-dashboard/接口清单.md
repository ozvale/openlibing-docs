# 资源运营看板 — 接口清单

> 来源：`design.md` 第 4 章接口设计。通用约定：请求均为 `POST` + `@RequestBody` + `@Validated`，响应统一 `Result<T>`；时间范围闭区间，`startDate <= endDate` 且跨度 ≤ 7 天。
>
> **数值精度约定**：百分比、NPU 卡时、时间(min) 等小数字段统一四舍五入保留 2 位小数（如 `86.4 → 86.4`、`18.634 → 18.63`）；null 原样返回。

---

## 1. KPI 汇总

- **请求方式**：`POST`
- **请求路径**：`/resource-operation/summary`
- **请求体** `ResourceOperationSummaryReq extends TimeReq`：

```json
{ "projectId": 100, "startDate": "2026-08-16", "endDate": "2026-08-16" }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| projectId | Integer | 否 | 为空时展示全部资源池 |
| startDate / endDate | LocalDate | 是 | 默认昨天，跨度 ≤ 7 天 |

- **响应体** `ResourceOperationSummaryResp`：

```json
{
  "poolTotal": { "cloud": 1, "lab": 2 },
  "resourceTotal": {
    "cloud": [ { "generation": "A5", "npuNum": 1 }, { "generation": "A3", "npuNum": 2 } ],
    "lab": [ { "generation": "A5", "npuNum": 1 } ]
  },
  "allocRate": { "cloud": 86.4, "lab": 71.2 },
  "usageRate": { "cloud": 63.8, "lab": 47.5 }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| poolTotal | Map\<String,Integer> | 资源池总量（**存量口径，不随查询时间变化**），按 `location` 分组（key 为云上/实验室，原样返回，前端映射「华为云/实验室」）；来自机器静态维表 `sdi_rd_efc_server_machine_hidevlab`，按 `(resource_pool_id, location)` 组合计数：**同一池 id 跨云上/实验室时在两侧各计 1**，同池同位置多机器行不重复 |
| resourceTotal | Map\<String,List\<ResourceTotalItem>> | 资源总量（代际卡数，**存量口径，不随查询时间变化**），按 `location` 分组；来自 `sdi_rd_efc_server_machine_hidevlab`，先按 `(resource_pool_id, server_ip, location, generation)` 机器级去重（同池同 IP 多行取 MAX 卡数，避免重复累加），再按 `location + generation` SUM；跨位置池的机器按各自位置的行分别归组 |
| resourceTotal[].generation | String | 代际（A5/A3） |
| resourceTotal[].npuNum | Integer | 该代际卡数 |
| allocRate | Map\<String,Double> | NPU 分配率(%) = `SUM(assign_npu_hours)/SUM(total_npu_hours)`，按 `location` 分组（**随查询时间窗口变化**）；**分母兜底：`SUM(total_npu_hours)` 为 0 时改用 `SUM(actual_npu_num)`**（宽表跨小时行求和，量纲=实际卡数×有数据小时数，与全窗口卡时一致；一卡多代按系数折算） |
| usageRate | Map\<String,Double> | NPU 使用率(%) = `SUM(used_npu_hours)/SUM(total_npu_hours)`，按 `location` 分组（**随查询时间窗口变化**） |

## 2. NPU 趋势图

- **请求方式**：`POST`
- **请求路径**：`/resource-operation/trend`
- **请求体** `ResourceOperationTrendReq extends TimeReq`：

```json
{ "projectId": 100, "startDate": "2026-08-10", "endDate": "2026-08-16", "dim": "pool" }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| projectId | Integer | 否 | 为空展示全部 |
| startDate / endDate | LocalDate | 是 | 跨度 ≤ 7 天 |
| dim | String | 否 | `pool`（默认）/ `gen`；响应始终返回两个维度 |

- **响应体** `ResourceOperationTrendResp`（X 轴小时刻度 + 各分组分配/使用曲线）：

```json
{
  "labels": ["2026-08-10 00:00", "2026-08-10 01:00", "...", "2026-08-16 23:00"],
  "pool": [
    { "name": "华为云",  "alloc": [22, 20, 18, "..."], "usage": [12, 11, 10, "..."] },
    { "name": "实验室 A", "alloc": [10, 8, 6, "..."],  "usage": [6, 5, 4, "..."] }
  ],
  "gen": [
    { "name": "A5", "alloc": [16, 14, 12, "..."], "usage": [10, 9, 8, "..."] },
    { "name": "A3", "alloc": [12, 10, 9, "..."],  "usage": [8, 7, 6, "..."] }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| labels | List\<String> | 小时刻度，起始日 00:00 至结束日 23:00 逐小时，格式 `yyyy-MM-dd HH:mm` |
| pool | List\<TrendGroup> | 按 `resource_pool_name` 分组的曲线；**返回静态维表全量资源池（存量口径，projectId 非空时限项目池），窗口内无数据的池也返回（曲线补 0）** |
| gen | List\<TrendGroup> | 按 `generation` 分组的曲线 |
| pool[].name / gen[].name | String | 分组名 |
| pool[].alloc / gen[].alloc | List\<Double> | 逐小时分配率(%)，与 labels 对齐，缺失补 0；**分母兜底：该小时 `SUM(total_npu_hours)` 为 0 时改用 `SUM(actual_npu_num)`（实际卡数，一卡多代乘系数后）** |
| pool[].usage / gen[].usage | List\<Double> | 逐小时使用率(%)，与 labels 对齐，缺失补 0 |

## 3. 服务器 NPU 热力图

- **请求方式**：`POST`
- **请求路径**：`/resource-operation/heatmap`
- **请求体** `ResourceOperationHeatmapReq extends TimeReq`：

```json
{ "projectId": 100, "resourcePoolId": 1, "startDate": "2026-08-16", "endDate": "2026-08-16" }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| projectId | Integer | 否 | 为空展示全部 |
| resourcePoolId | Long | 否 | 下钻抽屉复用：指定资源池时仅返回该池服务器（PoolDrawer 内嵌热力图） |
| startDate / endDate | LocalDate | 是 | 默认昨天，跨度 ≤ 7 天 |

- **响应体** `ResourceOperationHeatmapResp`：

```json
{
  "labels": ["2026-08-16 00:00", "2026-08-16 01:00", "..."],
  "servers": [
    { "ip": "10.10.5.21", "pool": "华为云", "gen": "A5",
      "alloc": [
        { "value": 22, "jobs": [ { "pipeline": "pr-gate-ut", "name": "unit_test" } ] },
        { "value": 20, "jobs": [] },
        "..."
      ],
      "usage": [14, 12, 10, "..."] }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| labels | List\<String> | 小时刻度，格式 `yyyy-MM-dd HH:mm` |
| servers | List\<ServerHeatmap> | 机器列表；**返回静态维表全量机器（存量口径，projectId/resourcePoolId 过滤），窗口内无数据的机器也返回（alloc/usage 补 0）**；`resourcePoolId` 为空时按 `resource_pool_id` 分组（同名 IP 多池各池独立一行）；非空时直接过滤单池 |
| servers[].ip | String | 服务器 IP |
| servers[].pool | String | 资源池名（`resource_pool_name`） |
| servers[].gen | String | 代际（`generation`） |
| servers[].alloc | List\<AllocCell> | 逐小时分配率单元格，与 labels 下标对齐，缺失小时 `value=0/jobs=[]`；每格自包含率值与悬浮任务 |
| servers[].alloc[].value | Double | 分配率(%)，**分母兜底：该格 `total_npu_hours` 为 0 时改用 `actual_npu_num`（实际卡数，一卡多代乘系数后）** |
| servers[].alloc[].jobs | List\<JobItem> | 该小时该机器上正在使用的任务列表，供分配率热力图悬浮展示（高保真「运行业务」）；使用率热力图不展示任务 |
| servers[].alloc[].jobs[].pipeline | String | 所属流水线名（`pipeline_name`） |
| servers[].alloc[].jobs[].name | String | 任务名（`job_name`） |
| servers[].usage | List\<Double> | 逐小时使用率(%)，与 labels 对齐，缺失补 0 |

> 效率（alloc − usage）由前端根据 `alloc`/`usage` 数组计算，接口不返回。
>
> **jobs 数据来源**：任务切片表 `dwr_rd_efc_resource_npu_detail`，取该小时切片内排队秒或运行秒 > 0 的任务（按**流水线名+任务名**去重，同任务名不同流水线各计一条）；机器范围与热力图同口径（`resourcePoolId` 非空过滤单池 / 否则项目池过滤），npu_detail 无池字段，经宽表 `server_ip` 反查池归属。一机多池时各池行共享同一份任务列表。

## 4. 资源池明细（下钻）

- **请求方式**：`POST`
- **请求路径**：`/common/detail`，`category = ops-resource-pool-detail`
- **请求体** `OpsResourcePoolDetailDetailReq extends DetailReq`：

```json
{
  "category": "ops-resource-pool-detail",
  "projectId": 100,
  "startDate": "2026-08-16",
  "endDate": "2026-08-16",
  "sortField": "allocRate", "sortRule": "DESC"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| category | String | 是 | `ops-resource-pool-detail` |
| projectId | Integer | 否 | 为空展示全部 |
| startDate / endDate | LocalDate | 是 | 跨度 ≤ 7 天 |
| sortField | String | 否 | 白名单：`allocRate / usageRate / totalNpuHours / serverIp` |
| sortRule | String | 否 | `asc / desc`，默认 DESC |

> **不分页**：池总数不超过 50，全量返回；`page/pageSize` 入参忽略（响应 PageResult 包装保留以兼容 /common/detail 框架，`page=1`、`pageSize=total=records 数`）。

- **响应体** `PageResult<OpsResourcePoolDetailDetailResp>`，每条 = 一个资源池：

```json
{
  "resourcePoolId": 1,
  "resourcePoolName": "华为云资源池",
  "location": "cloud",
  "allocRate": 86.4,
  "usageRate": 66.2,
  "projectNames": ["MindIE", "MindSpeed", "PTA", "openlibing"],
  "machines": [
    { "ip": "10.10.5.21", "totalNpuHours": 24.0, "assignNpuHours": 21.1,
      "usedNpuHours": 18.6, "allocRate": 88.0, "usageRate": 78.0 }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| resourcePoolId | Long | 资源池 ID |
| resourcePoolName | String | 资源池名 |
| location | String | 位置（cloud 云上 / lab 实验室） |
| allocRate | Double | 分配率(%) = `SUM(assign)/SUM(total)`，按 `(resource_pool_id, location)` 聚合（**随查询时间窗口变化**，无数据返回 0）；**分母兜底：`SUM(total_npu_hours)` 为 0 时改用 `SUM(actual_npu_num)`**（宽表跨小时行求和，量纲=实际卡数×有数据小时数，与全窗口卡时一致；一卡多代按系数折算）；**超过 100% 时截断为 100%** |
| usageRate | Double | 使用率(%) = `SUM(used)/SUM(total)`（**随查询时间窗口变化**，无数据返回 0） |
| projectNames | List\<String> | 该池绑定项目名 chips（`project_name` 去重） |
| machines | List\<MachineDetail> | 该池机器级明细，按 `(resource_pool_id, server_ip)` 机器级去重（同池同 IP 多行合并为一台），机器按自身 `location` 只挂到对应位置行（跨位置池不重复展示） |
| machines[].ip | String | 机器 IP |
| machines[].totalNpuHours | Double | 总卡时（**随查询时间窗口变化**）；**兜底：窗口内 `SUM(total_npu_hours)` 为 0 时 = `SUM(actual_npu_num) × 窗口小时数`**（实际卡数×查询窗口小时数） |
| machines[].assignNpuHours | Double | 分配卡时（**随查询时间窗口变化**，无数据返回 0） |
| machines[].usedNpuHours | Double | 使用卡时（**随查询时间窗口变化**，无数据返回 0） |
| machines[].allocRate | Double | 分配率(%)（无数据返回 0）；**分母兜底：`SUM(total_npu_hours)` 为 0 时改用 `SUM(actual_npu_num)`**（实际卡数×有数据小时数，量纲对齐卡时；一卡多代乘系数后）；**超过 100% 时截断为 100%** |
| machines[].usageRate | Double | 使用率(%)（无数据返回 0） |

> **池粒度 = `(resource_pool_id, location)`**：同一池 id 跨云上/实验室时出两行（率值按位置分开算），不按 pool_id 合并。
>
> **存量口径**：资源池列表与机器列表均来自机器静态维表 `sdi_rd_efc_server_machine_hidevlab`（无时间维度），**不随查询时间过滤**——时间窗口内没有使用记录的池/机器也照常展示；卡时与率值 LEFT JOIN 宽表 `dm_rd_efc_server_resource_hour` 时间窗口聚合计算。
>
> 分页包装：`PageResult` 含 `page / pageSize / total / records`。抽屉展开某池后，前端用 `resourcePoolId` 再调一次 `POST /resource-operation/heatmap`（接口 3）渲染该池机器热力图。

## 5. 项目资源效率（一级下钻）

- **请求方式**：`POST`
- **请求路径**：`/common/detail`，`category = ops-project-resource-efficiency`
- **请求体** `OpsProjectResourceEfficiencyReq extends DetailReq`：

```json
{
  "category": "ops-project-resource-efficiency",
  "projectName": "open",
  "startDate": "2026-08-16", "endDate": "2026-08-16",
  "page": 1, "pageSize": 10,
  "sortField": "queueP90", "sortRule": "DESC"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| category | String | 是 | `ops-project-resource-efficiency` |
| projectName | String | 否 | 项目名模糊搜索（复用 `name` 字段） |
| startDate / endDate | LocalDate | 是 | 默认昨天，跨度 ≤ 7 天 |
| page / pageSize | int | 否 | 默认 1 / 10 |
| sortField | String | 否 | 白名单：`queueP90 / npuUsageRate / projectName / projectId`；不传时默认按 `projectName` 升序 |
| sortRule | String | 否 | `asc / desc`，默认 DESC |

- **响应体** `PageResult<OpsProjectResourceEfficiencyResp>`，每条 = 一个项目：

```json
{
  "projectId": 100,
  "projectName": "openlibing",
  "queueP90": 12.6,
  "npuAllocHours": 18.4,
  "npuUsageRate": 64.1,

}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| projectId | Integer | 项目 ID |
| projectName | String | 项目名 |
| queueP90 | Double | PR 资源排队时长(测试任务)[P90](min)，`npu_detail` 的 `job_type='DT'` 任务（按 job 去重）`job_pending_duration` P90 / 60，按 `job_start_time` 落窗全窗口；PR 流水线集合以 `npu_detail.pipeline_name` 的 pr% 识别（覆盖三平台，不依赖 run_fact） |

| npuUsageRate | Double | NPU 使用率(%)，按绑定资源池聚合 `SUM(used)/SUM(total)` |
| resourcePools | List\<String> | 项目关联资源池名称（项目下钻顶部框 pills，去重） |

## 8. 流水线运行分析（「查看运行明细」面板同屏数据）

- **请求方式**：`POST`
- **请求路径**：`/resource-operation/run-analysis`（独立 REST 接口，不进 `/common/detail`）
- **请求体** `OpsPipelineRunAnalysisReq`（**只传流水线运行 ID + 项目 ID**，后端按该次运行的时间窗口分析，无需时间范围参数）：

```json
{ "runId": "86231", "projectId": 100 }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| runId | String | 是 | 流水线运行 ID（`pipeline_run_id`，跨平台统一，gitcode/github 为 `workflow_run_id` 映射） |
| projectId | Integer | 是 | 项目 ID，分配率分析（allocServers）据此返回**项目下所有资源池**的分配情况 |

**时间窗口（labels）**：由该次运行起止时间（来自任务切片表 `dwr_rd_efc_resource_npu_detail`：运行起 = `MIN(job_start_time)`、运行止 = `MAX(job_end_time)`，覆盖 codearts/gitcode/github）对齐整点生成——起始向下取整点、结束非整点向上进位（含边界整点）。例：任务运行 `2026-08-20 16:34:49 - 2026-08-20 17:34:49` → 窗口 = `2026-08-20 16:00` / `17:00` / `18:00`；结束整点 `17:00:00` → `16:00` / `17:00`。运行未结束时结束按当前时间处理。

- **响应体** `OpsPipelineRunAnalysisResp`（按一次运行分析：labels = 该运行整点时间窗口；**allocServers = 项目下所有资源池的分配率热力**（按 projectId 查项目资源池集合，含未涉及本次运行的机器）；**usageServers = 本次运行任务涉及机器（资源池）的使用率热力**；任务排队/运行连线 jobs 按 `serverIp` 挂载到对应机器单元格下（未涉及任务的机器 jobs 为空列表），每个任务带 `states[]` 标识各时间段「排队/运行/无」，前端两张热力图各自直接渲染）：

```json
{
  "labels": ["2026-08-20 16:00", "2026-08-20 17:00", "2026-08-20 18:00"],
  "allocServers": [
    {
      "ip": "10.10.5.21", "pool": "昇腾统一资源池-CICD", "gen": "A5",
      "values": [12.5, 88.3, 0.0],
      "jobs": [
        { "runId": "86231", "taskName": "unit_test", "queueStart": "16:34:49", "queueEnd": "16:49:12",
          "runEnd": "17:34:49", "queueMinutes": 15.0, "npuHours": 6.2, "serverIp": "10.10.5.21",
          "states": ["QUEUING", "RUNNING", "NONE"] }
      ]
    },
    {
      "ip": "10.10.5.22", "pool": "昇腾统一资源池-训练", "gen": "A3",
      "values": [30.0, 45.0, 20.0],
      "jobs": []
    }
  ],
  "usageServers": [
    {
      "ip": "10.10.5.21", "pool": "昇腾统一资源池-CICD", "gen": "A5",
      "values": [9.2, 61.0, 0.0],
      "jobs": [
        { "runId": "86231", "taskName": "unit_test", "queueStart": "16:34:49", "queueEnd": "16:49:12",
          "runEnd": "17:34:49", "queueMinutes": 15.0, "npuHours": 6.2, "serverIp": "10.10.5.21",
          "states": ["QUEUING", "RUNNING", "NONE"] }
      ]
    }
  ]
}
```

> 注：`usageServers` 仅含任务涉及机器（资源池），`allocServers` 含项目全部资源池机器（未涉及任务的机器 jobs 为空列表）。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| labels | List\<String> | 运行整点时间窗口，格式 `yyyy-MM-dd HH:mm`，与 allocServers/usageServers 各机器数组及 jobs[].states 对齐 |
| allocServers | List\<ServerCell> | **NPU 分配率分析热力**：机器×小时分配率 cells（项目下所有资源池的机器，仅运行窗口内，缺失补 0） |
| usageServers | List\<ServerCell> | **NPU 使用率分析热力**：机器×小时使用率 cells（仅本次运行任务涉及机器/资源池） |
| allocServers[].ip / usageServers[].ip | String | 机器 IP |
| allocServers[].pool / usageServers[].pool | String | 资源池名 |
| allocServers[].gen / usageServers[].gen | String | 代际 |
| allocServers[].values / usageServers[].values | List\<Double> | 逐小时分配率/使用率(%)，与 labels 对齐，缺失补 0（数值语义由所属列表决定）；分配率**分母兜底：该格 `total_npu_hours` 为 0 时改用 `actual_npu_num`（实际卡数，一卡多代乘系数后）** |
| allocServers[].jobs / usageServers[].jobs | List\<JobAnalysis> | 该机器上的任务排队/运行连线（按 `serverIp` 挂载到对应机器单元格，分配/使用两份各自携带，按排队开始时间升序） |
| jobs[].runId | String | 运行 ID（`pipeline_run_id`），用于关联接口 7 明细表选中行 |
| jobs[].taskName | String | 任务名（`job_name`） |
| jobs[].queueStart | String | 排队开始（HH:mm:ss）= `job_start_time`（创建/申请时间） |
| jobs[].queueEnd | String | 排队结束（HH:mm:ss）= `job_run_start_time`（开始运行时间） |
| jobs[].runEnd | String | 运行结束（HH:mm:ss）= `job_end_time` |
| jobs[].queueMinutes | Double | 排队时长(min) = `job_pending_duration / 60` |
| jobs[].npuHours | Double | NPU 消耗(卡时) = `SUM(assign_npu_second) / 3600` |
| jobs[].serverIp | String | 分配机器（切片 `server_ip`，与所在 ServerCell 的 `ip` 一致） |
| jobs[].states | List\<String> | 各时间段状态，与 labels 对齐：`QUEUING`-排队 / `RUNNING`-运行 / `NONE`-无 |

> 数据来源：**运行时间窗、任务连线与 `states[]` 均来自任务切片表 `dwr_rd_efc_resource_npu_detail`**（按 `pipeline_run_id` 取该运行全部任务切片：窗口 = `MIN(job_start_time)`/`MAX(job_end_time)`，按 job 聚合后按 `serverIp` 挂载），**不再依赖运行事实表 `dwr_rd_efc_pipeline_run_fact`**（该表仅 codearts 且到 npu_detail 有过滤丢失）；热力 cells 来自宽表 `dm_rd_efc_server_resource_hour`：allocServers 按项目资源池集合过滤（`dwi_rd_efc_project_resource_pool_relation`），usageServers 按任务涉及机器过滤，均限运行窗口。每个任务在各整点段内切片排队秒 > 0 标 `QUEUING`，否则运行秒 > 0 标 `RUNNING`，否则 `NONE`。

## 10. 项目下钻折线图（流水线资源分配热力顶部曲线）

- **请求方式**：`POST`
- **请求路径**：`/resource-operation/project-alloc-trend`（独立 REST 接口，不进 `/common/detail`）
- **请求体** `OpsProjectAllocTrendReq extends TimeReq`：

```json
{ "projectId": 100, "startDate": "2026-08-16", "endDate": "2026-08-16" }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| projectId | Integer | 是 | 项目 ID（下钻项目） |
| startDate / endDate | LocalDate | 是 | 默认昨天，跨度 ≤ 7 天 |

- **响应体** `OpsProjectAllocTrendResp`：

```json
{
  "labels": ["2026-08-16 00:00", "2026-08-16 01:00", "...", "2026-08-16 23:00"],
  "reqCounts": [3, 1, 0, "..."],
  "queueMinutes": [15.0, 1.0, 0.0, "..."]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| labels | List\<String> | X 轴小时刻度，起始日 00:00 至结束日 23:00 逐小时，格式 `yyyy-MM-dd HH:mm`，与 reqCounts/queueMinutes 对齐 |
| reqCounts | List\<Integer> | 每小时资源申请次数，与 labels 对齐，缺失小时补 0 |
| queueMinutes | List\<Double> | 每小时总排队时长(min)，与 labels 对齐，缺失小时补 0，保留 2 位小数 |

> **数据来源**：`dwr_rd_efc_resource_npu_detail`（任务×小时切片）。项目范围 = 项目绑定资源池（`dwi_rd_efc_project_resource_pool_relation` 查项目 `resource_pool_id` 集合；npu_detail 经 `server_ip` 关联 `dm_rd_efc_server_resource_hour` 判资源池归属后过滤到项目资源池集合）；资源申请次数 = 每小时申请资源的任务数（按 `pipeline_id/pipeline_run_id/job_id` 去重、按 `job_start_time` 落小时）；每小时总排队时长 = 该小时申请任务 `job_pending_duration` 求和（秒 → 分）。
