# 威胁模型：产品质量-质量策划模块

## 1. 范围与假设

- 业务 Issue：[openlibing-ops #328](https://gitcode.com/openlibing/openlibing-ops/issues/328)。
- 范围：新增项目里程碑、质量策划初始化、目录、项目质量负责人、17 类策划内容的 REST API 与 MySQL 持久化。
- 不在范围内：前端、质量评估、导入导出、列设置、外部作业平台集成。
- 认证继续使用 OPS 现有 token Cookie 与 JWT 组件；产品质量模块不接受 query 参数身份。
- 网关、HTTPS、数据库账号和日志平台属于现有信任基础设施，本需求不重建，但上线前必须验证其安全配置。

## 2. 资产清单

| 资产 | 分类 | 责任域 | 主要保护目标 |
|---|---|---|---|
| token Cookie / JWT | 机密 | 客户端、网关、OPS | 不记录、不泄露、不用 query 参数替代 |
| 项目角色与归属关系 | 敏感 | MySQL 权限库、OPS | 决策准确、默认拒绝、防止越权 |
| 项目质量负责人配置 | 敏感 | `pq_project_quality_owner` | 仅项目管理员可修改 |
| 里程碑、策划、目标、风险及措施 | 内部 | `pq_*` 业务表 | 项目隔离、完整性、可追溯 |
| 版本摘要富文本 | 内部、主动内容 | `pq_version_summary` | 防存储型 XSS、限制大小 |
| 思维导图 JSON | 内部、主动内容 | `pq_quality_mindmap` | 不执行内容、限制大小和深度 |
| 姓名、工号、参与人等文本 | 内部人员信息 | 策划业务表 | 最小收集、限制日志暴露 |
| 操作日志与前后快照 | 敏感、审计资产 | 现有日志平台 | 白名单字段、无凭证、可回放、防抵赖 |
| 数据库连接与部署配置 | 机密 | OPS 部署环境 | 不入仓、不入日志、不进入接口响应 |

## 3. 信任边界

| 边界 | 数据流 | 信任要求 |
|---|---|---|
| 浏览器/调用方 → 网关 | HTTPS，token Cookie，JSON | 外部输入不可信；网关完成入口认证、CSRF 与传输安全控制 |
| 网关 → OPS Controller | 路径参数、请求体、token Cookie | OPS 仍独立提取有效身份、校验参数，不因内网调用放行 |
| Controller → App Service | 强类型 DTO、当前用户 ID | DTO 不含可信归属/审计字段；App Service 强制执行权限矩阵 |
| App Service → Domain Service / Mapper | 项目、策划、记录归属条件 | 所有 SQL 参数化，查询条件包含项目和策划范围 |
| OPS → MySQL 权限库 | 用户 ID、项目 ID，只读角色查询 | 最小权限账号；查询失败默认拒绝 |
| OPS → `pq_*` 表 | 策划内容、审计字段 | 服务端设置归属和审计字段，逻辑删除，事务保证批量原子性 |
| OPS → 现有操作日志链路 | 白名单业务快照、资源元数据 | 禁止 token/Cookie/完整 HTTP 报文；日志访问受控 |
| API → 后续前端 | JSON、清理后的富文本、思维导图数据 | JSON 编码；前端按上下文渲染，不能信任原始 HTML/URL |

## 4. 关键数据流

1. **里程碑与初始化**：调用方 → 网关 → Controller → 写权限校验 → 里程碑归属校验 → 事务写入策划及目录 → 操作日志。
2. **策划 CRUD**：调用方 → token-only 身份 → 项目成员/写权限 → `projectId + planId` 校验 → 字段校验 → 可选执行里程碑归属校验 → MySQL → 快照日志。
3. **质量负责人维护**：管理员身份 → 项目管理员校验 → 目标用户成员资格校验 → 事务替换 → 审计日志。
4. **查询**：有效身份 → 项目成员校验 → 带项目/策划/逻辑删除条件查询 → 最小化强类型响应。

## 5. STRIDE 评估

| 资产/流程 | S | T | R | I | D | E | 风险与缓解措施 |
|---|---|---|---|---|---|---|---|
| 用户身份 | 高 | 中 | 中 | 高 | 中 | 高 | query `userId` 可伪造：新模块仅使用 token Cookie；匿名和解析失败默认拒绝 |
| 项目归属查询 | 中 | 中 | 中 | 高 | 中 | 高 | 仅路径校验不足：App Service 显式成员检查，所有 SQL 带项目范围 |
| 质量负责人维护 | 高 | 高 | 高 | 高 | 中 | 高 | 负责人自我提权：独立管理员判定，负责人不能修改负责人，目标用户必须是项目成员 |
| `planId` / 记录 ID | 中 | 高 | 中 | 高 | 中 | 高 | IDOR：校验 `projectId → planId → id` 归属链，修改/删除 SQL 同样限定范围 |
| 明细行 `milestoneId` | 低 | 高 | 中 | 高 | 低 | 中 | 跨项目引用：允许同项目其他里程碑，但禁止跨项目，服务端校验 |
| 批量删除 | 中 | 高 | 高 | 中 | 高 | 高 | 部分越权、部分成功：数量上限、事务、行锁、全量归属校验，任一失败整体回滚 |
| 版本摘要 | 低 | 高 | 中 | 中 | 高 | 低 | 存储型 XSS/大报文：OWASP 白名单清理、危险 URL 移除、100k 字符上限 |
| 思维导图 JSON | 低 | 高 | 中 | 中 | 高 | 低 | 深层 JSON/脚本内容：200k 大小、节点/深度限制，仅作为数据处理 |
| 普通文本与 URL | 低 | 高 | 中 | 中 | 中 | 低 | 注入/伪协议：长度限制、参数化 SQL、链接仅 http/https，后端不请求链接 |
| 列表和批量接口 | 低 | 中 | 低 | 中 | 高 | 中 | 资源耗尽：页大小和批量最大 200，固定排序，不开放任意 SQL 片段 |
| 操作日志 | 中 | 高 | 高 | 高 | 中 | 中 | 抵赖/敏感泄露：所有写操作留白名单前后快照；禁止凭证和完整 HTTP 报文 |
| 唯一约束与初始化 | 低 | 高 | 中 | 中 | 中 | 中 | 并发双策划：数据库唯一键、事务、特定冲突重查，目录失败整体回滚 |
| 错误响应 | 低 | 低 | 低 | 高 | 低 | 低 | 信息泄露：复用统一异常，不返回 SQL、堆栈、数据库地址或目标资源内容 |

## 6. 关键安全决策

1. 新模块使用 token-only 身份入口，不继承 `UserUtil.currentUserId` 的 query 参数兜底。
2. 权限决策集中在 App Service；Controller 注解不能代替写权限和资源归属校验。
3. 项目管理员沿用当前 `role_type_info.type = 'project'` 语义，质量负责人为独立项目级授权，不允许自我授权。
4. 所有业务读写使用项目、策划、记录三重范围；批量操作先验证全部再执行。
5. 富文本在服务端进行白名单清理；思维导图永远不执行；所有外部链接只保存、不访问。
6. 所有写操作保留结构化白名单前后快照，认证凭证和完整 HTTP 报文不得进入日志。

## 7. 遗留风险与验证前提

- 现有其他模块仍可能使用 query 参数身份，本需求不扩大全局认证改造；新方法不得改变存量行为。
- token Cookie 的 `Secure`、`HttpOnly`、`SameSite` 和网关 CSRF 防护属于部署前提，需在 beta/生产上线检查中证实；若缺少 CSRF 防护，写接口不得仅凭 Cookie 放行上线。
- 当前角色数据将 project 类型视作项目管理员。若权限库实际引入普通 project 成员角色，必须先调整管理员映射并补回归测试，不能默认所有 project 角色都可写。
- 富文本和思维导图最终渲染在前端范围内，前端后续必须继续按上下文安全渲染；后端清理不能替代前端输出编码。
