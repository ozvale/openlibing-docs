## 已归档的非问题结论（closed 部分）

- `gitleaks` 的 Secret / Match 掩码交由使用方通过 `.pre-commit-config.yaml` 的 `args: [--redact]` 控制，插件侧不做额外处理。
- `pull_request_target` + 检出 PR merge commit + 执行 PR 内配置，是面向开源仓外部人员 PR 的有意门禁设计，`allow-unsafe-pr-checkout: true` 即该场景的显式开关。
- `spawn` 不设超时/输出上限是有意为之：大项目时长不可预估，超时会误杀合法任务。
- 配置缺失静默通过属于既定契约，配置存在性与门禁断言归属使用方职责。

## 可复用经验

- 凭证传递加固必须覆盖全部调用点后统一切换，禁止双通道并存。
- 集中配置化必须保持默认值与原硬编码值完全一致，否则视为行为变化需评审。
- 判定「非问题」时要写明设计意图与兜底机制，并同步沉淀到 `ai_memory.md`，避免后续扫描重复告警。
