# 社区项目代码仓定时下载与用例扫描

## 需求背景

为掌握社区对 OpenLibing 体系的实际使用情况（沉淀案例、发现问题、收集改进建议），需要在 `openlibing-sync` 服务中新增一个**定时任务**：定期拉取社区项目代码仓（如基于 GitCode / AtomGit 平台托管的开源样例仓）的最新代码，对其进行测试用例全集扫描，提取测试覆盖范围、运行特征等元数据，为后续运营分析提供原始输入。

目前 `openlibing-sync` 已有类似定时采集能力（如 IDE 插件用户资源、Issues 数据采集等），本需求复用其定时调度、数据写入 Doris 的现有框架，扩展"代码仓克隆 + 用例扫描"的能力。

## 功能描述

### 定时下载代码仓
- 按预设的社区项目清单（白名单），定期（如每日凌晨）克隆或拉取最新代码至 `openlibing-sync` 服务本地工作区
- 支持配置：仓库地址、分支、克隆深度（推荐 `depth=1`）、工作目录、单仓超时
- 失败处理：单仓失败不影响其他仓；失败记录写日志 + Doris

### 测试用例扫描
- 对每个克隆后的代码仓，调用用例扫描引擎（基于 openlibing-pytest-executor 已有的 pytest 扫描逻辑，或独立实现）解析用例全集
- 提取关键指标：测试文件 / 用例 / 函数 / 类的数量、命名空间分布、跳过率、用例平均行数等
- 输出结构化 JSON 结果

### 数据入库与运营看板
- 写入统一数据接入 API（参考 `2026-04-01_IDE插件用户资源运营数据收集` 已有能力）
- 表模型设计：`community_repo_scan_record`（仓级结果）+ `community_testcase_summary`（用例汇总）
- 看板维度：仓库维度、时间维度、规模维度（用例数量级）

## 验收标准

- [ ] 定时任务能按 CRON（如 `0 2 * * *`）成功触发并完成单次扫描
- [ ] 至少支持 5 个社区仓的并行 / 串行扫描（可配置）
- [ ] 扫描结果成功写入 Doris，表模型可查询
- [ ] 单仓失败有完整日志与指标记录，不影响其他仓
- [ ] 具备断点续扫能力（上次失败仓下次优先重试）
- [ ] 全链路有 metrics 埋点（耗时、成功率、扫描用例数）
