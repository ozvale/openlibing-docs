# 一站式作业 — 系统设计

> 更新时间：2026-06-01

## 模块定位

一站式作业是 computing-resource-workspace 的两大业务板块之一，作为 IDE 插件的后端服务，提供从**环境申请 → 软件安装 → 任务执行 → 资源释放**的完整闭环。底层对接HiDevLab 平台，通过 REST API + HMAC 签名鉴权交互。前端以 IDE 插件形式提供给用户。

## 架构概览

```
前端/IDE 插件
    │ HTTP (Cookie 鉴权 + HiDevLab 权限校验)
    ▼
Workspace 后端 (Spring Boot)
    ├── PlanController      → PlanQueryService          资源规格查询
    ├── EnvController       → EnvApplyService           环境申请
    │                       → EnvQueryService           环境查询
    │                       → EnvReleaseService         环境释放
    │                       → EnvInstallService         软件安装
    │                       → EnvStatusTransitionService 状态流转
    ├── TaskController      → TaskExecutionService      任务执行
    │                       → TaskQueryService          任务查询
    ├── EnvStatusScheduler  → 定时轮询非终态环境状态
    │                       → Redis 分布式锁防重复
    ├── HiDevLabClient      → HMAC 签名 + HTTP 调用
    └── ResourceUsageReportService  资源用量上报
        │
        ▼
HiDevLab 平台 (外部服务)
```

## 核心模块

### 资源计划查询 (Plan)

查询可用计算资源规格列表（CPU/NPU/内存/存储等），数据存储在 `workspace_plan_info` 表。

### 环境管理 (Env)

一站式作业的核心模块，涵盖环境完整生命周期：

| 接口 | 路径 | 说明 |
|------|------|------|
| 创建环境 | POST `/api/env/createEnv` | 申请计算环境，调用 HiDevLab 创建 |
| 查询状态 | GET `/api/env/getEnvStatus` | 查询环境当前状态和节点信息 |
| 释放环境 | POST `/api/env/deleteEnv` | 释放计算环境资源 |

**环境状态机**：

```
queuing → allocating → deploying
    ├── success → installing → success (安装完成，可用)
    │                       └── install_failed → 自动释放
    └── deploy_failed
用户主动释放: success → waiting_release → releasing → released
```

- `deploy_failed` / `install_failed` 自动触发释放流程
- `waiting_release` 由定时轮询驱动，根据 HiDevLab 实际状态决定执行释放或等待

**定时轮询**：`EnvStatusScheduler` 每隔 60s 轮询非终态环境，使用 Redis 分布式锁 `env:poll:global` 防止多实例重复轮询。

### 任务执行 (Task)

| 接口 | 路径 | 说明 |
|------|------|------|
| 执行任务 | POST `/api/task/runTask` | 在指定环境中异步执行命令 |
| 查询任务 | GET `/api/task/getTaskInfo` | 查询任务执行结果 |

任务通过 `AsyncTaskStarter` 在远程环境中通过 SSH 异步执行，不阻塞主线程。

### 软件安装 (Software)

环境部署成功后，`EnvInstallService` 触发 `SoftwareInstallService`，通过 SSH 在环境中逐个安装用户指定的软件。

### 资源用量上报 (Resource)

环境释放时，`ResourceUsageReportService` 上报资源使用记录（用户、规格、使用域、来源类型、申请/授予/释放时间等）。

## 关键数据模型

| 表 | 说明 |
|------|------|
| `workspace_plan_info` | 资源规格（CPU/NPU/内存/存储） |
| `workspace_env_record` | 环境记录（含 SSH 连接信息加密存储、完整参数 JSON 冗余） |
| `workspace_task_record` | 任务记录（含 PID、退出码、起止时间） |

## 关键设计决策

| 决策 | 说明 |
|------|------|
| HMAC 签名鉴权 | 与 HiDevLab 交互采用 AK/SK + HMAC-SHA256 签名 |
| 定时轮询 + 分布式锁 | 环境状态通过轮询 HiDevLab 获取，Redis 锁防重复 |
| 状态机模式 | `EnvStatusTransitionService` 统一管理环境状态流转 |
| 异步任务执行 | SSH 命令异步执行，不阻塞主线程 |
| 冗余存储 | `EnvRecord` 冗余存储 `resourceConfig` 和 `allocationResult`，便于重试和排查 |
| 加密存储 | SSH 密码和操作者 IP 使用 `CryptoUtil` 加密存储 |

## 鉴权方式

使用 `AuthInterceptor`，拦截 `/api/env/**`, `/api/plan/**`, `/api/task/**`：
- 从 Header 提取 `user` / `cookie` / `ip`
- 调用 HiDevLab `checkPermission(cookie)` 校验
