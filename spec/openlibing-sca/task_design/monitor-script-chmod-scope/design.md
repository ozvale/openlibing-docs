# monitor-script-chmod-scope — 技术设计

## 方案概述

`monitor.sh#delete_file()` 的权限收紧策略由"全盘脚本统一 `chmod 550`"改为"`*.py` 单独处理"：

- 全盘 find 保留其它脚本类型，移除 `-o -name "*.py"`；
- 新增一条仅作用于 `/opt/app/openlibing` 的 `*.py` 命令，权限收为 `400`。

## 架构决策

| 决策                                                                         | 理由                                                                                                                                                                                            |
| ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1 从全盘 find 中摘除 `*.py`，而不是给命令追加 `! -path "/usr/*"` 等排除条件 | 全盘 find 仍在为业务外脚本设权限，排除列表难以穷举；直接摘除 `*.py` 可精确消除 issue 指出的系统 Python 库误伤                                                                                   |
| D2 `*.py` 改为业务目录专项 find                                              | `/opt/app/openlibing` 是容器内唯一业务代码目录，`license-scanner`、`ossinfo-extraction` 均在其下，范围可控                                                                                      |
| D3 权限从 `550` 收紧为 `400`                                                 | 业务 Python 脚本由 `python3 <脚本>` 方式调用，解释器只需读权限；`400` 去掉 owner 执行位与 group 读权限，与同目录 `*.jar` 的 `400` 对齐，符合最小权限                                            |
| D4 保持原有执行顺序                                                          | 先 `find /opt/app/openlibing -type f -exec chmod 600`，再由全盘 find 处理其它脚本（`550`），最后 `.py` `400` / `.jar` `400` / `jre` `500`；后执行的规则覆盖先前结果，顺序决定最终权限，不能调换 |
| D5 其它脚本类型维持全盘 `550`                                                | issue 的风险论证仅针对 root 属主的系统 Python 库；`.sh` 等系统脚本改为 550 后 others 不可读，是否误伤未在本轮评估，故不动，避免扩大变更面                                                       |
| D6 不改 `monitor.sh` 触发时机                                                | `sleep 300` + 单次执行的既有设计服务于启动期证书/临时文件清理，调整时机与本次权限范围整改无关                                                                                                   |

## 修复前后对比

```
# 修复前
find / -path /proc -prune -o -path /sys -prune -o -type f \( \
    -name "*.sh" ... -o -name "*.py" -o -name "*.pl" ... \) -exec chmod 550 {} +

# 修复后（monitor.sh 当前 L17-L23）
find / -path /proc -prune -o -path /sys -prune -o -type f \( \
    -name "*.sh" -o ... -o -name "*.pl" -o ... -o -name "*.awk" \
\) -exec chmod 550 {} +
# issue #129: *.py 不做全盘 chmod 550（避免误伤 /usr 下 root 属主的系统 Python 库），仅收紧业务目录
find /opt/app/openlibing -type f -name "*.py" -exec chmod 400 {} +
```

## 涉及文件

| 文件         | 操作 | 说明                                                                    |
| ------------ | ---- | ----------------------------------------------------------------------- |
| `monitor.sh` | 修改 | 全盘 find 移除 `*.py`；新增业务目录 `*.py` 专项收紧，权限 `550` → `400` |

## 风险 & 缓解

| 风险                                                                    | 缓解                                                                                                 |
| ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 业务 `.py` 变为 `400` 后无法直接执行                                    | 业务链路统一通过 `python3` 调用，只依赖读权限；如后续需要 `./script.py` 直接执行需回调为 `500`/`550` |
| `*.py` 已不在全盘 find，`/opt` 之外若存在业务 Python 脚本将保持默认权限 | 当前业务代码只在 `/opt/app/openlibing`；新增业务目录需同步维护 monitor.sh                            |
| 其它脚本类型仍全盘 `550`，可能误伤系统 shell 脚本                       | 本轮未评估该场景；issue 仅覆盖 Python 库，保留现状避免扩大变更                                       |
| `chmod -R g-w,o-rwx /opt` 等既有命令仍作用于整个 `/opt`                 | 属既有行为，未在本轮变更范围内                                                                       |
| 权限规则依赖 find 执行顺序                                              | 保持原顺序：`600` → 全盘 `550` → `.py` `400` → `.jar` `400`；新增命令只能追加在 `550` 之后           |

## 跨仓影响

无。spec 文档归档 `openlibing-docs` 仓。

## 明确不在范围

- 全盘 find 中其它脚本类型的范围收窄（issue 验收第 1 条仅部分覆盖）。
- `monitor.sh` 触发时机与证书清理逻辑调整。
