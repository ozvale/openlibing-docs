# 流水线白名单支持按人员维度配置

## 需求背景

当前流水线白名单仅支持整体维度的触发控制（是否纳入平台管理），无法对单条流水线进行精细化权限管理。部分关键流水线需要限制为仅指定触发人员可以触发，以降低误触发风险。

## 功能描述

在现有「流水线白名单管理」页面基础上，为单条流水线增加「触发人员」维度配置：

- 项目管理员/CIE 可为已开启白名单的流水线配置触发人员名单（支持批量增减账号）
- 配置名单后，该流水线的页面手动运行、重试操作需同时满足：①具备现有流水线执行权限（角色校验）；②在触发人员名单内（AND 叠加）
- 未配置名单的流水线维持现状（不限制）
- 名单外用户在前端（列表执行图标、详情页运行/重试）按钮置灰 + 悬浮提示统一文案；后端 Service 层强制校验兜底

不做（一期）：

- 跨流水线批量配置触发人员（二期评估，触发条件见 design.md）
- PR 流水线评论触发场景（由历史需求 #120 覆盖）
- 定时任务、Webhook 自动触发的拦截（系统行为，不限制）

## 验收标准

- [ ] 白名单管理页每行可进入触发人员编辑弹窗（展示现有名单、单个删除、批量粘贴添加）
- [ ] 已配置名单的流水线：名单外用户手动运行/重试被拦截（前端置灰提示 + 后端强制校验）
- [ ] 未配置名单的流水线：行为与现状完全一致
- [ ] 仅项目管理员/CIE 可编辑名单；仅白名单已开启的流水线可配置
- [ ] 名单配置与变更记录操作日志（log_pipeline_whitelist）
- [ ] 存量流水线数据无需迁移（config_json 扩展字段，空=不限制）

## 影响范围

- 后端：openlibing-cicd（本需求实现仓）
- 前端：openlibing-cicd-web（参考 frontend-guide.md，由前端独立实现）
