## 一、通用资源权限端点（按钮点亮唯一数据源）

### 需求背景

前端操作按钮目前只从全局接口 `get-operation-permissions` 取点亮数据，该接口只统计默认权限组（id=0）的角色。权限组需求上线后，"绑定到自定义权限组的资源"的操作按钮必须按**资源级**口径判定，否则会出现：

- **组内成员按钮误灰**：chenning 是 test 权限组的 project_manager（默认组只有 project_member），打开 test 组绑定的流水线，执行/编辑按钮灰——但接口层实际放行（点击会被后端允许），按钮"撒谎"
- **修正方向**：绑定资源的按钮改用新的**通用资源权限端点**判定；未绑定资源维持现状

> 旧方案（从 getPipelineDetail 响应读 groupOperations 内联字段）**已废弃**，后端已拆除该三字段，前端请勿引用。

### 接口契约

#### 请求

```
GET /openlibing-framework/perm-group/query-resource-permissions
    ?projectId=3&resourceType=PIPELINE&resourceIds=<id1,id2,...>（可选）
```

| 参数           | 必填 | 说明                                                                                                        |
| -------------- | ---- | ----------------------------------------------------------------------------------------------------------- |
| `projectId`    | 是   | 项目 id                                                                                                     |
| `resourceType` | 是   | 资源类型，当前取值 `PIPELINE`（白名单校验，传错返回参数错误而非空数据）                                     |
| `resourceIds`  | 否   | 资源 id 列表（逗号分隔）。**详情页传单个 id；列表页不传**（返回全项目绑定关系，本地按行匹配，避免逐行请求） |
| `userId`       | —    | **无需传**，网关从 Cookie 解析注入（覆盖式，伪造不生效）                                                    |

#### 响应

```json
{
  "code": 200,
  "data": {
    "resourceBindings": { "<流水线id>": 1 },
    "groupOperations": { "1": { "pipeline_run": true, "pipeline_stop": true } }
  }
}
```

| 字段               | 类型                              | 语义                                                                              |
| ------------------ | --------------------------------- | --------------------------------------------------------------------------------- |
| `resourceBindings` | `Map<String, Long>`               | 流水线 id → 组 id，**只含已绑定资源**；某 id 不在此 Map = 未绑定 = 默认组         |
| `groupOperations`  | `Map<Long, Map<String, Boolean>>` | 组 id → 当前用户在该组的操作权限码（全局角色 admin 等的操作码已由后端合并进各组） |

#### 三个边界态（后端行为已固定，前端照此处理）

| 状态              | 后端响应             | 前端处理                                                                                            |
| ----------------- | -------------------- | --------------------------------------------------------------------------------------------------- |
| 匿名用户          | 200，两个 Map 均为空 | 全部按"未绑定"处理 → 走全局矩阵                                                                     |
| resourceType 拼错 | 参数错误（非 200）   | 开发期修正，**禁止兜底成"全部按默认组"**                                                            |
| 请求失败/超时     | 网络错误             | 降级：全部按"未绑定"处理（走全局矩阵），不白屏不误杀；按钮误亮不构成越权（接口层 fail-closed 挡截） |

### 前端改造点

1. **双通道判定函数（核心）**：

```
hasOperationPermission(auth, { resourceType, resourceId }) 判定规则：

resourceBindings 里有 resourceId？
├─ 有（绑定了组 G）→ groupOperations[G][auth] === true ? 按钮 : 灰
└─ 没有（未绑定）  → 现有全局矩阵 hasOperationPermission(auth)（逻辑零改动）
```

建议将通用端点调用 + 判定封装为共享 util（主/子应用两仓同签名引入）。

2. **列表页（pipeline.vue）**：进入列表时调一次通用端点（**不传 resourceIds**），`resourceBindings + groupOperations` 存 store 或组件状态；行内执行/停止/编辑等操作按钮按双通道规则逐行判定。
3. **详情页（Detail.vue）**：进入详情时调通用端点（`resourceIds=<该流水线id>`）；`getPipelineDetail` 响应已不含任何权限组字段（后端已删），详情页判定只能走通用端点。
4. **降级与匿名**：通用端点失败 → 按未绑定处理，按钮回退全局矩阵（不白屏）；匿名 → 同上（两个空 Map 天然走未绑定分支）。
5. **本期不做**：无权限气泡组版文案（另行安排，勿混入本次）。
6. **后端已删除的接口（勿对接）**：cicd 旧列表端点 `/openlibing-cicd/project/{projectId}/pipeline/group-permissions` 已由后端删除（功能与通用端点完全一致，属模块专用重复实现）；列表页数据源**唯一**为通用端点，如历史代码有对接旧端点的调用请一并迁移。

### 验收用例（BETA）

前置：framework 部署 + 管理中心配置新 URL 挂 `perm_group_enquire` 菜单（联调前确认，否则接口 403）。

| 用例          | 账号/条件                                             | 预期                                                                                             |
| ------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| F1 组内点亮   | chenning（test 组 project_manager）打开绑定流水线详情 | 通用端点返回 `groupOperations["1"]["pipeline_run"]=true` → 执行/编辑按钮亮，点击执行成功         |
| F2 列表页判定 | chenning 打开流水线列表                               | 绑定行按钮亮；未绑定行按钮维持全局矩阵判定（灰）                                                 |
| F3 组外灰     | 组外账号打开绑定流水线                                | 按钮灰；直接调操作接口返回业务码 4030001（组拒绝专用码，区别于存量 403，前端可据此分流组版提示） |
| F4 匿名       | 未登录访问绑定流水线详情                              | 空 Map → 按未绑定处理，操作按钮灰                                                                |
| F5 全局角色   | admin 打开绑定流水线                                  | groupOperations 含全量码，按钮全亮（无需前端特判）                                               |
| F6 降级       | framework 重启窗口                                    | 按钮回退全局矩阵判定，不白屏                                                                     |
| F7 未绑定回归 | 任意账号打开未绑定流水线                              | 行为与改造前完全一致（走全局矩阵）                                                               |

### 数据口径说明（联调常见问题预案）

1. **为何不改 get-operation-permissions 把组角色并进去**：全局矩阵是项目级、无资源上下文，并入组角色会导致"组内角色点亮全项目所有流水线按钮"（含未绑定的），按钮与接口口径倒挂。资源级判定必须按"这条流水线绑的组"计算，这正是通用端点存在的意义。
2. **组名哪里拿**：按钮灰时若需展示"未加入权限组「test」"，组名从 `query-binding`（按资源反查）或 `query-groups` 获取（本期仅判定可不含此）。
3. **admin 不需要特判**：后端已把全局角色操作码合并进 groupOperations，两通道对 admin 结果一致。

## 二、组拒绝响应业务码 4030001

组拒绝场景（绑定资源 + 已登录 + 非组内成员）操作接口响应体 `code` 为 **4030001**（区别于存量 403），前端据此单字段精确匹配分流组版无权限提示；`errorCode` 字符串（`PERMISSION_DENIED_BY_GROUP`）仅后端日志排障用，前端不消费。401 匿名提示登录（`LOGIN_REQUIRED_BY_GROUP`）、RPC fail-closed 500、存量 403 语义均不变。

## 三、绑定资源列表分页 + 筛选（契约变更，需适配）

### 背景

权限组管理弹窗的「绑定资源」列表原为全量返回（`query-bindings-by-group` 直接吐 List）。单组绑定达千级时全量渲染有性能风险，趁需求未上线统一改为服务端分页，并顺带支持筛选。

### 新契约

```
GET /gateway/openlibing-framework/perm-group/query-bindings-by-group
    ?projectId=&permGroupId=
    &resourceType=（可选）&resourceName=（可选）
    &pageNum=1&pageSize=20
```

| 参数                    | 必填           | 说明                                               |
| ----------------------- | -------------- | -------------------------------------------------- |
| projectId / permGroupId | 是             | 同旧契约                                           |
| resourceType            | 否             | 资源类型筛选，当前取值 `PIPELINE`；不传 = 全部类型 |
| resourceName            | 否             | 资源名关键词，模糊匹配 `resourceDisplayInfo`       |
| pageNum                 | **是（新增）** | 页码，从 1 起                                      |
| pageSize                | **是（新增）** | 每页大小，1-100，超限返回参数错误                  |

### 响应变更（结构变了）

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "count": 35,
    "bindings": [
      {
        "id": 12,
        "resourceType": "PIPELINE",
        "resourceId": "8866",
        "resourceDisplayInfo": "每日构建流水线",
        "permGroupId": 3,
        "operator": "y00845766",
        "createTime": "2026-09-18 10:00:00",
        "updateTime": null
      }
    ]
  }
}
```

与旧契约的差异（适配点）：

| 项        | 旧                      | 新                                                             |
| --------- | ----------------------- | -------------------------------------------------------------- |
| data 结构 | `data: [ ... ]`（数组） | `data: { count, bindings }`                                    |
| 分页      | 无（全量）              | 服务端分页，`count` 为过滤后总数                               |
| 排序      | id 升序                 | **id 降序**（最近绑定在前）                                    |
| 筛选      | 无                      | resourceType（下拉）+ resourceName（搜索框），两者可叠加取交集 |

### 前端改造点

1. 弹窗「绑定资源」列表接分页组件：`count` 计算页数，翻页改 pageNum 重查
2. 列表上方加两个筛选控件：资源类型下拉（当前只有"流水线"一项，仍建议保留控件，未来类型扩展时只加选项）、资源名搜索框（输入后重置回第 1 页）。**搜索框只搜名字**（匹配 `resourceDisplayInfo`，不匹配 resourceId）
3. 列表展示两列：**资源名**（主列，`resourceDisplayInfo`）+ **资源 ID**（次列，`resourceId`，32 位 UUID 较长，建议截断显示 + hover 全显/点击复制，或支持整列隐藏）
4. 筛选/翻页时机：控件变更即重查（该列表量级小，无需防抖纠结）

> 数据说明：`resourceId` 为流水线 UUID（绑定方传入的精确标识）；`resourceDisplayInfo` 为绑定时的资源名快照（资源后续改名不会同步，展示以快照为准）。DDL 允许 displayInfo 为空（首次绑定未传名时），列表需容忍空值（显示 "-" 或回退显示 resourceId）。

## 四、权限组说明文案（新增展示，文案待产品终审）

面向没用过权限组的用户补三处说明，位置与推荐文案如下：

### 1. 「权限组」列名旁小问号（tooltip，一句说完"是什么 + 边界"）

> 将资源（如流水线）单独绑定到某个组，仅组内成员可访问和操作；未绑定的资源不受影响。

### 2. 默认权限组行说明（默认组行内小问号）

> 项目创建时自动生成，不可编辑或删除；未绑定自定义组的资源均按默认权限组开放。

### 3. 管理弹窗顶部 info 提示（一次性展示，不占 hover）

> 白名单管理、成员同步等与具体资源无关的功能，仅以默认权限组内的角色为准；自定义权限组只对已绑定的资源生效。

> 精确性说明（前端写实现时注意，不用展示给用户）：自定义组**不剥夺**成员已有功能权限——用户可同时在默认组持有角色；文案语义是"自定义组不额外授予此类功能权限"，勿在前端逻辑里做"自定义组成员禁止使用白名单"之类的强制拦截。

### 文案状态

以上三段为后端+前端讨论推荐稿，**最终文案以产品确认为准**；位置（列名问号/行内问号/弹窗 info）是建议，前端可按组件库习惯微调。
