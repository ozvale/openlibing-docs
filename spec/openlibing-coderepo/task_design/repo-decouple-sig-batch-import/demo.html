代码仓管理优化 + SIG 仓一键同步 · 页面原型
本原型展示关键交互（整体思路：尽量规避多项目下统一代码仓配置项不一致）：①项目级「全局配置」弹窗（三页签公共账号 / GitCode 角色映射 + 代码仓录入配置区：sig-info.yaml 多路径配置（输入后即时校验路径存在性与 sig-info.yaml 文件）+ SIG 仓一键同步按钮（异步 + 分布式锁）与任务状态展示，任务状态在本弹窗内展示）；②手动录入（输入链接 blur 自动检测 → 命中其他项目已录入时表单自动复制上次录入配置、可修改，提交时配置不一致仅提示性告警、不覆盖其他项目行；默认分支从平台获取、只读展示）；③编辑代码仓配置（存在跨项目行且配置不一致时保存前提示性告警，用户确认后仅更新本行，不覆盖；开关类配置按「任一项目开启即生效」OR 聚合）；样式对齐 openlibing-web Element Plus 主色 #006be6。
场景一
项目级「全局配置」：三页签（项目公共账号 / GitCode 角色映射）+ 代码仓录入配置区（sig-info.yaml 多路径 + SIG 仓一键同步）
工具栏「导出仓库」右侧新增「全局配置」按钮，对当前项目下所有代码仓生效；原「gitcode 角色映射」「项目公共账号」两个按钮的能力并入本弹窗。
本弹窗能力由 /project-config/global-config 接口统一读写（ProjectConfigController）：项目公共账号（实现层仍存现有公共账号表）/ 代码仓录入配置（sig-info.yaml 多路径；GET 回显按平台分组——gitcode/gitee/github 外层 key，便于前端区分，提交时将各组 url 拍平为 URL 数组）/ GitCode 角色映射；路径输入后经 POST /project-config/validate-sig-path 即时校验；「SIG 仓一键同步」由 POST /project-config/sig-sync 触发（异步 + 分布式锁），任务状态经 GET /project-config/sig-sync/status 轮询（在本弹窗内展示）。

「SIG 仓一键同步」：从以上全部路径拉取 sig-info.yaml 并合并去重，仅同步尚未录入当前项目的仓库（已录入的不覆盖）；已存在于其他项目的仓库自动复制上次录入配置。默认参数：别名=repoUrl 中的 repo 名（项目内同名冲突依次尝试「repo名-平台名」、加数字递增）、责任人=代码托管平台创建人账号名、用途=自研源码、开源类型=主导开源、默认分支=从平台实时获取（不可修改）、公共账号令牌=项目级公共账号令牌；所有开关除「是否参与运营=是」外均默认为否。

Gitee / GitHub 页签：同样支持「项目公共账号」（可直接配置），但不含「角色映射」；「代码仓录入配置」（sig-info.yaml 多路径 + 一键同步）为跨平台独立区域，不归属任何页签。
