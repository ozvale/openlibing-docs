# Proposal：【openLiBing】ICSL安全送检排查及整改（openlibing-coderepo 侧）

> FE 需求：openlibing/openlibing-codecheck#372（<https://gitcode.com/openlibing/openlibing-codecheck/issues/372>）
> 整改仓：openlibing/openlibing-coderepo｜问题台账：`20261012091116_issues_export.xlsx`
> 性质：安全整改（需编码，免功能测试）｜归档时间：2026-10-29

## 需求背景

为 IT-ICSL 安全认证送检做准备，openlibing-coderepo 按六类来源完成安全问题的排查、定性与整改：

1. **漏洞挖掘**（外部/内部漏洞挖掘报告，编号 L-xxxx / M-xxxx / H-xxxx / I-xxxx）；
2. **安全威胁分析**（威胁建模输出的机制级隐患）；
3. **产品网络安全红线**落地指导与解读（红线条款逐条核对，编号 7.1.2 等）；
4. **计算IT应用安全编码要求**（XSS / 输入校验 / 异常泄露 / 整数溢出 / 混淆等）；
5. **华为Web应用安全开发规范 V3.2**（HTTP 响应头 / CSRF / SSRF / 敏感数据 / 日志 / 文件管理）；
6. **计算生态型应用 TOP 问题 / SENINFO 公网地址核查**。

累计 32 项安全问题，收敛为：**已合并 26 项（25 个 PR）/ 正在修复中 1 项 / 暂不修复 5 项（登记接受）**。本 spec 汇总排查结论与整改交付，作为送检材料的版本化底稿。

## 范围

### 做什么

- 逐项修复已确认的安全问题并留痕：issue 评论区记录修改方案，PR 描述关联 FE 需求 #372；
- 形成 26 项已合并问题的「问题 → 修改方案 → PR → 验证」证据链（见 `archive.md`）；
- 对暂不修复项登记接受理由，作为送检回复材料；
- 统一整改口径：确定性错误码按平台实测、脱敏分层防线、路径统一分段编码、凭据只传引用、降级方向按语义。

### 不做什么

- 不覆盖 openlibing-coderepo 之外的微服务（codecheck `EmailUtil`、cicd `EmailHelper` 等为同源拷贝工具类，需各自修复）；
- 不替代网关/APIG 侧整改（安全响应头注入、转发头清洗、机机接口登记、限流等由网关承担）；
- 不做功能需求开发，除安全校验拒绝非法输入外不改变业务语义与接口路径。
