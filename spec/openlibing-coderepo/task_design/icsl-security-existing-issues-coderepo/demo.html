一、治理思路：按链路分层收口

L1 出站 URL 公共出口ApiUrlUtil 分段编码 + 拒绝 . / ..
L2 入口坐标校验Webhook / SIG / token 探测入口白名单
L3 查询语义收敛LIKE 转义 + GraphQL variables
L4 暴露面收敛关闭 Swagger 调试端点（配置中心）

二、5 个存量问题与整改

#282 三方 API 出站路径段注入

CWE-22!306 已合入
修复前：不可信 owner/repo 直接进入平台 URL
GET /api/v5/orgs/../repos  → 路径被规范化，请求偏移到非预期端点
修复后：公共出口 + 入口双重防线
ApiUrlUtil 拒绝 . / ..；入口 isLegalSegment 白名单，非法 fail-closed

#286 仓库/分支列表 LIKE 通配符未转义

CWE-20!309 已合入
修复前：用户输入 % / _ 被当作通配符
where repo_name like concat('%', #{name}, '%')
输入 repo_% → 匹配范围被放大
修复后：统一 SqlLikeUtil 转义 + 显式 ESCAPE
SqlLikeUtil.escape(name)
... like concat('%', #{name}, '%') ESCAPE '\\'

#287 GitHub GraphQL 查询字符串拼接

CWE-943!310 已合入
修复前：外部取值拼进查询语句
query { repository(owner: "<owner>", name: "<repo>") { ... } }
修复后：固定语句 + variables
query($owner:String!, $repo:String!, $after:String) { ... }
variables: { owner, repo, prNumber, pageSize, after }

#288 Webhook 入口仓库坐标未校验

CWE-22!311 已合入
修复前：报文 owner/repo 未经校验进入下游
payload.namespace / owner.login 直接写 MQ、反查 token
修复后：三个入口统一校验
PrSync / Notify / PrSyncPush：
if (!RepoUrlUtil.isLegalCoordinate(owner, repo)) 记录 [SECURITY] 并丢弃

#225 生产 Swagger 调试端点暴露
