交互规则

与设计文档 2.2 / 2.3 / 2.6 一致

  • 选择「否」：展示不参与运营备注输入框，必填，最多 200 字。
  • 选择「是」：不展示不参与运营备注，保存时置空，不保留历史值。
  • 存量仓当前为「否」但无不参与运营备注：编辑任意字段保存时，必须先补充。
  • 存量仓当前为「是」：编辑保存不要求不参与运营备注。
  • 后端以「本次提交的开关值」判定；未提交开关时取数据库现值。
  • 未被编辑的存量仓不触发任何强制与提示。

联动规则

  • 左侧字段列表只有「是否参与运营」，不再单独放不参与运营备注项。
  • 勾选「是否参与运营」后默认「是」，与单个新增一致；选择「否」时才展示不参与运营备注并必填。
  • 选择「是」时不参与运营备注行隐藏并清空，与单个新增一致。
  • 批量编辑其他属性时，若所选仓库存在「否」且无不参与运营备注，会被拦截，需勾选开关设为「否」补充不参与运营备注。
  • 「全选」只包含左侧现有字段。
  • 批量保存仍为单条 SQL 更新，不产生 N 次请求。

设计要点

  • 新增列 repo_info.operation_remark VARCHAR(200) NULL，不建索引、不做存量回填。
  • 复用现有新增 / 编辑 / 批量编辑 / 列表查询接口，不新增 HTTP 接口与权限锚点。
  • 后端为最终校验闸门；前端负责联动展示与即时提示。
  • 开关为「是」时备注统一落库为 NULL，避免残留脏数据。
  • 列表接口返回 operationRemark；列表在「是否参与运营」列后新增「不参与运营备注」列；导出 Excel 最后一列同样包含「不参与运营备注」，既有导出列顺序不变。
