UT 覆盖率详情页来源流水线信息补齐 — 设计评审方案

对齐同仓 code metrics 既有先例（#219 已修）：插件标准 JSON 元数据一次补齐三个缺失字段（runNumber / pipelineName / detectionCompletedAt），后端解析入库展示链路就位后，UT 覆盖率详情页呈现完整来源信息——扫描时间、流水线名称 + 编号组合链接。

openlibing-coderepo · 后端 openlibing-web · 前端 upload-ut-action · 插件 关联 Issue #249 设计评审稿 v1.0
现状与痛点根因链路方案总览 关键设计决策交付范围风险与对策验收标准

1现状与痛点

详情页信息条「检查时间、流水线名称、流水线编号」三项恒空（Issue #249），用户无法判断覆盖率数据来自哪次检测、哪条流水线。同类问题 code metrics 下钻页已在 #219 修复，本次对齐同款口径。
缺失 ①

检查时间恒为空

detection_completed_at 自 2026-09-23 后全 NULL；早期少数「有值」记录是后端 parseDateTime 空值兜底 new Date() 产生的假时间（≈create_time），兜底已在 379bed9e 刻意移除后暴露数据源缺失。

缺失 ②

流水线编号恒为空

run_number 生产库全量 NULL（截图实证）——插件从未上报该元数据；前端已实现 #{{runNumber}} 渲染但存量记录仅显示「#」。

缺失 ③

流水线名称整链路缺失

报告 JSON 无该元数据、code_ut_record 无列、VO 无字段、上报 DTO 不携带——四层全缺，是本设计主体。

2根因链路

后端解析与入库链路大半已存在，数据源头（插件标准 JSON 元数据区仅 5 字段）缺失是唯一根因。

3方案总览

三仓三段：插件补数据源（核心），后端补一个 case + 一列，前端对齐 metrics 口径；上报请求契约零变更。
▎插件侧（upload-ut-action，核心改动）
index.js新增读取 ATOMGIT_RUN_NUMBER（编号）+ ATOMGIT_WORKFLOW（名称），手动触发无变量兜底空串
→
CoverageNormalizer元数据区 5 → 8 字段新增 runNumber / pipelineName / detectionCompletedAt（组装完成时刻打点）
→
dist 重建发版ncc 打包 + 版本升级
▎后端侧（openlibing-coderepo）
db.changelog加列code_ut_record.pipeline_name VARCHAR(255) 可空，preConditions 防重跑
→
readUtMetaField仅加 1 个 casecase "pipelineName"；runNumber / detectionCompletedAt case 已存在，数据到位即生效
→
saveUtRecord / VO实体、入库、UtCoverageFileDetailVO 各加 1 字段透出
▎前端侧（openlibing-web）
信息条对齐 metrics 口径label 统一「扫描时间」（移除同源重复的「检测时间」）+ 空值兜底 --
→
pipelineDisplayName组合链接名称+编号整体跳转，缺名称退化仅编号，双缺整段 --

4关键设计决策

7 个决策项，均以「单一数据来源 + 零契约破坏 + 向后兼容」为原则。
决策点方案理由与备选
数据来源pipelineName / runNumber / detectionCompletedAt 只进 OBS 标准 JSON 元数据，请求 DTO 不动与 runNumber / commitId 同口径，避免「请求参数 vs JSON 内容」双源不一致；metrics 先例（CodeMetricsPayload.pipelineName）同为 JSON 元数据
一次补齐三字段三个缺失元数据同源同模式一次补齐：流水线上下文 → JSON 元数据 → 后端既有解析 case → 入库runNumber / detectionCompletedAt 的解析与入库链路已存在（L283/L292、L444/L448），插件补数据后立即生效、后端零改动
向后兼容旧版插件 JSON 无新字段 → 流式解析 default: skipChildren 跳过 → 入库 NULL → VO 返回 null既有机制零破坏；旧后端对新 JSON 未知字段跳过、旧前端不读新字段，三环节任意顺序上线均兼容
detectionCompletedAt 打点语义取标准 JSON 组装完成时刻（此时扫描已完成），无上下文时不兜底假值，空串由后端归一 NULL吸取 379bed9e 教训：不用服务器当前时间冒充检测时间（失真展示 + 打乱取最近一次排序）
发版顺序后端先行 → 插件发版 → 前端发版（§2.5 灰度顺序）后端兼容旧 JSON；插件上线后新数据三要素齐全；前端发版后存量记录兜底 --，任一环节单独上线无破坏
存量数据run_number / detection_completed_at 历史 NULL 不刷数回填，详情页空值兜底 --分界线前少数记录为兜底假时间无真实语义，不清洗不参与展示口径；如需回填另行评估基于 pipeline_run_id 的离线任务（不在本次范围）
「检测时间」展示移除与扫描时间同源同值（同一最新记录），对齐 metrics 页口径去重UI 口径统一决策；若评审认为分支快照检测时间有独立价值可保留，不阻塞

6风险与对策

风险影响对策
Liquibase 加列（可空，单行 DDL）低锁表时间短；preConditions 防重跑（columnExists MARK_RAN）幂等安全
存量数据 run_number / detection_completed_at 全 NULL低数据源缺失所致（列一直存在），详情页空值兜底 --，不刷数回填
旧版插件共存期低新数据三要素为 NULL，前端空值兜底展示，无功能破坏
pipelineName 环境变量已闭环ATOMGIT_WORKFLOW，与 code-metrics-action ciContext.js GitCode 分支同源（已核实）；手动触发兜底空串，组合展示自动退化仅编号
UT 插件双平台适配中存量仅 GitCode（ATOMGIT_*）；GitHub 平台（GITHUB_WORKFLOW）适配为可选增强，随插件上 GitHub 需求另行评估
明细接口响应体膨胀低新增 1 个可空字符串字段，影响可忽略

7验收标准

新版插件上报后：详情页展示扫描时间、流水线（名称 + 编号组合链接），与 code metrics 下钻页信息口径一致。
旧版插件 / 历史记录（JSON 无新增字段）：明细接口 pipelineName / runNumber / checkTime 返回空，前端流水线段与扫描时间兜底 --，不影响既有功能；存量数据不做刷数回填。
上报契约零破坏：请求 DTO 不变，幂等清理与定位逻辑不变。
单测覆盖「有 pipelineName」「无 pipelineName（历史 / 旧插件）」两条解析与返回路径。
上报解析失败落失败记录的路径不受影响（失败记录不带 pipelineName，与 runNumber / commitId 同口径）。
