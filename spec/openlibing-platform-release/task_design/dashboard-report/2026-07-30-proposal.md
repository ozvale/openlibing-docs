# 运营看板数据上报功能

## 需求背景

OpenLibing 平台需要为运营团队提供发布评审流程的运营看板数据，用于监控各社区/项目的发布效率和质量。

当前痛点：
1. 发布评审流程的运营指标（评审单数量、成功率、平均时长等）缺乏自动化采集
2. 各社区（欧拉社区、通用流程项目）的数据源分散在 MongoDB 和 MySQL 中，需要统一采集和上报
3. 运营看板需要每日更新的历史数据，但缺乏历史数据补录能力

## 目标

实现 openlibing-platform-release 侧的运营看板数据上报能力，包含：

1. **每日定时上报**：每日凌晨定时采集发布评审相关指标，通过 Feign 调用 openlibing-framework 的上报接口
2. **历史数据补录**：支持对历史日期范围的手动数据补录
3. **统一指标口径**：对欧拉社区（MongoDB）和通用流程（MySQL）分别采集，产出 5 个统一指标

## 验收标准

### 功能验收

| 功能点 | 验收标准 |
|--------|---------|
| 每日定时上报 | 每日凌晨 1 点自动执行，采集昨日数据并上报 |
| 5 个指标采集 | 发布评审单数量、发布成功数、发布失败数、发布中数量、评审平均时长 |
| 欧拉社区数据源 | 从 MongoDB review_items/review_history 正确采集 |
| 通用流程数据源 | 从 MySQL release_review/release_review_history 正确采集 |
| 历史数据补录 | POST `/dashboard/backfill` 接口可触发指定日期范围的补录 |
| 补录任务状态查询 | 异步任务支持进度查询（taskId） |
| 分布式锁 | 定时任务使用 Redis 分布式锁防止多实例重复执行 |

### 质量验收

| 质量指标 | 目标 |
|---------|------|
| 单元测试覆盖率 | ≥80%（新增代码） |
| 单元测试通过率 | 100% |
| 代码规范 | 通过 checkstyle 检查 |
| 敏感词检查 | 无硬编码凭证、无安全漏洞 |

### 非功能验收

| 指标 | 要求 |
|------|------|
| 定时任务健壮性 | 单次失败不影响下次执行，异常有完整日志 |
| 补录任务幂等性 | 同一日期范围可重复补录，不产生重复数据 |
| 并发安全 | 补录任务同 taskId 不允许重复执行 |

### 依赖变更

无新增外部依赖，使用现有技术栈：
- Spring Boot 3.x
- MyBatis-Plus（MySQL 查询）
- MongoDB Template（欧拉社区查询）
- Redis Distributed Lock（定时任务分布式锁）
- OpenFeign（跨服务调用）

## 技术方案概要

采用 Spring 定时任务 + Feign 跨服务调用架构：

```
定时任务(1AM) / 补录接口 → DashboardReportSchedule
                                ↓
          ┌─────────────────────┼────────────────────┐
          ↓                     ↓                    ↓
    MongoDB(欧拉社区)      MySQL(通用流程)         补录回放
    review_items           release_review          历史日期
    review_history         release_review_history
          ↓                     ↓                    ↓
          └─────────────────────┴────────────────────┘
                                ↓
                    DashboardReportRequest
                                ↓
                Feign → openlibing-framework
```

详细设计见 `design.md`。

## 风险与依赖

| 风险项 | 影响 | 缓解措施 |
|--------|------|---------|
| MongoDB 查询性能 | 大量评审单的 history 循环查询 | 限制日期范围单日查询，后续可优化批量查询 |
| 补录任务内存存储 | 重启后任务状态丢失 | 适用于低频运维补录场景，可接受 |
| Feign 接口异常 | 单个社区上报失败影响整体 | 逐社区 try-catch，失败记录日志不中断整体流程 |
