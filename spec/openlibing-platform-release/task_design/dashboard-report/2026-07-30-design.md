# 运营看板数据上报功能 — 技术方案

**日期**: 2026-07-30

## 架构图

```
┌─────────────────────────────────────────────────────────────┐
│                    DashboardReportSchedule                   │
│  @Scheduled(cron = "0 0 1 * * ?") 每日凌晨1点              │
│  + doJob() → doJobWork() → reportForDate(yesterday, null)  │
│                                                             │
│  1. Redis 分布式锁 (dashboard_report_work_${env})           │
│  2. 获取全量社区列表 (欧拉 + 通用流程项目ID)                │
│  3. 逐社区采集指标 → 构建 DashboardReportRequest            │
│  4. Feign 调用 openlibing-framework 上报                    │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                   DashboardBackfillService                    │
│  @Async 异步执行                                              │
│  + createTask(request) → 返回 taskId                         │
│  + runBackfill(taskId, request) → 遍历日期范围 → 逐日上报   │
│  + getTask(taskId) → 查询任务状态                            │
│                                                              │
│  任务状态存内存 ConcurrentHashMap (重启丢失)                 │
│  状态: PENDING → RUNNING → SUCCESS/PARTIAL/FAILED            │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                   DashboardReportController                   │
│  POST /dashboard/backfill                                     │
│  → 参数校验 → createTask → runBackfill → 返回 taskId        │
└──────────────────────────────────────────────────────────────┘
```

## 接口设计

### 内部服务调用（Feign → openlibing-framework）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/manage/feature-dashboard/report` | 上报运营看板数据 |

**请求体** (`DashboardReportRequest`):

| 字段 | 类型 | 说明 |
|------|------|------|
| community | String | 社区名称（project_name） |
| feature | String | 特性名称，固定为"发布评审" |
| businessMetrics | Map<String, String> | 业务指标 key-value |
| userMetrics | Map<String, String> | 用户指标（当前为空 Map） |
| timestamp | String | 上报日期，格式 yyyy-MM-dd HH:mm:ss |
| repo | String | 仓库地址 |

### 外部 REST 接口（platform-release → 用户）

#### POST /dashboard/backfill

触发运营看板数据补录（异步执行）。

**请求体** (`DashboardBackfillRequest`):

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| userId | String | 是 | 操作用户 ID |
| startDate | LocalDate | 否 | 起始日期（默认 2023-12-06） |
| endDate | LocalDate | 否 | 结束日期（默认昨天） |

**响应**:

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "taskId": "uuid-without-dash"
  }
}
```

## 核心流程

### 1. 每日定时上报流程

```
doJob()
  → 获取 Redis 分布式锁 (key: dashboard_report_work_${env}, timeout: 5s)
  → doJobWork()
    → reportForDate(yesterday, null)
      → getAllCommunities() 获取全量社区
        → openeuler (固定)
        + releaseReviewDao.getAllDistinctProjectIds() (通用流程)
      → 逐社区循环:
        1. buildRequest(community, startTime, endTime, timestamp)
           → 若 community == "openeuler":
             → fillOpenEulerMetrics() → MongoDB 查询
           → 否则:
             → fillGeneralMetrics() → MySQL 查询
        2. openlibingFrameworkClient.reportDashboard(request)
        3. 成功 → successCount++, 失败 → failCount++
      → 返回 [successCount, failCount]
  → 释放锁
```

### 2. 指标采集逻辑

#### 欧拉社区（MongoDB）

| 指标 | 查询方式 |
|------|---------|
| review_count | review_items 集合，按 projectId + createTime 范围 count |
| publish_success_count | review_items 集合，status = "已通过" count |
| publish_fail_count | review_items 集合，status = "已驳回" count |
| publish_in_progress_count | review_items 集合，status = "评审中" count |
| avg_review_duration_hours | review_items 取 status = "已通过" 的 _id 列表 → review_history 查"新建评审单"和"测试repo操作类型:release"的 operateTime → 计算平均时长 |

#### 通用流程（MySQL）

| 指标 | 查询方式 |
|------|---------|
| review_count | release_review 表，按 projectId + createTime 范围 count |
| publish_success_count | release_review 表，reviewStatus = 3 count |
| publish_fail_count | release_review 表，reviewStatus = 2 count |
| publish_in_progress_count | release_review 表，reviewStatus = 1 count |
| avg_review_duration_hours | 取 reviewStatus = 3 的 id → release_review_history 查"创建评审单"和"发布"的 operationTime → 计算平均时长 |

### 3. 历史数据补录流程

```
POST /dashboard/backfill
  → 参数校验 (startDate ≤ endDate, endDate ≤ 今天)
  → DashboardBackfillService.createTask(request)
    → 生成 taskId (UUID)
    → 初始化 DashboardBackfillTaskStatus (PENDING)
    → 存入 taskStore (ConcurrentHashMap)
    → 返回 taskId
  → DashboardBackfillService.runBackfill(taskId, request)  (异步)
    → 状态校验: 非 RUNNING 才能执行
    → 遍历 [startDate, endDate]:
      → dashboardReportSchedule.reportForDate(currentDate, null)
      → 更新进度 (processedDays, successCount, failCount)
    → 最终状态: failCount > 0 → PARTIAL, 否则 SUCCESS
  → 返回 { taskId }
```

## 关键技术点

- **分布式锁**: 使用 `DistributedLockService.acquireLock(key, 5s)` 防止定时任务在多实例下重复执行
- **异步补录**: `@Async` 注解 + `ConcurrentHashMap` 内存存储任务状态（重启丢失，适用于低频运维场景）
- **Feign 调用**: 通过 `OpenlibingFrameworkClient` 调用 openlibing-framework 的 `/manage/feature-dashboard/report` 接口
- **日期防御编程**: `DashboardReportRequest` 的 Map 字段使用防御性拷贝 + unmodifiable 视图（修复 SpotBugs EI_EXPOSE_REP/EI_EXPOSE_REP2）
- **定时任务 Cron**: 通过 Apollo 配置 `job.cron.dashboard.report.task` 可动态调整，默认 `0 0 1 * * ?`

## 安全注意事项

- 无硬编码凭证：Feign 调用通过内部服务发现，不涉及 API Key/Token
- 参数校验：补录接口校验日期范围合法性（startDate ≤ endDate, endDate ≤ 今天）
- 并发安全：补录任务同一 taskId 通过 `synchronized` 防止重复执行
- 异常隔离：逐社区 try-catch，单个社区上报失败不影响其他社区
