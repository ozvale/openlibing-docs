# 发布评审撤回与历史操作记录增强 - 技术设计

## 1. 总体方案

本需求围绕评审单的撤回与操作历史两个场景，分四块改造：

1. **DDL 层**：`release_review_history` 新增 `project_id` 列，用独立 changeSet + `MARK_RAN` 兼容已存在表
2. **实体层**：`ReleaseReviewHistoryEntity` 新增 `projectId` 字段
3. **服务层**：新增 `withdrawReleaseReview`、`queryReviewHistoryPage` 方法；`createReleaseReview`、`startReleaseDecision` 插入历史时填充 `projectId`
4. **接口层**：Controller 新增两个 `@PostMapping` 接口

## 2. DDL 设计

`release_review_history` 表新增 `project_id` 字段，采用独立 changeSet，使用 `preConditions onFail="MARK_RAN"` + `columnExists` 判断列是否存在，不存在时执行 `addColumn`，向前向后兼容：

```xml
<changeSet id="20260805_add_project_id_to_release_review_history" author="disiqi">
    <preConditions onFail="MARK_RAN">
        <not>
            <columnExists tableName="release_review_history" columnName="project_id"/>
        </not>
    </preConditions>
    <addColumn tableName="release_review_history">
        <column name="project_id" type="VARCHAR(64)" defaultValue="" remarks="项目ID">
            <constraints nullable="false"/>
        </column>
    </addColumn>
</changeSet>
```

**设计要点**：

- 不修改原 `20260727_create_release_review_history` changeSet 内容，避免 Liquibase checksum 校验失败
- `MARK_RAN` 保证已存在 `project_id` 列的环境跳过执行，不报错
- `nullable="false"` + `defaultValue=""` 保证历史数据有默认值

## 3. 撤回接口设计

### 3.1 接口契约

```
POST /base/withdrawReleaseReview?userId={userId}&projectId={projectId}&id={id}
返回: DataResult<Integer>（评审单 id）
```

### 3.2 处理流程

```
1. 根据 id 查询评审单 reviewEntityOld
2. 评审单不存在 → 返回 failureMessage("该评审单不存在")
3. 校验权限：userId != reviewEntityOld.creatorId → 返回"无修改权限"
4. 更新评审单状态为 SAVE
   reviewEntityOld.setReviewStatus(ReleaseStatus.SAVE.code)
   releaseReviewDao.updateById(reviewEntityOld)
5. 删除该评审单对应的发布结果数据
   releaseResultDao.delete(
       new LambdaQueryWrapper<ReleaseResultEntity>()
           .eq(ReleaseResultEntity::getReviewId, id))
6. 插入操作历史（含 projectId）
   historyEntity.setProjectId(projectId)
   historyEntity.setReviewId(id)
   historyEntity.setOperationName("撤回评审单")
   releaseReviewHistoryDao.insert(historyEntity)
7. 返回 successData(id)
```

### 3.3 关键设计决策

| 决策点       | 方案                                                  | 理由                                                       |
| ------------ | ----------------------------------------------------- | ---------------------------------------------------------- |
| 撤回状态范围 | 所有状态均可撤回                                      | 满足用户「所有状态都可以撤回」的最终要求，避免状态机碎片化 |
| 评审项处理   | 不重置评审项状态，不触碰 `release_field_items_review` | 线上评审方式撤回后不要求重新评审，保留评审结果             |
| 发布结果处理 | 撤回时删除 `release_result` 对应数据                  | 保证评审单状态与发布结果一致，避免脏数据导致重复发布       |
| 权限校验     | 仅创建人可撤回                                        | 与原有 `addReleaseReview` 等接口的权限模型一致             |
| 事务         | `@Transactional(rollbackFor = Exception.class)`       | 涉及多表写操作，保证原子性                                 |

## 4. 操作历史分页查询设计

### 4.1 接口契约

```
POST /base/queryReviewHistoryPage?userId={userId}&projectId={projectId}
Body: ReviewHistoryPageQuery
  - reviewId: Integer（必填）
  - pageNum: Integer（必填，1-10000）
  - pageSize: Integer（必填，1-100）
返回: DataResult<PageData<ReleaseReviewHistoryVo>>
```

### 4.2 实现要点

```java
Page<ReleaseReviewHistoryEntity> page = query.toPageRequest();
Page<ReleaseReviewHistoryEntity> resultPage =
    releaseReviewHistoryDao.selectPage(
        page,
        new LambdaQueryWrapper<ReleaseReviewHistoryEntity>()
            .eq(ReleaseReviewHistoryEntity::getReviewId, query.getReviewId())
            .orderByDesc(ReleaseReviewHistoryEntity::getOperationTime));
List<ReleaseReviewHistoryVo> voList =
    ConvertUtils.sourceToTarget(resultPage.getRecords(), ReleaseReviewHistoryVo.class);
return DataResult.successData(new PageData<>(voList, resultPage.getTotal()));
```

**设计要点**：

- 继承 `BasePageReqVO` 复用分页参数校验（`pageNum`/`pageSize` 范围校验）
- 用 MyBatis-Plus `selectPage` + `LambdaQueryWrapper`，按 `reviewId` 精确匹配，`operationTime` 降序
- 用 `ConvertUtils.sourceToTarget` 转换 Entity → VO
- `PageData` 包装列表与总数

## 5. 历史表插入点填充 project_id

| 插入点     | 文件                                              | operationName | 说明             |
| ---------- | ------------------------------------------------- | ------------- | ---------------- |
| 创建评审单 | `ReleaseBaseServiceImpl.createReleaseReview`      | 创建评审单    | 评审单创建时记录 |
| 发布决策   | `ReleaseDecisionServiceImpl.startReleaseDecision` | 发布          | 发布执行时记录   |
| 撤回评审单 | `ReleaseBaseServiceImpl.withdrawReleaseReview`    | 撤回评审单    | 撤回时记录       |

三处均通过 `historyEntity.setProjectId(projectId)` 填充项目维度。

## 8. 风险与回滚

| 风险                     | 应对                                                    |
| ------------------------ | ------------------------------------------------------- |
| Liquibase checksum 失败  | 用独立 changeSet + MARK_RAN，不修改原 changeSet         |
| 撤回误删 release_result  | 仅按 `review_id` 删除，不影响其他评审单；事务保证可回滚 |
| 历史数据 project_id 为空 | DDL `defaultValue=""`，历史行填充空串，新插入显式赋值   |
