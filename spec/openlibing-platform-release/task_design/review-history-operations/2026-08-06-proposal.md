# 发布评审撤回与历史操作记录增强

## 需求背景

openlibing-platform-release 发布基础功能中，评审单提交评审后缺乏撤回能力，且发布评审操作历史表 `release_review_history` 缺少 `project_id` 项目维度字段，无法支撑按项目隔离的操作历史分页查询。

当前痛点：

1. 评审单提交评审后无法撤回，用户误操作只能走线下流程，易用性差
2. `release_review_history` 表只有 `review_id` 维度，缺少 `project_id`，跨项目查询/隔离不便
3. 发布结果表 `release_result` 在撤回评审单后未同步清理，残留脏数据可能导致重复发布或状态不一致
4. 缺少按评审单维度分页查询操作历史的接口，前端只能全量拉取

## 目标

围绕发布评审单的「撤回」与「操作历史」两个场景做端到端增强：

1. **评审单撤回**：所有状态的评审单均可撤回，撤回后状态回到 `SAVE`；线上评审方式撤回时不重置评审项状态，不要求重新评审
2. **撤回时清理发布结果**：撤回评审单时同步删除 `release_result` 表中该评审单对应的发布结果数据，保证评审单状态与发布结果一致
3. **历史表增加 project_id**：`release_review_history` 新增 `project_id` 字段，所有插入点（创建评审单、发布决策、撤回）填充该字段
4. **操作历史分页查询**：新增 `POST /base/queryReviewHistoryPage` 接口，按 `reviewId` 分页查询操作历史，按操作时间降序

## 验收标准

### 功能验收

| 功能点            | 验收标准                                                                                                 |
| ----------------- | -------------------------------------------------------------------------------------------------------- |
| 评审单撤回        | `POST /base/withdrawReleaseReview` 所有状态均可撤回，状态回到 `SAVE`                                     |
| 撤回不重置评审项  | 线上评审方式撤回时不触碰 `release_field_items_review` 评审项表，评审项状态保持不变                       |
| 撤回权限校验      | 仅评审单创建人可撤回，非创建人返回「无修改权限」                                                         |
| 撤回清理发布结果  | 撤回时 `release_result` 表中该 `review_id` 的数据被删除                                                  |
| 撤回历史记录      | 撤回操作在 `release_review_history` 表插入一条「撤回评审单」记录，含 `project_id`                        |
| 历史表 project_id | `release_review_history` 表新增 `project_id` 字段，DDL 向前向后兼容                                      |
| 插入点填充        | `createReleaseReview`、`startReleaseDecision`、`withdrawReleaseReview` 三处插入历史时均填充 `project_id` |
| 操作历史分页      | `POST /base/queryReviewHistoryPage` 按 `reviewId` 分页返回，按 `operationTime` 降序                      |
| 分页参数校验      | `pageNum`/`pageSize` 必填且在合理范围，`reviewId` 必填                                                   |

### 质量验收

| 质量指标       | 目标                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------- |
| Liquibase 兼容 | 已存在 `release_review_history` 表的环境升级时 `project_id` 列通过 ALTER ADD COLUMN 正常添加，不破坏原 checksum |
| 代码规范       | 通过 checkstyle 检查                                                                                            |
| 接口契约       | Controller 入参/出参与 Service 声明一致，`@Validated` 校验生效                                                  |

## 影响范围

- **业务仓**：`openlibing-platform-release`
- **涉及表**：`release_review_history`（新增列）、`release_result`（删除）、`release_review`（更新状态）
- **接口**：新增 `POST /base/withdrawReleaseReview`、`POST /base/queryReviewHistoryPage`
- **无外部接口契约变化**，均为内部能力增强
