# HPM包签名验证服务 — 技术方案

**日期**: 2026-07-02

## 架构图

```
用户/服务 → SignedVerifyController / 内部调用
                ↓
         SignedVerifyServiceImpl
                ↓
     ┌──────────┼──────────────┐
     ↓          ↓              ↓
  ZIP-HPM   二进制HPM       ZIP压缩包
  (ZIP条目)  (ASCII Hex)   (解压→.hpm)

     ↓          ↓              ↓

                ↓
         SignedVerifyVo
```

## 接口设计

### 外部 REST 接口

| 方法 | 路径 | 说明 | 限流 |
|------|------|------|------|
| POST | `/signed/verify` | 上传 .hpm + .crt 验签 | 漏桶 3tps, burst=5 |

**请求**: `multipart/form-data`
- `hpmFile`: .hpm 文件 或 .zip 压缩包（内含 .hpm）
- `crtFile`: .crt 证书文件

### 内部 Service 接口

```java
DataResult<SignedVerifyVo> verifySigned(byte[] hpmBytes, String hpmFileName,
    byte[] crtBytes, String crtFileName);
```

## 核心流程

1. **文件校验** — 后缀名（.hpm/ .zip/ .crt）、大小（HPM≤500MB, CRT≤1MB）
2. **格式识别** — 读取魔数判断 ZIP 还是 二进制 HPM
3. **三种处理路径**：
   - **ZIP-HPM**: 遍历 ZIP 条目，匹配签名文件（SIGNATURE, sig, p7s 等模式），CMS 验签
   - **二进制 HPM（openUBMC）**: 解析 ASCII Hex 头部描述表 → 提取 Manifest + CMS 签名段 → 构造 CMSSignedData
   - **ZIP 压缩包**: 解压 → 提取 .hpm → 递归走 ZIP-HPM 或 二进制 HPM 流程
4. **CMS 验签**: 依赖 Bouncy Castle 库，PKCS#7/CMS 标准
5. **结果组装**: 返回验证结果、算法、证书详情

## 关键技术点

- **Bouncy Castle** 初始化：`Security.addProvider(new BouncyCastleProvider())`
- **ZIP 魔数检测**: `{0x50, 0x4B, 0x03, 0x04}`
- **签名文件匹配**: 20 种 entry 名称模式 + 10 种后缀模式
- **限流**: `@LeakyBucketRateLimiter(rate = 3, capacity = 5)`
- **异步不支持**: 文件上传场景，同步处理

## 安全注意事项

- 文件路径穿越防护（ZIP 解压时）
- ZIP Bomb 防护（限制解压大小）
- Linux 命令注入校验
- 限流保护接口
