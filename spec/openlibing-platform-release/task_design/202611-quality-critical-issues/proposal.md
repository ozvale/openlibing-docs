## 需求背景

质量管理需要统计评审单涉及代码仓的关键问题数量与需求交付率，作为发布门禁评估输入。发起评审时触发统计；发布失败后支持按制品包粒度重试发布，避免整单重复发布。

## 指标定义

| 指标           | 统计口径                                                                                                                                       | 达标判定 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| 缺陷关键问题数 | issue 类型或 label 为 bug/缺陷，且优先级 ∈ {致命, 严重}（P0，兼容 critical/serious），且状态 = open                                            | = 0      |
| 资料关键问题数 | issue 类型为 资料，且优先级 ∈ {致命, 严重}（P0），且状态 = open                                                                                | = 0      |
| 需求交付率     | issue 全量拉取（state=all）；需求类 = 类型或 label 命中 需求/requirement；交付率 = 已关闭需求 issue 数 / 全部需求 issue 数 × 100（百分比整数） | = 100    |

> GitCode 平台 Issue 优先级实际为中文枚举：无优先级/提示/一般/严重/致命；P0 取"致命+严重"，实现保留英文 critical/serious 兼容。

**特殊值口径**：

| 场景                                    | 返回值                              |
| --------------------------------------- | ----------------------------------- |
| 评审单未保存制品信息（无制品包）        | 关键问题数与需求交付率均返回 **-1** |
| 有制品但需求 issue 总数为 0（分母为 0） | 需求交付率返回 **0**                |
| 有制品但无已关闭需求 issue              | 需求交付率返回 **0**                |

## 需求范围

1. 发起评审（submitReleaseReview）时异步触发统计，不阻塞评审提交。
2. 统计汇总接口：入参 projectId + reviewId，按制品包分组返回各代码仓缺陷/资料关键问题数与需求交付率，同时透出病毒扫描状态与验签结果。
3. 明细接口：入参 projectId + reviewId + repoUrl + metricType（defect/doc），按制品包分组返回 issue 名称 + 链接。
4. Redis 缓存改为**评审单维度 2 分钟**；miss/过期重算回写；查不到计 0。
5. 权限：projectId 走 @ProjectPermission；reviewId 校验归属；userId 从登录态解析；repoUrl 必须属于该评审单。
6. 发布决策支持**单个软件包重试发布**（retryArtifactRelease）：仅发布失败（RELEASE_FAILED）可重试，重试前清理该制品历史失败发布记录，成功记录幂等跳过。
7. tag 描述改为非必填。
